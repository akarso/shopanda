# PR-1080 — On-Save Reindex Trigger Generalization

Status: planned

## Summary

- Extend Phase 11 PR-1036's on-save reindex subscriber list to also fire on visibility-affecting changes this phase introduces.

## Why

PR-1079 gets the new fields into the index; this PR makes sure they stay fresh — a linked child getting assigned/revoked, or a bundle's rollup stock crossing zero, needs to trigger the same single-item reindex Phase 11 already built for price/stock/category changes, or the index silently drifts from reality.

## Scope

- Add event subscribers (same shape as `internal/application/cache/invalidation.go` and Phase 11 PR-1036) for: linked-child assignment created/revoked (Track D), bundle rollup-stock crossing the zero boundary (Track C), and any other visibility-affecting event introduced by this phase — enumerate the actual list during implementation by reviewing every place this phase computes `Purchasable`/`VisibleIn*`.
- Confirm whether `DownloadGrant` issuance (Track E) needs a reindex trigger — likely not, since it's post-purchase and doesn't affect catalog-facing visibility, but verify explicitly rather than assuming.

## Out Of Scope

- The subscriber mechanism itself (already built in Phase 11) — this PR only adds new triggers to it.

## Follow-up

- None further within Track F for this specific concern.
