# PR-1080 — On-Save Reindex Trigger Generalization

Status: done

## Summary

- Extend Phase 11 PR-1036's `IndexUpdateSubscriber` so Phase 12 visibility-affecting writes keep the search index fresh: leaf product/stock/price/variant changes also reindex parent bundles, and bundle-component / downloadable-file admin writes publish `catalog.EventProductUpdated`.
- Expand bulk stock reindex sets (`import:stock`, ERP `StockSyncService`) through `BundleParentLookup` so kits stay fresh without per-row stock events.
- Fan the same lookup into FPC / product-cache invalidation so kit PDPs drop when a leaf changes.
- Explicitly confirm `DownloadGrant` issuance/revoke and linked-child `ProductAssignment` create/revoke do **not** need reindex triggers (catalog index resolves with empty assignment context; grants are post-purchase).

## Why

PR-1079 denormalizes Type/Status and storefront-effective visibility axes into the index. Without new triggers, those fields drift: a dynamic bundle's `QuantityPositive`/`HasPrice` depend on leaf stock, prices, status/type, the component set, and "exactly one active leaf variant", and `MissingDownloadableFile` flips Purchasable when the first/last file is attached/removed — none of which previously reached `IndexUpdateSubscriber` for the parent product.

## Scope

- `catalog.BundleParentLookup` + `postgres.BundleComponentRepo.ListBundleIDsByComponentID`.
- `IndexUpdateSubscriber.WithBundleParents` — `HandleProductCreated` / `HandleProductUpdated` / `HandleStockUpdated` / `HandlePriceUpserted` / `HandleVariantCreated` / `HandleVariantUpdated` schedule reindex for parent bundles that include the leaf.
- `ProductCompositionAdminHandler.SetBus` — publish `catalog.EventProductUpdated` (Publish-then-`PublishAsync` fallback) after successful bundle component add/remove. Grouped membership is display-only and does not publish.
- `DownloadableFileAdminHandler.SetBus` / `SetProducts` — publish enriched `catalog.EventProductUpdated` after successful file attach/replace/remove. Grant-settings writes do not publish.
- Bulk stock: `StockImporter.WithBundleParents` / `StockSyncService.SetBundleParents` expand touched IDs before `Trigger`.
- FPC / product-cache: `WithBundleParents` on `FPCInvalidationSubscriber` and `InvalidationSubscriber`.
- Wire `WithBundleParents` / `SetBus` / `SetProducts` / bulk expand in `cmd/api/wire_services.go`, `import:stock`, and the standalone worker.

## Out Of Scope / remaining gaps

- The subscriber/debounce/job-queue mechanism itself (Phase 11).
- CSV `import:bundle-components` / `import:downloadable-files` batch reindex (accepted gap — manual/scheduled `search:reindex` remains the fallback; PR-1081 may tighten CSV consistency separately).
- Price CSV does **not** batch parent IDs in the importer — each row already publishes `EventPriceUpserted`, and the subscriber fans parents out. A huge import still pays per-product debounce cost (same as pre-1080 for leaves).
- Changing index-time Resolve to honor live assignment context (PR-1079 deliberately indexes with empty Assignment).
- Subscribing to `download.grant.*` or `assignment.revoked`.

## Design decisions

- **Assignment create/revoke → no reindex.** Index-time Resolve uses empty `AssignmentContext`, so `RequiresLinkedParent` products always index `Purchasable=false` regardless of unit assignment. Display axes are unaffected. Reindexing on assign/revoke would not change indexed fields.
- **DownloadGrant issued/revoked/reissued → no reindex.** Grants are post-purchase fulfillment; they do not feed `VisibilityInputs` / MissingDownloadableFile (that gate is join-table emptiness on the product).
- **Fan-out at the subscriber (and bulk Trigger sites), not every stock publish site.** Checkout already publishes a synthetic parent `EventStockUpdated` for dynamic-bundle reserve; admin Adjust / returns / expiry only publish the leaf. Extending product/stock/price/variant handlers once covers every producer (including checkout's leaf event). Debounce coalesces double parent scheduling from checkout's explicit parent publish. Bulk stock publishes no per-row event, so expand through `BundleParentLookup` before `Trigger`.
- **Publish-then-`PublishAsync` fallback for composition/downloadable.** Matches category assignment (PR-1036 Round 4): a sync `rewrite.Subscriber` failure must not skip async reindex/cache. Composition/file attach do not change slug.
- **`BundleParentLookup` is not on `BundleComponentRepository`.** Keeps ~20 test stubs free of a no-op method; Postgres repo implements both interfaces.
