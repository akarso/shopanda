# PR-1081 — CSV visibility columns + Phase 12 consistency tests

Status: done (visibility columns + create-only `status` + downloadable+active create guard + EventProductCreated on create + targeted in-memory consistency tests; full empty-catalog export→fresh-DB→diff deferred)

## Summary

- Product CSV gains create-only `visibility_catalog` / `visibility_search` / `visibility_individually` / `visibility_purchasable` (`auto|visible|hidden`) and create-only `status` (`draft|active|archived`), matching the `type` / bundle-modes pattern.
- Downloadable + `active` on CSV create is rejected (`DownloadableRequiresFileMessage`); path is draft → `import:downloadable-files` → admin activate. Exported active simple/virtual/bundle still round-trip active.
- Successful product-CSV creates publish `catalog.EventProductCreated` (Publish-then-PublishAsync); CLI also batch-Triggers created IDs when `ReindexService` is available — `import:products` is **not** on the RUNBOOK remaining-stale list.
- Cross-pipeline **in-memory** consistency tests for named Phase 12 CSV surfaces that ship today: product columns (type, status, modes, requires_linked_parent, visibility), additive composition / linked-eligibility / downloadable-files CSVs.
- Confirms and documents remaining non-CSV gaps (assignment units, downloadable grant settings, blobs, product↔category links, untested prices/stock/attributes/categories pipelines).
- Aligns naming/formatting conventions across tracks (lowercase enum tokens; `true`/`false` bools; case-sensitive visibility/status tokens like `type`).

## Why

PR-1052, PR-1066, PR-1073, and PR-1078 each added CSV support for their own track. Visibility override modes (PR-1055) shipped on the admin API/GUI but never on product CSV, so a fresh import silently reset every axis to `auto`. Lifecycle `status` likewise defaulted to `draft` on create, so storefront-effective visibility could not survive a create-only re-import even with forced-visible axes. This PR closes those product-CSV holes and adds targeted consistency coverage — it does **not** claim a full catalog export → empty database → field-by-field diff.

## Scope

- Product CSV columns `visibility_*` (four exact headers) and `status` — create-only; empty → `auto` / `draft`; mismatch on existing slug skips (including new SKUs in that group); reserved attribute keys.
- Phase 12 consistency tests (in-memory): product export→import field checks (incl. SKU / variant name / description / grouped+configurable / RequiresLinkedParent false); composition required=false round-trip; linked eligibility; downloadable metadata + omitted position/label retention + attach after product CSV create.
- Docs: PR spec, phase index/roadmap/README, DEVELOPER / MERCHANT / RUNBOOK notes + explicit remaining-gap list.

## Design decisions

- **Visibility columns are product CSV, not a new pipeline.** Exact headers `visibility_catalog`, `visibility_search`, `visibility_individually`, `visibility_purchasable` (not a `visibility_*` glob). Values mirror admin JSON axis tokens (`auto|visible|hidden`), **case-sensitive** like `type` (`HIDDEN` is rejected).
- **`status` is create-only**, same as `type`. Empty → `draft` (`NewProduct`). CSV does not update lifecycle on existing products.
- **Create-only writes** for visibility / status / type / modes / requires_linked_parent. Partial-merge updates stay on admin `PUT`.
- **Empty visibility → `auto`**, matching `DefaultVisibilityAxes()` / `NewProduct`.
- **Assignment and grant settings stay non-CSV.** Consistency suite covers catalog CSV surfaces only.
- **Bool convention:** product and composition `required` export `true`/`false`. Bundle `required` empty-on-import still means `true` (pre-existing hand-edit convenience); export always writes an explicit token so re-import is stable.
- **Downloadable + active on create rejected** — same message as admin; CSV never attaches files.
- **Create publishes `EventProductCreated`** — Prefer bus (Publish-then-PublishAsync); CLI also `WithReindex` batch Trigger of created IDs.
- **`applyImportVisibilityModes` create-path reset** — if any stored axis token is invalid before applying CSV cells, the helper resets all four axes to `DefaultVisibilityAxes()` then overlays non-empty CSV values. Intentional create-only behavior (matches empty→`auto` defaults); not a partial-merge path. Left unchanged.
- **No C4 / plugin / config change** — no new component, port, or env key.
