# PR-1081 — CSV Import/Export Final Consistency Pass

Status: planned

## Summary

- One pass across every existing import/export pipeline confirming every field this phase added round-trips correctly and consistently, not just within its own track's PR.

## Why

PR-1052, PR-1066, PR-1073, and PR-1078 each add CSV support for their own track's fields independently; this PR is where someone actually re-imports what was just exported, across the whole phase's field set at once, and confirms nothing was lost, mis-typed, or inconsistently formatted between tracks (e.g. one track using a bare string for an enum and another using a different casing convention).

## Scope

- Full round-trip test: export every product (including bundle/grouped/linked/downloadable), re-import into a fresh database, diff the result against the original.
- Cross-track consistency check: field naming/formatting conventions match across `type`, visibility axes, bundle/grouped composition, linked eligibility, and downloadable metadata columns.
- Fix whatever the round-trip test finds — this PR's scope is defined by its own test results, not a fixed list decided up front.

## Out Of Scope

- New CSV columns/fields — this PR fixes consistency in what already shipped, it doesn't add new import/export surface.

## Follow-up

- None further within Track F for CSV specifically.
