# PR-1061 — Grouped Domain Model

Status: planned

## Summary

- `grouped_member(group_product_id, member_product_id)` — members are fully independent, separately priced, separately orderable products.

## Why

A "grouped" display (several standalone products shown together on one page, each independently purchasable, no dependency between them) is a genuinely different mechanic from a bundle (fixed composition, usually one order line) and from Track D's linked products (many-to-many, dependency-gated purchasability). Modeling it separately keeps each mechanism's rules simple instead of one relation type trying to express three different behaviors via flags.

## Scope

- New table `grouped_member`, FK to `products` on both sides.
- Domain type `catalog.GroupedMember` + repository methods to add/remove/list members for a given group product.
- Explicitly document (in code comments and the storefront display logic) that grouping never affects a member's own `Purchasable`/visibility computation (PR-1055) — a grouped member is exactly as purchasable standalone as it would be outside the group.

## Out Of Scope

- Any pricing rollup for the parent — a grouped parent has no price of its own; see PR-1062.
