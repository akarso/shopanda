# PR-1052 — CSV Import/Export: Type Field

Status: done

> **Numbering note:** Phase 12 Track A — unrelated to any Phase 11 PR id.

## Summary

- Product CSV import accepts optional `type` (empty → `simple`; invalid → per-row + sibling-skip; slug-group type consensus fail-closed, with blanks counting as `simple` when any cell is set).
- Product CSV export includes `type`; attribute keys that collide with base headers are omitted (with a non-fatal `Result.Warnings` note); empty Type → `simple`, invalid Type emitted as-is.
- Case-sensitive values match the admin API (`Virtual` is rejected; use `virtual`).

## Why

Every other product field has CSV import/export support; without `type`, bulk catalog ops cannot set or round-trip the taxonomy from PR-1049/1051.

## Scope

- `importer/products.go`: `type` reserved in `knownColumns` (breaking for any prior free-form attribute column named `type` — rename that attribute); parse with `TrimSpace` only (no lowercasing); validate via `IsValid` / `InvalidTypeMessage`; explicit `TypeSimple` + `Validate()` before create; slug-group type consensus (all-empty → create `simple` / existing may add variants; blanks normalize to `simple` when any cell is set); existing products reject a non-empty CSV type that differs from stored; sibling rows of a failed slug group are marked skipped.
- `exporter/products.go`: `type` column after `description`; single `productCSVBaseHeader` drives reserved-key skip; reserved attribute keys omitted from CSV + one `Result.Warnings` note (not `Errors`); empty Type → `simple`; invalid Type written raw so re-import fails closed.
- `cmd/api/io_commands.go`: `runExportProducts` maps warnings to `ioOutcome.Warnings` / `export.products.warning` so exit status stays success when the CSV was written.

## Breaking / operator notes

- CSV header `type` is product taxonomy, not a variant attribute. Old files that used `type` as an attribute must rename that column.
- **Export** also omits attribute keys that collide with base columns (`name`, `slug`, `sku`, `description`, `type`, `variant_name`); those DB attribute values are not in the file — rename the attribute to round-trip them. Export reports omitted keys once in `Result.Warnings` (logged, does not fail the CLI).
- Column order changed (`type` inserted before `variant_name`); header-based parsers are fine.
- Type is create-only on import: re-importing an export that changed `type` for an existing slug errors explicitly rather than silently ignoring the column. Empty `type` on existing products still allows adding variants.
- Values are case-sensitive (`virtual`, not `Virtual`), same as admin create/update.

## Out Of Scope

- Mutating type on existing products via CSV (use admin API).
- Type-specific composition columns — later tracks / PR-1081.
