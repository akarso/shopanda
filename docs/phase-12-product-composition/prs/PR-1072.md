# PR-1072 — Returns Integration for Assigned Children

Status: planned

## Summary

- Return a single assigned ticket without touching the card's order line.

## Why

Direct extension of the card/ticket use case: a customer should be able to return one ticket without affecting the card it was assigned to (or other tickets on the same card). Extends Returns/RMA (Phase 6) the same way PR-1064 did for bundle components, at assignment granularity instead of bundle-component granularity — reusing that groundwork rather than building a second returns mechanism.

## Scope

- Confirm a ticket's order item is already returnable independently through the existing Returns/RMA domain (it should be, if it's a normal order item — a `RequiresLinkedParent` product doesn't change its order-line structure, only its purchasability computation).
- On return approval/refund: the associated `ProductAssignment` (PR-1069) transitions to `revoked` automatically — a returned ticket shouldn't remain `assigned` to a card it's no longer valid for.
- Decide during implementation whether returning a *card* with assigned tickets should be blocked, warned, or cascade-revoke those tickets' assignments — this needs an explicit merchant-facing decision, not a silent default either way.

## Out Of Scope

- Bundle component returns — already covered by PR-1064, this PR is Track D-specific.
