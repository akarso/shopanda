# PR-1078 — Admin API + CSV + GUI for Downloadable Management

Status: done

## Summary

- Admin HTTP for downloadable file attach/replace/remove and per-product grant settings.
- Admin HTTP for DownloadGrant list (customer / order item / order), revoke, and re-issue (Extend + ResetCount).
- Additive CSV `import`/`export:downloadable-files` for attachment metadata (not blobs).
- Admin GUI: product form `downloadable` section; grant list/revoke/re-issue on order and customer detail.
- Audit log entries for **writes only** (file attach/replace/remove, settings put/delete, grant revoke/re-issue). New `downloads.read` / `downloads.write` for Support.

## Why

Closes Track E's admin-reachability loop, same principle as PR-1066 (Track C) and PR-1073 (Track D) — support needs to re-issue a grant or attach a private file without direct SQL.

## Scope

- Admin API:
  - `GET`/`POST`/`PUT` `/api/v1/admin/products/{id}/downloadable-files` and `DELETE …/{assetId}` (`products.read` / `products.write`)
  - `GET`/`PUT`/`DELETE` `/api/v1/admin/products/{id}/downloadable-grant-settings`
  - `GET /api/v1/admin/download-grants?customer_id=` or `?order_item_id=`
  - `GET /api/v1/admin/orders/{orderId}/download-grants`
  - `POST /api/v1/admin/download-grants/{id}/revoke` and `…/reissue` (`downloads.read` / `downloads.write`)
- CSV: `import`/`export:downloadable-files` — columns `product_slug,asset_id,position,label` (assets must already exist under `private/downloads/`).
- Admin GUI: form section `downloadable` (type-gated); private upload from the section always sets `private_download=1`; grant panels on order/customer detail.
- Audit: write actions only (no successful GET list/settings audits).
- Migration `109` backfills `downloads.*` for Admin, Manager, Support (Editor omitted).

## Out Of Scope

- Nothing further within Track E — this is the closeout PR.
- Guest-order grant rebind on `LinkToCustomer`.
- GraphQL (PR-1082) and phase-wide CSV consistency (PR-1081).
- New config keys / plugin ports.

## Design decisions

- **`downloads.read` / `downloads.write` mirror assignments.** Support can revoke/re-issue without `products.write`; Editor manages file attach/settings via catalog write but cannot touch grants.
- **Reissue is one transaction.** Lock the grant row `FOR UPDATE`; reject `expires_at` not strictly after now; extend expiry; when `reset_count=true` CAS-reset count (and apply a lower `download_limit` only after count is 0 so Validate never sees count > limit); roll back on failure. Publishes `download.grant.reissued`. Default `reset_count=true`. A `WithTx`-capable grant repo **requires** `WithTxStarter` (fail closed, same as Issuer); mem/test repos without `WithTx` keep the unlocked path.
- **Replace retargets grants by asset id.** In the same TX as the join swap, `RetargetAsset` rewrites `download_grants.asset_id` old→new for **all** rows on that asset (live and expired) — no `order_items`/`variants` product join — so bundle leaf grants minted under the parent unit move with direct SKUs. **Shared-asset fail-closed:** before retarget, count other `downloadable_files` rows for `old_asset_id`; if any other product still attaches it, return 422 unless `global_retarget=true`. Without the flag this does **not** rewrite "this product only" — it refuses. With the flag, every grant on the blob moves. Response returns `grants_moved` / `grants_revoked`. Conflict rules: delete expired `(order_item_id, new_asset_id)` blockers first; prefer moving expired rows when UNIQUE allows; delete expired old rows still blocked by a live new grant (those grant IDs **vanish** — no revoke event); revoke only live old grants that still conflict with a **live** new grant (publish `download.grant.revoked` after commit; notifier required when step 4 revokes — fail closed). Missing `grantRetarget` on a real replace fails closed. Omitted `position`/`label` preserve the previous join values; the SPA sends them on replace and prompts for `global_retarget`.
- **`download.grant.reissued` is webhook-subscribable.** Registered next to `download.grant.issued` / `download.grant.revoked` in `domain/webhook.SupportedEvents` (admin webhook catalog + outbound dispatcher).
- **Additive CSV, not product CSV columns.** Attachment metadata uses asset UUIDs (no slug); same pattern as composition/linked CSV. Import counts `Updated` vs `Added`. PR-1081 folds consistency.
- **Private upload from the downloadable section always sets `private_download=1`.** Matches PR-1077 Attach prefix gate; media library checkbox remains for ad-hoc uploads.
- **Grant settings are products.write.** Overrides are catalog-time; issuance still merges with global `catalog.downloadable` defaults. Settings GET 404s when the product is missing; DELETE is idempotent when no override exists.
