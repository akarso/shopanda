# PR-1084 — Public catalog price and availability

Status: done

## Summary

- Public catalog reads attach a sibling offer (`amount`, `currency`, `variant_id`, `in_stock`) so a headless client can render a price and on-hand availability without a second lookup.
- Search does not return those fields. Meili never indexes them, and the Postgres search SQL does not match the catalog rule.
- One product that fails a dynamic rollup keeps whatever stock it resolved and gets `amount: null`. A failed batch read fails a list. On a product page it is logged and `meta.offer` is left unset so the page still renders.

## Why

The spec stays in phase 12. That phase owns the composition pipeline this offer plugs into. Phase 17 (PR-1500–1540) is product packaging, not catalog reads. This is a follow-up after the PR-1083 closeout, not a reopening of Track F.

## Scope

- `PublicOffer` on product list, product detail, public variant list, public variant get, and category product list.
- Dynamic-price bundles sum required components. Dynamic-stock bundles use the component rollup. Grouped parents have no price and are out of stock.
- `in_stock` is on-hand quantity greater than zero (or that rollup). Reservations already reduced `stock.quantity`.
- Guest catalog responses stay `Cache-Control: public, max-age=300`. Offers are advisory inside that window.
- `GET /api/v1/products` now copies the request store into the listing pipeline, so price indication uses the store currency.

## Out of scope

- Search `price` / `in_stock`, including teaching Meili to index them and fixing the Postgres search query that subtracts reservations a second time. HTML search cards still read the engine's own fields.
- A batched SQL walk of every bundle leaf on a listing page. The request uses the unit-price cache. PDP JSON-LD and price indication reuse `meta.offer` instead of resolving again. Per-bundle leaf walks remain.
- The cart purchasable-axis gate (visibility, linked parent, downloadable files). `in_stock` is the quantity check only.
- A truncated flag for the 100-variant card cap. The variant list query caps at 100, so a product with exactly 100 variants cannot be told apart from a longer one.
- Duplicating store-then-global price fallback in the offer layer. `PriceRepository.FindByVariantsCurrencyAndStore` already does that in one call.
- Admin reads. Variant and category product lists under operator scope (`catalog.BypassProductVisibility`) do not attach offers. Admin prices can include draft leaves; the storefront offer does not.
- `AggregateOffer`. JSON-LD mirrors the one card price. Availability on that Offer can come from a different variant than the price.
- A currency exponent table. JSON-LD and Omnibus both format minor units with two decimal places (`amount / 100`).
- Folding `Stock` and `Stocks` into one field. `ResolveAvailableQty` takes `inventory.StockRepository`. The batch port is the listing read.
- `.idea/`, `.gitattributes`, and the untracked phase 15 / phase 16 directories.

## What changed

| Area | Change |
| --- | --- |
| Composition | `OfferSources.ProductOffers` / `VariantOffers`, listing and product offer steps. `StockBatch.GetStocks` is a required port. `Components` is required before the step runs. Per-product dynamic failures are logged. Stock stays when it resolved. Amount stays null. |
| HTTP | Product list fills the composition store. Category lists call the offer resolver and do not run the rest of the listing pipeline. Offers attach only outside operator scope. |
| PDP reuse | Product offer runs before JSON-LD and price indication. Those steps read `meta.offer` when it is present. JSON-LD has no private price or stock lookup. It emits an Offer only when `amount` is set. The price is the cheapest considered variant. Availability is the card flag and can come from another variant. Omnibus still skips dynamic headlines. Listing price indication reads `meta.offers` and still loads history. |
| Failures | A list batch failure (`GetStocks`, variant list, price batch) fails the request. The product page logs that error and does not write `meta.offer`. Price indication and JSON-LD see the failure flag and do not walk variants. The flag is stripped from the public meta map. A validation warning and a later stock error for the same product are both logged, once each. A cancelled context is not logged. |
| Admin | Offers attach only when `catalog.BypassProductVisibility` is false. That covers public variants and public category lists. Admin category product lists do not get `meta.offers`. |
| Search JSON | No `price` or `in_stock`. |
| Postgres | `StockRepo.GetStocks` for the batch port. |
| OpenAPI | `PublicOffer` (`amount` nullable integer), referenced from the five catalog operations. Search example has no price. |
| Guides | `HEADLESS.md`, `DEVELOPER.md`, `EXTENSION_POINTS.md`. |
| C4 | Updated — composition pipeline description includes the catalog offer. |
