# PR-1071 — Admin API for Assignment

Status: planned

## Summary

- List/create/revoke assignments.
- "This card's assigned tickets" and "this ticket's current card" views.

## Why

PR-1069 and PR-1070 build the domain and the flow; this PR is what makes assignment state actually operable by an admin — support/ops needs to see and correct assignment state without direct SQL, same reachability principle as every admin-surface PR in Phase 11.

## Scope

- `GET /admin/products/{cardId}/assignments` — list tickets assigned to a card instance.
- `GET /admin/products/{ticketId}/assignment` — a ticket's current assignment, if any.
- `POST /admin/assignments` — admin-initiated assignment (the admin side of PR-1070's post-purchase path).
- `POST /admin/assignments/{id}/revoke` — matches the `revoked` state transition from PR-1069, not a delete.
- Audit log entries for create/revoke, matching the pattern established for jobs retry/cancel (Phase 11 PR-1029) and store-credit issuance.
- New `RBAC` permissions if the existing `products.write`/`products.read` split doesn't cleanly cover this — decide during implementation whether assignment needs its own permission or fits under the existing product permissions.

## Out Of Scope

- Returns integration — PR-1072.
- CSV/GUI — PR-1073.

## Follow-up

- PR-1072, PR-1073 build on this PR's API.
