# PR-1059 — Visibility Admin GUI

Status: planned

## Summary

- Per-axis toggle + override-mode indicator (computed vs. forced) on the product edit form.
- A "why is this hidden" explanation next to the toggle when the computed default is driving a `hidden` state.

## Why

Four independent axes plus an override mode is a lot for a merchant to reason about blind — without surfacing *why* the computed default landed where it did (missing price? zero stock? no store assignment?), this becomes a confusing feature instead of a useful one.

## Scope

- Product edit form section: four toggles (one per axis), each showing `auto (computed: visible/hidden)` or the forced override state, wired via PR-1053's type-agnostic form-section mechanism (this section applies regardless of product type).
- The "why hidden" explanation: surface which specific condition(s) in PR-1055's default rule are currently failing (e.g. "quantity is 0," "no price set for the active store/currency"), not just a flat "hidden."

## Out Of Scope

- None specific — this is the GUI closeout for Track B.

## Follow-up

- None within this phase's core scope; Track D's assignment-driven purchasability (PR-1068) will want its own explanation surfaced here too — confirm during implementation whether this PR's "why hidden" mechanism is generic enough to absorb that without a rework.
