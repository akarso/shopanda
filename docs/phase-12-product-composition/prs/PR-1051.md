# PR-1051 — Admin API Type Field Support

Status: planned

## Summary

- Product create/update admin endpoints accept and validate `type`.
- List/filter endpoints accept a `type` query filter.

## Why

PR-1049 shipped the field and its domain-level validation; this PR is the HTTP plumbing so an admin (or a CSV import, PR-1052) can actually set it. `bundle`/`grouped`/`configurable`/`downloadable` don't have their full behavior yet — that's later tracks — this PR only makes the field itself reachable.

## Scope

- `internal/interfaces/http/admin/product_admin.go` (or wherever product create/update live): request struct gains `Type`; validation delegates to the domain-layer check from PR-1049, mapped to a `422` via the existing `apperror.Validation` convention.
- Product list endpoint: `?type=bundle` filter, following the same pattern as existing filters.
- `openapi.yaml`: document the new field and filter parameter on the existing product paths.

## Out Of Scope

- Type-specific request fields (bundle components, downloadable files, etc.) — those land with their own tracks' admin API PRs.
