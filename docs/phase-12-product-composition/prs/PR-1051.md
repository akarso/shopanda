# PR-1051 — Admin API Type Field Support

Status: planned

## Summary

- Product create/update admin endpoints accept and validate `type`.
- List/filter endpoints accept a `type` query filter.

## Why

PR-1049 shipped the field and its domain-level validation; this PR is the HTTP plumbing so an admin (or a CSV import, PR-1052) can actually set it. `bundle`/`grouped`/`configurable`/`downloadable` don't have their full behavior yet — that's later tracks — this PR only makes the field itself reachable.

## Scope

- `internal/interfaces/http/admin/product_admin.go` (or wherever product create/update live): request struct gains `Type`; set it on the product **before** the existing `Validate()` call from PR-1049, mapped to a `422` via `apperror.Validation`.
- Product list endpoint: `?type=bundle` filter, following the same pattern as existing filters; add an index on `products.type` with the filter (avoid seq-scan).
- `openapi.yaml`: document request/filter `type`, and note that product responses **already** expose `Type` from PR-1049 (additive JSON field on create/get/list/update).

## Out Of Scope

- Type-specific request fields (bundle components, downloadable files, etc.) — those land with their own tracks' admin API PRs.

## Follow-up

- PR-1052 — CSV import/export.
- PR-1053 — admin GUI.
