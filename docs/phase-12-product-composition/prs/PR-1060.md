# PR-1060 — Bundle Domain Model

Status: planned

## Summary

- `bundle_component(bundle_product_id, component_product_id, quantity, required bool)`.
- A bundle is one order line by default (see PR-1064 for the itemized alternative).

## Why

Catalog-time composition — a fixed set of components sold as one unit — has no existing analog in this codebase (`Variant` is SKU variation of *one* product, not composition of *several*). This PR is the relational model only; pricing (PR-1062) and stock (PR-1063) rollup come after.

## Scope

- New table `bundle_component`, FK to `products` on both sides, `quantity` (int, default 1), `required` (bool — `false` for an optional/swappable component the customer selects at purchase time).
- Domain type `catalog.BundleComponent` + repository methods to add/remove/list components for a given bundle product.
- Validation: only a `Type = bundle` product can have components; a component product cannot itself be `Type = bundle` (nesting is out of scope — see below); a bundle cannot reference itself as a component (cycle guard).
- Bundle nesting (a bundle containing another bundle) is explicitly out of scope for this phase — see the phase `ROADMAP.md`'s "Out of scope" table.

## Out Of Scope

- Pricing rollup — PR-1062.
- Stock rollup — PR-1063.
- Bundle nesting.

## Follow-up

- PR-1062, PR-1063 build directly on this PR's model.
