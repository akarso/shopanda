# PR-1079 — Search Index Schema Extension

Status: planned

## Summary

- Add `Type` and the visibility axes (PR-1055) to what Phase 11's indexer writes.
- Filter search/catalog results on `Purchasable`/`VisibleInSearch`/`VisibleInCatalog`.

## Why

Without this, an unassigned linked-child ticket (Track D) or a hidden product (Track B) still shows up in search results even after every other enforcement point in this phase is correct — the index is a separate data copy that needs its own filter, not something that inherits filtering from the primary read path automatically.

## Scope

- **Hard dependency:** Phase 11 Track B (search indexing rework, PR-1033–1038) must have already shipped — this PR extends `search.Product` and the indexer additively, per the forward-compatibility note already added to Phase 11's `ROADMAP.md`, rather than reworking the index schema a second time.
- Add `Type` and the four visibility-axis fields to `search.Product` and both `SearchEngine` implementations (Postgres tsvector, Meilisearch core plugin).
- Query-time filtering: exclude non-`VisibleInSearch`/non-`Purchasable` (where purchasability is relevant to the query context) results.
- Reindex existing products once the new fields land (a one-time full reindex, using Phase 11's own reindex-as-a-job mechanism, PR-1033).

## Out Of Scope

- Bundle/grouped/linked-specific faceting (e.g. "show only bundles") — a plausible future enhancement, not required for this phase's core goal of not leaking hidden/unassigned products.
