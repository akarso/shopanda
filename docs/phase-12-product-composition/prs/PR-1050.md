# PR-1050 — Type-Driven Shipping/Tax Requirements

Status: done

> **Numbering note:** Phase 12 Track A — unrelated to any Phase 11 PR id.

## Summary

- `virtual` and `downloadable` products never require a shipping method (`Type.RequiresPhysicalShipping`).
- Shared `checkout.CartRequiresPhysicalShipping` (fail-closed) drives both `SelectShippingStep` and storefront UX.
- Digital-only carts skip shipment creation and the storefront shipping step; mixed carts still require a method.

## Why

Every product previously implied a shipping method. Virtual cards and digital downloads should not force checkout to ask for/charge shipping. This derivation is also the seam Track E’s digital-goods VAT (PR-1076) will consume — no VAT logic here.

## Scope

- `catalog.Type.RequiresPhysicalShipping` — `false` only for `virtual`/`downloadable`; otherwise `true` (including composites until Track C rollup). Empty type lists fail closed (`AnyRequiresPhysicalShipping` → true).
- `checkout.CartRequiresPhysicalShipping` — one helper for step + storefront; empty cart / lookup errors / missing product fail closed.
- `SelectShippingStep` skips provider/shipment for digital-only (`shipping_not_required` + `shipment_selected` meaning step done).
- Storefront: address primary → payment when digital-only; progress omits Shipping; confirm tolerates nil selected rate.
- Default theme `checkout_address.html` uses `{{ .PrimaryAction }}` and button copy (same as the test theme) so digital carts post to `/checkout/payment`, not only soft-skip via `CheckoutShipping`.
- Full shipping address remains required for digital-only carts (billing/tax destination) — accepted tradeoff, not relaxed here.

## Out Of Scope

- Bundle/configurable shipping rollup from children — Track C.
- Digital-goods VAT category — PR-1076.
- Changing how physical shipping is *priced* (including excluding digital qty from `CalculateRate`) — follow-on.
- Dropping address collection for digital-only — intentional keep for tax/billing.
