# PR-1065 — Omnibus catalog history for kits

Status: done

## Summary

- Dynamic bundle headlines stay exempt on PDP (`PriceIndicationStep`) and PLP (`ListingPriceIndicationStep`). The skip does not depend on `explode_order_lines`. JSON-LD already omits the Offer for `pricing_mode=dynamic` (PR-1062).
- Checkout does not call `PriceHistoryRepository.Record`. `CreateOrderStep` has no history dependency. Sale-time snapshots stay forbidden: exploding a kit does not append `price_history` for the parent or the leaves.
- Admin price PUT records a snapshot on the same transaction as the upsert, matching CSV `upsertWithHistory`. A nil history repo, or one that cannot join the transaction, fails the PUT closed. That is the merchant path that gives a leaf or component SKU its 30-day history. Catalog snapshots are written on CSV import and admin PUT, not at sale time.
- Omnibus reads that catalog history per SKU:
  - fixed kit PDP/PLP → the parent variant's `price_history`
  - dynamic kit PDP/PLP → no block
  - leaf (component) PDP/PLP → that variant's `price_history`
  - explode does not change any of the above
- An exploded order keeps tax on the order. `Order.TaxAmount` is the pipeline `TaxTotal` already on the pricing context, and `PayableAmount` is the order total plus that tax (no store credit in the explode test). That copies the snapshot; it does not check VAT rules. `order.Item` has no tax field. Per-line tax is PR-1076.

## Why

Itemized sale does not create a new price. The component already has a catalog price, and a merchant price change is what appends `price_history`. Writing the sale unit into history would treat checkout as a price change and would move the prior-30-day low.

A dynamic bundle's display price is the sum of required component prices at read time (`ResolveUnitPrice`). That sum is not stored on the bundle variant. EU Omnibus lowest-30-day disclosure is the prior price of the offer that is being reduced. The offers that have history are the leaf SKUs and, for a fixed kit, the parent variant. A headline block on a dynamic kit would compare a computed sum with one SKU's history, or would need a history of sums that checkout does not record.

## Order tax snapshot

`CreateOrderStep` calls `Order.SetTaxSnapshot(country, PricingContext.TaxTotal)` after the lines are built. Explosion replaces the parent line with leaf lines and does not split tax onto those lines. `order_items` has no tax column. `PayableAmount` is `TotalAmount + TaxAmount − store credit`. The explode test checks that copy. It does not check VAT rules. Per-line tax class and digital-goods VAT stay in PR-1076.

## Scope

- Admin `PUT /products/{id}/variants/{variantId}/price`: `WithHistory`, `Record` inside the price transaction, fail closed when history is unwired.
- Checkout: explode does not call `Record` and does not change pre-seeded snapshots. `TaxAmount` equals `TaxTotal`. `PayableAmount` matches the exploded order total plus that tax. Order items have no tax field.
- Composition: dynamic PDP and PLP return no indication with explode on and off. A fixed non-explode bundle uses the parent variant's history. `LowestSince` is store-scoped. A mixed PLP (dynamic kit + normal product) skips the kit and still indicates the normal product.

## Out of scope

- Per-line VAT / tax class (PR-1076).
- Admin GUI / CSV for explode (PR-1066).
- Sale-time price snapshots.
- Wiring `ResolveUnitPrice` into PDP indication or JSON-LD.

## Verification results

| Check | Result |
| --- | --- |
| Explode `CreateOrderStep` inserts `price_history` | No. `CreateOrderStep` has no `PriceHistoryRepository` field. The price repo it holds does not `Upsert` (count stays 0). Explode still writes the leaf lines. |
| Dynamic PDP / PLP, explode true and false | No indication. History is not read. |
| Fixed bundle, explode false | PDP and PLP indication use the parent variant's lower 30-day price (29.99). The variant list is only the parent, so a leaf snapshot is not in the fixture. |
| Store-scoped history | PDP `LowestSince` is called with the active store. A cheaper global snapshot for the same variant is not the indication. |
| Mixed PLP | Dynamic kit is skipped. The normal product still has an indication. History is read only for that product's variant. |
| Admin price PUT | Records one snapshot for the variant, store, and amount just upserted, including amount 0. A store-scoped PUT snapshots that store and not `""`. A nil history repo, or one without `WithTx`, returns 500 and does not upsert. `Record` returning an error returns 500, does not `Commit`, and leaves the price unapplied. |
| Exploded order tax snapshot | `TaxAmount` equals the pipeline `TaxTotal` already on the pricing context (380 EUR). `TotalAmount` is 2000 EUR. `PayableAmount` is 2380 EUR. This is the order snapshot copy, not a VAT-rules check. `order.Item` fields stay VariantID, SKU, Name, Quantity, UnitPrice, Restockable, CreatedAt. Simple leaf `Restockable` true; virtual leaf false. |
