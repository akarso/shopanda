# PR-1065 — Omnibus/VAT Per Component Line

Status: planned

## Summary

- Extend `PriceSnapshot` (lowest-30-day-price tracking for EU Omnibus) to component-level granularity when a bundle is sold itemized (PR-1064).

## Why

A component needs its own price history independent of the bundle's headline price once it's sold on its own order line — the existing Omnibus tracking (`internal/domain/pricing/price_snapshot.go`) is per-SKU already, so this is mostly "make sure it actually gets recorded for a component sold via a bundle," not a new tracking mechanism. This is shared groundwork with Track E's digital-goods VAT handling (PR-1076) in the sense that both are about getting tax/compliance granularity right below the order-line level a merchant might otherwise treat as atomic.

## Scope

- Confirm `PriceSnapshot` recording already fires correctly for an itemized bundle component's order line (it should, if PR-1064 made itemized lines structurally identical to any other order line) — this PR is primarily a verification + gap-fill, not a new mechanism, unless the itemized-line implementation in PR-1064 turns out to need an explicit hook.
- Non-itemized bundles: confirm the bundle's own headline price gets Omnibus tracking as today (`fixed` pricing mode) or is explicitly exempted with a documented reason (`dynamic` mode, where "the price" is a sum that changes with component prices — decide during implementation whether Omnibus tracking even applies meaningfully to a dynamic bundle's headline number).

## Out Of Scope

- Digital-goods VAT category — PR-1076 (related concept, different domain: VAT category vs. price-history tracking).

## Follow-up

- None within Track C; this closes out the pricing/tax correctness work for bundles.
