# PR-1055 — Four-Axis Visibility Model

Status: done

## Summary

- Domain model for four visibility axes with per-axis `VisibilityMode` (`auto` | `visible` | `hidden`).
- Documented `AutoBasis` default rule and `Resolve` computation; modes persisted on `products`.

## Why

A single lifecycle `Status` cannot express promo-only (visible, not purchasable), search-excluded but linkable, or Track D ticket gates. Four independent overridable axes cover those cases without one-off flags per feature.

## Scope

- `catalog.VisibilityMode`, `VisibilityAxes`, `Visibility`, `VisibilityInputs`, `VisibilityOptions`, `AutoBasis`, `ResolveAxis`, `VisibilityAxes.Resolve`, `Product.Visibility`.
- Default when `auto`: product `Status = active` AND quantity > 0 AND a price row exists (incl. amount 0) AND assigned to ≥ 1 store/view (any assignment). Category opt-in via `VisibilityOptions.RequireCategory` (off by default).
- Migrations `086` (single `ALTER TABLE` ADD columns + CHECK NOT VALID) + `087` (VALIDATE).
- `ProductRepo` create/update/scan of the four mode columns; `Product.Validate` rejects unknown modes.

## Out Of Scope

- Enforcement on storefront/admin read paths — PR-1056 / PR-1057.
- Wiring stock/price/store/category inputs into API handlers — PR-1056/1057 (this PR only defines the computation contract).
- Writable admin API/GUI for modes — PR-1059 (admin GET/list already encode `VisibilityModes` additively via `catalog.Product` JSON).
- Request-scoped store/currency eligibility — contract is product-global “any assignment / any price row” until a later PR changes inputs.
- Per-axis different AutoBasis formulas — shared basis; force display axes for OOS-visible catalog.
- `RequiresLinkedParent` → `Purchasable = false` — PR-1068.
- Config key for `RequireCategory` — callers pass `VisibilityOptions`; config plumbing with enforcement PRs.

## What changed

- Products carry `VisibilityModes` (default all `auto`); effective flags via `Product.Visibility(inputs, opts)` (status always from the receiver).
- Schema stores four mode columns with CHECK aligned to `AllVisibilityModes()`.
- `ResolveAxis` fail-closed for unknown/empty modes; only `auto` uses `AutoBasis`.
