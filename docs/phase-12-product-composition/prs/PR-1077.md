# PR-1077 — Storefront Download Delivery Endpoint

Status: done (with documented residual local-proxy risk)

## Summary

- Auth-gated **`POST /api/v1/account/downloads/{grantID}`** that checks the requesting customer's `DownloadGrant` (ownership, expiry, download limit) before delivering the Media asset.
- Local storage streams bytes via `ReadableStorage`; S3 **Heads** then redirects to a short-lived signed URL (`SignedURLStorage`) with `ResponseCacheControl: private, no-store` and `Content-Disposition: attachment`. Permanent `storage.URL()` is never returned. Signed Location hosts are restricted to `SignedURLHosts()` — AWS path-style + virtual-hosted regional hosts (and custom MinIO endpoint when set); CDN `BaseURL` is not a required/only presign host.
- Count changes only via ownership-checked **`ClaimDelivery`** (atomic `download_count + 1`) **after** the blob is proven and the signed URL / stream bytes are ready. Head/Read miss → **404**, no increment. Presign failure → **500** (stable message, cause logged via platform logger), no increment.
- **`DownloadableFileService.Attach`** rejects assets whose path is not under `private/downloads/`. Admin media FormData accepts `private_download=1`; the SPA media library checkbox sends it for downloadable uploads.
- Expired or limit-exhausted grants return **422**. Wrong owner / unlinked guest grant → **403**. Concurrent last-slot race → **409**.

## Why

The grant (PR-1075) is meaningless without an endpoint that enforces it — this closes the loop from "order paid" to "customer can download the file, within the limits that were set."

## Scope

- `download.Service.PrepareDelivery` — ownership + `CanDownload` without mutating count.
- `download.Service.ClaimDelivery` + repo `ClaimDownload` — atomic owned increment.
- Storefront `DownloadAccountHandler.Deliver` under existing `requireAuth` account routes (**POST**).
- `media.SignedURLStorage` — `Head` + `SignedURL(SignURLOptions)`; S3 `PresignClient` interface + private disposition/cache overrides.
- `private/downloads/` upload prefix (`private_download` form field) — private Cache-Control on S3 Save; no public ACL under that prefix; Attach enforces the prefix.
- OpenAPI path + unit/handler/postgres ClaimDownload tests.
- Docs: this PR, phase index/roadmap/README, DEVELOPER, RUNBOOK, C4 component/code notes.

## Out Of Scope / deferred

- Admin-facing grant management (re-issue, revoke, list) — **PR-1078**. Until then operators need careful SQL / in-process `Extend`+`ResetCount` (see RUNBOOK); do not 422 customers into an impossible self-serve re-issue.
- Guest-order grant rebind on `LinkToCustomer` (guest grants stay 403 until that lands).
- Account list endpoint (`GET /account/downloads`).
- Large-file streaming via `io.ReadCloser`.
- Defaulting *all* media uploads to private storage (product images stay public `uploads/`).

## Residual risk (honest)

Attach + `private_download` close the “public upload attached as downloadable” hole for **new** grant targets. Remaining:

- New `Attach` is prefix-gated: public `uploads/` assets **cannot** be re-attached. Legacy `downloadable_files` joins that already point at `uploads/` remain **deliverable** until those assets are re-uploaded under `private/downloads/` and re-linked.
- Operators can still upload without the private checkbox; those assets simply cannot pass Attach.
- Local `./public/media` (and any reverse-proxy `/media`) can still expose bytes if a private-prefix object is mistakenly placed on a public filesystem tree — keep `private/downloads/` off public aliases.
- Guest-order grant rebind and admin re-issue UI remain deferred (PR-1078 / link flow).

## Design decisions

- **Head/Read before claim.** Missing blobs must not burn slots. Local: read-then-claim. S3: Head → Presign → Claim → 302.
- **POST for state change.** GET must not increment; use POST so probes are safe.
- **Atomic claim.** `UPDATE … SET download_count = download_count + 1 WHERE … < limit AND expires_at > now() RETURNING *` with ownership in the application claim path.
- **Presign errors are 500**, not “not configured” fallthrough.
- **Validate signed URL** (non-empty, https, or http for S3/MinIO, no CR/LF) before Redirect.
- **TTL capped** to remaining grant expiry.
- **Never return permanent `URL()`.**
