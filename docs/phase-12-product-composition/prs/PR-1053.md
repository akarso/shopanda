# PR-1053 — Admin GUI: Type Selector + Type-Specific Sections

Status: planned

## Summary

- Product edit form gets a type selector.
- A section-visibility switch that later tracks hook their own type-specific form sections into.

## Why

The admin GUI needs a way to set `type` at all, and a stable extension point so bundle/grouped/linked/downloadable sections (added by their own tracks) don't each reinvent how to conditionally show/hide a form section based on the selected type.

## Scope

- Schema-driven forms/grids pattern (existing admin panel convention, no new frontend framework) — a `type` field on the product form schema, plus a documented convention for "sections registered for type X only render when type X is selected."
- This PR ships the selector and the switch mechanism only — no type-specific section content yet (those are added incrementally: PR-1066 for bundle/grouped, PR-1073 for linked, PR-1078 for downloadable).

## Out Of Scope

- Any type-specific section content — see above.

## Follow-up

- PR-1059, PR-1066, PR-1073, PR-1078 all register a section through this PR's switch mechanism.
