# PR-1053 — Admin GUI: Type Selector + Type-Specific Sections

Status: done

> **Numbering note:** Phase 12 Track A — unrelated to any Phase 11 PR id.

## Summary

- Product admin form/grid schemas expose `type` (required select of all `catalog.AllTypes()`, default `simple`; grid shows human labels).
- `FormSection` + `RegisterFormSection` (strict ID / no duplicates) + `RegisterProductFormSection` (catalog type validation); SPA visibility via `product_type_sections.js`.
- Edit preserves unknown/legacy type values; changing type confirms; section bodies are outside the product form (own save APIs).

## Why

Operators needed a GUI to set `type` after PR-1051’s API, and a stable extension point so bundle/grouped/linked/downloadable sections do not each reinvent conditional visibility.

## Scope

- `internal/application/admin/product_schema.go` — `type` field + grid column; `ProductTypeLabel`; `RegisterProductFormSection`.
- `internal/domain/admin` — `FormSection`, `Form.Sections`, `RegisterFormSection` (empty/duplicate ID + blank Types rejected), clone helpers.
- `schema_handler.go` — serialize `sections` with `types` always present (`[]` = always visible).
- `product_type_sections.js` + Node tests — visibility helpers (inline fallback if script missing); `admin.js` wires selector, unknown-type option (inline fallback), confirm-on-change; grid type labels from `product.form` options (non-critical `.catch` so forms failure cannot blank the products page).
- Docs: ADMIN_SCHEMA, DEVELOPER, MERCHANT, C4, phase index/roadmap/README.

## Out Of Scope

- Type-specific section **content** (PR-1066 bundle/grouped, PR-1073 linked, PR-1078 downloadable).
- Freezing type after create / transition matrix (confirm dialog documents shipping risk until then).
