# PR-1073 — CSV Import/Export + Admin GUI

Status: done

## Summary

- Bulk eligibility-rule import/export (`linked-eligible-parents` / `linked-eligible-categories`).
- Admin HTTP for linked eligibility on a child product (list/add/remove parents and categories).
- Product form section `linked` for eligibility pickers; Assignments admin page for card/ticket unit lookup with assign/revoke.
- Concurrent category-delete FK `linked_eligible_categories_category_id_fkey` maps to `"category not found"`.
- Product CSV round-trips `requires_linked_parent` (create-only; mismatch on existing skips).

## Why

Closes Track D's admin-reachability loop, matching the same principle Track C's PR-1066 closes for bundle/grouped — a domain model and an API alone aren't reachable enough for day-to-day merchant/support use.

## Scope

- When admin add-category hits insert `23503`, map `linked_eligible_categories_category_id_fkey` to `"category not found"` so a concurrent category delete matches the pre-check. Product FKs map to `"product not found"`.
- Admin HTTP (deferred from PR-1067):
  - `GET`/`POST /api/v1/admin/products/{id}/linked-eligible-parents` and `DELETE .../linked-eligible-parents/{parentId}`
  - `GET`/`POST /api/v1/admin/products/{id}/linked-eligible-categories` and `DELETE .../linked-eligible-categories/{categoryId}`
  - `products.read` lists; `products.write` adds/removes. Operator product-read scope via existing admin middleware.
- CSV (additive; omitted rows are not deletes):
  - `import`/`export:linked-eligible-parents` — columns `child_slug,parent_slug`
  - `import`/`export:linked-eligible-categories` — columns `child_slug,category_slug`
- Product CSV column `requires_linked_parent` (true/false; empty → false on create; existing mismatch is a skip).
- Assignment CSV / bulk-assign tool: **not in scope** — assignment stays transactional/order-tied; operators use PR-1071's API (or the Assignments GUI).
- Admin GUI:
  - Product form section `linked` (`Types: nil`, type-agnostic) — parent allowlist + category rules, wired via PR-1053's section mechanism.
  - `/admin/sales/assignments` — card (parent unit) list of assigned tickets, ticket (child unit) current card, assign/revoke (PR-1071 endpoints).

## Out Of Scope

- Nothing further within Track D — this is the closeout PR.
- GraphQL (PR-1082) and the phase-wide CSV consistency pass (PR-1081).
- New config keys, env vars, or plugin ports.

## Design decisions

- **Eligibility admin HTTP ships here with CSV/GUI.** PR-1067 deferred all three; routes mirror composition (products permissions, enrich name/slug).
- **No assignment CSV.** Instance assignment is order-tied; a bulk CSV would invent units. The Assignments page + PR-1071 API cover support workflows. No separate bulk-assign tool beyond the page's assign form.
- **Linked section is type-agnostic.** Eligibility is not a product type; `Types: nil` like visibility. It appears on every product edit form (not ticket-only). `requires_linked_parent` is a product form checkbox (create/update); CSV remains create-only.
- **Category CSV uses slugs.** Matches parent-product CSV using product slugs; ids stay on the HTTP API.
- **`requires_linked_parent` is create-only in product CSV.** Same pattern as type/modes — an existing mismatch skips the slug rather than silently flipping the purchasability gate.
- **Duplicate eligibility CSV rows count as Added.** Insert-ignore (same shape as composition CSV): a duplicate composite key is a no-op at the DB but the importer still increments `Added`, matching bundle/grouped import.
