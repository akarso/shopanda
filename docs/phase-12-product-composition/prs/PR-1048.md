# PR-1048 — Allow Zero-Price Products

Status: done

> **Numbering note:** Phase 11 also shipped different **PR-1048** (search reindex stuck-run) and **PR-1049** (stock-change indexing) under `docs/phase-11-jobs-search-cache/prs/`. Phase 12 keeps roadmap ids as written; disambiguate by phase folder. Track A’s planned PR-1049+ has the same collision class — renumbering is a follow-up, not this PR.

## Summary

- Relax `pricing.NewPrice`, `pricing.NewPriceSnapshot`, and `customergroup.NewGroupPrice` to non-negative amounts.
- Align Postgres CHECKs (`price_history`, `prices`, B2B `customer_group_prices`) so free prices persist end-to-end (CSV import + Omnibus history + group prices).
- CSV importer accepts `0` with history wired; admin price inputs allow `min="0"`.

## Why

A product sellable at 0 failed domain validation while the cart already accepted non-negative unit prices. After constructors were relaxed, storage CHECKs still rejected `0` on history/group-price tables, so production CSV (always wires history) could not land a free price.

## Scope

- Domain constructors + CSV importer non-negative rule.
- Core migrations `081` (install `amount >= 0` NOT VALID) + `082` (VALIDATE in a separate TX) — `price_history` / `prices`.
- B2B migrations `003` + `004` — same split for `customer_group_prices` (per-file TX holds ACCESS EXCLUSIVE through commit).
- Admin GUI variant + bulk price inputs: `min="0"`.
- Audit: percentage/fixed promos on a zero line; Omnibus both-zero, free-now/higher-history, paid-now/was-free.

## Out Of Scope

- Storefront “Free” label presentation.
- Recording Omnibus history on admin price PUT (pre-existing gap for all amounts, not only zero — importer/seed remain the history writers).
- Free checkout / `NewPayment` positive-amount paths — sellable at 0 ≠ free checkout done.
- Composite/bundle pricing rollup (Track C).
- Renumbering Phase 12 PR ids past Phase 11’s 1048–1049.

## What changed

- Domain + importer accept amount `0`.
- Migrations replace `amount > 0` CHECKs with `>= 0` (and add `prices` non-negative CHECK); VALIDATE is a follow-on migration so the scan is not under ACCESS EXCLUSIVE.
- Admin UI `min="0"` on catalog price fields.
- Tests: importer with non-nil history, admin PUT `0`, Omnibus mixed zeros, fixed promo on zero line, DSN-gated history/group-price Record/Upsert of `0`.
