# PR-1048 — Allow Zero-Price Products

Status: planned

## Summary

- Relax `pricing.NewPrice` and `pricing.NewPriceSnapshot` from "amount must be positive" to "amount must be non-negative."
- Audit every consumer that implicitly assumed a positive price (discount math, Omnibus lowest-price comparisons, any divide-by-price calculation) and add explicit zero-handling where needed.

## Why

A card product that should be sellable at 0 hits a validation error before there's even a visibility question to answer — `internal/domain/pricing/price.go`'s `NewPrice` rejects any amount that isn't strictly positive, and `price_snapshot.go`'s `NewPriceSnapshot` has the identical guard. Meanwhile `cart.Item.NewItem` already only rejects a *negative* unit price — the cart/order line-item model has no problem with 0, only the base-price layer does. This is a real, independent bug (a merchant cannot price *anything* at 0 today, free products or not), not something invented for this phase's card/ticket use case.

## Scope

- `internal/domain/pricing/price.go` — `NewPrice`: `IsPositive()` guard → `!IsNegative()`.
- `internal/domain/pricing/price_snapshot.go` — `NewPriceSnapshot`: same change.
- Grep every call site that constructs or compares a `Price`/`PriceSnapshot` for an implicit "> 0" assumption (percentage-discount calculations, any division by unit price, Omnibus lowest-price-in-30-days comparisons) and confirm 0 is handled correctly, not just "doesn't panic."
- Admin price-set endpoint, CSV price importer, seed data: confirm none of them independently re-validate "> 0" outside the domain constructor (if they do, fix there too).

## Out Of Scope

- Any change to how a 0-priced item displays on the storefront (e.g. "Free" label instead of "$0.00") — presentation-layer concern, not this PR's scope.
- Composite pricing (dynamic bundle sum reaching 0) — this PR is the prerequisite; Track C (PR-1062) is where it's actually exercised.

## Follow-up

- Track B (visibility/purchasability) and Track C (bundle pricing rollup) both depend on this shipping first.
