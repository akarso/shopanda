# PR-1057 — Enforce Visibility in Storefront Read Paths

Status: done

## Summary

- Wire PR-1056's axis gate into every `EnforceIn=PR-1057` public read when `catalog.visibility.enforce` is enabled (default **false** for safe rollout).
- Load AutoBasis facts via `VisibilityFactsSource` / `postgres.VisibilityFactsRepo` and apply `AllowWithFacts` / `FilterWithFacts` / `FilterIDsWithFacts` / `ListVisiblePage`.

## Why

PR-1056 defined the boundary and audit table; without this PR the axes are stored but never enforced on storefront reads. Search still lacks indexed visibility fields (PR-1079), so query-time post-filter is the interim.

## Scope

- `catalog.VisibilitySnapshot`, `VisibilityFactsSource`, helpers above.
- `ListVisiblePage` → `VisiblePage{Products, Truncated, HasMore, NextAfter}`. Opaque cursor (`NextAfterCursor`) carries DB offset + remaining visible skip so a budget stop mid-`offset` does not drop owed skip.
- No multi-batch probe: on budget stop, `has_more` + `next_after` at `resumeAt` (client walks). Cap after offset/skip at 100000; never emit a cursor past the cap (`depth_limited` + no `next_after`). Classic `offset` is not capped the same way.
- Handlers decode `after` once and pass `AfterSet`/`AfterOffset`/`AfterSkip` into `ListVisiblePage` (nil facts / enforce off still honour `after`).
- Handlers gated when enforce is on: product list/get, category products, variants (parent), reviews GET/POST (parent → **404**), search + suggest, sitemap (**individually**), HTML/SSR, recently-viewed, CMS carousels.
- Config: `catalog.visibility.enforce` / `SHOPANDA_CATALOG_VISIBILITY_ENFORCE` via `parseEnvBool` (default false).
- Search: query-time filter until PR-1079; **no HTML overfetch**. Short or **empty** HTML pages with pagination driven by index `Total` are accepted until 1079.
- FPC: `ListingTag()` purge on stock/price only when enforce is on (`WithVisibilityListingPurge`).
- Meta set **after** PLP pipeline; category products always include `meta`.

## Out Of Scope

- GraphQL — PR-1082.
- Cart/checkout purchasability — PR-1058.
- Indexing visibility — PR-1079.
- SQL-level / keyset visible listing (preferred long-term).
- Threshold-crossing FPC purge (qty 0↔positive / first price).
- Writable admin GUI for modes — PR-1059.

## Rollout

Migration 086 left every product at mode=`auto`. AutoBasis requires qty &gt; 0 and a price row. **Do not set `catalog.visibility.enforce: true` until** you accept OOS/unpriced 404s or force display axes to `visible`. See RUNBOOK.

## Paging contract (enforce on)

| Field | Meaning |
| --- | --- |
| `meta.has_more` | More repository rows may exist; next page may still be empty (trailing hidden) |
| `meta.next_after` | Opaque cursor for `?after=` (encodes offset + remaining skip) |
| `meta.truncated` | Scan budget stopped early — page may be short/empty; continue with `after` |
| `meta.depth_limited` | Cursor resume hit the 100k-row cap; `next_after` omitted |

**Do not** advance `offset` by `len(products)`. When `after` is set, `offset` is ignored. Cursors are position-based and can drift across inserts/deletes (same class of issue as SQL OFFSET; keyset follow-up).

## What changed (behaviour notes)

- Reviews for a non-individually-visible parent return **404**.
- Sitemap gates on **individually**.
- Missing snapshots fail closed when facts are wired.
- `ListVisiblePage` batch size ≤ 100 (postgres `maxListLimit`) so capped batches are not mistaken for EOF.
- Carousel FPC tags keep configured product IDs (including filtered-out) so restock/first-price purges hit home/CMS.
- FPC `Vary` includes visibility enforce so enforce-off pages are not reused after enable.
- Listing handlers decode `after` before `offset`; invalid `offset` is ignored when `after` is set.
