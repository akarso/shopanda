# PR-1076 — Tax class seam + digital rate-table wiring

Status: done

## Summary

Engineering ships a **tax class seam** and rate-table wiring for downloadable lines — **not** “EU digital-goods VAT complete.”

- `downloadable` → tax class `digital`; `virtual` → `standard` (ESS virtual needs a future opt-in; do not force digital).
- Cart recalculate and checkout `ValidateCartStep` share `pricing.EnsureTaxClasses` (fill-missing; reject empty/unknown overrides; coerce `map[string]interface{}`).
- Rate-table calculator **fails closed** when class is `digital` and the rate is missing or `Rate == 0` — validation error (`apperror.CodeValidation`), never silent 0% VAT. Shared helper: `tax.MissingRateFailsClosed(class, rate)`.
- **Zero-rate policy:** do not copy zero-bps `standard` into `digital` (migration + seed). Intentional 0% VAT must use class `zero`. Existing digital rows with `rate = 0` fail checkout after this release.
- **Migrate path required:** migration `108` idempotently `INSERT … SELECT … ON CONFLICT DO NOTHING` copies every non-zero `(country, store_id, rate)` from `class = 'standard'` into `class = 'digital'`. Seed TaxSeeder is a **second** idempotent backfill via `tax.RateRepository` — fail-closed must not ship without migrate-path data.
- Application `Upsert` does **not** create digital rows. After migrate, **new** standard destinations need a matching digital SQL `INSERT` (RUNBOOK). No `application/tax.RateService` until Tax settings UI exists.
- Place-of-supply for checkout remains address country (`tax_country`). Cart preview still uses store country when no destination is set — do not claim cart == OSS destination.
- **Tax-domain sign-off required.** Track E VAT/compliance requirement is **not** marked done by this PR.

## Why

Treating a downloadable line like a physical `simple` SKU under a single class is a compliance gap. This PR extends the existing rate-table / Meta tax path with an explicit `digital` class and fail-closed lookup — not a parallel tax subsystem and not a finished EU digital VAT product.

## Scope

- `tax.TaxClassStandard` / `tax.TaxClassDigital` (+ known-class helpers).
- `catalog.TaxClassCode(Type)` — string literals (no `tax` import).
- Shared `pricing.EnsureTaxClasses` used by cart + checkout.
- Fail-closed missing / zero-bps `digital` rate in `RateTableCalculator` via `MissingRateFailsClosed`.
- Migration `108` + `TaxSeeder` backfill digital from non-zero standard rows (seed through `tax.RateRepository`).
- `tax.RateRepository.ListByClass` / `CreateIfNotExists` — justified by seed backfill (and postgres impl).
- Docs honesty: RUNBOOK migrate + optional seed; new destinations need digital INSERT; Upsert does not mirror; no “confirm in Tax settings” (no tax admin UI); COMPLIANCE_EU softened; plugin taxdemo ignores `tax_classes` noted as operator trap; hook override trusted-VAT risk.
- Unit / postgres tests listed under Validation.

## Out Of Scope

- **EU digital VAT / OSS compliance complete** — tax-domain sign-off still required; Track E VAT requirement stays open.
- Reverse charge / VAT ID capture (B2B).
- Non-EU digital tax (US sales tax nexus, etc.).
- OSS export column changes (PR-534 CSV stays as-is).
- Admin Tax settings UI for editing rates per country/class (and any RateService that would mirror standard → digital on Upsert).
- ESS opt-in for `virtual` products (remain `standard` until a future flag).
- Bundle/grouped/configurable tax-class rollup from downloadable leaves (parent stays `standard`; document gap vs `RequiresPhysicalShipping`).
- PR-1077 storefront download delivery; PR-1078 admin downloadable GUI/API.
- Plugin `taxdemo` / custom `tax.Calculator` implementations reading `tax_classes` (they ignore class Meta today).

## Design decisions

- **Fail-closed for digital, not fallback-to-standard.** Missing or zero-bps destination digital rate → validation error at pricing (`MissingRateFailsClosed`). Do not invent 0% and do not silently use `standard`.
- **Zero-bps digital refused.** Prefer not copying zero-bps standard into digital; calculator refuses `digital` + `Rate == 0` unless the line’s class is explicitly `zero`.
- **Migrate + optional seed.** Migration creates digital rows from standard; seed also backfills through the RateRepository port. Operators need destination coverage for post-migrate standard inserts (SQL).
- **No RateService until Tax settings UI.** Dead application facades that nothing wires are not part of the guarantee; operators use SQL (RUNBOOK).
- **downloadable → digital; virtual → standard.** Spec once mapped both to digital; review prefers not forcing virtual without ESS opt-in.
- **Type → class, not `RequiresPhysicalShipping`.** Composite parents (`bundle`/`grouped`/`configurable`) stay `standard` even if all leaves are downloadable. Shipping derivation and tax class stay separate seams (documented gap).
- **Catalog literals, tax constants.** `catalog.TaxClassCode` returns `"digital"` / `"standard"` so catalog does not import tax. Application-layer bridge test asserts equality with `tax.TaxClassDigital` / `TaxClassStandard`.
- **Fill-missing + validate overrides.** Shared `EnsureTaxClasses` preserves existing keys; empty string and unknown codes error; `map[string]interface{}` with string values is coerced. Cart skips `FindByID` when an override already exists. Hook override to a non-digital class can skip fail-closed — trusted-VAT risk.
- **Place-of-supply honesty.** Checkout sets `tax_country` from address; cart may use store country for preview — not claimed as destination VAT.
- **Tax-domain sign-off.** Engineering seam is shippable; compliance claims are not.
