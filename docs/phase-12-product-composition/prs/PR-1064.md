# PR-1064 — Order Line Explosion + Returns Integration

Status: planned

## Summary

- Per-bundle config flag: sell as one order line (default) or itemize into one order line per component.
- Itemized bundles extend the existing Returns/RMA domain (Phase 6) to support returning a single component.

## Why

Some tax/invoice jurisdictions require per-item granularity that a single "Bundle X" order line can't express; other merchants are fine with one line. Making this a per-bundle choice (not a global default) avoids forcing every merchant into the more complex itemized path when they don't need it, while making the itemized path a real, first-class option rather than a workaround.

## Scope

- `explode_order_lines bool` on the bundle product (or per-order-at-purchase-time, if component prices need to be locked at sale time either way — confirm during implementation which is more correct for this codebase's existing order-immutability model).
- Non-itemized: one order line, `bundle_component` rows are metadata only (what was inside, for display/fulfillment reference).
- Itemized: one order line per component at the component's price-at-time-of-sale, same immutable-order-line convention the rest of the order domain already uses.
- Returns/RMA (Phase 6): itemized bundles can return a single component's order line independently, exactly like returning any other order line today — this should require little to no change to the Returns domain itself if the itemized order lines are structurally indistinguishable from any other order line, which is the goal.

## Out Of Scope

- Per-component Omnibus/VAT price history — PR-1065 (related but separate: this PR is about order-line structure, PR-1065 is about price-tracking history).

## Follow-up

- PR-1065 depends on this PR's itemized-line structure existing.
- PR-1072 (Track D) does the equivalent for assignment-based returns, reusing this PR's groundwork.
