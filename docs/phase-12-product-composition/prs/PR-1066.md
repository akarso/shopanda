# PR-1066 — Bundle/Grouped Admin API + CSV + GUI

Status: done

## Summary

- Admin HTTP lists, upserts, and removes bundle components and grouped members on `ProductCompositionAdminHandler`. Wrong parent type is 422. A missing link on delete is 404.
- Product CSV columns after `type`: `pricing_mode`, `stock_mode`, `explode_order_lines`. Create applies and validates them. An existing product whose stored mode does not match a non-empty cell is skipped. Empty cells on create are `fixed` / `fixed` / `false`. Several invalid mode fields on one row are all reported, and that row increments `Skipped` once.
- Composition CSV is additive: `import`/`export:bundle-components` and `import`/`export:grouped-members`. A row omitted from the file is not deleted. A `FindBySlug` error is `line N:` and the import continues.
- The product form section `bundle` sends the three mode fields only when type is bundle. Component and member pickers use the composition routes after the product is saved. Only the picker for the saved type starts, because the list routes reject the other parent type. A successful edit starts that picker from `payload.type` (the type sent on that request). A type-selector change while the save is still in flight does not choose the picker: the list route would reject the other type, and a failed bind still marks the picker bound so a later save could not start it. Saving a type change to bundle or grouped starts that picker. Opening a picker loads one page of 100 products for each leaf type (`simple`, `virtual`, `downloadable`). **Load more** fetches the next offset and continues until a page is short. A recursive leaf walk stops after 50 full pages; that cap does not finish a type for Load more. A saved quantity or required value is kept when Load more rebuilds the list. Loaded pages stay cached for the life of the picker, so a checkbox or reload refreshes the assigned list and reuses those pages. Search filters loaded pages only; it does not query the rest of the catalog. A failed component or member save reloads the picker and shows the error, including the required-component cap.
- Composition export lists with `ListFilter.Type` `bundle` or `grouped`. Child products are loaded with one `ListByIDs` batch per parent when the repository implements it. A child lookup error is a skipped row (`line N:`), the same as a missing slug, and does not abort the file.

## Why

Track C's domain, pricing, stock, and explode work (PR-1060–1065) had no merchant path to define components or members, or to choose bundle modes. Admin reachability here is API, CLI/CSV, and GUI.

## Scope

- `GET`/`POST /api/v1/admin/products/{id}/bundle-components` and `DELETE .../bundle-components/{componentId}`.
- `GET`/`POST /api/v1/admin/products/{id}/grouped-members` and `DELETE .../grouped-members/{memberId}`.
- POST bundle body `{component_product_id, quantity, required?}`. Omitted `required` is true. `BundleService.Add` upserts. After that upsert and before commit, `Add` returns validation (422) when the required-component count is greater than `catalog.MaxBundleRequiredComponents` (50). The upsert is rolled back. POST grouped body `{member_product_id}` is insert-ignore.
- List DTOs are snake_case and include the child `name`, `slug`, and `type`. Children are loaded with `ListByIDs` when the product repository implements it, otherwise one `FindByID` per child. A missing child, or a `FindByID` error for one child, leaves that row's name, slug, and type empty and does not fail the list. A `ListByIDs` error fails the list (500) instead of blanking every child. POST returns 200 from the request ids, quantity, and required; enrichment is best-effort and does not turn a committed write into an error. DELETE checks the parent type with one `FindByID` and does not list the composition. `componentId` and `memberId` are product ids.
- `products.read` lists. `products.write` adds and removes. Operator product-read scope is the existing admin middleware.
- Product importer/exporter. Those three header names are reserved and are not stored as variant attributes.
- CLI wired in `cmd/api` (`main.go`, `io_commands.go`). Row errors are `line N:`.
- Admin sections `bundle` (`Types: ["bundle"]`) and `grouped` (`Types: ["grouped"]`), registered in `cmd/api/wire_services.go`. Helpers in `product_composition_section.js`. The explode checkbox is enabled only when both modes are dynamic. The picker for the saved type loads the first page of simple, virtual, and downloadable products (limit 100 each), excludes the parent, and offers Load more for the next offset until a page is short. Search matches loaded pages only. Assigned component or member ids that are not on the loaded pages stay in the list. A saved quantity and required flag stay on that row when Load more rebuilds the list.
- `collectProductPayload` merges `pricing_mode`, `stock_mode`, and `explode_order_lines` only when type is bundle.

## Out of scope

- Linked products and downloadable files (Tracks D and E).
- Updating bundle modes on an existing product from product CSV. The admin product PUT still owns the lock and the own-price / own-stock checks.
- Deleting composition rows by omitting them from a CSV file.
- GraphQL (PR-1082) and the phase-wide CSV consistency pass (PR-1081). PR-1081 does not own these columns.
- New config keys, env vars, or plugin ports.
