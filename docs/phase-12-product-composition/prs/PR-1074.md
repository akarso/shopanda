# PR-1074 — `Downloadable` Type + File Asset Attachment

Status: done

## Summary

- Product-to-asset attachment table `downloadable_files` referencing existing `assets` (Media domain / `media.Storage`).
- Domain `catalog.DownloadableFile`, repository port, postgres adapter, and `DownloadableFileService` (list / attach / remove).
- `Type = downloadable` already implies no shipping via PR-1050's `RequiresPhysicalShipping` — confirmed, no new shipping logic.
- Hard validation: a downloadable product cannot be `StatusActive` (or remain active after removing its last file) without ≥1 attachment; purchasable axis forced false via `VisibilityInputs.MissingDownloadableFile`.
- Sell path (cart add / checkout validate_cart) rejects downloadable products with zero files **independent of** visibility enforce/bypass/nil facts (mirrors PR-1068 linked-parent).
- Required bundle leaves: `RejectRequiredMissingDownloadableFileLeaves` walks required components for **every** bundle (fixed and dynamic) and rejects a file-less downloadable leaf (including draft) with the same message.
- Media asset delete: **row-then-blob** (assets delete first so `ON DELETE RESTRICT` fails closed if still attached); after a successful row delete, blob/thumbnail errors are logged, `EventAssetDeleted` still publishes, Delete returns nil. Nil attachment counter fails closed. `Attach` locks the asset `FOR UPDATE` in the same transaction as the upsert (`AssetRepo.LockForUpdate` requires a tx).
- Soft-write admin: name-only updates of an already-Active file-less downloadable succeed; Active→Draft always allowed; Create / Draft→Active / type-change onto Active downloadable without files still blocked. Soft-write takes **status from the same `LockTypeAndModes` lock** (type/modes/explode/status) so a concurrent Active→Draft is not overwritten from a stale Active FindByID. Attach HTTP / `DownloadableFileService` construction remain PR-1078.
- `List` and `Remove` are type-agnostic (illicit join rows on a non-downloadable are visible/clearable); `Attach` stays type-gated.

## Why

`downloadable` needs to be more than "virtual with a file attached" for delivery, expiry, and licensing to work correctly (PR-1075), but the *storage* of the file itself has no reason to be a new mechanism — the Media domain already handles upload/storage.

## Scope

- Migration `104_create_downloadable_files.sql` — `(product_id, asset_id)` PK; product FK `ON DELETE CASCADE`; asset FK `ON DELETE RESTRICT`; `position` / `label`.
- Domain validation + `DownloadableFileService.Attach` (locks product `FOR UPDATE`, requires existing asset, downloadable type only) and `Remove` / `List` (any product type; last-file-while-active only when locked type is downloadable and status is active).
- `ProductAdminHandler.WithDownloadableFiles` — type-change fail-closed; leaving `downloadable` with rows blocked; Create / transition **to** Active requires count ≥ 1; soft-write allows already-Active file-less name-only and Active→Draft using locked status.
- Visibility facts + resolve: `MissingDownloadableFile` forces Purchasable false (including `VisibilityModeVisible`); ExplainAxes code `no_downloadable_file` on the purchasable axis only.
- Wiring at serve startup (`DownloadableFileRepo`; sell-path / media / admin guards). `DownloadableFileService` HTTP construction deferred to PR-1078.

## Out Of Scope

- Download link generation, expiry, limits — PR-1075.
- Actual delivery endpoint — PR-1077.
- Admin HTTP / CSV / GUI for attach/replace — PR-1078.
- Broadening media `AllowedMimeTypes` beyond images — PR-1078 (attachments reference any existing `assets` row; tests insert assets directly).

## Design decisions

- **Hard sell-path + soft admin write.** Sell path and visibility force Purchasable false without a file. Admin soft-write allows name-only (and Active→Draft) on an already-Active file-less SKU so operators are not dead-ended before PR-1078 attach HTTP; Create / transition **to** Active without files still fail closed. Soft GUI warnings remain PR-1078.
- **Soft-write uses locked status.** `LockTypeAndModes` returns status with type/modes/explode on one `FOR UPDATE` (omit pattern; `RequiresLinkedParentForUpdate` stays separate) and feeds `ensureActiveDownloadableHasFile`. Soft-write skip must not use pre-lock Active. Already-Active soft-write returns **before** the nil-guard check; Create / Draft→Active / type-change onto Active with a nil guard still fail closed.
- **List type-agnostic like Remove.** Operators can see illicit asset IDs on a non-downloadable product before Remove / type-change. Attach stays type-gated.
- **`MissingDownloadableFile` is a post-ResolveAxis gate** (same shape as `RequiresLinkedParent`), not an AutoBasis input — display axes stay independent; zero value is false so existing fixtures are unchanged. Admin SPA mirrors the purchasable-axis gate via `missing_downloadable_file` + `FAILURE_LABELS.no_downloadable_file` (not only `input_failure_codes`). Forced-visible badge shows both linked-parent and missing-file reasons when both apply.
- **Asset delete is row-then-blob.** `media.Service.Delete` fails closed when the attachment counter is nil, counts as defense-in-depth, deletes the `assets` row first (`RESTRICT` if still attached), then the blob. After a successful row delete, blob/thumbnail failures are logged and `EventAssetDeleted` still publishes with a nil return — do not 500 a completed unlist. An orphan blob is recoverable; a join to a missing blob is not. `Attach` locks the asset row `FOR UPDATE` in the upsert transaction (`AssetRepo.LockForUpdate` rejects `tx == nil`).
- **No admin attach HTTP in this PR.** Soft-write unblocks name/status demotion; attach/list/remove HTTP + GUI remain PR-1078 (checked against PR-1078 scope).
- **Known hole until PR-1077:** downloadable attachments currently reference ordinary media assets served via public media URLs. Private/authorized download delivery is PR-1077 — do not treat public URLs as the final download path.

## Follow-up

- PR-1075 builds the grant/expiry model on top of this PR's file attachment (`asset_id` on the grant).
- PR-1077 private / authorized delivery closes the public media URL hole for downloadable blobs.
- PR-1078 adds admin HTTP / CSV / GUI and broader media MIME for non-image uploads. Soft-write in this PR is the interim; attach reachability is not merchant-complete here.
- Folding downloadable file-count into `RequiredLeafVariants` (so pricing/reserve cannot drift from cart/checkout) is deferred — linked-parent is inlined there without an extra port; file count needs `DownloadableFileCounter` and would widen that signature.
- Caps on attachment count / unique position / FK 23503 message specificity for future FKs are deferred.
- Path/checksum pinning on the join row is deferred with private storage (PR-1077).
