# PR-1068 — `RequiresLinkedParent` Purchasability Gate

Status: done

## Summary

- A product with `RequiresLinkedParent = true` computes `Purchasable = false` until the request assignment context is non-empty.
- Cart add, quantity increase, guest-cart claim, and checkout enforce that rule even when visibility enforcement is off. Cart lines persist assignment; claim keeps a stamped line. Required bundle leaves are rejected.

## Why

A ticket must not be sellable on its own until a purchase context names a parent (or defers assignment). The flag is explicit. Deriving it from `HasRules` would couple purchasability to catalog-rule rows and would treat a missing child as "no rules." Eligibility (`IsEligible`) stays a join-table predicate. Purchasable stays the Track B axis, with one documented context-dependent override.

## Scope

- `products.requires_linked_parent BOOLEAN NOT NULL DEFAULT false` (migration 097).
- `catalog.Product.RequiresLinkedParent`. `NewProduct` sets false. `Validate` does not restrict the flag by type.
- `catalog.AssignmentContext` (`ParentProductID`, `Deferred`), `Empty` (whitespace parent is empty), `WithAssignmentContext` / `AssignmentContextFrom` / `ResolvePurchaseAssignment` (line then request) / `LinkedParentBlocksPurchase`.
- Persist and scan the column in `ProductRepo`. `LockTypeAndModes` is unchanged.
- Purchasable axis only: after `ResolveAxis`, flag && empty context forces false. `VisibilityModeVisible` does not bypass it. Display axes are unchanged. The flag is copied from the product or `VisibilitySnapshot`. Facts filters copy `AssignmentContextFrom(ctx)`.
- `VisibilityFactsRepo` selects `requires_linked_parent` onto `VisibilitySnapshot.RequiresLinkedParent`.
- `ExplainAxes` adds purchasable failure code `requires_linked_parent`. That code is not an AutoBasis code and is not in the shared failure list.
- `ensureVariantPurchasable` and `ValidateCartStep` return `RequiresLinkedParentNotPurchasableMessage` after the active check (cart also keeps the grouped-parent check first). They read the cart-line assignment first, then the request. Visibility bypass and nil facts do not skip it. Add stamps a non-empty request context onto the line. Guest claim keeps a stamped line and drops an unstamped one. Required bundle leaves are rejected in cart, checkout, `RequiredLeafVariants`, and `BundleService.Add`. The gate does not use `HookCartAddItemBefore`.
- Admin create/update accept `requires_linked_parent` (`*bool`). Nil on create stores false. Nil on update keeps the stored value. OpenAPI documents the field. The product JSON name is `RequiresLinkedParent`. GET visibility includes `requires_linked_parent` so the purchasable badge can show the code. CSV treats the header as reserved and ignores it.

## Out Of Scope

- The assignment record — PR-1069.
- Writers of the assignment context, and `IsEligible` at purchase time — PR-1070.
- CSV, admin GUI, GraphQL — PR-1073 (GraphQL parity is Track F).
- No config or env var.

## Design decisions

- **Explicit flag, not `HasRules`.** A merchant can have eligibility rules without gating the SKU, and a missing child must not look independently purchasable because a caller mapped `NotFound` to "no rules."
- **Purchasable only.** Catalog, search, and PDP axes stay a function of modes and AutoBasis. The card/ticket "not visible until assigned" display rule is not this PR.
- **`visible` does not bypass the gate.** `Purchasable=visible` still forces the axis on for ordinary products. A linked child with an empty context stays not purchasable.
- **Empty context is whitespace-insensitive.** `Deferred: true` or a non-blank parent id restores the axis. That parent is not validated until PR-1070. Storefront must not set `Deferred` on every request.
- **Cart lines persist assignment.** Add stamps a non-empty request context. Later qty increase, claim, and checkout prefer the line, then the request.
- **Cart and checkout do not consult the visibility flag.** Enforce-off, a nil facts source, and `BypassProductVisibility` still deny. The check sits in `ensureVariantPurchasable` because `HookCartAddItemBefore` runs after that function and checkout never calls the hook.
- **Required bundle leaves.** A flagged required component cannot be composed or purchased through the parent bundle while assignment is empty.
- **Guest claim keeps a stamped line.** An unstamped flagged line is still dropped so a failed claim cannot retry forever.
- **Admin omit semantics match other optional bools that are not type-coerced.** Create defaults false via `NewProduct`. Update keeps the `FindByID` value. The column is not part of `LockTypeAndModes`.
