# PR-410 — Core Plugin Enablement Contract (Track B)

Status: done

## Summary

- define the config contract for enabling core plugins (`plugins.core.*` and driver switches such as `search.engine`, `cache.driver`, `queue.driver`)
- register core plugin packages in `main.go` through `PluginRegistry`; failed init disables the plugin without crashing startup
- extend `plugin.App` with provider registration hooks needed by infrastructure adapters (search, cache, queue, payment, storage) without domain imports in plugins

## Why

`PluginRegistry` exists and `InitAll` handles failures gracefully, but `main.go` still wires Meilisearch, Stripe, S3, and Postgres adapters directly and registers zero plugins. Track B needs a shared enablement pattern before extracting each adapter into `plugins/core/*`.

## Scope

- config: add `plugins.core` section (or document driver-based enablement where a driver switch implies the plugin); add `queue.driver` (`postgres` | `redis` | `rabbitmq`, default `postgres`) if not present
- `plugin.App`: add registration methods for infrastructure providers (e.g. `RegisterSearchProvider`, `RegisterCache`, `RegisterQueue`, `RegisterPaymentProvider`, `RegisterMediaStorage`) — minimal surface, no premature generic DI
- bootstrap: `main.go` registers core plugin structs; after `InitAll`, bootstrap reads registered providers from registry/app or a small `BootstrapContext` populated by plugins
- startup logging: plugin name, state (`active`/`failed`), driver selected
- tests: config parsing for new keys; registry init with a stub core plugin that registers a provider; failed plugin does not panic

## Out Of Scope

- Extracting individual adapters (PR-411–416)
- Dynamic plugin discovery / `.so` loading
- Admin UI for plugin toggles

## Validation

- default config starts with Postgres search/cache/queue and no optional plugins active
- a stub core plugin registers via registry and its provider is used at runtime
- misconfigured optional plugin logs failure and app continues with fallback or clear error for required driver
- `go test ./internal/platform/plugin ./internal/platform/config -count=1`

## What changed

- **`config.go`**: `queue.driver` (default `postgres`), `plugins.core` optional toggles; validation for search/cache/queue drivers; `SHOPANDA_QUEUE_DRIVER` env overlay
- **`core_plugins.go` / `validate.go`**: driver-based core plugin enablement helpers and config validation at load time
- **`plugin.App`**: `Bootstrap` (DB handle), provider registration/getters for search, cache, queue, payment, storage
- **`plugins/core/postgres/`**: stub core plugins for postgres search, cache, and queue
- **`plugins/core/register.go`**: registers core plugins implied by active driver switches
- **`cmd/api/main.go`**: early plugin registry init; `resolveSearchEngine` / `resolveMediaStorage` / `resolveJobQueue` / `resolveCache` prefer plugin-registered providers with direct wiring fallback (Meilisearch, S3, etc. until PR-411–416)
- **`plugin.LogStartup`**: logs each plugin state and selected drivers at startup
- **Tests**: config parsing/validation; stub plugin provider registration; failed plugin does not panic
