# PR-402 — Admin Attributes UI (Track A)

Status: done

## Summary

- deliver attribute and attribute-group management in the admin catalog area
- wire `/admin/catalog/attributes` off the placeholder over the existing catalog attribute registry and import infrastructure

## Why

Product attributes are modeled (`catalog.Attribute`, `AttributeRegistry`, CSV `import:attributes`) and used in product composition/import, but the admin route rendered a placeholder. Merchants must use CLI import for attribute definitions.

## What changed

- `internal/application/admin/attributes.go` — `AttributeStore` read-modify-write on `catalog.attributes` / `catalog.attribute_groups` config keys
- `AttributeAdminHandler` CRUD at `/api/v1/admin/attributes` and `/api/v1/admin/attribute-groups`; RBAC via `CategoriesRead`/`CategoriesWrite`
- audit actions: `attribute.*`, `attribute_group.*`
- `SchemaHandler` merges live attribute fields into `product.form` on each request (no restart after creating attributes)
- admin UI: attributes grid with group filter; create/edit forms for attributes and groups
- product form: attribute values read from `product.attributes`; number fields parsed on save

## Scope

- admin API: list/create/update/delete attribute groups and attributes (code, label, type, group membership) — extend or add handlers consistent with existing catalog admin patterns
- admin UI: grid of attributes with group filter; create/edit forms for attribute and group
- product form: ensure attribute fields on product edit remain consistent with registry (no regression)
- audit: attribute/group mutations logged
- tests: handler CRUD tests; admin static guard for attributes route

## Out Of Scope

- Configurable product variants from attributes (matrix/configurable products)
- Attribute-based search facets in storefront
- Bulk attribute import UI (CLI remains)

## Validation

- merchant can create an attribute group and an attribute, then assign attribute values on a product edit form
- duplicate attribute codes are rejected
- `go test ./internal/interfaces/http -count=1`
