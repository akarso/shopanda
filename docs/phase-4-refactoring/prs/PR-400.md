# PR-400 — Admin Coupons CRUD (Track A)

Status: done

## Summary

- deliver list/create/edit/delete for coupon codes in the admin marketing area
- wire `/admin/marketing/coupons` off the placeholder onto a working grid + form backed by new admin HTTP handlers

## Why

Coupons are fully modeled (`promotion.Coupon`, `postgres.CouponRepo`) and consumed by the cart pricing pipeline, but merchants had no UI or admin API to manage them.

## What changed

- `CouponRepository.List` on domain + postgres repo
- `CouponAdminHandler` with CRUD at `/api/v1/admin/coupons`; RBAC via `ProductsRead`/`ProductsWrite`
- audit actions: `coupon.read/create/update/delete`
- admin UI: `renderCouponsGrid`, create/edit form at `/admin/marketing/coupons`; promotion ID as UUID field until PR-401
- routes wired in `cmd/api/main.go`

## Scope

- admin API: CRUD endpoints under `/api/v1/admin/coupons` (list, get, create, update, delete) using `CouponRepository`; RBAC via existing marketing or products write permissions (align with nearest admin pattern)
- validation: coupon code format (`couponCodeRegex`), promotion reference exists, usage limit ≥ 0
- admin UI: grid with code, linked promotion name, usage count/limit, active flag; create/edit form; delete with confirm
- route: replace `renderPlaceholder("Coupons")` in `admin.js`
- audit: coupon create/update/delete logged through `Auditor` with admin scope triad
- tests: handler tests for CRUD, validation, RBAC; static admin asset guard for coupons route wiring

## Out Of Scope

- Promotion rule editing (PR-401)
- Cart-side coupon application UX changes (storefront cart already applies codes if present)
- Bulk coupon import/export
- Auto-generating coupon codes

## Validation

- merchant can create a coupon bound to an existing promotion and see it in the grid
- invalid code format returns 422 with a clear message
- delete removes the coupon; cart no longer accepts the code
- `go test ./internal/interfaces/http -run Coupon -count=1`
