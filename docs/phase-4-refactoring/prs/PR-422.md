# PR-422 — Plugin Config Registration In Admin (Track C, Stretch)

Status: planned

## Summary

- use `RegisterConfig` (or equivalent plugin config hook) in the example plugin so settings appear on the admin integrations page
- stretch goal — implement only if PR-420/421 expose a clear, minimal config surface

## Why

Admin integrations page exists for system settings; plugin-defined config would complete the external author story. This is lower priority than the example plugin and docs; skip if timeboxed.

## Scope

- extend `plugin.App` with config registration if not already present from PR-410
- example plugin registers one bool or string setting (e.g. `example.discount_cents`)
- admin integrations UI reads registered plugin config schema and renders simple fields; save persists to config store or env-backed settings per existing pattern
- tests: registered config appears in API; update persists

## Out Of Scope

- Complex config types, validation DSL, secrets in admin UI
- Enabling/disabling plugins from admin (config file remains source of truth)

## Validation

- with example plugin enabled, integrations page shows example setting
- changing value affects example pricing step behavior
- skip PR entirely if hook does not exist and would require large admin refactor — document deferral in ROADMAP
