# PR-413 — Storage Core Plugins (Local, S3) (Track B)

Status: done

## Summary

- extract local filesystem and S3 media storage selection into `plugins/core/storage-local` and `plugins/core/storage-s3`
- config-driven media backend; local remains default

## Why

`main.go` switches between `localfs` and `s3store` based on config. Core plugins make storage backends explicit optional integrations consistent with search and queue.

## Scope

- `plugins/core/storage-local`: registers local filesystem storage (default)
- `plugins/core/storage-s3`: registers S3 storage when `media.storage=s3` (or existing config key) and required AWS env vars present
- bootstrap uses registered `media.Storage` from plugins
- media upload, URL generation, and admin media library unchanged in behavior
- tests: local plugin always active; S3 plugin init with missing credentials fails gracefully

## Out Of Scope

- CDN plugins
- Image transformation pipeline
- Multi-bucket routing

## Validation

- default config: uploads land on local filesystem; URLs resolve
- S3 config with valid credentials: upload and public URL work (integration or documented smoke)
- `go test ./plugins/core/... -count=1`

## What changed

- **`plugins/core/storagelocal/`**: registers `localfs` storage when `media.storage=local` (default)
- **`plugins/core/storages3/`**: registers `s3store` storage when `media.storage=s3`; fails init on missing bucket/region
- **`plugins/core/register.go`**: if/else-if registers one storage plugin (local or s3)
- **`core_plugins.go` / `validate.go`**: `CoreLocalStorageEnabled`, `CoreS3StorageEnabled`, media.storage validation
- **`cmd/api/providers.go`**: removed direct `s3store.New` fallback; s3 requires successful plugin init
- **Tests**: plugin init guards; register selection; resolve media storage integration
