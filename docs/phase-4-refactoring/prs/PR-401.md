# PR-401 — Admin Promotions CRUD (Track A)

Status: done

## Summary

- deliver list/create/edit/delete for **simple** catalog and cart promotions in the admin marketing area
- wire `/admin/marketing/promotions` off the placeholder; encode/decode the JSON `Conditions`/`Actions` shapes the existing pricing step already understands

## Why

`promotion.Promotion` and `postgres.PromotionRepo` exist and `CatalogPromotionStep` applies percentage/fixed discounts with optional min-quantity and date windows — but there was no admin surface.

## What changed

- `PromotionRepository.List` on domain + postgres repo
- `internal/application/admin/promotion_rules.go` — encode/decode admin form ↔ JSON conditions/actions
- `PromotionAdminHandler` CRUD at `/api/v1/admin/promotions`; RBAC via `ProductsRead`/`ProductsWrite`
- audit actions: `promotion.read/create/update/delete`
- admin UI: promotions grid + form; coupon form now uses promotion `<select>` dropdown
- integration test: admin-encoded rules applied by `CatalogPromotionStep`

## Scope

- admin API: CRUD under `/api/v1/admin/promotions` using `PromotionRepository`
- **simple rules only** — admin form maps to existing action/condition JSON:
  - types: `catalog` and `cart`
  - actions: `percentage` or `fixed` discount (minor units for fixed)
  - optional conditions: `min_cart_total` (cart), `min_quantity` (catalog line)
  - optional `start_at` / `end_at`, `active`, `priority`, `coupon_bound` flag
- admin UI: grid + create/edit form; no visual rule builder; raw JSON escape hatch not exposed
- audit: promotion mutations logged
- tests: handler tests for each supported action shape; pricing step integration test that a promotion created via API is applied in cart

## Out Of Scope

- Tiered discounts, buy-X-get-Y, customer segments, product/category conditions
- Cart-rule DSL or drag-and-drop rule builder
- Coupon management (PR-400)

## Validation

- merchant can create a 10% catalog promotion and see it affect cart line pricing
- expired or inactive promotions are skipped by pricing (existing behavior, verified via test)
- `go test ./internal/interfaces/http ./internal/application/pricing -count=1`
