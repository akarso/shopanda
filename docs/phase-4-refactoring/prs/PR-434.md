# PR-434 — Persistent Audit Log (Track D, Stretch)

Status: planned

## Summary

- add `admin_audit_log` table and persist admin audit entries from `Auditor`; read-only list in admin
- logger remains fallback when DB write fails; skip if timeboxed

## Why

Admin audit events today go to structured logs only. Merchants and compliance workflows benefit from a queryable in-app audit trail. Stretch because logger-based audit already exists from Phase 3 scoped editing work.

## Scope

- migration: `admin_audit_log` (timestamp, actor, action, resource type/id, store/language/currency scope, metadata JSON)
- `Auditor`: write-through to repo after log line; best-effort, non-blocking or transactional per existing patterns
- admin API: `GET /api/v1/admin/audit` paginated, filter by action/resource/date
- admin UI: simple read-only table under Settings or Operations
- RBAC: audit read permission
- tests: write on product update creates row; list returns entry

## Out Of Scope

- Audit export, retention policies, PII redaction tooling
- Storefront customer action audit

## Validation

- admin product edit produces visible audit row with correct scope triad
- list endpoint respects RBAC
- skip PR if schema + UI exceeds stretch budget — note in ROADMAP
