# PR-404 — Scoped Price Editing In Product Admin (Track A)

Status: planned

## Summary

- extend the product edit screen so merchants can view and edit variant prices for the active store/currency context without CSV import
- build on PR-395's per-variant price API and context switcher

## Why

PR-395 added `GET/PUT .../variants/{variantId}/price` for scoped prices, but routine price changes still require `app import:prices` for bulk work. Day-to-day single-SKU edits belong in the product form.

## Scope

- admin UI: on product edit, each variant row shows editable price for active `X-Admin-Store-ID` + `X-Admin-Currency`; save calls existing price API; clear empty-state when currency context missing (reuse PR-395 prompt)
- optional: display global vs store-scoped indicator on the price field
- tests: extend `product_scoped_admin_test.go` or admin static guards for variant price inputs on edit page

## Out Of Scope

- Bulk price grid across all products (future)
- Price history UI
- Tiered / customer-group pricing
- Changes to pricing pipeline logic

## Validation

- merchant with currency context selected can change a variant price on product edit and see it on storefront PDP for that store
- without currency context, UI prompts to select one (no silent wrong-scope write)
- `go test ./internal/interfaces/http -run Price -count=1`
