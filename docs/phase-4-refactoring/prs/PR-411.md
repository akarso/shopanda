# PR-411 — Search Core Plugin (Meilisearch) (Track B)

Status: planned

## Summary

- move Meilisearch wiring from `cmd/api/main.go` into `plugins/core/meilisearch`
- activate when `search.engine=meilisearch`; preserve Postgres FTS as default

## Why

Search engine selection is already config-driven in `main.go` (`case "meilisearch":`), but it bypasses the plugin registry. Packaging as a core plugin makes optional search a first-class extension and shrinks bootstrap.

## Scope

- new package `plugins/core/meilisearch` implementing `plugin.Plugin`
- `Init`: when `search.engine=meilisearch`, construct `meili.Client`, register as search provider via PR-410 hooks; return error if Meili URL/key missing (plugin marked failed, startup may fall back or fail fast — match existing behavior)
- remove direct `meili.New` branches from `main.go`; bootstrap obtains search provider from plugin wiring
- config/env unchanged: `SHOPANDA_SEARCH_ENGINE`, Meili host/API key
- tests: plugin init with mock or skipped integration; config guard when engine is meilisearch but client init fails

## Out Of Scope

- Elasticsearch or other search engines
- Index management UI
- Changing search query behavior

## Validation

- `search.engine=postgres` (default): no Meilisearch connection attempted
- `search.engine=meilisearch` with valid env: catalog search uses Meili (existing integration tests or manual smoke)
- `go test ./plugins/core/meilisearch -count=1` (or package path chosen in implementation)
