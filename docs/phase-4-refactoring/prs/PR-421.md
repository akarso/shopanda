# PR-421 — Three-Tier Plugin Documentation (Track C)

Status: planned

## Summary

- align `README.md`, `docs/guides/DEVELOPER.md`, `PLUGINS.md`, and `docs/diagrams/c4-component.md` with the core / core-plugin / external plugin model
- document honestly what still requires `main.go` compile-time registration

## Why

Documentation still describes plugins abstractly while infrastructure is wired directly in `main.go`. After Track B/C work begins, docs must reflect the three tiers and set correct expectations for external authors.

## Scope

- README: three-tier diagram or table; default stack vs optional plugins; link to Phase 4 roadmap
- DEVELOPER.md: how to enable core plugins (env/config); how to add an external plugin (import + `registry.Register`)
- PLUGINS.md (or `docs/phase-1-core/specs/PLUGINS.md` cross-link): extension mechanisms (events, pipelines, permissions); core vs external boundaries
- C4 component diagram: PluginRegistry connections to core plugins and example external plugin
- list deferred capabilities: `.so` loading, marketplace, plugin CLI

## Out Of Scope

- Video tutorials
- Rewriting all Phase 1 specs

## Validation

- a new contributor can answer: what is core, what is core-plugin, what is external, from README + DEVELOPER.md alone
- C4 diagram matches post-PR-410 registry wiring (update when B lands if needed; this PR can target planned state with note)
