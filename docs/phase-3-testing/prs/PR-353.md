# PR-353 - Admin Login-To-Products End-To-End Flow Coverage (Track 3)

Implemented the next Track 3 hardening slice by adding a real HTTP end-to-end test for the admin login-to-products path.

## Summary

The codebase already had coverage for:

- auth login behavior in isolation
- schema permission checks in isolation
- product-admin permission checks in isolation

But it did not have one test that exercised the full runtime path an operator actually uses:

1. log in through `POST /api/v1/auth/login`
2. carry the issued JWT through the real validating token parser
3. resolve the authenticated admin identity through middleware
4. load `GET /api/v1/auth/me`
5. load `GET /api/v1/admin/grids/product.grid`
6. load `GET /api/v1/admin/products?page=1&per_page=20&sort=created_at&order=desc`

This PR adds that exact flow.

## Why This Slice

This is the most direct way to prove the current Track 3 admin products path works end to end:

- no mock token shortcuts
- no direct identity injection shortcuts
- real JWT issuance
- real token validation against customer state
- real auth and permission middleware
- real admin grid and products endpoints behind the same login token

## Changes

### Tests

Added ../../../internal/interfaces/http/admin_login_products_flow_test.go:

- Seeds an admin-role customer with a real password hash
- Logs in through `POST /api/v1/auth/login`
- Uses the returned bearer token for all subsequent requests
- Verifies `GET /api/v1/auth/me` returns the admin role and expected account email
- Verifies `GET /api/v1/admin/grids/product.grid` succeeds through the real permission path
- Verifies `GET /api/v1/admin/products?page=1&per_page=20&sort=created_at&order=desc` succeeds and returns product data
- Exercises the real `ValidatingTokenParser`, `AuthMiddleware`, `AdminContextMiddleware`, `RequireAuth`, and `RequirePermission(rbac.ProductsRead)` chain

## Notes

This slice did not require a production code change because the real login-to-products backend path is currently working. The value of the slice is that future auth, token, permission, or route regressions in this admin workflow will now fail a single end-to-end test instead of surfacing later as a broken admin products screen.
