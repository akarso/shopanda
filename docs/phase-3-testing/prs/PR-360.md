# PR-360 - Admin Store Languages Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/store/languages` placeholder with a working store languages page backed by the existing admin stores API.

## Summary

The admin shell already exposed a Languages route under Store Management, but it still rendered a placeholder even though the backend already supported the data needed for a usable screen:

- `GET /api/v1/admin/stores`

This PR wires a focused store languages screen into the admin SPA using that existing endpoint.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- converts another admin navigation dead end into a working screen
- reuses the existing normalized store payload instead of introducing a new admin API

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/store/languages` placeholder route with `renderStoreLanguagesPage`
- Reused the existing stores list endpoint and store normalization helpers
- Added a store languages table showing:
  - store name
  - language
  - domain
  - default store flag
- Added explicit `forbidden` handling with `Your account does not have stores access.`
- Added explicit malformed/load failure handling with `Failed to load store languages.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderStoreLanguagesPage`
  - `/admin/store/languages`
  - `Your account does not have stores access.`
  - `Failed to load store languages.`
