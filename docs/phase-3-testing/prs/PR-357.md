# PR-357 - Admin Stores List Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/store` placeholder with a working stores list backed by the existing admin stores API.

## Summary

The admin shell already exposed a Stores navigation entry, but the route still rendered a placeholder even though the backend already supported:

- `GET /api/v1/admin/stores`

This PR wires the first usable stores surface into the admin SPA by rendering a stores table from the existing list endpoint.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- directly turns another existing admin navigation dead end into a working screen

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/store` placeholder route with `renderStoresGrid`
- Reused the existing `normalizeStore()` helper for admin store payloads
- Added a stores table view showing:
  - name
  - code
  - domain
  - language
  - currency
  - default store flag
- Added explicit `forbidden` handling with `Your account does not have stores access.`
- Added explicit malformed/error payload handling with `Failed to load stores.`
- Avoided treating permission or backend failures as an empty stores list

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderStoresGrid`
  - `/admin/stores`
  - `Your account does not have stores access.`
  - `Failed to load stores.`
