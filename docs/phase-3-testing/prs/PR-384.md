# PR-384: Prevent Duplicate Product Category Mutation Submissions

## Summary

Product-edit category assign/remove actions now use a lightweight in-flight mutation
lock so repeated rapid clicks do not trigger duplicate assign/remove API requests.

## Motivation

Recent slices moved product category assignment mutations to local state updates for
faster UX. Without a transient lock, users can still fire overlapping mutation requests
via rapid clicking, which can create noisy error handling and inconsistent transient UI.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- In `bindProductCategoryAssignmentActions`:
  - Added `isMutationBusy()` helper using a container-level busy attribute.
  - Added `setMutationBusy(isBusy)` helper that:
    - toggles `data-product-category-mutation-busy`
    - disables/enables assign and remove action buttons during mutation requests.

- Updated assign handler:
  - Early-return when busy.
  - Calls `setMutationBusy(true)` before API call.
  - Calls `setMutationBusy(false)` on all completion paths (error, fallback reload,
    successful local update, catch).

- Updated remove handler with identical busy guard behavior.

### internal/interfaces/http/admin_handler_test.go

- Extended product assignment static JS wiring checks with:
  - `data-product-category-mutation-busy`
  - `setMutationBusy(true)`
