# PR-343 — Customer Admin Revoke-Sessions Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for customer-admin revoke-sessions all-or-nothing scope behavior.

## Summary

PR-342 added `POST /api/v1/admin/customers/{customerId}/revoke-sessions` with scoped audit logging on both success and repository failure paths. That endpoint already delegates scope extraction to the shared full-scope helper used across other audited admin surfaces.

This PR adds the missing regression tests that prove revoke-sessions follows the same contract when only a partial scope is supplied.

## Why This Slice

The production behavior already existed through the shared helper, but the new revoke-sessions write endpoint did not yet have explicit coverage for partial-scope omission on its audited paths.

This keeps the change narrow and test-focused:

- no production behavior change
- no new route
- no new audit action
- direct hardening of the newest customer-admin write surface

## Changes

### Tests

Updated [../../../internal/interfaces/http/customer_admin_test.go](../../../internal/interfaces/http/customer_admin_test.go):

- Added `TestCustomerAdminHandler_RevokeSessions_AuditOmitsPartialScopeContext`
- Added `TestCustomerAdminHandler_RevokeSessions_AuditFailureOmitsPartialScopeContext`

The new tests verify that revoke-sessions audit entries still include the expected core metadata when only two of the three scope headers are present:

- action
- resource type
- resource id
- admin id
- result
- error on failure

They also verify these scope keys are absent under partial scope:

- `detail_store_id`
- `detail_language`
- `detail_currency`

## Validation

Executed:

```bash
go test ./internal/interfaces/http -run 'TestCustomerAdminHandler_RevokeSessions_' -count=1
```

The command passed.

This PR intentionally strengthens the test contract around existing behavior rather than widening customer-admin production code again.
