# PR-363 - Admin Integrations Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/integrations` placeholder with a grounded integrations overview backed by existing admin config APIs.

## Summary

The admin shell already exposed an Integrations route, but it still rendered a placeholder and there is no dedicated integrations status API in the current backend.

This PR wires a read-only integrations overview into the admin SPA using the configuration data already available today:

- `GET /api/v1/admin/config?group=email`
- `GET /api/v1/admin/config?group=media`

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- converts another admin navigation dead end into a working screen
- stays grounded in current backend capabilities instead of inventing runtime integration status APIs that do not exist

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/integrations` placeholder route with `renderIntegrationsPage`
- Reused the existing email and media config endpoints to show current integration-related configuration
- Added an integrations overview covering:
  - email delivery configuration
  - media storage backend configuration
  - links to shipping and payments operational provider pages
  - a plugin extension note that matches the current runtime contract
- Added explicit `forbidden` handling with `Your account does not have settings access.`
- Added explicit malformed/load failure handling with `Failed to load integrations.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderIntegrationsPage`
  - `/admin/config?group=email`
  - `/admin/config?group=media`
  - `Plugin integrations are registered at application boot.`
  - `Failed to load integrations.`
