# PR-327 — PR-D Scoped Data Model And Config API Contracts (Track 3)

## Summary

Implemented the next Track 3 slice by introducing explicit scope contracts for admin config fields and adding store-level override behavior with global fallback.

This slice focuses on backend contract clarity and deterministic behavior:

- field scope metadata is now explicit in admin config responses
- store-scoped config keys support `global + store override` resolution
- writes can target either global values (no store scope) or store overrides (when store scope is set)

## Scope

- internal/interfaces/http/config_admin.go
  - added explicit scope constants (`global`, `store`, `translatable`)
  - added per-key scope map for admin-managed config keys
  - GET `/api/v1/admin/config` now returns:
    - `field_scopes` (key -> scope)
    - `scope.store_id` (resolved request scope)
  - implemented scoped read resolution for store-scoped keys:
    - if store scope exists, read `store override` first
    - fallback to global key when no override exists
  - implemented scoped write routing:
    - store-scoped keys persist as store overrides when store scope exists
    - otherwise persist to global key
  - store scope resolution now supports:
    - explicit query param `store_id`
    - fallback to `admin.AdminContext.StoreID`
- internal/interfaces/http/config_admin_test.go
  - added test for `field_scopes` in config responses
  - added end-to-end test proving:
    - global value write
    - store override write
    - scoped read returns override
    - global read retains base value

## Behavior

### Explicit scoped contract in API response

`GET /api/v1/admin/config` now exposes the field scope model so clients can render and reason about scoped editing without implicit assumptions.

### Simple override model

For store-scoped fields:

- global value remains the base value
- store override supersedes global only for that store scope
- no deep inheritance chains are introduced

## Why this slice

Track 3 PR-D requires explicit scoped contracts and the simple global + store override model.

This implementation keeps changes narrow to admin config flows while enabling future scoped editing UX in PR-E.
