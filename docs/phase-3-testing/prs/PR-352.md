# PR-352 - Admin Reauthentication Flash On Session Expiry (Track 3)

Implemented the next visible Track 3 production slice by making expired admin sessions surface a working reauthentication message on the login screen after an API-triggered redirect.

## Summary

The admin SPA's shared API helper redirected to `/admin` on `401 Unauthorized`, but it rejected the request immediately and did not preserve any user-facing context. That meant screen-level `401` handling inside pages like the products screen was effectively dead code, and operators were sent back to login without a clear reason.

This PR fixes that runtime behavior by carrying a one-shot login message through the redirect.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no route changes
- no permission model changes
- directly improves the admin recovery path when a session expires during a protected workflow

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Added a transient login message key for the admin SPA
- Persist a one-shot reauthentication message before redirecting to `/admin` on API `401` responses
- Applied the same behavior to media upload `401` responses
- Render the pending login message into the admin login error area on page load
- Removed the dead inline `unauthorized` branch from the products grid renderer, since `401` responses are handled centrally before page-level rendering

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - the login-flash storage key
  - `Your session expired. Sign in again to continue.`
