# PR-354 - Admin Customers List Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/customers` placeholder with a working customers list backed by the existing admin customers API.

## Summary

The admin shell already exposed a Customers navigation entry, but the route still rendered a placeholder even though the backend already supported customer reads through:

- `GET /api/v1/admin/customers`
- `GET /api/v1/admin/customers/{customerId}`

This PR wires the first usable customers surface into the admin SPA by rendering a customers table from the existing list endpoint.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no route changes on the API side
- no permission model changes
- directly turns an existing dead-end admin navigation entry into a usable screen

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/customers` placeholder route with `renderCustomersGrid`
- Added `normalizeCustomers()` and `normalizeCustomer()` helpers for admin customer payloads
- Added a customers table view showing:
  - name
  - email
  - role
  - status
  - email verification state
  - created date
- Added explicit `forbidden` handling with `Your account does not have customer access.`
- Added explicit malformed/error payload handling with `Failed to load customers.`
- Avoided treating permission or backend failures as an empty customer list

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderCustomersGrid`
  - `/admin/customers?offset=0&limit=50`
  - `Your account does not have customer access.`
  - `Failed to load customers.`
