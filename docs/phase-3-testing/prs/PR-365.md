# PR-365 - Admin Categories API Read Slice (Track 3)

Implemented the smallest viable production category-admin slice by adding `GET /api/v1/admin/categories` and rewiring the existing Categories admin page to use that permission-gated admin route.

## Summary

The Categories page in the admin UI had already been converted from a placeholder into a read-only tree view, but it still depended on the public category tree API.

This PR moves that surface onto a real admin route backed by the same category tree handler with admin permission enforcement:

- `GET /api/v1/admin/categories`

## Why This Slice

This is the smallest real backend-backed admin categories step:

- introduces an actual admin category endpoint
- keeps the existing read-only UI intact
- uses the existing category tree handler instead of creating a new abstraction
- applies the existing categories permission model rather than widening access through the public route

## Changes

### Backend

Updated ../../../cmd/api/main.go:

- Added `RequirePermission(rbac.CategoriesRead)` wiring for `GET /api/v1/admin/categories`
- Reused the existing `categoryHandler.Tree()` implementation for the first admin categories read surface

Updated ../../../internal/interfaces/http/category_test.go:

- Added focused admin route coverage for:
  - categories read allowed for an editor role
  - categories read forbidden for a support role

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Rewired `renderCategoriesPage` from `/categories` to `/admin/categories`
- Added explicit `forbidden` handling with `Your account does not have categories access.`
- Kept the existing read-only category tree rendering and malformed/load failure handling

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Tightened static asset coverage for the categories admin page to include:
  - `/admin/catalog/categories`
  - `/admin/categories`
  - `Your account does not have categories access.`
  - `Failed to load categories.`
