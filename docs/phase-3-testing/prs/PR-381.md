# PR-381: Local Assign/Remove Re-render for Product Category Assignment

## Summary

Product-edit category assignment now applies successful assign/remove mutations to the
in-memory assigned/available category lists and re-renders immediately, instead of always
reloading both product and category payloads after each action.

## Motivation

The product category panel already loads the full category tree and keeps local paging/search
state. For assign/remove actions, forcing a full reload caused avoidable round-trips and
loading flashes. A local re-render keeps the user anchored on their current filtered/page view.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- In `bindProductCategoryAssignmentActions` assign handler:
  - On successful API response, move the selected category from `availableCategories`
    to `assignedCategories` in memory.
  - Clamp paging offsets and call `rerender(assignedCategories, availableCategories)`.
  - If local reconciliation fails unexpectedly, fall back to `reload()`.

- In remove handler:
  - On successful API response, move the removed category from `assignedCategories`
    back to `availableCategories` in memory.
  - Clamp paging offsets and call `rerender(assignedCategories, availableCategories)`.
  - If local reconciliation fails unexpectedly, fall back to `reload()`.

### internal/interfaces/http/admin_handler_test.go

- Extended static JS guard to assert local mutation/re-render tokens are present:
  - `availableCategories.splice`
  - `assignedCategories.push`
  - `availableCategories.push`
  - `rerender(assignedCategories, availableCategories)`
  - `reload()`
