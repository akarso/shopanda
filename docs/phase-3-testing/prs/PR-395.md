# PR-395 — Admin Scoped Product Editing (Track 3, PR-E Catalog)

Status: done

## Summary

- delivered the catalog half of the deferred PR-E slice: product editing that distinguishes global, translatable, and store-scoped fields
- exposed per-language product translations for editing in the admin, backed by the existing `content_translations` infrastructure
- surfaced store-scoped variant pricing in the product form using the existing pricing domain support
- made the global context switcher (store / language / currency) actually drive what the product form shows and saves

## Why

PR-328 shipped scoped editing for Settings only and explicitly deferred catalog/content. Before this PR the product admin schema declared flat fields with no scope metadata, the product form had no scope banner or badges, there was no admin API/UI to write product translations, and the pricing domain's store-scoped prices were not editable from the admin. The context switcher headers (`X-Admin-Store-ID` / `X-Admin-Language` / `X-Admin-Currency`) were only used for audit metadata, never to drive data.

## What changed

- schema: `internal/application/admin/product_schema.go` now declares a `scope` for each field via `Meta` (`name`/`description` → `translatable`, `slug`/`status` → `global`), mirroring the `field_scopes` model used by Settings.
- audit: added `product.translation.read/update` and `price.read/update` actions in `internal/application/admin/audit.go`.
- translations API (`internal/interfaces/http/product_translation_admin.go`):
  - `GET /api/v1/admin/products/{id}/translations` returns the translated `name`/`description` for the active language scope plus `field_scopes`.
  - `PUT /api/v1/admin/products/{id}/translations` upserts the per-language values via `content_translations`. Empty values are a no-op (the store has no single-field delete); only allowed translatable fields are accepted.
  - language is taken from `X-Admin-Language`; missing language → validation error.
- pricing API (`internal/interfaces/http/product_price_admin.go`):
  - `GET /api/v1/admin/products/{id}/variants/{variantId}/price` returns the price for the active store + currency context (empty store = global/default price).
  - `PUT .../price` upserts the store-scoped price (amount in minor units) for the active store + currency. Currency is taken from `X-Admin-Currency`; missing currency → validation error.
  - both verify the variant belongs to the product (404 otherwise).
- audit: translation and price writes/reads log through the existing scoped auditor, so entries carry the full `store_id` / `language` / `currency` triad.
- routes: wired the four endpoints in `cmd/api/main.go` behind `ProductsRead` / `ProductsWrite`.
- UI (`internal/interfaces/http/admin/dist/admin.js`):
  - product form renders the Settings-style scope banner and per-field scope badges (reusing the existing `settings-scope-badge` styles).
  - translatable fields load from / save to the active language via the translations API; in edit mode they are excluded from the global product `PUT` so the base record is untouched. On create, base values are written as before.
  - the variant panel gains a store/currency-scoped price editor that loads and saves per-variant prices and notes the active scope; with no currency context it prompts to select one.
  - scope changes re-route through `handleRoute()`, so the form reloads its scoped values for the new context.

## Out Of Scope

- store-scoped product status/visibility (status stays global)
- category or page scoped editing (pages are PR-396; categories stay global)
- attribute management (deferred)
- clearing an individual translation (no single-field delete in the content-translation store)

## Validation

- `go test ./internal/interfaces/http ./internal/application/admin -count=1`
- translation handler tests: returns active-language entries + `field_scopes`, language required, product 404, upsert writes only the active language (empty fields skipped), invalid field rejected, audit triad present.
- price handler tests: returns store-scoped price, currency required, variant-not-found-for-product 404, write targets only the active store scope (pre-existing global price untouched), amount required, audit triad present.
- product schema test asserts each field's declared scope.
- static admin asset guards (`admin_handler_test.go`) updated for the product scope banner/badges, translation + price wiring, and the new variant price column.
