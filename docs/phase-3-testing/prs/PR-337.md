# PR-337 — Stats Admin Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for stats-admin all-or-nothing scope behavior.

## Summary

PR-336 moved stats admin onto the shared full-scope helper used by other scope-aware admin endpoints. That helper intentionally emits scope details only when all three scope values are present:

- `store_id`
- `language`
- `currency`

This PR adds the missing regression test that proves stats-admin follows that contract when only a partial scope is supplied.

## Why This Slice

The production behavior already existed through the shared helper, but stats admin did not yet have the explicit regression coverage that product admin already had.

This slice keeps the change narrowly scoped: strengthen the test contract around an existing behavior rather than widening production code again.

## Changes

### Tests

Updated [../../../internal/interfaces/http/stats_admin_test.go](../../../internal/interfaces/http/stats_admin_test.go):

- Added `TestStatsAdminHandler_Overview_AuditOmitsPartialScopeContext`
- Verifies the audit entry is still emitted on success
- Verifies standard audit metadata is still present:
  - action
  - resource type
  - result
  - dashboard read parameters
  - admin id
- Verifies scope keys are absent when only two of the three scope headers are provided:
  - `detail_store_id`
  - `detail_language`
  - `detail_currency`

## Validation

Executed:

```bash
go test ./internal/interfaces/http -run 'TestStatsAdminHandler_' -count=1
```

## Notes

This PR is intentionally test-focused. No production code change was required because stats admin already delegates scope extraction to the shared full-scope helper.
