# PR-355 - Admin Customer Detail Surface (Track 3)

Implemented the next visible Track 3 admin surface by adding a customer detail page for `/admin/customers/{customerId}` backed by the existing admin customer detail API.

## Summary

After PR-354, the admin shell had a working customers list, but each customer row still stopped at the list view even though the backend already supported:

- `GET /api/v1/admin/customers/{customerId}`

This PR wires the customer detail route into the admin SPA and links each customer row to that detail page.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- builds directly on the new customers list instead of adding another placeholder-adjacent surface

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Added route resolution for `/admin/customers/{customerId}`
- Added `renderCustomerDetail(customerID)` backed by `GET /api/v1/admin/customers/{customerId}`
- Added row links from the customers list into the detail route
- Rendered the customer detail view with:
  - name
  - email
  - role
  - status
  - email verification state
  - created date
  - updated date
  - customer ID
- Added explicit detail-page error handling for:
  - `forbidden` -> `Your account does not have customer access.`
  - `not_found` -> `Customer not found.`
  - malformed/failed response -> `Failed to load customer.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderCustomerDetail`
  - `/admin/customers/`
  - `Customer not found.`
  - `Failed to load customer.`
