# PR-320

## Summary

- enable guests to discover and claim their orders using contact email
- generate secure claim tokens (encrypted, time-bounded) for order lookup
- allow guests to later register and link claimed orders to new customer account
- add domain-level and HTTP endpoint support for order claim workflow

## Scope

- **domain/order/repository.go**: add `FindByContactEmail` interface method for guest order discovery
- **infrastructure/postgres/order_repo.go**: implement `FindByContactEmail` with case-insensitive email matching and batch item loading
- **storefront_account_security.go**: add `storefrontOrderClaimTokenClaims` type, `orderClaimToken()` and `verifyOrderClaimToken()` methods with AES-256-GCM encryption; derive separate AES key via `orderClaimAESKey()`
- **application/order/claim_service.go**: new `ClaimService` with `SearchGuestOrders()` and `VerifyOrderBelongsToEmail()` methods
- **interfaces/http/storefront.go**: add `orderClaim` field to `StorefrontHandler`, new `WithOrderClaim()` builder method, import `orderApp`
- **interfaces/http/storefront_order_claim.go**: new file with HTTP handlers:
  - `ClaimOrderSearch()` → POST `/api/v1/orders/claim-search` (public, no auth required)
  - `ClaimOrder()` → POST `/api/v1/orders/claim` (public, no auth required)
- **tests**: 
  - order_repo_test.go: add `TestOrderRepo_FindByContactEmail`, `FindByContactEmail_Empty`, `FindByContactEmail_CaseInsensitive`; new helpers `mustNewGuestOrder()`, `mustNewAuthenticatedOrderWithEmail()`
  - claim_service_test.go: unit tests for service layer (mock repository)
  - all HTTP test stubs updated to implement `FindByContactEmail()` method

## Design Notes

- **Claim Token Security**: Uses same AES-256-GCM pattern as checkout resume tokens; separate key derivation (`order-claim-aes256gcm:`) ensures isolation
- **Case-Insensitive Email Lookup**: Repository normalizes email to lowercase for query consistency
- **Batch Hydration**: `FindByContactEmail` follows existing pattern of batch loading items to reduce N+1 queries
- **No Contact Email Exposure**: HTTP responses include order ID + status + total; contact email only in claims verification
- **Integration Points**: Storefront handler builder pattern allows optional claim service wiring; fully backward compatible
