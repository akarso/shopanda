# PR-335 — Product Admin Create Scoped Audit Logging (Track 3)

Implemented the next real Track 3 slice by extending scoped audit coverage to product creation flows.

## Summary

PR-334 added scoped audit logging for product list and update operations. This slice closes the remaining product-admin write gap by adding audit coverage to `POST /api/v1/admin/products`.

Product create operations now emit audit entries that include the active admin scope triad when present:

- `store_id`
- `language`
- `currency`

The create path now records both:

- successful product creation
- failed create attempts caused by invalid request bodies or product validation failures

## Why This Slice

The previous PR documented customer-admin scoped audit logging as the likely next slice, but there is currently no customer-admin backend surface in the workspace to extend without introducing a new subsystem.

Product create was the next smallest real slice on an existing admin write path, so this PR preserves Track 3 momentum without inventing new API surface.

## Notes

This slice keeps product-admin audit semantics consistent with the current Track 3 pattern:

- success emits `admin.action`
- failure emits `admin.action.failed`
- scope details are only emitted when the full triad is present
