# PR-321

## Summary

- implement guest claim plus first-use registration workflow
- link guest orders to the newly registered customer account
- return authentication token immediately after successful linking
- expose a public claim-register endpoint guarded by encrypted claim tokens

## Scope

- **domain/order/order.go**: add `LinkToCustomer(customerID string)` to convert a guest order into an authenticated order
- **application/order/link_service.go**: add `LinkOrderService` with `RegisterAndLink()` orchestration
  - validates input fields
  - registers account through `OrderAuther` abstraction
  - loads order and links via domain method
  - persists through `UpdateStatus`
  - returns customer id and auth token
- **application/order/link_service_test.go**: add unit tests for success, order-not-found, already-linked, and empty-input validation
- **interfaces/http/storefront.go**:
  - add `orderLinker` dependency to `StorefrontHandler`
  - add `WithOrderLinker()` builder
- **interfaces/http/storefront_order_claim.go**:
  - add `OrderLinker` interface and `NewStorefrontOrderLinkerAdapter()`
  - add `ClaimLink()` endpoint handler (POST `/api/v1/orders/claim-register`)
  - verify `claim_token`, enforce token email match, verify order ownership, then invoke registration+linking
  - return `customer_id`, `email`, and `token` on success
- **cmd/api/main.go**:
  - wire `LinkOrderService` into storefront handler
  - register public route `POST /api/v1/orders/claim-register`
- **interfaces/http/storefront_order_claim_test.go**:
  - add HTTP tests for successful claim-register flow, invalid claim token rejection, and missing field validation

## Design Notes

- **No Side-Channel Ownership Leaks**: claim-link flow keeps ownership failures generic (`order ownership verification failed`)
- **Composition-Friendly Wiring**: HTTP layer consumes `OrderLinker` interface so handler remains testable and decoupled from concrete application service
- **First-Use UX**: successful claim-register returns auth token directly for immediate signed-in experience
- **Domain Guardrails**: `LinkToCustomer()` prevents empty customer ids and double-linking
