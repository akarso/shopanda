# PR-344 — Customer Admin Delete Surface + Scoped Audit Logging (Track 3)

Implemented the next concrete Track 3 slice by adding a customer-admin delete endpoint on top of the existing account deletion use case.

## Summary

Customer-admin already had read surfaces plus the focused revoke-sessions write action. This PR adds a second concrete write operation that is already justified by the current application boundary:

- `DELETE /api/v1/admin/customers/{customerId}`
- permission-guarded with `customers.write`
- delegates deletion to the existing account deletion service
- emits scoped audit entries for success and failure paths

This reuses the account deletion workflow that already handles consent cleanup and customer removal, so the admin surface extends an existing use case instead of bypassing it with a raw repository delete.

## Why This Slice

The customer repository exposes a low-level delete operation, but the existing account service is the correct abstraction because it already coordinates related cleanup work before removing the customer record.

That made admin customer delete the next smallest justified write slice because it:

- has existing application behavior
- avoids skipping consent cleanup
- requires no new domain contract
- extends customer-admin with a concrete administrative operation rather than a speculative edit API

## Changes

### Production

Updated [../../../internal/application/admin/audit.go](../../../internal/application/admin/audit.go):

- Added `admin.AuditCustomerDelete`

Updated [../../../internal/interfaces/http/customer_admin.go](../../../internal/interfaces/http/customer_admin.go):

- Added support for injecting an account deletion use case into `CustomerAdminHandler`
- Added `Delete()` for `DELETE /api/v1/admin/customers/{customerId}`
- Delegates to the existing account deletion service via `DeleteAccount`
- Returns a small JSON confirmation payload:
  - `deleted: true`
  - `customer_id`
- Emits `customer.delete` audit entries for:
  - successful deletion
  - non-not-found failure paths
- Includes full scope triad in audit details when present:
  - `store_id`
  - `language`
  - `currency`
- Preserves neighboring admin-write behavior by not emitting an audit entry for not-found lookups

Updated [../../../cmd/api/main.go](../../../cmd/api/main.go):

- Constructs `customerAdmin` with the existing `accountService`
- Wired `DELETE /api/v1/admin/customers/{customerId}` behind `requireCustomersWrite`

## Notes

This PR deliberately routes deletion through the existing account application service instead of calling the customer repository directly. That keeps admin delete behavior aligned with the current deletion workflow and avoids widening low-level deletion semantics at the HTTP layer.
