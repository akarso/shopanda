# PR-358 - Admin Localization Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/settings/localization` placeholder with a working localization page backed by existing admin config and store APIs.

## Summary

The admin shell already exposed a Localization route, but it still rendered a placeholder even though the backend already supported the data needed for a usable surface:

- `GET /api/v1/admin/stores`
- `GET /api/v1/admin/config?group=currency`
- `PUT /api/v1/admin/config`

This PR wires a focused localization screen into the admin SPA using those existing endpoints.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- converts another admin navigation dead end into a working screen
- reuses existing settings helpers instead of introducing new admin-specific plumbing

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/settings/localization` placeholder route with `renderLocalizationSettingsPage`
- Reused the existing currency settings form backed by the config admin API
- Added a store-localization summary table showing:
  - store name
  - assigned language
  - default currency
  - domain
- Reused the existing settings scope banner so store-scoped overrides remain visible
- Added explicit `forbidden` handling with `Your account does not have settings access.`
- Added explicit malformed/load failure handling with `Failed to load localization settings.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderLocalizationSettingsPage`
  - `/admin/config?group=currency`
  - `Your account does not have settings access.`
  - `Failed to load localization settings.`
