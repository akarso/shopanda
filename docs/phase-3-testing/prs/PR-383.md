# PR-383: De-duplicate Local Ordered Category Insertion

## Summary

Local assign/remove mutations in the product-edit category assignment panel now
remove any existing duplicate entry for the same category id before inserting the
moved category into the ordered target list.

## Motivation

PR-382 preserved deterministic order with `insertCategoryByOrder`, but the helper
still allowed duplicate entries in edge cases where local state drifted (for example,
if a category already existed in the target list before insertion). This slice hardens
local mutation behavior by enforcing single-entry semantics per category id.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- In `insertCategoryByOrder(list, category, orderLookup)`:
  - Added a duplicate-removal pass for matching `categoryID` before insertion.
  - Preserved existing ordered insertion behavior and fallback append behavior.

### internal/interfaces/http/admin_handler_test.go

- Extended product assignment static JS wiring checks with token:
  - `String(existing.id || '') === categoryID`
