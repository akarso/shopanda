# PR-385: Mutation Progress Feedback For Product Category Assignment

## Summary

Product-edit category assign/remove mutations now surface explicit in-flight feedback
through a transient status message and `aria-busy` state while the existing mutation
lock is active.

## Motivation

PR-384 prevented duplicate submissions with a busy lock, but operators still had no
explicit progress cue while waiting for API completion. This slice adds lightweight
feedback without changing data flow or mutation semantics.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- In `bindProductCategoryAssignmentActions`:
  - `setMutationBusy(isBusy)` now also toggles `aria-busy` on the assignment container.

- In assign handler:
  - Before `setMutationBusy(true)` and API call, sets message:
    - `Saving category assignment...`

- In remove handler:
  - Before `setMutationBusy(true)` and API call, sets the same in-flight message.

### internal/interfaces/http/admin_handler_test.go

- Extended product assignment static JS wiring checks with:
  - `aria-busy`
  - `Saving category assignment...`

## Validation

```bash
go test ./internal/interfaces/http -run TestAdminHandler_StaticJS -count=1

```

Both commands pass.
