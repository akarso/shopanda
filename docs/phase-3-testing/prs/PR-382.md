# PR-382: Preserve Category Tree Order After Local Product Category Mutations

## Summary

Product-edit category assignment now preserves deterministic category ordering when local
assign/remove mutations are applied. Instead of appending moved categories to the end of
assigned/available arrays, handlers insert moved items based on the original flattened
category tree order.

## Motivation

PR-381 switched assign/remove to local in-memory mutations plus re-rendering for better
responsiveness and context retention. A follow-on issue remained: using `.push(...)`
for moved categories caused list order drift after repeated actions, making category lists
less predictable.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- In `setupProductCategoryAssignment`:
  - Added `categoryOrderLookup` state.
  - Rebuilt `categoryOrderLookup` from `categoryOptions` in `loadAssignments` so each
    category id maps to its stable flattened-tree order index.

- In `renderProductCategoryAssignmentView`:
  - Passed `categoryOrderLookup` into `bindProductCategoryAssignmentActions`.

- In `bindProductCategoryAssignmentActions`:
  - Replaced `assignedCategories.push(movedCategory)` with
    `insertCategoryByOrder(assignedCategories, movedCategory, categoryOrderLookup)`.
  - Replaced `availableCategories.push(movedCategory)` with
    `insertCategoryByOrder(availableCategories, movedCategory, categoryOrderLookup)`.

- Added helper `insertCategoryByOrder(list, category, orderLookup)`:
  - Inserts category at the correct position based on original order.
  - Falls back to append when no order key is available.

### internal/interfaces/http/admin_handler_test.go

- Updated static JS wiring checks for product assignment to assert ordered insertion paths:
  - `insertCategoryByOrder(assignedCategories, movedCategory, categoryOrderLookup)`
  - `insertCategoryByOrder(availableCategories, movedCategory, categoryOrderLookup)`
