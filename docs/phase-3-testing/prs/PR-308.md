# PR-308 — Admin Account Page For Current User

## Summary

Continued Track 3 with a small admin self-service slice.

This PR adds a minimal `/admin/account` page to the embedded admin SPA so the currently signed-in admin user can edit their own first and last name and change their password without leaving the admin shell.

## Scope

### Current-user auth endpoints

- updated `internal/interfaces/http/auth.go`
- added `PUT /api/v1/auth/me/profile` for updating the currently authenticated user profile
- added `POST /api/v1/auth/me/password` for changing the currently authenticated user password
- reused the existing auth application service methods instead of introducing a separate admin-only account service

### Route wiring

- updated `cmd/api/main.go`
- wired the new current-user profile and password routes behind the existing `requireAuth` middleware
- kept the slice focused on self-service for the signed-in user rather than broader admin-user management

### Admin shell account page

- updated `internal/interfaces/http/admin/dist/index.html`
- added an `Account` navigation entry in the admin sidebar
- made the header user-name area link to the new account page
- updated `internal/interfaces/http/admin/dist/admin.js`
- added the `/admin/account` route in the embedded admin SPA
- loaded the current authenticated user via `/api/v1/auth/me`
- rendered a basic account form for first name and last name updates
- rendered a password change form for the current account
- updated the header label to show the current admin user context instead of a fixed `Admin` label

### Regression coverage

- updated `internal/interfaces/http/auth_test.go`
- added focused handler coverage for:
  - current-user profile update
  - current-user password change
- updated `internal/interfaces/http/admin_handler_test.go`
- extended the embedded admin asset checks to assert:
  - the admin shell includes `/admin/account`
  - the shipped admin bundle contains the new account route
  - the shipped admin bundle wires profile and password requests to `/auth/me/profile` and `/auth/me/password`

## Files Changed

- `internal/interfaces/http/auth.go`
  - added current-user profile and password change handlers
- `cmd/api/main.go`
  - registered authenticated profile and password routes
- `internal/interfaces/http/admin/dist/index.html`
  - added admin account navigation
- `internal/interfaces/http/admin/dist/admin.js`
  - added the admin account page and current-user loading
- `internal/interfaces/http/auth_test.go`
  - added focused handler tests for the new auth endpoints
- `internal/interfaces/http/admin_handler_test.go`
  - added static-asset checks for the new account route and API wiring

## Validation

- `go test ./internal/interfaces/http -run 'TestAuthHandler_(UpdateProfile|ChangePassword|Me|Logout|Login|Register)|TestAdminHandler' -count=1`

## Notes

- this slice intentionally covers only the currently authenticated admin account
- broader admin-user management, roles, and permission repair remain separate Track 3 slices
