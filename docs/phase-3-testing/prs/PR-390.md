# PR-390: Explicit Action Headers in Remaining Admin Tables

## Summary

Remaining admin tables with action controls now use explicit `Action` table headers.

## Motivation

Some admin tables still rendered action controls under an empty header cell. Adding `Action` headers improves table semantics and screen reader clarity without changing the UI behavior.

## Changes

### internal/interfaces/http/admin/dist/admin.js

- Updated remaining empty action headers to `Action` in:
  - product grid table
  - variant list table
  - orders table

## Validation

The admin JavaScript now includes explicit `Action` table headers in product grid, variant list, and orders tables. The static bundle guard test in `internal/interfaces/http/admin_handler_test.go::TestAdminHandler_StaticJS` currently verifies `"Action</th>"` only within the product/category assignment context; the other tables are validated through the broader HTTP handler test suite.

```bash
go test ./internal/interfaces/http -run TestAdminHandler_StaticJS -count=1
```

This command verifies the static admin JavaScript bundle is served correctly and contains expected `Action</th>` headers (currently validated for product assignment tables).

```bash
go test ./internal/interfaces/http -count=1
```

This command runs the full HTTP handler test suite in `internal/interfaces/http`, including all admin routes and static asset serving, to validate overall functionality.

Both commands pass.
