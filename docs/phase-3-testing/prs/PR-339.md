# PR-339 — Customer Admin Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for customer-admin all-or-nothing scope behavior.

## Summary

PR-338 moved customer admin onto the shared full-scope helper already used by other scope-aware admin endpoints. That helper intentionally emits scope details only when all three scope values are present:

- `store_id`
- `language`
- `currency`

This PR adds the missing regression test that proves customer-admin follows that contract when only a partial scope is supplied.

## Why This Slice

The production behavior already existed through the shared helper, but customer-admin did not yet have the explicit regression coverage that product admin and stats admin already had.

This keeps the change narrowly scoped: strengthen the test contract around an existing behavior rather than widening the new customer-admin surface again.

## Changes

### Tests

Updated [../../../internal/interfaces/http/customer_admin_test.go](../../../internal/interfaces/http/customer_admin_test.go):

- Added `TestCustomerAdminHandler_List_AuditOmitsPartialScopeContext`
- Verifies the audit entry is still emitted on success
- Verifies standard audit metadata is still present:
  - action
  - resource type
  - admin id
  - result
  - pagination details
- Verifies scope keys are absent when only two of the three scope headers are provided:
  - `detail_store_id`
  - `detail_language`
  - `detail_currency`

## Validation

Executed:

```bash
go test ./internal/interfaces/http -run 'TestCustomerAdminHandler_(List_AuditIncludesScopeContext|List_AuditOmitsPartialScopeContext|List_AuditInvalidPaginationIncludesError|List_AuditFailureIncludesError)' -count=1
```

## Notes

This PR is intentionally test-focused. No production code change was required because customer-admin already delegates scope extraction to the shared full-scope helper.
