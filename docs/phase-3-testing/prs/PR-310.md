# PR-310 — Storefront Profile And Security Split

## Summary

Continued Track 4 with a small account-UX hardening slice.

This PR separates low-risk customer profile editing from sensitive account actions by moving password change, logout, and account deletion into a dedicated storefront security page. The result is a clearer account area that better matches the sensitivity boundary described in the roadmap without taking on step-up authentication yet.

## Scope

### Dedicated security surface

- updated `internal/interfaces/http/storefront_account.go`
- added a dedicated `GET /account/security` page for sensitive account actions
- moved password-change and delete-account error rendering off the profile page and onto the new security page
- kept the implementation small by reusing the existing auth and account-deletion services

### Storefront route wiring

- updated `cmd/api/main.go`
- added storefront routes for:
  - `GET /account/security`
  - `POST /account/security/password`
  - `POST /account/security/delete`
- kept the existing profile password/delete POST handlers wired as compatibility aliases so stale tabs and old rendered forms still submit successfully during the transition

### Account navigation and templates

- updated `themes/default/templates/layout.html`
- added a `Security` shortcut to the signed-in header account actions next to `Profile` and `Orders`
- updated `themes/default/templates/account_profile.html`
- reduced the profile page to customer identity fields only
- added account-section navigation across the profile page
- replaced inline password/delete actions with a single link to the security page
- updated `themes/default/templates/account_orders.html`
- updated `themes/default/templates/account_order_detail.html`
- added account-section navigation so orders, profile, and security are easier to discover from inside the account area
- added `themes/default/templates/account_security.html`
- created the dedicated security page for password change, logout, and destructive account actions

### Shared storefront account state

- updated `internal/interfaces/http/storefront.go`
- extended `StorefrontLayoutData` with `AccountSecurityURL` so shared header templates and test themes can route to the new security surface consistently

### Regression coverage

- updated `internal/interfaces/http/storefront_test.go`
- updated the test theme and test router to include the security surface and header shortcut
- updated `internal/interfaces/http/storefront_account_test.go`
- added focused coverage for:
  - signed-in header rendering exposing the new security link
  - profile page rendering without embedded security forms
  - security page rendering with password, delete, and logout controls
- updated existing delete/logout tests to acquire CSRF state from the new security page

## Notes

- this slice intentionally stops short of step-up authentication or email 2FA
- the next Track 4 security-oriented slice can build on this separation by placing stronger authentication only in front of the new `/account/security` surface instead of the entire account area
