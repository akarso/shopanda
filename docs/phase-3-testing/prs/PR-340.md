# PR-340 — Customer Admin Detail Read Surface + Scoped Audit Logging (Track 3)

Implemented the next Track 3 slice by extending customer-admin from list-only into a concrete per-customer read surface.

## Summary

PR-338 introduced `GET /api/v1/admin/customers` as the first concrete customer-admin backend surface. This PR adds the matching detail read endpoint:

- `GET /api/v1/admin/customers/{customerId}`
- permission-guarded with `customers.read`
- sanitized customer response payload
- scoped audit logging for success and repository failure paths

This keeps customer-admin moving forward as a coherent read surface rather than stopping at list-only behavior.

## Why This Slice

The repository contract already supported customer lookup via `FindByID`, and the existing customer-admin handler already had the shared response mapping and scope-aware audit primitives in place.

That made a per-customer read endpoint the next smallest concrete slice:

- no new subsystem
- no new domain contract
- no new audit action needed
- direct reuse of the existing `customer.read` audit model

## Changes

### Production

Updated [../../../internal/interfaces/http/customer_admin.go](../../../internal/interfaces/http/customer_admin.go):

- Added `Get()` for `GET /api/v1/admin/customers/{customerId}`
- Reads a customer via `CustomerRepository.FindByID`
- Returns a sanitized customer payload using the existing response mapper
- Emits `customer.read` audit entries for:
  - successful reads
  - repository failure paths
- Includes full scope triad in audit details when present:
  - `store_id`
  - `language`
  - `currency`
- Includes `resource_id` for detail reads
- Returns `not_found` when the customer does not exist
- Preserves neighboring admin-read behavior by not emitting an audit entry for not-found lookups

Updated [../../../cmd/api/main.go](../../../cmd/api/main.go):

- Wired `GET /api/v1/admin/customers/{customerId}` behind `requireCustomersRead`

### Tests

Updated [../../../internal/interfaces/http/customer_admin_test.go](../../../internal/interfaces/http/customer_admin_test.go):

- Added `TestCustomerAdminHandler_Get_AuditIncludesScopeContext`
- Added `TestCustomerAdminHandler_Get_AuditFailureIncludesError`
- Added `TestCustomerAdminHandler_Get_NotFound`
- Added `TestCustomerAdminHandler_Get_CustomerForbidden`
- Added `TestCustomerAdminHandler_Get_GuestUnauthorized`

The new tests verify:

- sanitized detail response payload
- `resource_type` and `resource_id` audit metadata
- success vs failure audit event emission
- scope detail inclusion on audited paths
- no audit entry on not-found lookups
- permission/auth guards on the new route
