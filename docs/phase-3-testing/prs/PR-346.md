# PR-346 — Product Admin Create/Update Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for product-admin create and update all-or-nothing scope behavior.

## Summary

PR-334 and PR-335 added scoped audit logging to product list, create, and update operations. Both the create and update handlers already delegate scope extraction to the shared full-scope helper used across other audited admin surfaces.

This PR adds the missing regression tests that prove create and update follow the same contract when only a partial scope is supplied.

## Why This Slice

The production behavior already existed through the shared helper, but the product create and update write endpoints did not yet have explicit coverage for partial-scope omission on their audited paths.

This keeps the change narrow and test-focused:

- no production behavior change
- no new route
- no new audit action
- direct hardening of product-admin write surfaces

## Changes

### Tests

Updated [../../../internal/interfaces/http/product_admin_test.go](../../../internal/interfaces/http/product_admin_test.go):

- Added `TestProductAdminHandler_Create_AuditOmitsPartialScopeContext`
- Added `TestProductAdminHandler_Create_AuditFailureOmitsPartialScopeContext`
- Added `TestProductAdminHandler_Update_AuditOmitsPartialScopeContext`
- Added `TestProductAdminHandler_Update_AuditFailureOmitsPartialScopeContext`

The new tests verify that create and update audit entries still include the expected core metadata when only two of the three scope headers are present:

- action
- resource type
- resource id
- admin id
- result
- error on failure

They also verify these scope keys are absent under partial scope:

- `detail_store_id`
- `detail_language`
- `detail_currency`
