# PR-349 - Customer Admin Revoke-Sessions Partial-Scope Regression Cleanup (Track 3)

Implemented the next small Track 3 hardening slice by applying the same minimal partial-scope test pattern used in prior admin slices to revoke-sessions tests.

## Summary

The revoke-sessions partial-scope regression tests were correct in assertions, but still set two scope headers in the partial-scope scenarios. This PR removes those redundant header assignments so the tests express the partial-scope condition directly and consistently.

## Why This Slice

This keeps the change narrow and test-focused:

- no production code changes
- no route or handler changes
- no audit action changes
- aligns revoke-sessions partial-scope tests with the established all-or-nothing scope regression style

## Changes

### Tests

Updated ../../../internal/interfaces/http/customer_admin_test.go:

- In TestCustomerAdminHandler_RevokeSessions_AuditOmitsPartialScopeContext:
  - removed X-Admin-Store-ID header assignment
  - removed X-Admin-Language header assignment
- In TestCustomerAdminHandler_RevokeSessions_AuditFailureOmitsPartialScopeContext:
  - removed X-Admin-Store-ID header assignment
  - removed X-Admin-Language header assignment

Assertions remain unchanged:

- success path still verifies admin.action with scope detail keys absent
- failure path still verifies admin.action.failed with error and scope detail keys absent
