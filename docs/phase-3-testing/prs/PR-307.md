# PR-307 — Admin Login Autofill Hardening And Currency Format Hint

## Summary

Started Track 3 of the phase 3 roadmap with a narrow admin UX hardening slice.

This PR discourages browser-driven credential prefill on the admin login form and adds clear in-context guidance for the currency display format setting so operators understand how `{currency}` and `{amount}` are interpreted.

## Scope

### Admin login hardening

- updated `internal/interfaces/http/admin/dist/admin.js`
- changed the admin login form to disable form and field autocomplete
- disabled email-field autocapitalization and spellcheck to reduce accidental credential mangling on admin sign-in
- added a short login note clarifying that the form uses an admin account created during setup or seeding and does not expose default credentials in the UI

### Currency settings guidance

- updated `internal/interfaces/http/admin/dist/admin.js`
- added inline help text below the display format field in admin currency settings
- documented the supported placeholders: `{currency}` and `{amount}`
- added concrete examples so operators can understand the format without external docs

### Admin SPA styling

- updated `internal/interfaces/http/admin/dist/admin.css`
- added lightweight styling for the new login note and settings hint so they read as supporting guidance instead of primary form content

### Regression coverage

- updated `internal/interfaces/http/admin_handler_test.go`
- extended the embedded admin asset test to assert:
  - the login guidance is present in the shipped admin bundle
  - the currency display format hint is present in the shipped admin bundle
  - the admin bundle does not hardcode the seeded admin email
  - the login form markup disables autofill in the embedded asset

## Files Changed

- `internal/interfaces/http/admin/dist/admin.js`
  - hardened the login form markup and added the display format hint
- `internal/interfaces/http/admin/dist/admin.css`
  - styled the new admin helper text
- `internal/interfaces/http/admin_handler_test.go`
  - added static-asset regression checks for the embedded admin bundle

## Validation

## Notes

- this is an intentionally small first Track 3 PR: it improves a concrete operator-facing admin surface without widening into the broader admin permission or navigation refactors yet
- the product-grid 403 and broader admin permission failures remain tracked in the roadmap as a separate next slice
