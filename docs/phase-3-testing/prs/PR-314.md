# PR-314

## Summary

- add registration-time email verification using the existing signed storefront email-link machinery
- persist nullable customer `email_verified_at` state and expose an auth service method to mark it verified
- send a verification email after successful storefront registration and render a dedicated `/account/verify-email` status page

## Scope

- customer domain and postgres persistence
- auth and notification services
- storefront registration and public email-verification handler
- production wiring and focused regression coverage

## Validation

- targeted `go test` over customer, auth, notification, and storefront account slices
