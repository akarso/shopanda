# PR-356 - Admin Pages List Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/content/pages` placeholder with a working pages list backed by the existing admin pages API.

## Summary

The admin shell already exposed a Pages navigation entry, but the route still rendered a placeholder even though the backend already supported:

- `GET /api/v1/admin/pages`

This PR wires the first usable pages surface into the admin SPA by rendering a pages table from the existing list endpoint.

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- directly turns another existing admin navigation dead end into a working screen

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/content/pages` placeholder route with `renderPagesGrid`
- Added `normalizePages()` and `normalizePage()` helpers for admin page payloads
- Added a pages table view showing:
  - title
  - slug
  - active/draft status
  - updated date
- Added explicit `forbidden` handling with `Your account does not have pages access.`
- Added explicit malformed/error payload handling with `Failed to load pages.`
- Avoided treating permission or backend failures as an empty pages list

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderPagesGrid`
  - `/admin/pages?offset=0&limit=50`
  - `Your account does not have pages access.`
  - `Failed to load pages.`
