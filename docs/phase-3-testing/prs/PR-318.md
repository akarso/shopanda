# PR-318

## Summary

- start Track 2 by enabling guest checkout in the existing checkout pipeline
- allow checkout and order creation with an empty `customer_id` for guest carts
- remove the storefront hard stop that returned unauthorized during checkout confirmation for guests

## Scope

- domain: `order.NewOrder` accepts guest orders (`CustomerID == ""`)
- application: `checkout.Service.StartCheckout` no longer rejects empty customer ids and relies on cart ownership matching (`cart.CustomerID == customerID`)
- storefront: checkout confirmation no longer blocks guests and guest address page renders the same form flow
- tests: add guest coverage at domain, application, and storefront layers

## Validation

- `go test ./internal/domain/order -run 'TestNewOrder_(EmptyCustomerID_AllowsGuestOrder|Success)' -count=1`
- `go test ./internal/application/checkout -run 'TestService_StartCheckout_(EmptyCustomerIDForbiddenForCustomerCart|GuestCartSuccess|Success)' -count=1`
- `go test ./internal/interfaces/http -run 'TestStorefrontHandler_(CheckoutAddress_GuestCanAccessAddressForm|CheckoutFlow_Manual_GuestOK|CheckoutFlow_Manual_OK)' -count=1`
- `go test ./internal/application/checkout ./internal/domain/order ./internal/interfaces/http -run 'Test(StorefrontHandler_Checkout|Service_StartCheckout|NewOrder_)' -count=1`
