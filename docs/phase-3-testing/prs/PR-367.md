# PR-367 - Admin Category Ordering Controls (Track 3)

Followed up the admin categories CRUD slice by adding minimal ordering controls directly to the Categories tree in the admin UI.

## Summary

The previous slice added category CRUD, but ordering still required editing each category manually through the numeric `position` field.

This PR adds admin-side ordering controls on the existing Categories page by reusing the current `PUT /api/v1/admin/categories/{id}` update contract.

## Why This Slice

This is the smallest real ordering follow-up for categories:

- keeps the existing backend contract unchanged
- avoids introducing a separate reorder endpoint prematurely
- makes sibling ordering usable directly from the tree view
- preserves the existing manual `position` field for direct edits

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Added `Move up` and `Move down` controls for sibling categories in the category tree
- Reused the existing admin category update endpoint to persist ordering changes
- Reassigns sibling positions after a move so the visible order is saved consistently
- Added user-facing status messages:
  - `Category order saved.`
  - `Failed to save category order.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Extended shipped admin JS assertions to cover:
  - `Move up`
  - `Move down`
  - `Category order saved.`
  - `Failed to save category order.`
