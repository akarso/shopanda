# PR-330 — PR-G Admin Context-Aware Config APIs And Scoped Audit Trail (Track 3)

## Summary

Implemented the next Track 3 slice by completing a focused PR-G increment in admin configuration APIs:

- config admin endpoints now return consistent context payloads (`store_id`, `language`, `currency`)
- config reads/writes now emit scoped audit logs with admin identity and scope details
- constructor wiring now requires explicit logger injection for deterministic audit behavior

This keeps changes narrow while strengthening role/context/audit guarantees for scoped admin operations.

## Scope

- internal/interfaces/http/config_admin.go
  - `ConfigAdminHandler` now owns an `admin.Auditor`
  - `NewConfigAdminHandler(...)` now requires `logger.Logger`
  - GET `/api/v1/admin/config`:
    - audit logs for success/error (`settings.read`)
    - response `scope` includes `store_id`, `language`, `currency`
  - PUT `/api/v1/admin/config`:
    - audit logs for success/error (`settings.change`)
    - response `scope` includes `store_id`, `language`, `currency`
  - added internal helpers:
    - `scopePayloadFromRequest`
    - `adminAuditInfoFromRequest`
    - `mergeAuditDetails`
    - scoped audit log wrappers
- cmd/api/main.go
  - updated `NewConfigAdminHandler(...)` call site to pass app logger
- internal/interfaces/http/config_admin_test.go
  - updated test helper for new constructor signature
  - added tests for context-aware scope fields in GET/PUT responses:
    - `TestConfigAdmin_Get_ScopeIncludesLanguageAndCurrency`
    - `TestConfigAdmin_Update_ScopeIncludesLanguageAndCurrency`

## Behavior

### Context-aware config APIs

Admin config GET/PUT responses now expose full active scope context:

- `scope.store_id`
- `scope.language`
- `scope.currency`

This makes scope explicit to admin clients and avoids hidden context inference.

### Scoped audit trail for config changes

Config reads and writes now emit audit entries that include:

- admin ID
- action type (`settings.read` / `settings.change`)
- scoped details (`store_id`, `language`, `currency`)
- operation metadata (group/entry counts)
- success/error result

## Why this slice

PR-G requires context-aware admin APIs and scoped audit coverage for admin state that can vary by scope. This implementation delivers that for config administration with minimal architecture impact.
