# PR-397 — Admin Hardening Closeout: Bootstrap Credentials And Audit Coverage (Track 3)

Status: planned

## Summary

- remove the remaining insecure bootstrap admin password defaults (`changeme`) from the install path and examples
- close the audit-logging gaps on the admin handlers that mutate state without an `Auditor`: categories, stores, media
- update stale documentation that still advertises a default admin password

## Why

PR-324 removed the credential prefill from the login UI and PR-305/seeding made admin creation conditional on `SHOPANDA_SEED_ADMIN_PASSWORD`, but the delivery story is still weak:

- `install.sh` defaults `SHOPANDA_SEED_ADMIN_PASSWORD` to `changeme`; `.env.example` suggests the same
- `docs/phase-1-core/specs/SEEDING.md` still documents an `admin123` default
- category CRUD/assignment (`category_admin.go`), store CRUD (`store_admin.go`), and media upload/delete (`media.go`) perform admin mutations with no audit logging, unlike products/orders/customers/config (pages are covered by PR-396)

## Scope

- bootstrap: `install.sh` generates a random password (printed once at the end of install) instead of defaulting to `changeme`; `.env.example` ships the variable empty with a comment that seeding skips admin creation when unset
- docs: correct `SEEDING.md` (historical PR docs stay as written)
- audit: wire the existing `Auditor` with scoped details into category, store, and media mutation handlers, following the `product_admin.go` pattern
- tests: seed behavior test for the unset-password path if not already covered; audit assertions in the category/store/media handler tests

## Out Of Scope

- a one-time credential reveal UI in the admin (env-based delivery is the accepted operator flow)
- a persistent audit table or audit browsing UI (audit stays logger-based, as noted in `internal/application/admin/audit.go`)
- admin user/role management (Users & Roles stays read-only; see deferred items in the ROADMAP)

## Validation

- a fresh install never produces a guessable default admin password
- every state-mutating admin handler emits an audit log entry with scope details
- `go test ./internal/seed ./internal/interfaces/http -count=1`
