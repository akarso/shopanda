# PR-397 — Admin Hardening Closeout: Bootstrap Credentials And Audit Coverage (Track 3)

Status: done

## Summary

- removed the remaining insecure bootstrap admin password defaults (`changeme`) from the install path and examples
- closed the audit-logging gaps on the admin handlers that mutated state without an `Auditor`: categories (+ assignment), stores, media
- updated stale documentation that still advertised a default admin password

## Why

PR-324 removed the credential prefill from the login UI and PR-305/seeding made admin creation conditional on `SHOPANDA_SEED_ADMIN_PASSWORD`, but the delivery story was still weak:

- `install.sh` defaulted `SHOPANDA_SEED_ADMIN_PASSWORD` to `changeme`; `.env.example` suggested the same
- `docs/phase-1-core/specs/SEEDING.md` still documented an `admin123` default
- category CRUD/assignment, store CRUD, and media upload/delete performed admin mutations with no audit logging, unlike products/orders/customers/config/pages

## What changed

- bootstrap (`install.sh`):
  - the seed admin password now defaults to empty; if the operator leaves the prompt blank, a random secret is generated via `generate_secret` and printed once at the end of the run (with guidance to store it and change after first login).
  - `.env.example` ships `SHOPANDA_SEED_ADMIN_PASSWORD=` empty with a comment that seeding skips admin creation when unset and that there is no default.
- seeding (`internal/seed/admin.go`): the unset-password check now runs before any DB access, so the skip path is side-effect free and unit-testable with a nil DB. Behavior is unchanged when a password is set.
- docs: `SEEDING.md` now states the admin password comes from `SHOPANDA_SEED_ADMIN_PASSWORD` with no default (historical PR docs left as written).
- audit actions (`internal/application/admin/audit.go`): added `category.create/update/delete`, `category.product_assign`, `category.product_unassign`, `store.create/update`, and `media.upload/delete`.
- audit wiring (following the established admin pattern, using a compact `audit()` helper with `fullAdminScopeDetailsFromRequest` so every entry carries the `store_id`/`language`/`currency` triad and the admin id):
  - `category_admin.go`: Create/Update/Delete, with a `NewCategoryAdminHandlerWithAuditor` constructor.
  - `category_product_assignment_admin.go`: Assign/Unassign (details include `product_id`), with a `WithAuditor` constructor.
  - `store_admin.go`: Create/Update, with a `WithAuditor` constructor.
  - `media.go`: Upload/Delete, with a `WithAuditor` constructor.
  - `cmd/api/main.go` passes `adminApp.NewAuditor(log)` into each of these handlers.

## Out Of Scope

- a one-time credential reveal UI in the admin (env-based delivery is the accepted operator flow)
- a persistent audit table or audit browsing UI (audit stays logger-based)
- admin user/role management (Users & Roles stays read-only)
- the `changeme` default for the unrelated `SHOPANDA_DATABASE_PASSWORD` (separate concern, not an admin credential)

## Validation

- `go test ./internal/seed ./internal/interfaces/http -count=1`
- seed test: with `SHOPANDA_SEED_ADMIN_PASSWORD` unset, the admin seeder skips creation (nil DB, no panic) and logs the unset-password reason.
- handler audit tests: category create/update/delete, category-product assign/unassign, store create/update, and media upload/delete each emit an audit entry with the action and full scope triad.
- `install.sh` passes `bash -n`; a fresh install with a blank seed-password prompt generates and prints a random password instead of `changeme`.
