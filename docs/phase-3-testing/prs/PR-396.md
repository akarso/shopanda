# PR-396 — Admin Pages Editing With Language Scope (Track 3, PR-E Content)

Status: planned

## Summary

- turn the read-only Content → Pages grid into a working create/edit/delete surface on top of the existing pages CRUD API
- expose language assignment on page editing so content scope is explicit
- move pages off the `settings.*` permission gate onto content-domain permissions so the Editor role can manage content
- add scoped audit logging to page mutations

## Why

The content half of PR-E never shipped:

- `renderPagesGrid` in `internal/interfaces/http/admin/dist/admin.js` is a read-only table with no create/edit routes, while `internal/interfaces/http/page_admin.go` already implements Create/Update/Delete unused by any UI
- `cms.Page` (`internal/domain/cms/page.go`) is a flat single-locale model with no visible language assignment in the admin
- pages routes are gated by `settings.read` / `settings.write` (`cmd/api/main.go`), which both misplaces content under Settings permissions and locks out the Editor role (`internal/domain/rbac/role_permissions.go`: Editor lacks `SettingsRead`)
- `page_admin.go` has no `Auditor`, unlike products/orders/customers/config

## Scope

- UI: page list rows link to an edit form; add create and delete actions wired to the existing `page_admin.go` endpoints; keep the form small (title, slug, body, status, language)
- language scope: the page form shows and saves the page's language explicitly; the active admin language context preselects it; the list shows the language column so per-language content is discoverable
- permissions: introduce content-domain permissions (e.g. `content.read` / `content.write`) in `internal/domain/rbac`, grant them to Admin and Editor, and switch the pages routes in `cmd/api/main.go` from `settings.*` to them
- audit: wire the existing `Auditor` into `page_admin.go` mutations with the same scoped-details pattern used by `product_admin.go`
- tests: permission guard tests (Editor allowed, Viewer read-only), page CRUD handler tests with audit assertions, static JS guard updates

## Out Of Scope

- a multi-locale page translation model (pages stay one record per language; linking translations of the same page is a later concern)
- store assignment for pages (no per-store page visibility model exists yet; defer until a real requirement)
- Navigation and Blocks placeholder sections

## Validation

- an Editor can create, edit, and delete a page from Content → Pages without `settings.*` permissions
- a Viewer can list pages but not mutate them
- page mutations appear in the audit log with scope details
- `go test ./internal/interfaces/http ./internal/domain/rbac -count=1`
