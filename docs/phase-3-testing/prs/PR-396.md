# PR-396 — Admin Pages Editing With Language Scope (Track 3, PR-E Content)

Status: done

## Summary

- turned the read-only Content → Pages grid into a working create/edit/delete surface on top of the existing pages CRUD API
- exposed explicit per-page language assignment in the admin so content scope is visible and editable
- moved pages off the `settings.*` permission gate onto new content-domain permissions so the Editor role can manage content
- added scoped audit logging to page mutations

## Why

The content half of PR-E never shipped:

- `renderPagesGrid` in `internal/interfaces/http/admin/dist/admin.js` was a read-only table, while `internal/interfaces/http/page_admin.go` already implemented Create/Update/Delete unused by any UI
- `cms.Page` was a flat single-locale model with no visible language assignment
- pages routes were gated by `settings.read` / `settings.write`, which misplaced content under Settings permissions and locked out the Editor role
- `page_admin.go` had no `Auditor`, unlike products/orders/customers/config

## What changed

- domain: `cms.Page` (`internal/domain/cms/page.go`) gains a `language` field with `Language()` and `SetLanguage()`. `NewPage` leaves it empty by default; `NewPageFromDB` now takes the stored language. Pages stay one record per language — no multi-locale model.
- migration: `migrations/043_add_pages_language.sql` adds a `language TEXT NOT NULL DEFAULT ''` column (empty = unspecified/default) plus an index. Slug stays globally unique; language is metadata, so storefront slug lookups are unchanged.
- repo: `internal/infrastructure/postgres/page_repo.go` reads/writes the `language` column in `pageColumns`, hydrate, Create, and Update.
- permissions: added `content.read` / `content.write` in `internal/domain/rbac/permission.go`. Grants: Admin and Editor get both (content authors); Manager and Support get `content.read` only (read-only); Customer/Guest get neither.
- audit: added `page.read/create/update/delete` actions in `internal/application/admin/audit.go`.
- handler (`internal/interfaces/http/page_admin.go`):
  - request/response structs and `toAdminPageResponse` carry `language`.
  - `Create`/`Update` set the language from the request; `NewPageAdminHandlerWithAuditor` wires the shared `admin.Auditor`.
  - all mutations log through the scoped auditor, so entries carry the full `store_id` / `language` / `currency` triad via `fullAdminScopeDetailsFromRequest`.
- routes: `cmd/api/main.go` switches the four `/api/v1/admin/pages` routes from `settings.*` to `content.read` / `content.write` and passes the auditor.
- UI (`internal/interfaces/http/admin/dist/admin.js`):
  - the Pages grid gains a "New Page" action, a Language column, and edit links per row.
  - new `renderPageForm` / `renderPageCreate` / `renderPageEdit` provide a small form (title, slug, language, body, active) wired to the existing Create/Update/Delete endpoints, with a Delete action on edit.
  - new pages create/edit routes are registered in `resolveRoute` (`/admin/content/pages/new`, `/admin/content/pages/{id}`).
  - the create form preselects the active admin language from the context switcher (`adminScope.language`).

## Out Of Scope

- a multi-locale page translation model (pages stay one record per language; linking translations of the same page is a later concern)
- store assignment / per-store page visibility (no model exists yet; deferred)
- language-aware storefront slug routing (slug stays globally unique; storefront lookups unchanged)
- Navigation and Blocks placeholder sections

## Validation

- `go test ./internal/interfaces/http ./internal/domain/rbac -count=1`
- rbac tests: Admin/Editor have `content.read` + `content.write`; Manager/Support have `content.read` only (read-only); Customer/Guest have neither. Admin permission count updated to 17.
- page handler tests: create persists language and emits a `page.create` audit entry with the scope triad; update persists language with a `page.update` scoped audit entry; delete emits a `page.delete` scoped audit entry. Existing CRUD and not-found tests retained.
- static admin asset guards (`admin_handler_test.go`) updated for the page CRUD form, create/delete wiring, and route hooks.
