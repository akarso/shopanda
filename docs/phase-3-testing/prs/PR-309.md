# PR-309 — Storefront Header Account Visibility

## Summary

Started Track 4 implementation with a small storefront account-navigation slice.

This PR makes customer account state visible in the shared storefront header so shoppers can immediately tell whether they are signed in, reach profile and orders without hunting through account pages, and log out directly from the same header area near the minicart.

## Scope

### Shared storefront layout data

- updated `internal/interfaces/http/storefront.go`
- extended `StorefrontLayoutData` with explicit account URLs, signed-in state, CSRF token, and a display name for the current customer
- changed the default account target for authenticated shoppers to `/account/profile`
- reused the existing storefront auth service to resolve a display name from first name / last name or email when available

### Header account controls

- updated `themes/default/templates/layout.html`
- added an account control block next to the cart / minicart area in the shared header
- anonymous shoppers now see a clear sign-in entry point and a short note explaining that orders and profile live behind sign-in
- authenticated shoppers now see:
  - their account identity label in the header
  - a direct link to profile
  - a direct link to orders
  - a logout form wired to the existing storefront logout endpoint
- updated the footer account link to follow the same account destination logic as the rest of the layout

### Storefront styling

- updated `themes/default/static/css/custom.css`
- added lightweight styles for the new account pill, signed-in account panel, and responsive header utility layout
- kept the slice isolated in the theme override stylesheet rather than widening the base theme CSS unnecessarily

### Regression coverage

- updated `internal/interfaces/http/storefront_test.go`
- updated the test theme layout to expose the new shared header account controls
- updated `internal/interfaces/http/storefront_account_test.go`
- added focused coverage for:
  - anonymous home-page rendering showing the login entry instead of logout controls
  - authenticated home-page rendering showing the signed-in customer name plus profile, orders, and logout controls

## Files Changed

- `internal/interfaces/http/storefront.go`
  - added shared account header data for storefront templates
- `themes/default/templates/layout.html`
  - added account controls beside the minicart and aligned footer account navigation
- `themes/default/static/css/custom.css`
  - styled the new account header block
- `internal/interfaces/http/storefront_test.go`
  - updated the test layout used by storefront handler tests
- `internal/interfaces/http/storefront_account_test.go`
  - added focused header-account rendering tests

## Validation

- `go test ./internal/interfaces/http -run 'TestStorefrontHandler_(Home_ShowsAccount(LoginEntry_WhenAnonymous|Controls_WhenAuthenticated)|Account(Login|Register|Profile|Orders|Logout|CartAdd))' -count=1`

## Notes

- this is intentionally a small Track 4 slice built on the existing `/account/profile`, `/account/orders`, and `/account/logout` flows
- it improves storefront account visibility without taking on the larger guest-checkout or account-security refactors tracked elsewhere in the roadmap
