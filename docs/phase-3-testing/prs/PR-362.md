# PR-362 - Admin Users & Roles Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/settings/users` placeholder with a read-only Users & Roles page backed by existing customer admin data and the current core RBAC model.

## Summary

The admin shell already exposed a Users & Roles route under Settings, but it still rendered a placeholder and there was no dedicated admin users or roles API.

This PR wires a grounded, read-only Users & Roles screen into the admin SPA using the existing data already available today:

- `GET /api/v1/admin/customers?offset=0&limit=50`
- the core static RBAC role model in the backend

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- converts another admin navigation dead end into a working screen
- stays honest about current backend capabilities instead of inventing user-management APIs that do not exist yet

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/settings/users` placeholder route with `renderUsersRolesPage`
- Reused the existing admin customers list to surface admin-capable users from the current customer page
- Added a role capabilities table that reflects the current core RBAC model for:
  - admin
  - manager
  - editor
  - support
- Added explicit partial-access handling with `Your account does not have customer access.` when the caller can view the route shell but not the customer list
- Added explicit malformed/load failure handling with `Failed to load users and roles.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderUsersRolesPage`
  - `/admin/customers?offset=0&limit=50`
  - `Your account does not have customer access.`
  - `Role capabilities reflect the current core RBAC model.`
  - `Failed to load users and roles.`
