# PR-331 — PR-H Config Admin Validation Audit Hardening (Track 3)

## Summary

Implemented the next Track 3 slice by hardening config admin validation/audit behavior with minimal changes:

- fixed a nil-error panic risk in config audit error logging
- preserved query-provided store scope in config response payloads when admin context store is empty
- added focused tests for scope preservation and validation-path safety

This keeps PR-H narrow while improving reliability and traceability for scoped admin config updates.

## Scope

- internal/interfaces/http/config_admin.go
  - `auditConfigError(...)` now safely handles `nil` errors without calling `err.Error()`
  - `scopePayloadFromRequest(...)` keeps query `store_id` when admin context `StoreID` is empty
  - `adminAuditInfoFromRequest(...)` includes `store_id` only when admin context store is non-empty
  - validation branches in `Update()` continue emitting `settings.change` failure audit entries

- internal/interfaces/http/config_admin_test.go
  - added `TestConfigAdmin_Update_UsesQueryStoreScopeWhenContextStoreIsEmpty`
  - added `TestConfigAdmin_Update_InvalidBody_DoesNotPanicAndReturnsValidation`

## Behavior

### Safe validation-path auditing

Invalid update attempts (`invalid request body`, `entries are required`) now audit consistently without panic risk, even when no concrete error object is passed to the shared audit error helper.

### Correct scope payload fallback

When admin context omits `StoreID`, the response `scope.store_id` now preserves query scope so client-visible scope matches resolved store behavior.

### Audit details avoid empty store context

Audit context no longer forces empty `store_id` into details from admin context, reducing incorrect scope attribution.

## Why this slice

PR-H focuses on hardening correctness after PR-G context-aware audit rollout. This increment closes reliability and scope-attribution gaps without expanding architecture or API contracts.

Both pass.

## Notes

- This slice is intentionally constrained to config admin safety and scope consistency.
- The same nil-safe audit helper pattern can be reused in other admin handlers as needed.
