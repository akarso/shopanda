# PR-326 — Global Context Switcher Foundation (Track 3)

## Summary

Implemented the first end-to-end context foundation for admin scope:

- one always-visible store/language/currency switcher in the admin shell
- explicit scope propagation on admin API requests
- backend middleware support that captures and exposes scoped context for downstream handlers

This is a foundation slice only. It does not yet apply scope-specific filtering rules to each endpoint.

## Scope

- internal/interfaces/http/admin/dist/index.html
  - added global context switcher controls in the header:
    - Store selector
    - Language selector
    - Currency selector
- internal/interfaces/http/admin/dist/admin.css
  - styled the new context switcher controls
  - hid the switcher on unauthenticated login state (same shell visibility pattern as other admin controls)
- internal/interfaces/http/admin/dist/admin.js
  - added persisted admin scope state (`shopanda_admin_scope`)
  - loads store options from `/api/v1/admin/stores`
  - derives language/currency defaults from selected store
  - sends scope headers on all admin API requests and media uploads:
    - `X-Admin-Store-ID`
    - `X-Admin-Language`
    - `X-Admin-Currency`
  - reloads current route when scope changes so pages refresh under explicit scope
- internal/application/admin/validation.go
  - extended `AdminContext` with:
    - `StoreID`
    - `Language`
    - `Currency`
- internal/interfaces/http/auth_middleware.go
  - `AdminContextMiddleware` now reads and sanitizes admin scope headers from request
  - injects scoped values into `admin.AdminContext`
- internal/interfaces/http/auth_middleware_test.go
  - added tests for scope header propagation and sanitization
- internal/interfaces/http/admin_handler_test.go
  - added static asset assertions for context switcher markup/styles and scope header constants in JS

## Behavior

### Always-visible scope controls in shell

Authenticated admin pages now show a persistent context switcher in the top header.

### Explicit request context propagation

Every admin SPA API call now includes explicit scope headers when selected.

### Backend context availability

Admin middleware captures scope headers and exposes them via `admin.FromContext(...)` for downstream handlers.

## Why this slice

Track 3 requires explicit context propagation so future scoped reads/writes do not rely on hidden inference.

This PR establishes that contract without introducing broad data-model changes or endpoint-by-endpoint scoped logic.

## Validation

- go test ./internal/interfaces/http -run 'AdminContextMiddleware|TestAdminHandler' -count=1

Both pass.

## Notes

- Scope headers are currently captured and propagated; per-endpoint scoped behavior will be implemented in follow-up slices.
- Store/language/currency options are currently sourced from existing store records.
