# PR-364 - Admin Categories Surface (Track 3)

Implemented the next visible Track 3 admin surface by replacing the `/admin/catalog/categories` placeholder with a read-only categories page backed by the existing category tree API.

## Summary

The admin shell already exposed a Categories route under Catalog, but it still rendered a placeholder and there is no dedicated admin category-management API in the current backend.

This PR wires a grounded, read-only categories screen into the admin SPA using the existing data already available today:

- `GET /api/v1/categories`

## Why This Slice

This is a small, visible production improvement:

- no backend contract changes
- no API route changes
- no permission model changes
- converts another admin navigation dead end into a working screen
- stays honest about current backend capabilities instead of inventing category CRUD APIs that do not exist

## Changes

### Admin UI

Updated ../../../internal/interfaces/http/admin/dist/admin.js:

- Replaced the `/admin/catalog/categories` placeholder route with `renderCategoriesPage`
- Reused the existing category tree endpoint to show the current category structure
- Added a nested category tree showing:
  - category name
  - category slug
  - child category nesting
- Added a read-only note explaining that category management is not yet writable in the admin UI
- Added explicit malformed/load failure handling with `Failed to load categories.`

### Tests

Updated ../../../internal/interfaces/http/admin_handler_test.go:

- Added static asset coverage for:
  - `renderCategoriesPage`
  - `/categories`
  - `Category management is currently read-only in the admin UI.`
  - `Failed to load categories.`
