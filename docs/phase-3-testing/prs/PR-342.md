# PR-342 — Customer Admin Session Revocation Surface + Scoped Audit Logging (Track 3)

Implemented the next concrete Track 3 slice by adding the first customer-admin write endpoint on top of an existing authentication contract.

## Summary

Customer-admin already had list and detail read surfaces. This PR adds a minimal write operation that is already justified by the current model and repository contracts:

- `POST /api/v1/admin/customers/{customerId}/revoke-sessions`
- permission-guarded with `customers.write`
- invalidates issued customer sessions by bumping token generation
- emits scoped audit entries for success and failure paths

This uses the same mechanism the auth service already relies on for logout and password-reset session invalidation, so it adds an admin workflow without inventing a new subsystem.

## Why This Slice

The customer repository already exposes `BumpTokenGeneration`, and the auth service already uses that operation as the concrete session invalidation mechanism.

That made admin session revocation the smallest justified write slice because it:

- has existing behavioral meaning
- requires no new domain contract
- avoids speculative customer-edit APIs
- extends customer-admin with a focused operational action rather than a broad update surface

## Changes

### Production

Updated [../../../internal/application/admin/audit.go](../../../internal/application/admin/audit.go):

- Added `admin.AuditCustomerRevoke`

Updated [../../../internal/interfaces/http/customer_admin.go](../../../internal/interfaces/http/customer_admin.go):

- Added `RevokeSessions()` for `POST /api/v1/admin/customers/{customerId}/revoke-sessions`
- Calls `CustomerRepository.BumpTokenGeneration`
- Returns a small JSON confirmation payload:
  - `customer_id`
  - `status: sessions_revoked`
- Emits `customer.revoke_sessions` audit entries for:
  - successful revocation
  - repository failure paths
- Includes full scope triad in audit details when present:
  - `store_id`
  - `language`
  - `currency`
- Preserves neighboring admin-write behavior by not emitting an audit entry for not-found lookups

Updated [../../../cmd/api/main.go](../../../cmd/api/main.go):

- Added `requireCustomersWrite := RequirePermission(rbac.CustomersWrite)`
- Wired `POST /api/v1/admin/customers/{customerId}/revoke-sessions` behind `requireCustomersWrite`

### Tests

- write permission and authentication guards are enforced
