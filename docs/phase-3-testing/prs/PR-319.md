# PR-319

## Summary

- add explicit guest contact capture during checkout using `contact_email`
- require a valid contact email for guest checkout submissions
- persist contact email on the order so guest purchases are discoverable/claimable later

## Scope

- checkout application input now carries `ContactEmail`
- checkout service validates `ContactEmail` for guests (`customer_id == ""`) and stores it in checkout metadata
- create-order step transfers `ContactEmail` into the order snapshot
- order domain now includes `ContactEmail`
- postgres order persistence now reads/writes `contact_email`
- migration `042_add_orders_contact_email.sql` adds the new nullable column and index
- storefront checkout forms now capture and propagate `contact_email` across address -> shipping -> payment -> confirm
