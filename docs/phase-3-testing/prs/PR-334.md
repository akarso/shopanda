# PR-334 — Product Admin Scoped Audit Logging (Track 3)

Implemented the next Track 3 slice by adding scoped audit logging to product admin read and update flows with minimal API-surface change.

## Summary

This slice extends the scope-aware audit pattern from config admin and order admin into product admin. Product list and product update operations now emit audit entries that include the active admin scope triad when present:

- `store_id`
- `language`
- `currency`

For product list operations, pagination context is also included in the audit details:

- `offset`
- `limit`

## Changes

### Backend

Updated [internal/interfaces/http/product_admin.go](internal/interfaces/http/product_admin.go):

- Added an `Auditor` dependency to `ProductAdminHandler`
- Kept the existing constructor shape via a default constructor:
  - `NewProductAdminHandler(repo, bus)` now provisions a default auditor
  - `NewProductAdminHandlerWithAuditor(repo, bus, auditor)` was added for focused tests
- Added local admin helpers for:
  - admin ID extraction from request context
  - scope triad extraction from `AdminContext`
- Added audit logging for `List()`:
  - success path
  - repository error path
  - includes `offset` and `limit`
- Added audit logging for `Update()`:
  - missing ID
  - invalid body
  - repository lookup failure
  - not found
  - validation failures
  - repository update failure
  - success path

### Tests

Updated [internal/interfaces/http/product_admin_test.go](internal/interfaces/http/product_admin_test.go):

- Added a middleware-backed test router that applies:
  - `RequireRole(identity.RoleAdmin)`
  - `AdminContextMiddleware()`
- Added focused audit assertions for product admin list success
- Added focused audit assertions for product admin update success
- Reused the package-level audit sink introduced in earlier Track 3 tests

## Why

Track 3 is converging on explicit, scope-aware admin behavior. Product admin was still missing audit visibility for scope-scoped operations, which left a gap relative to config admin and order admin.

This PR closes that gap without widening into create/variant audit policy or broader product-admin validation changes.

## Notes

This slice intentionally keeps scope extraction behavior aligned with the current order admin policy:

- scope details are emitted only when all three values are present
- partial scope context is treated as absent for audit-detail purposes
