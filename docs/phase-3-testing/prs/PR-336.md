# PR-336 — Stats Admin Scoped Audit Logging (Track 3)

Implemented the next real Track 3 slice by adding scoped audit logging to the admin dashboard overview endpoint.

## Summary

This slice extends the existing Track 3 scope-aware audit pattern to `GET /api/v1/admin/stats/overview`.

The stats overview endpoint now emits audit entries that include the active admin scope triad when present:

- `store_id`
- `language`
- `currency`

It also records the fixed dashboard read parameters used by the handler:

- `low_stock_threshold`
- `recent_limit`

Both success and failure paths now generate audit entries for dashboard reads.

## Why This Slice

The previous PR documented customer-admin scoped audit logging as the likely next slice, but there is still no concrete customer-admin backend handler in the workspace to extend without inventing new API surface.

`StatsAdminHandler` already exists, is wired into the admin API, and had no audit coverage or tests. That made it the next smallest real Track 3 slice on an existing admin endpoint.

## Notes

This slice keeps stats-admin audit semantics consistent with the current Track 3 pattern:

- success emits `admin.action`
- failure emits `admin.action.failed`
- scope details are emitted only when the full triad is present
