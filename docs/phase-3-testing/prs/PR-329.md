# PR-329 — PR-F Feature-Local Configuration Split (Track 3)

## Summary

Implemented the next Track 3 slice by moving operational configuration closer to feature domains and keeping the Settings page focused on non-operational concerns.

This delivers the PR-F direction with a minimal, explicit UI split:

- Shipping now hosts tax configuration
- Payments now hosts currency/display configuration
- Settings keeps store info, email, and media, with clear guidance that operational settings moved

## Scope

- internal/interfaces/http/admin/dist/admin.js
  - replaced Operations route placeholders with real pages:
    - `/admin/operations/shipping` -> `renderShippingSettingsPage`
    - `/admin/operations/payments` -> `renderPaymentSettingsPage`
  - slimmed `/admin/settings` page by removing Tax and Currency sections
  - added in-page relocation guidance linking to Shipping and Payments pages
  - added new feature-local pages:
    - Shipping page loads `group=tax` and renders scoped tax editing form
    - Payments page loads `group=currency` and renders scoped currency editing form
  - reused existing scope banner + field scope affordances from PR-328
  - generalized `renderSettingsScopeBanner` to accept page-specific banner target IDs
- internal/interfaces/http/admin_handler_test.go
  - added JS assertions for:
    - operations settings page wiring
    - relocation guidance presence

## Behavior

### Feature-local operational config

Operational settings are now edited under Operations:

- Shipping -> Tax rules
- Payments -> Currency/default display format

### Settings page now focused

Settings continues to host store, email, and media configuration and directs operators to feature-local operational settings.

## Why this slice

PR-F requires splitting behavioral feature config from broader settings structure so the admin does not accumulate a monolithic settings tree.

This implementation keeps the split explicit while preserving existing scoped editing behavior.

## Validation

- go test ./internal/interfaces/http -run 'TestAdminHandler_StaticJS|TestAdminHandler_StaticCSS|TestAdminHandler_IndexHTML' -count=1
- go build ./cmd/api

Both pass.

## Notes

- This slice is UI and routing focused; it reuses existing config API groups and scope contracts.
- Follow-up slices can widen feature-local pages with additional operational controls.
