# PR-348 — Config Admin Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for config-admin all-or-nothing scope behavior across both operations, and refactored config-admin to use the shared full-scope audit helper.

## Summary

Config-admin's Get and Update operations had audit logging but were using a different scope pattern (individual field inclusion) than other audited admin surfaces. This PR:

1. **Refactored config-admin audit helpers** to use the shared `fullAdminScopeDetailsFromRequest()` all-or-nothing scope helper (consistent with customer-admin, product-admin, order-admin)
2. **Added regression tests** that prove Get and Update follow the all-or-nothing contract when only partial scope is supplied

## Why This Slice

Config-admin was an outlier in scope handling. Bringing it into alignment with the shared pattern ensures consistency across all audited admin surfaces.

This keeps the change narrow and test-focused:

- no production behavior change for fully-scoped requests
- production behavior **improvement**: partial-scope requests now omit all scope keys instead of including them piecemeal
- no new route
- no new audit action
- direct hardening of both config-admin operations

## Changes

### Implementation

Updated [../../../internal/interfaces/http/config_admin.go](../../../internal/interfaces/http/config_admin.go):

- Refactored `auditConfigSuccess()` to use `adminIDFromRequest()` and `fullAdminScopeDetailsFromRequest()` 
- Refactored `auditConfigError()` to use `adminIDFromRequest()` and `fullAdminScopeDetailsFromRequest()`
- Removed `adminAuditInfoFromRequest()` (individual field inclusion pattern, no longer used)

### Tests

Updated [../../../internal/interfaces/http/config_admin_test.go](../../../internal/interfaces/http/config_admin_test.go):

- Added `testConfigAdminHandlerWithAudit()` factory function for tests that need audit sink injection
- Added `TestConfigAdmin_Get_AuditOmitsPartialScopeContext`
- Added `TestConfigAdmin_Get_AuditFailureOmitsPartialScopeContext`
- Added `TestConfigAdmin_Update_AuditOmitsPartialScopeContext`
- Added `TestConfigAdmin_Update_AuditFailureOmitsPartialScopeContext`

The new tests verify the following behavior under partial scope (only 2 of 3 headers):

**Get operations:**
- Success path (`TestConfigAdmin_Get_AuditOmitsPartialScopeContext`):
	- Emits `admin.action` event
	- Includes operation details (group, keys_count)
	- Omits scope keys (`store_id`, `language`, `currency`)
- Failure path (`TestConfigAdmin_Get_AuditFailureOmitsPartialScopeContext`):
	- Emits `admin.action.failed` event
	- Includes operation details (group, key)
	- Omits scope keys
	- Error field populated with failure reason

**Update operations:**
- Success path (`TestConfigAdmin_Update_AuditOmitsPartialScopeContext`):
	- Emits `admin.action` event
	- Includes operation details (entries_count, store_id)
	- Omits scope keys
- Failure path (`TestConfigAdmin_Update_AuditFailureOmitsPartialScopeContext`):
	- Emits `admin.action.failed` event
	- Includes operation details (entries_count, store_id)
	- Omits scope keys
	- Error field populated with failure reason

## Notes

- Config-admin's Get/Update operations return 500 (InternalServerError) for database errors, not 422 (UnprocessableEntity). Validation errors return 422. Tests adjusted accordingly.
- The refactored code now prevents partial-scope requests from appearing in audit logs with individual fields — full scope context is either present entirely or omitted entirely.
