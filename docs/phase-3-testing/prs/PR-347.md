# PR-347 — Order Admin Partial-Scope Regression Coverage (Track 3)

Implemented the next small Track 3 hardening slice by adding explicit regression coverage for order-admin all-or-nothing scope behavior across all three operations.

## Summary

Prior PRs added scoped audit logging to order list, get, and update operations. These endpoints already delegate scope extraction to the shared full-scope helper used across other audited admin surfaces.

This PR adds the missing regression tests that prove list, get, and update follow the same contract when only a partial scope is supplied.

## Why This Slice

The production behavior already existed through the shared helper, but order-admin operations did not yet have explicit coverage for partial-scope omission on their audited paths.

This keeps the change narrow and test-focused:

- no production behavior change
- no new route
- no new audit action
- direct hardening of all order-admin operations

## Changes

### Tests

Updated [../../../internal/interfaces/http/order_admin_test.go](../../../internal/interfaces/http/order_admin_test.go):

- Added `TestOrderAdminHandler_List_AuditOmitsPartialScopeContext`
- Added `TestOrderAdminHandler_List_AuditFailureOmitsPartialScopeContext`
- Added `TestOrderAdminHandler_Get_AuditOmitsPartialScopeContext`
- Added `TestOrderAdminHandler_Get_AuditFailureOmitsPartialScopeContext`
- Added `TestOrderAdminHandler_Update_AuditOmitsPartialScopeContext`
- Added `TestOrderAdminHandler_Update_AuditFailureOmitsPartialScopeContext`

The new tests verify that list, get, and update audit entries still include the expected core metadata when only two of the three scope headers are present:

- action
- resource type
- resource id (on success)
- admin id
- result
- error on failure
- pagination details on list operations

They also verify these scope keys are absent under partial scope:

- `detail_store_id`
- `detail_language`
- `detail_currency`
