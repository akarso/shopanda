# PR-338 — Customer Admin List Surface + Scoped Audit Logging (Track 3)

Implemented the next Track 3 slice by adding a concrete customer-admin backend surface and layering scoped audit logging on top.

## Summary

This PR introduces a minimal, reviewable admin customer read surface:

- `GET /api/v1/admin/customers`
- permission-guarded with `customers.read`
- pagination via shared `offset`/`limit` parsing
- sanitized customer response payloads (no password hash/token internals)

On top of that concrete surface, the endpoint now emits scoped admin audit entries for both success and failure paths.

## Why This Slice

The codebase already had:

- a customer repository list contract (`ListCustomers`)
- customer read RBAC permission (`customers.read`)
- shared admin audit/scoping primitives

But there was no dedicated customer-admin HTTP surface to use these contracts. This slice closes that gap with the smallest viable endpoint and follows the existing admin audit conventions used by products/orders/stats.

## Changes

### Production

Added [../../../internal/interfaces/http/customer_admin.go](../../../internal/interfaces/http/customer_admin.go):

- `CustomerAdminHandler` with:
  - `NewCustomerAdminHandler(repo, log)`
  - `NewCustomerAdminHandlerWithAuditor(repo, auditor)`
  - `List()` for `GET /api/v1/admin/customers`
- Parses pagination using shared `parsePagination`
- Fetches admin id with shared `adminIDFromRequest`
- Extracts all-or-nothing scope details via `fullAdminScopeDetailsFromRequest`
- Adds pagination details into audit metadata:
  - `offset`
  - `limit`
- Emits audit action `customer.read`:
  - success: `admin.action`
  - failure: `admin.action.failed`
- Maps `customer.Customer` into a safe response shape:
  - id, email, first/last name, role, status, verified timestamp, created/updated timestamps

Updated [../../../cmd/api/main.go](../../../cmd/api/main.go):

- Added `requireCustomersRead := RequirePermission(rbac.CustomersRead)`
- Instantiated `customerAdmin := shophttp.NewCustomerAdminHandler(customerRepo, log)`
- Wired route:
  - `GET /api/v1/admin/customers` behind `requireCustomersRead`

### Tests

Added [../../../internal/interfaces/http/customer_admin_test.go](../../../internal/interfaces/http/customer_admin_test.go):

- `TestCustomerAdminHandler_List_AuditIncludesScopeContext`
  - verifies success audit emission
  - verifies scope (`store_id`, `language`, `currency`) and pagination details in audit context
- `TestCustomerAdminHandler_List_AuditFailureIncludesError`
  - verifies failure audit emission and error metadata
  - verifies scope details are present when all scope headers are supplied
- `TestCustomerAdminHandler_List_CustomerForbidden`
  - verifies authenticated customer role cannot access admin route
- `TestCustomerAdminHandler_List_GuestUnauthorized`
  - verifies guest access is rejected
