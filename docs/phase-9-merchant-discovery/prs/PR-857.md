# PR-857 — Wire Core Exporters

Status: done

## Summary

- Invoke export row hook chain in all six CLI exporters before CSV write
- Add `WithRowHooks(registry)` on each exporter; shared `RowHookRunner` helper
- Bootstrap plugins on `export:*` CLI commands so registered hooks run

## Why

PR-856 shipped the registry; integrators need CLI exports to call registered hooks so ERP column remaps take effect on outbound CSV.

## Scope

- `internal/application/exporter/rowhooks.go` — `RowHookRunner`, `HandleRowHookOutcome`, `MergeExtraColumns`
- Wire row hooks in: `products`, `prices`, `stock`, `categories`, `customers`, `attributes`
- `cmd/api/export_plugins.go` — `bootstrapExportRegistry`
- `cmd/api/main.go` — all `export:*` entity commands pass registry via `WithRowHooks`
- Tests: row hook remap + hook error skip on product export

## Out Of Scope

- Reference export remap plugin (PR-858)
- EPR/OSS exporters (compliance-only, no entity hooks)

## Behavior

1. Build row map from entity fields
2. `registry.Invoke` → read mutated map / skip / structured errors
3. Handler error → row skipped, `row N: export row hook: …` in result errors
4. Product export merges hook-added columns into CSV header

## Validation

- `go test ./internal/application/exporter/...`
- `go build ./cmd/api/`
- Product export with hook adding `matnr` column includes it in CSV header

## What changed

- CLI exporters invoke plugin row hooks pre-write; plugin registration from PR-856 is now effective on `export:*` commands
