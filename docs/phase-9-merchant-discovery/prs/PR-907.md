# PR-907 — Meilisearch Discovery Facet Hot-Reload

Status: done

## Summary

- Admin attribute create/update/delete hot-reloads Meilisearch filterable `attr_<code>` fields
- No API restart needed when discovery flags change via admin API
- Startup sync reuses the same `DiscoveryFacetSyncer` service

## Why

PR-906 documented that Meilisearch discovery-flag changes required an API restart to sync filterable fields. Merchants toggling **Use in layered navigation** or **Use in advanced search** expect immediate facet availability.

## Scope

- `internal/application/admin/discovery_facets.go` — `DiscoveryFacetSyncer`
- `internal/interfaces/http/attribute_admin.go` — sync after create/update/delete
- `cmd/api/main.go` — wire syncer at startup and on admin handler
- Tests: discovery facet syncer + admin handler sync calls

## Out Of Scope

- CSV `import:attributes` hot-reload (shipped in PR-908)
- Automatic product reindex when flags change (merchants still reindex for facet counts on existing products)
- Postgres engine changes (already live on next request)

## Behavior

After a successful admin attribute mutation, `DiscoveryFacetSyncer` calls `ListDiscoveryAttributeCodes` and `ConfigureAttributeFacets` on Meilisearch. Clearing discovery flags removes the corresponding filterable field on the next sync.

If Meilisearch sync fails after the attribute is persisted, the admin API returns an internal error; retry the update to re-sync.

## Validation

- `go test ./internal/application/admin/... -run DiscoveryFacet`
- `go test ./internal/interfaces/http/... -run 'AttributeAdminHandler.*Facet'`
- `go build ./cmd/api/`
- Meilisearch enabled: toggle discovery flag in admin → facet field updates without restart
