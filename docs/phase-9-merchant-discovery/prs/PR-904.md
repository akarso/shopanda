# PR-904 — Attribute Facets (Layered Navigation)

Status: done

## Summary

- Interactive **attribute facet chips** on storefront PLP, search, and category pages
- Only attributes flagged `use_in_layered_nav` appear as filter groups
- Postgres search applies `attr_<code>` filters and returns attribute facet counts

## Why

PR-900 shipped category layered navigation. PR-902 added attribute metadata so merchants can choose which attributes participate. Shoppers still could not refine by color, size, or other catalog attributes on listings.

## Scope

- `internal/domain/search/search.go` — optional `FacetAttributes` on `SearchQuery`
- `internal/infrastructure/postgres/search_engine.go` — `attr_*` filters + attribute facet aggregation
- `internal/application/admin/attributes.go` — `ListLayeredNavAttributes`
- `internal/interfaces/http/storefront_attribute_filters.go` — param parsing, facet URLs, search wiring
- `internal/interfaces/http/storefront.go` — integrate attribute filters with listing/category pages
- `cmd/api/main.go` — `WithLayeredNavAttributes(attributeStore)`
- Tests: storefront attribute facets, attribute store lister

## Out Of Scope

- Meilisearch attribute facets (Postgres default engine only in this PR)
- Advanced search filter panel (PR-905 follow-up)
- Select-option label mapping (facet values show raw stored values)
- Admin UI beyond existing `use_in_layered_nav` checkbox (PR-902)

## Storefront behavior

| Param | Example | Effect |
| --- | --- | --- |
| `attr_<code>` | `?attr_color=red` | Filters products where `attributes.color = red` |

Facet chips toggle the param on the current path (`/products`, `/search`, `/categories/{slug}`). Category and sort/view params are preserved.
