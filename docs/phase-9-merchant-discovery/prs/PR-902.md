# PR-902 — Attribute Properties

Status: done

## Summary

- Extended `catalog.Attribute` with discovery and rules flags
- Admin API + SPA expose and edit the new properties
- CSV import/export round-trips the flags
- Registry helpers filter attributes by property for downstream consumers

## Why

PR-900/901 deferred attribute facets and advanced search filters until merchants could mark which attributes participate. The attribute model only had type/required/options with no behavioral metadata.

## Scope

- `internal/domain/catalog/attribute.go` — `use_in_advanced_search`, `use_in_layered_nav`, `use_in_promo_rules`
- `internal/domain/catalog/attribute_registry.go` — `AttributesForAdvancedSearch`, `AttributesForLayeredNav`, `AttributesForPromoRules`
- `internal/interfaces/http/attribute_admin.go` — request/response wiring
- `internal/application/importer/attributes.go`, `exporter/attributes.go` — optional CSV columns
- `admin/dist/admin.js` — form checkboxes + grid columns
- Tests: admin handler, registry filters, exporter header

## Out Of Scope

- Storefront advanced search filter UI — **PR-905** (PR-901 shipped header autosuggest only)
- Attribute facets on PLP — **PR-904** (shipped)
- Promotion rule engine consuming `use_in_promo_rules` (future PR)
- New attribute field types beyond existing text/number/boolean/select

## Properties

| JSON field | Admin label | Purpose |
| --- | --- | --- |
| `use_in_advanced_search` | Use in advanced search | Include in storefront search filters |
| `use_in_layered_nav` | Use in layered navigation | Include as PLP facet candidate |
| `use_in_promo_rules` | Use in promotion rules | Allow in promotion condition builders |

All default to `false` for backward compatibility with existing config.
