# PR-901 — Advanced Search (Storefront Autosuggest)

Status: done

## Summary

- Storefront header search autocomplete via `GET /fragments/search-suggest`
- Debounced htmx input on the search field; links to existing product suggest results
- Wires the PR-217 suggest API into merchant-facing discovery UX

## Why

`/api/v1/search/suggest` existed but the storefront only supported submit-to-search. Shoppers had no typeahead while typing, and advanced attribute filtering still depends on PR-902 metadata.

## Scope

- `internal/interfaces/http/storefront_search_suggest.go` — HTML fragment handler
- `storefront.go` — `EnableSearchSuggest` layout flag
- `themes/default/templates/_header.html` — htmx suggest panel
- `themes/default/templates/layout.html` — load htmx when suggest enabled
- `themes/default/static/css/style.css` — suggest dropdown styling
- `cmd/api/main.go` — route registration
- `storefront_test.go` — fragment tests

## Out Of Scope

- Attribute filters marked “use in advanced search” (PR-902 + follow-up)
- Advanced search filter panel on `/search`
- Search API attribute query params
- Meilisearch index enrichment fixes

## Routes

| Route | Purpose |
| --- | --- |
| `GET /fragments/search-suggest?q={prefix}` | HTML dropdown fragment for header autocomplete |

Uses `SearchEngine.Suggest()` with `search.DefaultSuggestLimit`.

## Validation

- `go test ./internal/interfaces/http/... -run 'TestStorefrontHandler_SearchSuggest'`
- Type in storefront header search — product suggestions appear; click navigates to product URL
