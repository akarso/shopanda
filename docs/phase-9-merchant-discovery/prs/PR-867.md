# PR-867 — Variant Extension Scopes

Status: done

## Summary

- Per-variant **Extensions** editor on the product edit Variants panel
- Loads `target_type=variant` field definitions and reads/writes values via existing PR-703 value API
- Expandable row per variant — lazy-load values on first open

## Why

PR-704 added product-scoped extension editing; PR-866 added field definition CRUD. Variant-scoped fields (`target_type=variant`) had API support but no merchant UI, leaving per-SKU custom data unreachable without REST calls.

## Scope

- `admin/dist/admin.js` — variant extensions toggle, load/save per variant row
- `admin_handler_test.go` — SPA wiring assertions

## Out Of Scope

- Backend / schema changes (generic value API already supports `variant` target)
- Product alias routes for variant values (uses `/admin/extensions/values/variant/{id}`)
- Access role matrix UI
- Storefront / GraphQL variant extension read surfaces

## Routes / API

| Surface | Purpose |
| --- | --- |
| Product edit → Variants → **Extensions** button | Toggle inline editor per variant row |
| `GET /admin/extensions/fields?target_type=variant` | Load variant-scoped field defs |
| `GET/PUT /admin/extensions/values/variant/{variantID}` | Read/write values for one variant |

## Permissions

- List/read fields + values: `extensions.read`
- Save: `extensions.write`
- Private fields excluded from panel (same filter as product Extensions)

## Validation

- `go test ./internal/interfaces/http/... -run 'TestAdminHandler_StaticJS|SidebarNav'`
- Create variant-scoped field in Settings → Extension Fields → open product edit → expand Extensions on a variant row → save → reload confirms value
