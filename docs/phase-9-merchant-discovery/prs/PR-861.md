# PR-861 — Reference Plugin: Mail Sender

Status: done

## Summary

- Ship `plugins/maildemo` reference plugin demonstrating mail port replacement
- `RegisterMailSender` with a log-backed `mail.Mailer` implementation
- Opt-in via `plugins.maildemo` config and compile-time registration

## Why

PR-860 shipped `RegisterMailSender` and `resolveMailer`. Integrators need a copy-paste template showing port replacement without forking `setupWorker` or the notification handler.

## Scope

- `plugins/maildemo/` — plugin, `LogMailer`, README
- `internal/platform/config` — `plugins.maildemo` config + env vars
- `cmd/api/register_plugins.go` — opt-in registration when enabled
- `cmd/api/providers_test.go` — `resolveMailer` prefers plugin registration
- Unit tests (mailer, plugin init)

## Out Of Scope

- Production SendGrid/Postmark HTTP client (swap `LogMailer` using same registration)
- Admin mail UI changes
- Changing notification job types

## Plugin behavior

| Mechanism | Registration | Default |
| --- | --- | --- |
| Mail sender port | `RegisterMailSender` | Log-backed sender with optional subject prefix |

Enable:

```yaml
plugins:
  maildemo:
    enabled: true
    subject_prefix: "[demo]"
```

When enabled, worker `email.send` jobs use the plugin mailer instead of core SMTP.

## Validation

- `go test ./plugins/maildemo/... ./cmd/api/... -run Mailer`
- `go build ./cmd/api/`
- Plugin enabled → `resolveMailer` returns plugin mailer; disabled → SMTP default

## What changed

- Reference mail sender plugin completes the mail port story started in PR-860
