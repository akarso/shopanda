# PR-905 — Advanced Search Attribute Filters

Status: planned

## Summary

- Storefront advanced search filter panel on `/search` for attributes flagged `use_in_advanced_search`
- Public search API attribute query params on `GET /api/v1/search`
- Builds on PR-901 autosuggest and PR-902 attribute metadata

## Why

PR-901 shipped header autosuggest but deferred attribute filtering. PR-902 added `use_in_advanced_search` flags; merchants can mark attributes but shoppers cannot filter by them yet.

## Scope (planned)

- `GET /api/v1/search` — accept `attr_<code>=<value>` (or equivalent) for flagged attributes
- Postgres search engine — apply attribute filters (reuse PR-904 filter path where possible)
- Storefront `/search` — filter chips/panel for advanced-search attributes
- Tests: search API + storefront filter round-trip

## Out Of Scope

- Meilisearch attribute filters (Postgres default first; same deferral as PR-904)
- Replacing or extending PR-901 autosuggest
- Promotion rules consuming `use_in_promo_rules`
- Admin changes beyond existing PR-902 property flags

## Dependencies

- **PR-902** — `use_in_advanced_search` attribute metadata (done)
- **PR-901** — storefront search entry + autosuggest (done)
- **PR-904** — postgres `attr_*` filter/facet patterns (done; reuse for search filters)

## Validation (when implemented)

- `go test ./internal/interfaces/http/... -run 'Search|StorefrontHandler.*Search'`
- Flag attribute **Use in advanced search** → `/search?q=…` shows filter UI → results narrow by attribute
