# PR-908 — CSV Attribute Import Facet Sync

Status: done

## Summary

- `app import:attributes` syncs Meilisearch discovery filterable fields after a successful import commit
- Reuses `DiscoveryFacetSyncer` from PR-907

## Why

PR-907 hot-reloaded discovery facets for admin API mutations. Bulk CSV imports bypass the admin handler and left Meilisearch filterable fields stale until restart.

## Scope

- `cmd/api/providers.go` — `newDiscoveryFacetSyncer`, `syncDiscoveryFacetsFromDB`
- `cmd/api/main.go` — call sync after `import:attributes` commit; dedupe serve wiring
- Tests: discovery facet syncer helper with mock configurer

## Out Of Scope

- Automatic product reindex after import (use `search:reindex` separately)
- Postgres engine changes (no facet configurer; sync is a no-op)

## Behavior

After CSV import commits, the CLI loads plugins, resolves the search engine, and calls `DiscoveryFacetSyncer.Sync`. If sync fails, the command errors with `import committed but discovery facet sync failed` — data is persisted; re-run import or toggle an attribute in admin to retry sync.

## Validation

- `go test ./cmd/api/... -run DiscoveryFacet`
- `go build ./cmd/api/`
- Meilisearch enabled: `app import:attributes attrs.csv` with discovery flags → filterable fields update without API restart
