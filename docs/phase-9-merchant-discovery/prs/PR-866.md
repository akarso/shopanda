# PR-866 — Extension Field Admin Grid

Status: done

## Summary

- Admin grid and CRUD forms for extension field definitions under Settings
- Wires existing PR-702 API (`/api/v1/admin/extensions/fields`) — no backend changes
- Scope filter, create/edit/delete with namespaced code validation surfaced from API errors

## Why

PR-702 shipped the field registry REST API; PR-704 added product **value** editing only. Operators had no UI to define fields without API calls or SQL.

## Scope

- `admin/dist/admin.js` — grid, create/edit forms, delete
- `admin/dist/index.html` — Settings → Extension Fields nav link
- `admin_handler_test.go` — SPA wiring assertions

## Out Of Scope

- Variant value editing UX (PR-867)
- Access role matrix UI (`read_roles` / `write_roles`)
- Plugin widget registration
- Backend / schema changes

## Routes

| Admin route | Purpose |
| --- | --- |
| `/admin/settings/extension-fields` | Paginated-style list with scope filter |
| `/admin/settings/extension-fields/new` | Create field definition |
| `/admin/settings/extension-fields/{code}` | Edit / delete definition |

## Permissions

- List/read: `extensions.read`
- Create/update/delete: `extensions.write`
- Private fields: list/detail uses `include_private=true` (server enforces `extensions.private.read`)

## Validation

- `go test ./internal/interfaces/http/... -run 'TestAdminHandler_StaticJS|SidebarNav'`
- Create field → appears in grid → editable on product Extensions panel (when `target_type=product`)
