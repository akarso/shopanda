# PR-856 — Export Row Hook Registry

Status: done

## Summary

- Add `exportctx` application registry with ordered row hook chains per entity
- Expose `app.Export().RegisterRowHook(entity, priority, fn)` to plugins during `Init`
- Publish stable `pkg/extapi` export entity constants and hook catalog
- Wire shared registry at API startup (`SetExportRegistry`)

## Why

Integrators need to remap CSV columns on export (ERP layouts) without forking `internal/application/exporter`. Symmetric to import Track C (PR-820); core exporters invoke the chain in PR-857.

## Scope

- `internal/application/exportctx/` — entities, `RowContext`, registry
- `pkg/extapi/export.go` — `ExportEntity`, `ExportRowContext`, `ExportRowHandler`, `ExportRowHookPoint`
- `internal/platform/plugin/export.go` — plugin bridge with extapi payload sync
- `pkg/pluginsdk/export.go` — typed registration helpers
- `cmd/api/main.go` — shared `exportRegistry` + `SetExportRegistry`
- `internal/application/pluginreport` — export hooks in registration report
- Unit tests

## Out Of Scope

- Wiring CLI exporters to invoke the chain (PR-857)
- Reference export remap plugin (PR-858)

## API

**Entities:** `product`, `price`, `stock`, `category`, `customer`, `attribute`

**Hook names:** `export.{entity}.row` (e.g. `export.product.row`)

```go
app.Export("acme/erp").RegisterRowHook(extapi.ExportEntityProduct, 100, func(ctx *extapi.ExportRowContext) error {
    ctx.Row["MATNR"] = ctx.Row["sku"]
    return nil
})
```

Handlers run in priority order (lower first). First handler error stops the chain. Panics are recovered and returned as errors.
