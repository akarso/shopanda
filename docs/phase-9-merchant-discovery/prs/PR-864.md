# PR-864 — Admin Idempotency UI

Status: done

## Summary

- Admin list/detail APIs for inbound integration idempotency records (PR-832 store)
- Integrations sub-page to inspect keys, request hash, and stored responses
- Replay preview endpoint returns the same payload ERP clients receive on idempotent retry

## Why

Integrators and operators need visibility into ERP callback deduplication without querying Postgres directly. PR-832 shipped middleware persistence; PR-864 completes the merchant-facing inspection path deferred from PR-833.

## Scope

- `internal/infrastructure/postgres/integration_idempotency_admin.go` — `List`, `Get`
- `internal/interfaces/http/integration_idempotency_admin.go` — admin HTTP handlers
- `cmd/api/main.go` — routes under `/api/v1/admin/integrations/idempotency`
- Admin SPA — `/admin/integrations/idempotency` list + detail with replay preview
- Unit tests (handler mocks, postgres list/get)

## Out Of Scope

- Storing original request bodies (only SHA-256 hash exists today)
- Admin reset/delete of in-progress keys
- HMAC nonce replay store UI (`ReplayStore` is separate from idempotency dedupe)
- Background TTL cleanup job

## API

| Method | Path | Permission | Purpose |
| --- | --- | --- | --- |
| GET | `/api/v1/admin/integrations/idempotency` | `settings.read` | Paginated list (`plugin`, `completed` filters) |
| GET | `/api/v1/admin/integrations/idempotency/{plugin}/{key}` | `settings.read` | Record detail incl. stored response |
| POST | `/api/v1/admin/integrations/idempotency/{plugin}/{key}/replay` | `settings.read` | Preview stored response (`replayed`, `status_code`, `response_body`) |
