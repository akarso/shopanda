# PR-900 — Layered Navigation (Category Facets)

Status: done

## Summary

- Interactive **category facet chips** on storefront PLP and category pages
- Facet counts from existing search engines; links navigate to category pages or apply `?category=` on `/products`
- Selected facet highlighted; sort/view params preserved in facet URLs

## Why

Search already returned category facet counts, but the storefront rendered them as static pills with no navigation. Category PLP (`category.html`) omitted filters entirely. Merchants could not refine listings interactively without manual URL hacking.

## Scope

- `internal/interfaces/http/storefront.go` — interactive filter builder, `?category=` param on listings
- `themes/default/templates/product_list.html` — clickable facet chips
- `themes/default/templates/category.html` — filter sidebar on category PLP
- `storefront_test.go` — facet link, selected state, category filter param tests

## Out Of Scope

- Attribute facets (deferred — needs PR-902 filterable-attribute metadata)
- Search API attribute filter params (PR-901)
- Meilisearch reindex enrichment for missing `category_id` on index docs
- Admin configuration UI for facet visibility

## Storefront behavior

| Page | Facet click | Selected state |
| --- | --- | --- |
| `/categories/{slug}` | Navigate to `/categories/{target-slug}` | Current category chip active |
| `/products`, `/search` | Toggle `?category={id}` on same path | Active when param matches |

Facet values resolve from search `category` (name, Postgres) or `category_id` (Meilisearch) via loaded category tree.

## Validation

- `go test ./internal/interfaces/http/... -run 'TestStorefrontHandler_(Products|Category)'`
- Browse `/categories/{slug}` — facet chips link to sibling/related categories with counts
- Browse `/products` — category facet applies `?category=` filter; chip shows selected state
