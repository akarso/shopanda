# PR-862 — Promotion Rule Evaluator Port

Status: done

## Summary

- Add `promotion.EvaluatorRegistry` for plugin-registered catalog/cart promotion rule types
- Wire registry through pricing promotion steps and `plugin.App.PromotionRules()`
- Ship `plugins/promodemo` reference plugin with `min_line_total` + `line_bonus_percent` rules

## Why

Integrators need custom promotion logic (ERP-driven thresholds, loyalty tiers, contract pricing) without forking core JSON rule decoding in `catalog_promotion_step` / `cart_promotion_step`.

## Scope

- `internal/domain/promotion/evaluator_registry.go` — registry + eval helpers
- `internal/application/pricing/*_promotion_step.go` — delegate unknown rule types to registry
- `internal/platform/plugin/promotion_rules.go` — `SetPromotionEvaluatorRegistry`, `PromotionRules(registrant)`
- `pkg/extapi/promotion.go`, `pkg/pluginsdk/promotion.go` — stable SDK surface
- `cmd/api/main.go` — shared registry + pass to promotion steps after `InitAll`
- `plugins/promodemo/` — reference rule types + README
- `internal/platform/config` — `plugins.promodemo.enabled`
- Unit tests (registry, plugin bridge, catalog step plugin path, promodemo rules)

## Out Of Scope

- Admin UI for defining plugin rule types (merchants still author JSON; types must be registered at init)
- Cart-level promodemo rules (port supports cart condition/action; reference plugin is catalog-only)
- Changing core built-in rule types

## Plugin behavior

| Mechanism | Registration | Default |
| --- | --- | --- |
| Catalog condition | `PromotionRules().RegisterCatalogCondition` | `min_line_total` |
| Catalog action | `PromotionRules().RegisterCatalogAction` | `line_bonus_percent` |

Enable:

```yaml
plugins:
  promodemo:
    enabled: true
```

## Validation

- `go test ./internal/domain/promotion/... ./internal/application/pricing/... ./internal/platform/plugin/... ./plugins/promodemo/...`
- `go build ./cmd/api/`
- Unknown rule type without registry → decode error (unchanged)
- Registered type → pricing step invokes plugin evaluator

## What changed

- Promotion steps accept optional evaluator registry; nil preserves pre-862 behavior for core-only rules
- Plugins register evaluators during `Init`; API process passes the same registry instance into pricing pipeline construction
