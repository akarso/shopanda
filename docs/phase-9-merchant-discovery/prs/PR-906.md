# PR-906 — Meilisearch Attribute Filter Parity

Status: done

## Summary

- Meilisearch search applies `attr_<code>` filters and returns attribute facet counts for discovery-flagged attributes
- Products index flattened `attr_<code>` fields alongside the nested `attributes` object
- Startup syncs filterable attribute fields from layered-nav + advanced-search flags

## Why

PR-904 and PR-905 shipped attribute filters and facets for the PostgreSQL search engine. Merchants using Meilisearch (`search.engine=meilisearch`) still could not filter or facet by catalog attributes on PLP or `/search`.

## Scope

- `internal/domain/search/attributes.go` — shared `attr_` key helpers
- `internal/infrastructure/meili/engine.go` — flatten attrs at index time, filter/facet in search, `ConfigureAttributeFacets`
- `internal/application/admin/attributes.go` — `ListDiscoveryAttributeCodes`
- `cmd/api/providers.go` — `configureSearchAttributeFacets` wired at startup
- Tests: meili engine + attribute store

## Out Of Scope

- Runtime reconfiguration when attributes are added (restart/reindex required for new Meilisearch facet fields)
- Select-option label mapping (raw stored values)
- Postgres engine changes (already supported)

## Behavior

| Engine | Attribute filter param | Facet keys |
| --- | --- | --- |
| PostgreSQL | `attr_<code>=<value>` | attribute code (e.g. `color`) |
| Meilisearch | same | same (mapped from `attr_<code>` index fields) |

At startup, when Meilisearch is active, the API registers `attr_<code>` as filterable for all attributes flagged for layered navigation or advanced search.

## Validation

- `go test ./internal/infrastructure/meili/... ./internal/application/admin/... -run 'Attribute|Facet|Discovery'`
- `go build ./cmd/api/`
- With Meilisearch enabled: flag attribute → reindex products → `/products` and `/search` show attribute facets
