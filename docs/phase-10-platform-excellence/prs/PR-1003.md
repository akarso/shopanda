# PR-1003 — CI Integration Job

Status: planned

## Summary

- Second CI job with `postgres:17-alpine` service and `SHOPANDA_TEST_DSN`
- Wait for Postgres readiness, then run the full DSN-gated suite (required for merge)

## Why

Postgres package tests (`testDB` + `SHOPANDA_TEST_DSN`) and related DSN-gated packages only run with a real DSN. Unit CI alone leaves the data layer ungated.

## Scope

- Extend `.github/workflows/ci.yml` with `integration` job (**required** for merge)
- Service: Postgres 17 with fixed credentials matching the job DSN
- **Readiness gate (mandatory):** before migrations/tests, run a bounded health check/retry against the service (e.g. `pg_isready` or `psql` loop, max ~60s). Fail the job with a clear error if Postgres never becomes ready
- Export `SHOPANDA_TEST_DSN` and run the **full DSN-gated set**:
  - `go test ./internal/infrastructure/postgres/... ./internal/platform/migrate/... ./plugins/b2b/...`
  - (These packages call `testDB` / skip without DSN; with DSN set they must execute)
- **Anti-skip assertion:** fail the job if test output shows `SHOPANDA_TEST_DSN not set; skipping` for any test, or if `-count` of skipped integration tests is non-zero when DSN is set (e.g. `go test -json` + jq check, or `grep` gate)
- Job required for merge (same as unit)

## Out Of Scope

- Meilisearch/Redis/RabbitMQ in CI (optional later profiles)
- Load tests
