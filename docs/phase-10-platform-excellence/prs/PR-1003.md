## Summary

- Second CI job (`CI / integration`) with Postgres 17 service and `SHOPANDA_TEST_DSN`

## Why

Postgres package tests (`testDB` + `SHOPANDA_TEST_DSN`) and related DSN-gated packages only run with a real DSN. Unit CI alone leaves the data layer ungated.

## Scope

- Extend `.github/workflows/ci.yml` with `integration` job
- Service: Postgres 17 (digest-pinned, same as compose) with fixed credentials matching the job DSN
- **Readiness gate:** `pg_isready` retry loop (max ~60s); fail clearly if not ready
- Run via [`.github/scripts/run-integration-tests.sh`](../../../.github/scripts/run-integration-tests.sh):
  - Assert `SHOPANDA_TEST_DSN` non-empty
  - `go test -p 1 -count=1 -json` on `./internal/infrastructure/postgres/... ./internal/platform/migrate/... ./plugins/b2b/...`
  - Fail on any `Action==skip` (default `go test` text hides skip reasons — do not grep plain output)
  - Require canary DSN tests to `Action==pass` (proves DB suite ran; `^ok` alone is insufficient)
- Document local integration run + require both checks in branch protection notes
