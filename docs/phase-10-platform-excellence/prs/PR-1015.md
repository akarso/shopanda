# PR-1015 — Typed Plugin Providers

Status: done

## Summary

- Replace `RegisterX(provider any)` with concrete interface parameters
- Fail at compile time when a plugin registers the wrong type

## Why

~71 `any` usages in `platform/plugin`; wrong types failed only at startup via type assert. Undermines Go’s type system at the extension boundary.

## Scope

- Typed methods for search/cache/queue/media/tax/mail/shipping/payment providers
- Update core + demo plugins to compile (already compatible; added `var _` checks)
- Remove redundant runtime asserts in registers and `cmd/api` resolvers
- Tests: compile-time via assignments; registry unit tests for all eight ports

## Out Of Scope

- Pricing/checkout/composition `Register*(any)` (generic / string test placeholders)
- Full SDK extraction from `internal` (PR-1017 honesty + later)
- Changing provider behavior

## What changed

| Area | Change |
| --- | --- |
| `internal/platform/plugin/providers.go` | Eight `Register*` + getters take/return domain interfaces |
| `internal/platform/plugin/plugin.go` | `App` fields typed (`search.SearchEngine`, `cache.Cache`, …) |
| `cmd/api/providers.go` | Resolvers use typed getters; drop `invalid type %T` branches |
| Tests | Full search stub; cache/queue/media/mail/shipping register tests; snapshot stubs |
| `plugins/taxdemo`, `plugins/maildemo` | `var _` interface satisfaction checks |
| Docs | `PLUGINS.md` typed register table; `PLUGIN_COMPOSITION.md` snippet; `DEVELOPER.md` typed port list |
