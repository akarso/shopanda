# PR-1022 — HTTP Package Split (Admin)

Status: done

## Summary

- Move all admin-privileged HTTP surface to `internal/interfaces/http/admin` (new package), continuing PR-1021's split
- `cmd/api` wiring updated to construct/reference admin handlers from the new package
- Behavior-identical: no route, permission, or response-shape changes

## Why

Continues PR-1021; isolates privileged surface for review and future auth audits.

## Scope decision: beyond the `*_admin.go` glob

The original scope line ("move `*_admin.go` files") undercounted the actual admin surface. Also moved, because they are genuinely part of the privileged surface despite not matching that filename pattern:

- `admin_handler.go` / `admin_identity.go` / `admin_mfa.go` / `admin_role.go` / `admin_scope.go` / `admin_user.go` — admin-prefixed (not admin-suffixed) handlers and helpers; `AdminMFAHandler`, `AdminRoleHandler`, `AdminUserHandler` are wired under `/api/v1/admin/*` exactly like the `*_admin.go` handlers
- `media.go` (`MediaHandler`) — every route is `/api/v1/admin/media*`; the file just wasn't `_admin`-suffixed
- `schema_handler.go` (`SchemaHandler`) — every route is `/api/v1/admin/forms|grids/*`
- `admin/dist/` (embedded admin SPA assets) — `admin_handler.go`'s `//go:embed` path simplified from `admin/dist/*` to `dist/*` now that the file lives next to the directory instead of above it

**Split, not moved whole:** two files mixed an admin handler with a non-admin one in the same file:

- `store_credit.go` → `StoreCreditAdminHandler` (+ `issueStoreCreditRequest`, `toStoreCreditLedgerResponses`) moved to `admin/store_credit_admin.go`; `StoreCreditAccountHandler` (customer-facing `/api/v1/account/store-credit`) stayed in `internal/interfaces/http`
- Their shared test file `store_credit_test.go` was split the same way; the account half needed a small local no-op `customer.CustomerRepository` stub since `mockAdminCustomerRepo` moved with the admin half

**Not moved — kept in `internal/interfaces/http`, exported so the new `admin` package can reach them:**

- `AuthMiddleware` / `RequireAuth` / `RequireRole` / `RequirePermission` / `AdminContextMiddleware` (`auth_middleware.go`) — per PR-1021's own scope decision, deferred to PR-1023
- `AccountDeleter` (`account.go`) — shared interface between storefront `StorefrontHandler.WithAccount` and admin `CustomerAdminHandler`
- `OrderResponse` / `ToOrderResponse` (`order.go`, was `orderResponse`/`toOrderResponse`) — shared between the storefront `OrderHandler`, `checkout.go`, and admin `order_admin.go`
- `ToReturnResponse` / `ToReturnResponses` (`return_response.go`, was `toReturnResponse(s)`) — shared between storefront `return_account.go` and admin `return_admin.go`
- `ToAdminReviewResponse` / `ToAdminReviewResponses` / `ParseReviewStatus` (`review.go`, was unexported) — `ReviewAccountHandler.Submit` (storefront) and `review_admin.go` both need the customer-ID-inclusive review shape

Exporting these was the only change to non-admin production code in this PR — pure visibility change, no behavior change (JSON field names are controlled by struct tags, not Go identifier names).

## Scope

- Moved `*_admin.go` (+ tests) plus the above to `internal/interfaces/http/admin`
- New code in `admin` imports `internal/interfaces/http/shared` directly for `JSON`/`JSONError`/`ParsePagination` (no shim usage, per PR-1021's stated direction), aliased `httpshared` where a file also needs `internal/domain/shared`
- Imports the legacy `internal/interfaces/http` package (aliased `shophttp`) where admin code needs the still-there symbols listed above
- Fixed import-cycle-shaped naming collisions: several admin test files also import `internal/application/admin` and/or `internal/domain/admin`, both of which default to package name `admin` — aliased those `adminapp` / `domainadmin` respectively where they collide with the new `internal/interfaces/http/admin` import
- **Mixed test files split**, not just moved: `category_test.go`, `page_test.go`, `content_block_test.go`, `menu_test.go` each mixed storefront and admin handler tests in one file (no separate `_admin_test.go` existed). Split along the same admin/non-admin line as the production code, duplicating small unexported mocks/stubs (`mockCategoryRepo`, `mockCatProductRepo`, `mockPageRepo`, `mockContentBlockRepo`, `mockMenuRepo`, `stubOrderRepo`, `authMockCustomerRepo`/`authMockResetRepo`/`authTestLogger`, `fixedTime`) that can no longer be shared once split across the `http_test`/`admin_test` package boundary

- Fixed a self-inflicted bug during the split: a batch alias-collision fix accidentally rewrote the string literals `"admin.action"` / `"admin.action.failed"` (audit log event names, asserted in `config_admin_test.go`/`order_admin_test.go`/`product_admin_test.go`) to `"adminapp.action"` because the fix script matched `admin.<word>` textually instead of syntactically. Reverted; confirmed no other test-assertion strings were affected by grepping for the literal `"adminapp.action` pattern repo-wide

### Investigated, not fixed: duplicated test doubles

Flagged: `auth_stub_test.go` and `order_stub_test.go` duplicate `authMockCustomerRepo`/`authMockResetRepo`/`authTestLogger`/`stubOrderRepo`/`fixedTime` verbatim from the storefront `http` package tests instead of sharing them via `internal/testutil`.

The finding is real, but consolidating turned out bigger than it looked: `internal/testutil` today only holds small stateless loop helpers (`repodelegates.go`), not full mock structs. Migrating these mocks there would mean **exporting their internal map fields** (`customers`, `byEmail`, `orders`) too — `auth_test.go` alone pokes `repo.customers[id].Role = ...` directly from ~15 call sites outside the type's own methods, relying on same-package field access. Making that work across a package boundary means widening the mocks' public surface and touching every one of those call sites in a currently-green, otherwise-untouched storefront test file — a materially bigger and riskier change than the "minor" label suggested, for a hygiene concern rather than a correctness bug.

Deferred rather than done as a blind mechanical move. If picked up later: export the fields (or add constructor-style setters), move the four types into `internal/testutil`, and update both the original and the `admin_test` copies to import from there.
