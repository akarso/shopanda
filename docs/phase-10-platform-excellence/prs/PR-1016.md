# PR-1016 — RBAC Registry Injection

Status: done

## Summary

- Eliminate package-level mutable plugin permission registry in `domain/rbac`
- Single app-owned `rbac.Registry` shared by plugin `Init` and authorization

## Why

`rbac.RegisterPluginPermission` mutated global state (forbidden by AGENTS.md) and caused cross-test pollution.

## Scope

- Introduce `rbac.Registry` owned by the composition root (`plugin.App`)
- **Same instance** is passed to:
  - plugin registration during `Init` (`app.RegisterPermission` → registry)
  - authorization / `HasPermission` / `PermissionsForRole` used by HTTP middleware (via `BindRuntime` on serve)
- **Lifecycle / ordering:**
  1. Create empty registry before `InitAll` (`preparePermissionRegistry`)
  2. Plugins register during `Init` only
  3. After `InitAll`, freeze registry (`freezePermissionRegistry` / `sealPermissionRegistry`)
  4. Request path reads the frozen registry — never an empty/different instance
- **Duplicate registration:** second register of the same permission code returns an error and fails plugin init
- Remove package-level `pluginPerms` map; hermetic tests use per-app registries + `UnbindRuntime`

## Out Of Scope

- Redesigning RBAC model / roles UX
- Removing process-level effective-permission store globals (`InitEffectivePermissions`) — still package state by design for DB-backed role overrides
- Fully eliminating `BindRuntime` / process-bound package helpers — HTTP auth still uses package `HasPermission`; bridge is freeze-before-bind + unbind-on-serve-failure until a later injection PR
