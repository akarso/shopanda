# PR-1016 — RBAC Registry Injection

Status: planned

## Summary

- Eliminate package-level mutable plugin permission registry in `domain/rbac`
- Single app-owned permission registry shared by plugin `Init` and authorization

## Why

`rbac.RegisterPluginPermission` mutates global state (forbidden by AGENTS.md) and causes cross-test pollution.

## Scope

### Chosen model (fixed)

- Introduce `rbac.Registry` (name flexible) owned by the composition root (`plugin.App` or explicit field on `App`)
- **Same instance** is passed to:
  - plugin registration during `Init` (`app.RBAC().Register(...)` or equivalent)
  - authorization / `HasPermission` / `PermissionsForRole` used by HTTP middleware
- **Lifecycle / ordering:**
  1. Create empty registry in composition root before `Register`/`InitAll`
  2. Plugins register during `Init` only
  3. After `InitAll` succeeds, freeze registry (or treat post-init Register as error)
  4. Request path reads only the frozen registry — never an empty/different instance
- **Duplicate registration:** second register of the same permission code returns an error and fails plugin init (fail-fast)
- Remove / stop using package-level `pluginPerms` map for runtime (tests may keep a reset helper only if still needed during migration)
- Update plugins that register permissions; hermetic tests

## Out Of Scope

- Redesigning RBAC model / roles UX
