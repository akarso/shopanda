# PR-1020 — Prometheus Metrics

Status: planned

## Summary

- Optional Prometheus `/metrics` (default **disabled**)
- Instrument RED metrics for HTTP plus checkout/queue/webhook counters with **bounded labels**

## Why

Zero metrics today. For commerce (orders, payments, queues) logs alone are insufficient for A+.

## Scope

### Exposure / defaults

- Default: metrics **disabled**
- When enabled: bind `/metrics` per config (`metrics.enabled`, optional `metrics.listen` / same server with auth)
- **Must not be publicly exposed by default.** Document required network restriction (private scrape network) and/or auth (e.g. bearer or IP allowlist). Prefer separate listen address defaulting to localhost if implemented that way — document the chosen approach
- Tests: disabled → `/metrics` absent or 404; default config does not expose metrics publicly; enabled path returns Prometheus text

### Labels (bounded)

- Use **route templates** (e.g. `/api/v1/products/{id}`), not raw URLs or query strings
- Status/outcome dimensions: fixed enums / status class (`2xx`, `4xx`, `5xx`) or exact code buckets — no unbounded cardinality
- **Exclude** from labels: raw URLs, query strings, user IDs, order IDs, webhook destination URLs, emails

### Instrumentation

- Client: `prometheus/client_golang`
- Metrics: request count/latency/status-class; checkout success/fail; job failures; webhook delivery success/fail

## Out Of Scope

- Full Grafana dashboards (example queries in docs only)
- OpenTelemetry (PR-1024)
