# PR-1004 — Login Abuse Protection

Status: planned

## Summary

- Enable HTTP rate limiting by default
- Add failed-login throttle / temporary lockout for customer and admin auth

## Why

Security audit High: unlimited credential stuffing against `/api/v1/auth/login` and admin login when `SHOPANDA_RATE_LIMIT_ENABLED=false` (current default).

## Scope

- Flip default `rate_limit.enabled` to `true` in config + `.env.example`
- **Counter store policy (choose one, document in PR):**
  1. **Preferred for multi-instance:** shared store (reuse configured cache/Redis driver when available) for failed-attempt counters; or
  2. **Single-instance only:** in-memory store allowed **only** when explicitly configured (`auth.lockout.store=memory`) and deployment docs state single-instance restriction
- In-memory fallback (if retained): bounded map with per-entry TTL + max entries / eviction; never unbounded growth
- Counters must be keyed by **IP + normalized account identifier** (or IP-primary with account secondary). Do **not** rely solely on account-keyed counters (lockout DoS against a victim email)
- Apply to customer login and admin login paths
- Uniform error responses (no user enumeration change vs today)
- Tests for lockout after N failures, reset on success, TTL expiry, and IP+account keying

## Out Of Scope

- Captcha / external WAF
