# PR-1004 — Login Abuse Protection

Status: planned

## Summary

- Enable HTTP rate limiting by default
- Add failed-login throttle / temporary lockout for customer and admin auth

## Why

Security audit High: unlimited credential stuffing against `/api/v1/auth/login` and admin login when `SHOPANDA_RATE_LIMIT_ENABLED=false` (current default).

## Scope

- Flip default `rate_limit.enabled` to `true` in config + `.env.example`
- Implement per-IP and/or per-account failed attempt counter with cooldown (in-memory OK for v1; document multi-instance caveat)
- Apply to customer login and admin login paths
- Uniform error responses (no user enumeration change vs today)
- Tests for lockout after N failures and reset on success

## Out Of Scope

- Captcha / external WAF
- Redis-backed distributed counters (follow-up if multi-node)

## Validation

- `go test ./internal/application/auth/... ./internal/interfaces/http/... -run 'Login|Rate|Lock'`
- Manual: 20 rapid wrong passwords → 429/lockout
