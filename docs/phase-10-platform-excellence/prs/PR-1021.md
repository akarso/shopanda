# PR-1021 — HTTP Package Split (Shared)

Status: done

## Summary

- Extract cross-cutting HTTP primitives (router, generic middleware, response envelope, pagination, server wrapper) with no handler-specific dependencies into `internal/interfaces/http/shared`
- Leave all ~170 handler/test files in `internal/interfaces/http` unchanged in this PR via a compatibility shim (`shared_compat.go`)

## Why

Flat `package http` (~170 files) hurts compile times and reviewability, and blocks PR-1022/1023 (moving admin/storefront handlers into their own packages): those future packages cannot import `internal/interfaces/http` for the router/middleware/response primitives without risking an import cycle once handlers live outside it. This PR gives them a dependency-free base package to import instead.

## Scope

- Create `internal/interfaces/http/shared` with the movable, handler-independent pieces:
  - `Router` / `Middleware` (`router.go`)
  - Generic middleware: `RequestIDMiddleware`, `LoggingMiddleware`, `RecoveryMiddleware` (`middleware.go`)
  - Response envelope: `JSON`, `JSONWithError`, `JSONError`, `StatusFromCode`, `Response`, `ErrorBody` (`response.go`)
  - `ParsePagination` (`pagination.go`)
  - `Server` (`server.go`)
  - `SecurityHeadersMiddleware`, `BodyLimitMiddleware`, `CacheControlMiddleware`, `RateLimitMiddleware`, `CSRFMiddleware`, `LanguageMiddleware`, `StoreMiddleware`, `ResolverMiddleware` (renamed from `rewrite_middleware.go`'s `RewriteHandler`-adjacent middleware), `MetricsMiddleware`
  - Trusted-proxy / client-IP network helpers used by both middleware and handlers: `ParseTrustedProxies`, `ClientIP`, `WriteRateLimited`, `IsRequestSecure`, `CSRFToken` (exported from formerly-unexported `parseTrustedProxies`/`clientIP`/`writeRateLimited`/`isRequestSecure`/`shopandaCSRFToken` so both the new middleware package and legacy handler call sites can use them)
- `internal/interfaces/http` keeps type aliases and thin forwarding functions for every moved exported name, plus package-private forwarders for the handful of unexported helpers (`parseTrustedProxies`, `clientIP`, `writeRateLimited`, `isRequestSecure`, `shopandaCSRFToken`) that handler files call directly outside the middleware chain (`health.go`, `storefront.go`, `auth.go`, `storefront_account.go`, `storefront_account_security.go`)
- No URL changes; no behavior changes — this is a pure code-organization PR

## Scope decision: `AuthMiddleware` stays put

`AuthMiddleware`, `RequireAuth`, `RequireRole`, `RequirePermission`, and `AdminContextMiddleware` (`auth_middleware.go`) were **not** moved. `AuthMiddleware` calls `storefrontSessionToken`, which is owned by `storefront_account.go` and tightly coupled to storefront cookie-handling helpers that live across several storefront handler files. Moving it would have required also exporting and relocating that cookie logic, which is handler-specific and out of scope for "leave handlers in place." Revisit when PR-1023 (storefront handler split) factors out session-cookie handling.

## Out Of Scope

- Moving admin/storefront handler files (PR-1022/1023)
- Migrating existing call sites in handler files from the `http` shim to `shared` directly (deferred to PR-1022/1023, when those handlers physically move into their own packages and will import `shared` natively instead of via this shim)
- `RewriteHandler` (`rewrite_handler.go`) — it's a request handler (resolves a rewrite from context to a JSON response), not a cross-cutting primitive, so it stays in `internal/interfaces/http`. Only its companion `ResolverMiddleware` moved.

| `internal/interfaces/http/rewrite_test.go` | Trimmed to `RewriteHandler` tests only; `ResolverMiddleware` tests moved to `shared/resolver_middleware_test.go` |
| `internal/interfaces/http/*.go` (handlers) | **Unchanged** — zero handler files edited; they continue to reference `Router`, `JSON`, `Middleware`, etc. as before, now resolved through the shim |
| `docs/diagrams/c4-code.md` | Package layout note describing the split and why the shim exists |

## Validation

- `GOTOOLCHAIN=go1.25.13 go build ./...` — pass
- `GOTOOLCHAIN=go1.25.13 go vet ./...` — pass
- `GOTOOLCHAIN=go1.25.13 go test ./internal/interfaces/... -count=1` — pass (`internal/interfaces/http` and `internal/interfaces/http/shared` both green)
- `GOTOOLCHAIN=go1.25.13 go test ./... -count=1` — pass (full repo, no regressions)
- `GOTOOLCHAIN=go1.25.13 go test ./internal/interfaces/http/shared/... -count=1 -race` — pass (2s)
- `gofmt -l internal/interfaces/http/...` — clean
- Note: `go test ./internal/interfaces/http/... -race` (legacy package, unmoved handler tests) times out under `-race` because bcrypt hashing in auth-flow tests runs ~5–10x slower under race instrumentation, pushing the whole package past the 10-minute default test timeout. This is a pre-existing characteristic of that test package unrelated to this PR — the same tests pass in 39s without `-race`.
