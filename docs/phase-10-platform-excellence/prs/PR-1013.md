# PR-1013 — Split Serve Wiring

Status: done

## Summary

- Extract construction from `runServe` into focused `cmd/api` files without behavior change
- Shrink `main.go` / `runServe` toward reviewable size

## Why

`cmd/api/main.go` is ~2,900 lines; `runServe` ~1,180 lines. Unmergeable conflict magnet; hides wiring bugs.

## Scope

- New files e.g. `wire_repos.go`, `wire_services.go`, `wire_routes.go` (names flexible)
- Move sequential repo/service construction and route registration blocks
- Keep explicit wiring (no DI framework)
- No route/URL/behavior changes
- Smoke: existing HTTP tests still pass

## Out Of Scope

- Collapsing import/export CLI (PR-1014)
- Plugin provider typing (PR-1015)
- Splitting `interfaces/http` packages (PR-1021+)

## What changed

| Area | Change |
| --- | --- |
| `cmd/api/wire_repos.go` | `openServeRepos` opens all postgres repos used by serve (`serveRepos`) |
| `cmd/api/wire_services.go` | `wireServeRuntime` — plugin bootstrap, pipelines, handlers, event wiring |
| `cmd/api/wire_routes.go` | `buildServeHandler` — middleware, route registration, `MountProbes` wrap |
| `cmd/api/main.go` `runServe` | Orchestration only: open DB → repos → services → routes → server/worker/scheduler lifecycle |
| Import/export CLI | No change — PR-1014 |

`runServe` stays in package `main` with explicit wiring (no DI framework). Routes, URLs, and probe wrapping are unchanged: `/readyz` still uses `ReadyHandler(conn)` plus `wrapProbe`.
