# PR-1019 — Event Bus Drain

Status: done

## Summary

- Track async event handler goroutines and drain them on shutdown with a defined barrier and wait-then-cancel policy
- Integrate with existing `ShutdownBackground` timeout (dones waited in parallel)

## Why

Async bus handlers were fire-and-forget on `context.Background()` with no WaitGroup — deploys could drop webhooks/notifications in flight.

## Scope

### Shutdown barrier (required)

1. **Stop admitting** new asynchronous publishes before waiting begins (shutting-down flag under mutex)
2. **Increment WaitGroup before** launching each async handler goroutine (not after)
3. Derive handler contexts from the **shutdown context** (request cancel does not abort them)
4. **Policy:** **wait-then-cancel** — wait for in-flight handlers with a live context for most of the timeout (grace), then cancel stragglers and wait the remainder; log `event.bus.drain.timeout` if they still exceed the deadline
5. Align unit tests: finish-during-grace sees a live ctx; stragglers see cancel; Drain returns within timeout
6. Do not change sync handler abort semantics

**Publish after barrier (choice):** sync-only — `Publish` still runs sync handlers with existing abort semantics and returns their errors; it does **not** fail solely because the bus is draining, and it does not start new async goroutines.

## Out Of Scope

- Persistent outbox pattern (larger reliability project)
- Wait-until-done-without-cancel (stragglers are still cancelled after grace)

## What changed

| Area | Change |
| --- | --- |
| `internal/platform/event/bus.go` | Shutdown context; WG add-before-go under `RLock`; `BeginShutdown` (barrier only); `Drain` wait-then-cancel; skip new async after barrier |
| `internal/platform/runtime/shutdown.go` | Wait all `dones` in **parallel** against the shared timeout |
| `cmd/api/main.go` | Barrier immediately; `Drain(10s)` in parallel; `ShutdownBackground` waits 11s (1s slack so drain timeout can log) |
| Tests | Grace live-ctx; straggler cancel; Drain timeout log; serve wiring including stuck-handler log; `ShutdownBackground` timeout log |

## Code review follow-ups (applied)

| Finding | Action |
| --- | --- |
| Cancel-at-t=0 aborted compliant handlers (emails/webhooks) | **wait-then-cancel**: ~9s grace with live ctx, then ~1s after cancel |
| Exclusive `Lock()` on every Publish async path | Admission + `wg.Add` under `RLock`; `BeginShutdown` takes `Lock()` |
| Sequential `dones` starved the bus | `ShutdownBackground` waits dones in parallel |
| Timeout log unasserted | `TestShutdownBackground_TimeoutLogs` + existing Drain log assert |
| `Drain` unused in serve | Serve runs `Drain` (production shutdown path) |
| Independent 10s Drain vs ShutdownBackground clocks | Outer wait is Drain timeout + 1s slack; stuck-handler wiring test asserts `event.bus.drain.timeout` before return |
| 1s remainder cap undocumented | RUNBOOK + this spec: hardcoded `min(timeout/5, 1s)`, not configurable |

**Known limitation:** no outbox. Work still inside a handler when grace ends is cancelled and not retried. Keep `OnAsync` bodies short (enqueue a job).
