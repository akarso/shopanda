# PR-1019 — Event Bus Drain

Status: planned

## Summary

- Track async event handler goroutines and drain them on shutdown with a defined barrier and cancel-or-wait policy
- Integrate with existing `ShutdownBackground` timeout

## Why

Async bus handlers are fire-and-forget on `context.Background()` with no WaitGroup — deploys can drop webhooks/notifications in flight.

## Scope

### Shutdown barrier (required)

1. **Stop admitting** new asynchronous publishes before waiting begins (e.g. set shutting-down flag under mutex; sync publish path returns error or runs sync-only — document choice)
2. **Increment WaitGroup before** launching each async handler goroutine (not after)
3. Derive handler contexts from the **shutdown context** (so cancel propagates if that policy is chosen)
4. **Policy (fixed for this PR):** **cancel-then-wait** — cancel the shutdown context, then `Wait` with the existing timeout so handlers observe cancellation and exit; log any that exceed the timeout
5. Align unit tests with cancel-then-wait (handler sees cancelled ctx; Wait returns within timeout)
6. Do not change sync handler abort semantics

## Out Of Scope

- Persistent outbox pattern (larger reliability project)
- Wait-until-done-without-cancel alternative (explicitly not chosen)
