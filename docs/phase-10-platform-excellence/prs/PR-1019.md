# PR-1019 — Event Bus Drain

Status: planned

## Summary

- Track async event handler goroutines and drain them on shutdown
- Integrate with existing `ShutdownBackground` timeout

## Why

Async bus handlers are fire-and-forget on `context.Background()` with no WaitGroup — deploys can drop webhooks/notifications in flight.

## Scope

- `event.Bus` waits for in-flight async handlers (WaitGroup) with context timeout
- Wire into API/worker shutdown
- Tests: handler still running at shutdown is waited/cancelled per policy (document: wait-until-done vs cancel)
- Do not change sync handler abort semantics

## Out Of Scope

- Persistent outbox pattern (larger reliability project)

## Validation

- `go test ./internal/platform/event/...`
- Manual: trigger async webhook + SIGTERM → delivery finishes or explicit cancel log
