# PR-1007 — Webhook SSRF Guard

Status: done

## Summary

- Validate webhook destination URLs; block private/link-local/loopback/metadata/CGNAT ranges
- Mandatory DNS-rebinding protection via custom `DialContext` (resolve → filter → dial allowed IPs only)

## Why

Admin `settings:write` could point webhooks at `169.254.169.254` / internal hosts (authenticated blind SSRF). Redirects already disabled — kept that.

## Scope

- Shared helper: `internal/platform/ssrf`
- Block: loopback, RFC1918, link-local, IPv6 ULA, unspecified/multicast, IANA special-purpose IPv4 (CGNAT, TEST-NET, `198.18/15`, `240/4`, …), well-known NAT64 `64:ff9b::/96`
- Delivery: `ssrf.NewHTTPClient` dials only allowed resolved addresses; reject if any A/AAAA is disallowed; **`Proxy = nil`** (env proxies must not skip destination checks)
- Create/update: reject literal blocked IPs and non-canonical IP-shaped hosts (`127.1`, decimal/hex forms) via `ssrf.ValidateURL`
- Clear validation / delivery errors (`ssrf: …`)
- Tests: literal private IPs; non-canonical hosts; NAT64; nil Proxy; allow-path dial-by-IP; injectable resolver private/mixed records; admin create rejection

## Out Of Scope

- No change — Egress proxy (client deliberately ignores `HTTP(S)_PROXY`)
- No change — Per-tenant URL allowlists
