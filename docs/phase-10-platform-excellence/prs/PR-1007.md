# PR-1007 — Webhook SSRF Guard

Status: planned

## Summary

- Validate webhook destination URLs; block private/link-local/loopback/metadata ranges
- **Mandatory** DNS-rebinding protection: connect only to validated resolved addresses (or revalidate immediately before dial)

## Why

Admin `settings:write` can point webhooks at `169.254.169.254` / internal hosts (authenticated blind SSRF). Redirects already disabled — keep that.

## Scope

- Shared URL allow/deny helper used by webhook deliver path
- Block: loopback, RFC1918, link-local, unique-local IPv6, cloud metadata aliases
- **DNS rebinding (required, not optional):**
  - Resolve hostname → filter to allowed addresses → dial those IPs (custom dialer / `http.Transport.DialContext`), **or** re-resolve and re-validate immediately before connect
  - Reject if any resolved A/AAAA is disallowed; cover multiple A/AAAA responses
  - Tests: literal private IPs; hostname whose resolver returns private then public (rebinding scenario via injectable resolver); multi-record responses
- Clear error surfaced to admin API / delivery failure reason

## Out Of Scope

- Egress proxy
- Per-tenant URL allowlists (optional later)
