# PR-1010 — Release to GHCR

Status: planned

## Summary

- On version tag, build and push container image to GHCR
- Deploy via **full commit-SHA tag or image digest** as the immutable identifier; version tags are convenience aliases only

## Why

Current "release" practice recommits `api`. Need immutable artifacts for deploys.

## Scope

- `.github/workflows/release.yml` on `v*` tags
- `docker build` + push:
  - **Immutable:** `ghcr.io/<org>/shopanda:sha-<full40gitsha>` and/or push-by-digest
  - **Alias only:** `ghcr.io/<org>/shopanda:<version-tag>` (mutable convenience; not the deploy pin)
- Do **not** describe short-SHA or version tags as immutable
- Permissions `packages: write`
- `DEPLOYMENT.md`: pin deploys to full SHA tag or digest; version tag optional alias

## Out Of Scope

- Multi-cloud deploy automation
- SBOM signing (nice-to-have follow-up)

## Validation

*(planned — run when implementing)*

- `go test ./...`
- `go build ./cmd/api/`
- Push a test tag on a fork/branch protection sandbox or workflow_dispatch dry-run
- Image (digest or full-SHA tag) runs `serve -h` / `/healthz`
