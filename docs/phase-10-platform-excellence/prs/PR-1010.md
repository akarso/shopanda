# PR-1010 — Release to GHCR

Status: planned

## Summary

- On version tag, build and push container image to GHCR
- Document deploy-from-image instead of committing binaries

## Why

Current "release" practice recommits `api`. Need immutable, versioned artifacts.

## Scope

- `.github/workflows/release.yml` on `v*` tags
- `docker build` + push `ghcr.io/<org>/shopanda:<tag>` and `:sha-<short>`
- Permissions `packages: write`
- Short `DEPLOYMENT.md` section: pull image / compose override

## Out Of Scope

- Multi-cloud deploy automation
- SBOM signing (nice-to-have follow-up)

## Validation

- Push a test tag on a fork/branch protection sandbox or workflow_dispatch dry-run
- Image runs `serve -h` / `/healthz`

## Documentation updates

| Artifact | Change |
| --- | --- |
| `DEPLOYMENT.md` | GHCR pull instructions |
| Root `README.md` | release badge/link optional |
