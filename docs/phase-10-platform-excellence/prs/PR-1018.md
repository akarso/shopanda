# PR-1018 — Checkout Context

Status: done

## Summary

- Thread `context.Context` through checkout `Step.Execute`
- Propagate that context into all blocking downstream calls; surface cancel/deadline errors unchanged at the workflow boundary

## Why

Checkout steps minted `context.Background()`, so hung PSPs and DB calls ignored client cancel and server timeouts — critical path blind spot.

## Scope

- `Step.Execute(ctx context.Context, cctx *Context) error`
- Core steps, payment/shipping/inventory/pricing pipeline calls, and `checkoutdemo` pass `ctx`
- Workflow returns `context.Canceled` / `DeadlineExceeded` without opaque wrapping (still `errors.Is`-detectable when steps wrap with `%w`)
- HTTP/application entrypoints already pass request context into `Workflow.Execute`
- Tests: blocked dependency receives cancelled context; step/workflow surface cancellation

## Out Of Scope

- Full tracing (PR-1024)
- Payment provider behavior changes unrelated to context

## What changed

| Area | Change |
| --- | --- |
| `internal/application/checkout/step.go` | `Execute(ctx, cctx)` |
| Core checkout steps | Request `ctx` for forward work; `detachedTimeout` for rollback / post-PSP persist |
| `detached_context.go` | `context.WithoutCancel(parent)` + bounded timeout helper |
| `workflow.go` | Pass `ctx` to steps; return context errors without opaque wrap (check once before publish) |
| `plugins/checkoutdemo` | Updated step signature |
| Tests | Call sites + cancel + detached rollback/persist coverage |
