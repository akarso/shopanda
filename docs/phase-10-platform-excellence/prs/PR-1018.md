# PR-1018 — Checkout Context

Status: planned

## Summary

- Thread `context.Context` through checkout `Step.Execute`
- Propagate that context into all blocking downstream calls; surface cancel/deadline errors unchanged

## Why

Checkout steps mint `context.Background()`, so hung PSPs and DB calls ignore client cancel and server timeouts — critical path blind spot.

## Scope

- Change `Step` interface to `Execute(ctx context.Context, cctx *Context) error` (or equivalent)
- Update **all** core steps, payment-provider calls, inventory repository calls, and plugin checkout steps (`checkoutdemo`, etc.) to pass `ctx` into blocking downstream APIs
- Return cancellation/deadline errors **unchanged** (do not wrap into generic 500s that hide `context.Canceled` / `DeadlineExceeded` at the step boundary)
- HTTP/application entrypoints pass the **request** context
- Test: blocked dependency receives the cancelled context and the step surfaces the cancellation error

## Out Of Scope

- Full tracing (PR-1024)
- Payment provider behavior changes unrelated to context
