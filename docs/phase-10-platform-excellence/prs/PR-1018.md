# PR-1018 — Checkout Context

Status: planned

## Summary

- Thread `context.Context` through checkout `Step.Execute`
- Propagate request cancellation/deadlines into payment and inventory steps

## Why

Checkout steps mint `context.Background()`, so hung PSPs and DB calls ignore client cancel and server timeouts — critical path blind spot.

## Scope

- Change `Step` interface to `Execute(ctx context.Context, cctx *Context) error` (or equivalent)
- Update core steps + plugin checkout steps (`checkoutdemo`, etc.)
- Pass request context from HTTP/application entrypoints
- Tests: cancelled context aborts step / surfaces error

## Out Of Scope

- Full tracing (PR-1024)
- Payment provider behavior changes

## Validation

- `go test ./internal/application/checkout/... ./plugins/checkoutdemo/...`
- `go build ./cmd/api/`
