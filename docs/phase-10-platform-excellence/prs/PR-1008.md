# PR-1008 — Secure-by-Default Config

Status: done

## Summary

- Reject `changeme` / `shopanda` secrets unless `SHOPANDA_DEV_MODE` is explicitly enabled
- Enforce non-local TLS (`sslmode`) and explicit opt-in for reset-token logging

## Why

Compose "production layout" falls back to `changeme`; `sslmode=disable` is the built-in default; `SHOPANDA_DEV_MODE` logged password-reset tokens in plaintext from any non-empty value.

## Scope

### Weak passwords/secrets

- Treat `changeme` and `shopanda` as forbidden for DB password (including `DATABASE_URL`) unless **`SHOPANDA_DEV_MODE` is explicitly truthy** (`1` / `true` / `yes`)
- Absent / empty / falsey → reject at startup
- Tests: `dev_mode` true / false / empty

### TLS (`sslmode`)

- Non-enforcing modes (`disable` / `prefer` / `allow` / empty→treated as `disable`) only when `SHOPANDA_DEV_MODE` truthy **and** DB host is `localhost` / `127.0.0.1` / `::1` / compose service `postgres`
- When `DATABASE_URL` is set: validate **only** that DSN (URL or libpq keywords); missing `sslmode` treated as insecure; YAML/env sslmode is not merged
- Production allowlist: `require` / `verify-ca` / `verify-full` only (unless local+dev)
- Otherwise startup fails

### Reset-token logging

- Requires `SHOPANDA_DEV_MODE` **and** `SHOPANDA_DEV_LOG_RESET_TOKENS` both truthy
- `config.ShouldLogPasswordResetTokens()` used from `cmd/api`

## Out Of Scope

- No change — Rewriting entire compose to secrets-only (local DX keeps defaults with compose `DEV_MODE`/`sslmode` injects)
