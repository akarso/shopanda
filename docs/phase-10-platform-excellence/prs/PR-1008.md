# PR-1008 — Secure-by-Default Config

Status: planned

## Summary

- Reject `changeme` / `shopanda` secrets unless `SHOPANDA_DEV_MODE` is explicitly enabled
- Enforce non-local TLS (`sslmode`) and explicit opt-in for reset-token logging

## Why

Compose "production layout" falls back to `changeme`; `sslmode=disable` is the built-in default; `SHOPANDA_DEV_MODE` logs password-reset tokens in plaintext.

## Scope

### Weak passwords/secrets

- Treat `changeme` and `shopanda` as forbidden for DB password (and any other composed default secrets in scope) unless **`SHOPANDA_DEV_MODE` is explicitly true**
- Explicitly true = env set to a documented truthy value (`1` / `true` / `yes`, case-insensitive)
- **Absent or empty or falsey** (`0` / `false` / `no`) → reject at startup
- Tests: `dev_mode` true / false / absent

### TLS (`sslmode`)

- Concrete signals for “local development” allowing `sslmode=disable`:
  - `SHOPANDA_DEV_MODE` explicitly true, **and**
  - DB host is loopback (`localhost`, `127.0.0.1`, `::1`) **or** a documented compose service name used only in local profiles
- Otherwise: startup **fails** if `sslmode=disable` (require `require` / `verify-full`)
- Document the exact env/config keys in `DEPLOYMENT.md`

### Reset-token logging

- Remove “log when DEV_MODE set” as sufficient
- Require **explicit development-only opt-in**: `SHOPANDA_DEV_MODE` truthy **and** `SHOPANDA_DEV_LOG_RESET_TOKENS=1` (new flag)
- Absent either flag → never log plaintext reset tokens
- Tests for combinations

- Update `docker-compose.yml` comments + `configs/config.yaml` caution

## Out Of Scope

- Rewriting entire compose to secrets-only (keep DX for local with explicit dev flags)
