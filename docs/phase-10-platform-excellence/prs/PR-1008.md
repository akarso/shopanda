# PR-1008 — Secure-by-Default Config

Status: planned

## Summary

- Fail fast on known-bad secrets outside explicit development mode
- Tighten DB TLS defaults/docs; hard-gate DEV_MODE reset-token logging

## Why

Compose "production layout" falls back to `changeme`; `sslmode=disable` is the built-in default; `SHOPANDA_DEV_MODE` logs password-reset tokens in plaintext.

## Scope

- If password/secret equals `changeme` / `shopanda` and `dev_mode` is not set → startup error
- Prefer documenting `sslmode=require` for non-local; consider changing default only with clear migrate note
- DEV_MODE token logging: require explicit second flag or refuse when `log.level=info` in "production" binding
- Update `docker-compose.yml` comments + `configs/config.yaml` caution
- Tests for fail-fast paths

## Out Of Scope

- Rewriting entire compose to secrets-only (keep DX for local with `dev_mode=true`)

## Validation

- `go test ./internal/platform/config/...`
- Boot with `changeme` and no dev mode → exit non-zero
