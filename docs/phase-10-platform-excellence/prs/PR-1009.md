# PR-1009 — Readiness Probe

Status: done

## Summary

- Add `/readyz` that pings the database with a bounded timeout (503 on failure/timeout)
- Keep `/healthz` as process liveness; **Docker `HEALTHCHECK` stays on `/healthz`**
- Mount both probes **outside** store/auth middleware so a hung DB cannot block them
- Probe responses set `Cache-Control: no-store`; `/readyz` has a dedicated per-IP limiter
- Document `/readyz` as the traffic/readiness probe for orchestrators/load balancers

## Why

`/healthz` returns static 200. Containers with a dead DB can still pass a mis-aimed healthcheck if readiness is conflated with liveness. Preserve the distinction: process up vs ready for traffic. Probes registered on the full mux were still behind `StoreMiddleware` (DB lookups on `r.Context()` with no deadline), which falsified the “bounded / never hang” guarantee.

## Scope

- `GET`/`HEAD` `/readyz` → 200 if `db.PingContext` succeeds within a **finite timeout**; else **503**
- Never wait indefinitely on a hung DB (handler timeout **and** middleware bypass)
- `GET`/`HEAD` `/healthz` unchanged (process up; no DB); both probes `Cache-Control: no-store`
- Dedicated `/readyz` per-IP rate limit (defaults match `rate_limit.default`) — probes sit outside `RateLimitMiddleware`
- **Dockerfile `HEALTHCHECK` remains `/healthz`** (liveness)
- Update compose/docs: use `/readyz` for readiness/traffic control; `/healthz` for container liveness
- OpenAPI documents `/readyz` alongside `/healthz`
- Tests:
  - fake ping success → 200
  - ping error → 503
  - slow/unreachable DB (blocked ping past timeout) → 503 without hanging the handler
  - `MountProbes` does not invoke next (StoreMiddleware) for probe paths
  - nil interface `DBPinger` → 503; typed-nil is a caller contract violation (not supported)
  - no-store cache headers; HEAD served; ready probe rate limit → 429 without ping
