# PR-1009 — Readiness Probe

Status: planned

## Summary

- Add `/readyz` that pings the database
- Keep `/healthz` as liveness; point Docker HEALTHCHECK at readiness

## Why

`/healthz` returns static 200. Containers with a dead DB report healthy; rolling deploys can send traffic to broken instances.

## Scope

- `GET /readyz` → 200 if `db.PingContext` succeeds, else 503
- `GET /healthz` unchanged (process up)
- Dockerfile `HEALTHCHECK` → `/readyz`
- Update compose/docs monitoring snippets
- Handler tests with fake ping

## Out Of Scope

- Checking Redis/Meili/Rabbit in ready (optional later knobs)

## Validation

- `go test ./internal/interfaces/http/... -run Health`
- Stop Postgres under compose → `/readyz` 503, `/healthz` 200
