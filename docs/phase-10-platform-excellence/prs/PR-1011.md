# PR-1011 — Migration Hygiene CI

Status: planned

## Summary

- CI validation for migration filename prefixes with an explicit historical allowlist for the existing `025_*` collision
- Document no-rename policy for applied migrations

## Why

Duplicate `025_*` files exist; tracking is by full filename so it "works" until someone renames. No down migrations — rollback is restore.

## Scope

### Validation policy (fixed before wiring CI)

1. Match files under `migrations/` with `^([0-9]+)_.*\.sql$`
2. Normalize numeric prefixes (strip leading zeros for comparison, or compare as integers — document choice; prefer integer normalization so `025` == `25`)
3. **Allowlist (filename-exact)** the existing collision only:
   - `025_add_cart_merged_guest_id.sql`
   - `025_create_invoices.sql`
4. Fail when:
   - Any **new** file reuses a normalized prefix already present (except the two allowlisted filenames above sharing `25`)
   - An allowlisted historical filename is **renamed** or removed without an explicit policy change PR
5. Wire check into CI (PR-1002 workflow) via Go test under `internal/platform/migrate` **or** a small script invoked by CI
6. Document this exact policy in `DEPLOYMENT.md`

Do **not** rename historical `025_*` in this PR (would break deployed `schema_migrations` rows).

## Out Of Scope

- Introducing golang-migrate/goose
- Writing down migrations for history
- Deleting root `migrations/` files

## Validation

*(planned — run when implementing)*

- `go test ./internal/platform/migrate/...` (or the chosen script’s check command — state which in the implementation PR)
- `go build ./cmd/api/`
- CI check passes on current tree with allowlisted `025_*` only
