# PR-1011 — Migration Hygiene CI

Status: planned

## Summary

- CI script fails if two `migrations/NNN_*.sql` share the same numeric prefix
- Document no-rename policy for applied migrations
- Remove any remaining dead migration copies

## Why

Duplicate `025_*` files exist; tracking is by full filename so it "works" until someone renames. No down migrations — rollback is restore.

## Scope

- Small script or Go test: unique `^[0-9]+` prefixes under `migrations/`
- Wire into CI (PR-1002 workflow)
- Doc note in `DEPLOYMENT.md` / migrator README comment: never rename applied files; new migrations get next free number
- Do **not** rename historical `025_*` in this PR (would break deployed `schema_migrations` rows)

## Out Of Scope

- Introducing golang-migrate/goose
- Writing down migrations for history

## Validation

- CI check passes on current tree (duplicate 025 is a known exception — either grandfather with allowlist **or** add a new unique prefix file only for future enforcement; document choice in PR)
- Prefer: allowlist existing collision once; forbid new collisions

| `DEPLOYMENT.md` | migration rules + rollback = backup restore |
