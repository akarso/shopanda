# PR-1012 — Supply-Chain Basics

Status: planned

## Summary

- Dependabot for Go modules, GitHub Actions, and Docker base digests
- Pinned `govulncheck` CI job with a documented fail-closed enforcement policy

## Why

Pinned digests/comments say "refresh periodically" with no automation. `lib/pq` and other deps need visibility even before pgx migration.

## Scope

- `.github/dependabot.yml`
- **Enforcement policy (choose and document one in this PR — recommended):**
  - **Fail-closed:** `govulncheck ./...` fails the job on any finding
  - Baseline/exceptions: if pre-existing findings block green, track them in `docs/phase-10-platform-excellence/GOVULN_BASELINE.md` (or CI config allowlist) with owner + expiry; **new** findings not on the baseline fail the job
- **Pin** the `govulncheck` version used by the job (module version or pinned binary URL/checksum)
- Validation step: introduce a known-vulnerable import in a throwaway branch / unit fixture and confirm the job fails (document the procedure; do not merge the fixture)
- No unrelated dependency upgrades bundled unless required to go green

## Out Of Scope

- Full pgx migration (PR-1025)
- Cosign/SBOM

- Confirm job fails when a newly introduced vulnerability is detected (procedure above)
