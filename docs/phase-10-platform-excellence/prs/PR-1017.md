# PR-1017 — Plugin Boundary Honesty

Status: planned

## Summary

- Enforce a **fixed** plugin import allowlist via CI/`go test`
- Forbid `internal/infrastructure` and `internal/interfaces` imports from `plugins/**`
- Update docs to describe the real in-module plugin model

## Why

Plugins import `internal/*` 263× vs `pkg/*` 34×. Isolation is a marketing claim.

## Scope

### Fixed allowlist (no alternatives in this PR)

Plugins may import:

- `github.com/akarso/shopanda/pkg/...`
- `github.com/akarso/shopanda/internal/domain/...`
- `github.com/akarso/shopanda/internal/application/...` (including ports/hooks/etc.)
- `github.com/akarso/shopanda/internal/platform/...`

Plugins must **not** import:

- `.../internal/infrastructure/...`
- `.../internal/interfaces/...`

Stricter boundaries (forbidding application/platform) are **out of scope** — defer to a later PR.

- CI/`go test` import-walking check under e.g. `plugins/plugin_imports_test.go` matching the allowlist above
- Refactor violators (notably `b2b`) to use registered routes/providers instead of importing HTTP/postgres
- Update `PLUGINS.md` + `PLUGIN_COMPOSITION.md` with accurate claims

## Out Of Scope

- Publishing a separate module for out-of-tree plugins (future)
- Runtime `.so` loading
- Tightening beyond the allowlist above
