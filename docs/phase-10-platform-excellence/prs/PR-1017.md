# PR-1017 — Plugin Boundary Honesty

Status: done

## Summary

- Enforce a **fixed** plugin import allowlist via `go test` (`TestImportBoundary`)
- Forbid `internal/infrastructure` and `internal/interfaces` imports from non-core `plugins/**`
- Update docs to describe the real in-module plugin model

## Why

Plugins imported `internal/*` heavily vs `pkg/*`. Isolation was a marketing claim without enforcement.

## Scope

### Fixed allowlist (enforced)

Non-core plugins may import:

- `github.com/akarso/shopanda/pkg/...`
- `github.com/akarso/shopanda/internal/domain/...`
- `github.com/akarso/shopanda/internal/application/...`
- `github.com/akarso/shopanda/internal/platform/...`
- sibling `github.com/akarso/shopanda/plugins/...`

Plugins must **not** import:

- `.../internal/infrastructure/...`
- `.../internal/interfaces/...`

**Exception:** `plugins/core/**` may import infrastructure (driver adapters). `*_test.go` excluded so fixtures can construct adapters.

- `plugins/plugin_imports_test.go` — import walk
- Refactored `b2b` off HTTP/postgres imports (`platform/httpx` + `Bootstrap` domain ports)
- Docs: `PLUGINS.md`, `PLUGIN_COMPOSITION.md`, C4 wiring note

## Out Of Scope

- Publishing a separate module for out-of-tree plugins (future)
- Runtime `.so` loading
- Tightening beyond the allowlist above (forbidding application/platform)
