# PR-1017 — Plugin Boundary Honesty

Status: planned

## Summary

- Enforce: `plugins/**` must not import `internal/infrastructure` or `internal/interfaces`
- Update docs to describe the real in-module plugin model and SDK path
- Fix violating plugins (notably `b2b`) by moving needed seams behind ports/`pkg`

## Why

Plugins import `internal/*` 263× vs `pkg/*` 34×. Isolation is a marketing claim. Either enforce a boundary or stop claiming third-party plugins work without forking.

## Scope

- CI/`go test` script walking imports under `plugins/`
- Allow `internal/domain`, `internal/application` ports, `internal/platform` as needed for in-module plugins **or** tighten further if feasible in one PR — document the chosen allowlist
- Hard-forbid infrastructure + interfaces imports from plugins
- Refactor violators to use registered routes/providers instead of importing HTTP/postgres
- Update `PLUGINS.md` + `PLUGIN_COMPOSITION.md` with accurate claims

## Out Of Scope

- Publishing a separate module for out-of-tree plugins (future)
- Runtime `.so` loading

## Validation

- Boundary test fails if a plugin imports forbidden packages
- `go test ./plugins/...` green
