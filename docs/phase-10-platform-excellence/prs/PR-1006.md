# PR-1006 — HTTP Boundary Hardening

Status: done

## Summary

- Route-aware request body size limits (default 1 MiB for JSON/API; 10 MiB for media uploads)
- Security headers middleware for API + SSR with exact-value tests
- HSTS only on TLS or trusted-proxy `X-Forwarded-Proto: https`

## Why

Most JSON handlers decoded `r.Body` without `MaxBytesReader` (DoS). No `X-Content-Type-Options` / frame options / Referrer-Policy / HSTS; SSR storefront was clickjackable. Media already used a 10 MiB `MaxBytesReader`.

## Scope

- **Body limits (route-aware):**
  - Default `http.max_body_bytes` (1 MiB) on non-media body-bearing methods
  - Media upload routes use `http.media_max_body_bytes` (10 MiB); caps are independent
  - 413 responses use `error.code=payload_too_large` (not `validation`)
  - Body-limit middleware sits inside Logging so access logs record 413
  - No uniform top-level wrap that would break media
- **Security headers** (exact values):
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` (chosen over CSP `frame-ancestors` for a single fixed header)
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains` only when TLS or trusted forwarded proto
- Tests for headers, HSTS presence/absence, 413 on oversized JSON, media above default under media cap

## Out Of Scope

- No change — Full CSP policy design
- No change — CORS configuration
