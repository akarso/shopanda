# PR-1006 — HTTP Boundary Hardening

Status: planned

## Summary

- Global request body size limit
- Security headers middleware for API + SSR

## Why

Most JSON handlers decode `r.Body` without `MaxBytesReader` (DoS). No `X-Content-Type-Options` / frame options / Referrer-Policy / HSTS anywhere; SSR storefront is clickjackable.

## Scope

- Wrap server handler with configurable max body (sensible default, e.g. 1MiB; media endpoints keep their own higher caps)
- Middleware setting: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` (or CSP frame-ancestors), `Referrer-Policy`, `Strict-Transport-Security` when request is TLS / trusted proto
- Tests for 413 on oversized body and header presence

## Out Of Scope

- Full CSP policy design
- CORS configuration changes

## Validation

- `go test ./internal/interfaces/http/... -run 'Body|SecurityHeader|MaxBytes'`
- `go build ./cmd/api/`
