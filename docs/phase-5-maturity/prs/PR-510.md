# PR-510 — Advanced Promotion Rules (Track B, OSS)

Status: done

## Summary

- Tiered catalog percentage discounts by line quantity
- Buy-X-get-Y free-item catalog discounts
- Cart-level promotion runtime step for min-cart-total rules

## Why

Phase 4 admin CRUD (PR-401) stored simple percentage/fixed rules but deferred tiered and buy-X-get-Y. Merchants need quantity breakpoints and bundle offers without custom code.

## Scope

- `internal/application/admin/promotion_rules.go` — encode/decode `tiered` and `buy_x_get_y` actions
- `internal/application/pricing/catalog_promotion_step.go` — tier selection and buy-X-get-Y discount math
- `internal/application/pricing/cart_promotion_step.go` — new `cart_promotions` pipeline step
- `internal/interfaces/http/promotion_admin.go` — `action_tiers`, `action_buy_qty`, `action_get_qty` on admin API
- `cmd/api/main.go` — insert cart step after catalog promotions, before tax
- Existing `min_quantity` and date window behavior unchanged

## Out Of Scope

- Customer group promotion conditions (B2B plugin + PR-501 follow-up)
- Product/category-scoped conditions
- Checkout order-line net pricing from adjustments (existing gap)
- Admin UI form updates (API only)
- Coupon redemption at checkout for cart promos beyond existing coupon_code meta

## Validation

- Create tiered catalog promo (2→5%, 5→15%); qty 5 line → 15% discount
- Create buy 2 get 1 free; qty 6 → 2 free units discounted
- Create cart promo min total 5000 + fixed 500; subtotal 6000 → context discount applied
- Admin rejects unknown action types; tiered requires valid tier rows
