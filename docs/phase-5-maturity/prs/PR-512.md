# PR-512 — Content Blocks (Track B, OSS)

Status: done

## Summary

- Reusable CMS block types: hero, rich text, product carousel
- Assign blocks to layout targets (home) or CMS pages
- Admin CRUD plus target placement API
- Public resolved block API and storefront SSR rendering

## Why

Merchants need reusable page sections without theme file edits. Phase 4 deferred content blocks; PR-511 added navigation, and blocks complete the CMS content slice for marketing pages.

## Scope

- `migrations/054_create_content_blocks.sql` — `content_blocks`, `content_block_placements`
- `internal/domain/cms/content_block.go` — block types, config validation
- `internal/infrastructure/postgres/content_block_repo.go` — CRUD and target placement replace
- `internal/application/cms/block_resolver.go` — product carousel hydration
- `internal/interfaces/http/content_block_admin.go` — admin block CRUD and target endpoints
- `internal/interfaces/http/content_block.go` — `GET /api/v1/content-blocks/{targetType}/{targetKey}`
- `internal/interfaces/http/storefront_content.go` — home/page block rendering
- `themes/default/templates/page.html`, `layout.html` `content-blocks` partial, `home.html` fallback
- `cmd/api/main.go` — wiring

## Out Of Scope

- Admin SPA block editor UI (API only)
- Additional layout targets beyond `home`
- Block translations
- Drag-and-drop ordering UI (position follows API array order)
- Rich text sanitization/HTML editor (plain body string)

## Validation

- `POST /api/v1/admin/content-blocks` creates hero/rich_text/product_carousel blocks with validated config
- `PUT /api/v1/admin/content-block-targets/layout/home` assigns ordered blocks to home
- `PUT /api/v1/admin/content-block-targets/page/{page-id}` assigns blocks to a CMS page
- `GET /api/v1/content-blocks/layout/home` returns resolved blocks; page target accepts slug
- Storefront `/` renders assigned home blocks; `/pages/{slug}` renders page blocks plus legacy page content
- Invalid block config and duplicate placement IDs rejected
