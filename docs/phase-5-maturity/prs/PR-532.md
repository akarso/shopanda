# PR-532 — EPR / Packaging Data (Track D)

Status: done

## Summary

- EPR packaging product/variant attributes (material, weight, recyclability, recycled content, scheme ID)
- CSV export for merchant EPR reporting (`export:epr` CLI + admin download)
- Store-level default scheme registration ID via admin legal settings

## Why

EU merchants must track packaging placed on market for Extended Producer Responsibility schemes. Core should store structured facts and export them; calculation and filing stay external.

## Scope

- `internal/domain/legal/epr.go` — attribute keys, config keys, merge product/variant parsing
- `internal/application/exporter/epr.go` — paginated SKU-level EPR CSV
- `internal/seed/epr_attributes.go` — EPR attribute group + demo data on usb-c-cable
- Admin: `legal.epr_enabled`, `legal.epr_scheme_registration_id`; Settings → Legal download button
- `GET /api/v1/admin/reports/epr` — CSV download (`products.read`)
- CLI: `app export:epr <file.csv>` (optional `--include-empty`)
- tests: domain, exporter, admin handler

## Out Of Scope

- National EPR registry filing or fee calculation
- Shipment-level packaging weights (SKU-level only)
- Storefront PDP display (reporting-only PR)

## Validation

- Seed registers EPR attributes under Catalog → Attributes
- Set packaging fields on a SKU → `export:epr out.csv` includes row with material/weight
- Admin Legal settings → Download EPR packaging CSV returns same data
- Store scheme ID fills `scheme_registration_id` when product attribute empty
- Variant `epr_packaging_weight_g` overrides product-level weight
