# PR-514 — Product Reviews (Track B, OSS)

Status: done

## Summary

- Signed-in customers submit 1–5 star product reviews (pending moderation)
- Admin approve/reject workflow via REST API
- Approved reviews render on PDP via composition pipeline and storefront template

## Why

Phase 2 storefront spec deferred reviews. PR-514 adds minimal moderated reviews so merchants can collect social proof without theme edits or third-party syndication.

## Scope

- `migrations/057_create_product_reviews.sql` — `product_reviews` with unique (product, customer)
- `internal/domain/review/` — review entity, statuses, repository port
- `internal/infrastructure/postgres/review_repo.go` — CRUD, approved listing, summary stats
- `internal/application/reviews/service.go` — submit, approve, reject, display helpers
- `internal/application/composition/reviews_step.go` — `product_reviews` PDP block
- `internal/interfaces/http/review_admin.go` — admin list/get/approve/reject
- `internal/interfaces/http/review.go` — public list + authenticated submit
- `themes/default/templates/product.html` — reviews section
- `cmd/api/main.go` — wiring, routes, PDP step

## Out Of Scope

- Admin SPA review moderation UI (API only)
- Verified-purchase-only reviews
- Review photos / rich text
- Syndication to third parties
- New RBAC permissions (uses `products.read` / `products.write`)
- Storefront review submit form (REST submit only)

## Validation

- `POST /api/v1/products/{id}/reviews` (auth) creates pending review; duplicate per customer rejected
- `GET /api/v1/products/{id}/reviews` returns approved reviews only
- `GET /api/v1/admin/reviews?status=pending` lists pending queue
- `POST /api/v1/admin/reviews/{id}/approve|reject` transitions pending reviews
- PDP API and storefront `/products/{slug}` include `product_reviews` block when approved reviews exist
- Only active products accept submissions
