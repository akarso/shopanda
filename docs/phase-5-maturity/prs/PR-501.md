# PR-501 — Group-Aware Pricing (Track A, B2B)

Status: done

## Summary

- Core `GroupPrice` port for optional tier prices per customer group
- B2B plugin schema, repository, pricing pipeline step, and admin HTTP API
- Cart/checkout pass `customer_id` into pricing context for group lookup

## Why

Wholesale and B2B buyers need contract prices without duplicating catalogs. Group prices override base prices after the base step and before promotions/tax.

## Scope

- `internal/domain/customergroup/group_price.go` — `GroupPrice` entity + `GroupPriceRepository` port
- `plugins/b2b/migrations/002_create_customer_group_prices.sql`
- `plugins/b2b/pricing/` — Postgres repo, `GroupPriceStep`, admin handler
- Permissions: `b2b.prices.read`, `b2b.prices.write` (Admin, Manager)
- Admin API:
  - `GET/PUT/DELETE /api/v1/admin/customer-groups/{groupId}/variants/{variantId}/price`
- Pricing pipeline: `b2b.group_price` step registered by B2B plugin (after base, before promotions)
- Core: cart/checkout set `customer_id` in `PricingContext.Meta`
- `cmd/api/main.go` — plugin pricing steps inserted after base price step

## Out Of Scope

- Promotion conditions scoped to groups (PR-510 + B2B license)
- Storefront price display hints (login-gated prices backlog)
- Admin UI screens (API only)
- Bulk import/export of group prices

## Validation

- Assign customer to wholesale group; set group price on variant lower than base
- Authenticated cart recalculate → line unit price matches group price
- Guest cart → base price unchanged
- Admin GET/PUT group variant price respects store/currency scope
