# PR-534 — OSS / IOSS Tax Export (Track D)

Status: done

## Summary

- Persist checkout shipping destination country and VAT total on paid orders
- CSV export for OSS/IOSS merchant accounting (`export:oss` CLI + admin download)
- Store-level opt-in toggle `legal.oss_enabled`

## Why

EU merchants using OSS/IOSS must reconcile VAT collected by destination country. Core stores checkout tax facts and exports them; return filing stays in external accounting tools.

## Scope

- Migration `051_add_orders_tax_snapshot.sql` — `orders.destination_country`, `orders.tax_amount`
- Checkout sets `tax_country` from shipping address before pricing; `create_order` persists tax snapshot
- `internal/domain/legal/oss.go` — config key + helpers
- `internal/application/exporter/oss.go` — detail + summary CSV modes
- Admin: `legal.oss_enabled`; Settings → Legal OSS date range + download buttons
- `GET /api/v1/admin/reports/oss` — CSV download (`orders.read`, query `from`, `to`, `summary`)
- CLI: `app export:oss [--summary] [--from=YYYY-MM-DD] [--to=YYYY-MM-DD] <file.csv>`
- tests: domain, exporter, admin handler, order repo round-trip

## Out Of Scope

- OSS/IOSS return filing or VIES validation
- Peppol / e-invoicing adapter (future core plugin)
- Credit notes in OSS aggregation (future enhancement)
- Legacy orders without destination country (excluded from export)

## Validation

- Place paid order with FR shipping address → order row has `destination_country=FR` and tax amount
- `export:oss out.csv --from=2026-01-01 --to=2026-12-31` lists order with tax breakdown
- Admin Legal → Download OSS tax summary CSV aggregates by country
- Empty `from`/`to` defaults to current calendar quarter (API + CLI)
