# PR-520 — Admin User CRUD (Track C, OSS)

Status: done

## Summary

- Dedicated admin user API for creating and managing admin-panel accounts
- Assign roles (admin, manager, editor, support), disable/enable users
- Force password reset with session invalidation

## Why

Phase 3 added a read-only Users & Roles screen backed by customer list filtering. Admin accounts were seed-only. PR-520 adds the backend contracts needed for in-app admin user management.

## Scope

- `internal/domain/customer/customer.go` — `IsAdminRole` helper
- `internal/domain/customer/repository.go` — `ListAdminUsers`, `CountActiveByRole`
- `internal/infrastructure/postgres/customer_repo.go` — admin user queries
- `internal/application/adminuser/service.go` — create, update, reset password
- `internal/interfaces/http/admin_user.go` — REST handlers + audit logging
- `internal/application/admin/audit.go` — admin user audit actions
- `cmd/api/main.go` — routes under `settings.read` / `settings.write`

## Out Of Scope

- Admin SPA UI changes (API only; existing Users & Roles page can adopt later)
- Custom roles editor (PR-521)
- MFA / TOTP (PR-522)
- Email invitation flow for new admins
- Deleting admin users (disable via status instead)

## Validation

- `GET /api/v1/admin/users` lists non-customer roles only
- `POST /api/v1/admin/users` creates admin-capable user with verified email
- `PUT /api/v1/admin/users/{id}` updates role/name/status
- `POST /api/v1/admin/users/{id}/reset-password` sets password and bumps token generation
- Cannot disable/demote self or remove last active admin
- Endpoints require `settings.read` / `settings.write` (admin role only)
