# PR-505 — Store Credit (Track A, OSS stretch)

Status: done

## Summary

- Issued store credit balance per customer and currency
- Redemption at checkout against order line-item total
- Admin issue/list API and customer account balance endpoint

## Why

Returns workflows (PR-502–503) create a natural need to refund as store credit instead of payment-provider reversal. This minimal slice enables manual issuance and checkout redemption without gift-card complexity.

## Scope

- `migrations/052_store_credit.sql` — accounts, ledger, `orders.store_credit_amount`
- `internal/domain/storecredit/` — ledger entry types + repository port
- `internal/infrastructure/postgres/store_credit_repo.go` — balance upsert with row lock
- `internal/application/storecredit/service.go` — issue, balance, redeem, list
- Order domain: `StoreCreditApplied`, `ApplyStoreCredit()`, `PayableAmount()`
- Checkout: `store_credit_amount` input; redeem in `create_order`; skip payment when payable is zero
- HTTP:
  - `GET /api/v1/admin/customers/{customerId}/store-credit`
  - `POST /api/v1/admin/customers/{customerId}/store-credit/issue`
  - `GET /api/v1/account/store-credit?currency=EUR`
  - `POST /api/v1/checkout` accepts `store_credit_amount`
- Permissions: reuse `customers.read` / `customers.write` for admin endpoints

## Out Of Scope

- Gift cards (codes, partial activation, expiry)
- Automatic refund-to-credit from returns
- Storefront UI
- Multi-currency conversion of credit

## Validation

- Admin issues 2500 EUR credit to customer → balance reflects amount
- Authenticated checkout with `store_credit_amount: 1000` on 2000 order → payable 1000, ledger redeem row
- Full credit coverage → payment step skipped (`payment_skipped` meta)
- Guest checkout with store credit → validation error
