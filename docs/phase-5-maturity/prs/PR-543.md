# PR-543 — GraphQL API Plugin (Track E, OSS)

Status: done

## Summary

- Optional read-only GraphQL catalog API at `POST /api/v1/graphql`
- Config-gated core plugin (`plugins.graphql.enabled`); REST remains canonical for writes
- Queries: product, productBySlug, products, category, categories, categoryProducts

## Why

Headless storefronts and mobile clients often prefer GraphQL for read-heavy catalog fetches. PR-543 adds an opt-in integrator layer without changing REST contracts or domain logic.

## Scope

- `internal/platform/plugin/public_routes.go` — `RegisterPublicRoute` for plugin-owned public HTTP handlers
- `plugins/core/graphql/` — schema, resolver, handler, core plugin (`core/graphql-api`)
- `internal/platform/config/` — `plugins.graphql.enabled`, `SHOPANDA_PLUGINS_GRAPHQL_ENABLED`
- `plugins/core/register.go` — register when enabled
- `cmd/api/main.go` — mount plugin public routes
- Docs: PR spec, config example, C4 diagram note, DEVELOPER.md

## Out Of Scope

- Mutations (checkout, cart, auth) — use REST
- Composition pipeline / pricing enrichment on GraphQL fields (raw catalog repo reads)
- GraphiQL playground UI
- Replacing OpenAPI as canonical API documentation

## Config

```yaml
plugins:
  graphql:
    enabled: false
```

Environment: `SHOPANDA_PLUGINS_GRAPHQL_ENABLED=true`

## Example query

```graphql
{
  productBySlug(slug: "widget") {
    id
    name
    status
  }
  categories {
    id
    name
    slug
  }
}
```

POST `Content-Type: application/json`:

```json
{"query": "{ products(limit: 10) { id name slug } }"}
```

## Validation

- `plugins.graphql.enabled=false` (default): no `/api/v1/graphql` route
- `plugins.graphql.enabled=true`: `POST /api/v1/graphql` returns product/category data
- Unknown fields return GraphQL errors; no Shopanda REST envelope on this endpoint
- `go test ./internal/platform/plugin/... ./plugins/core/graphql/... ./plugins/core/`
