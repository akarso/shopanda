# PR-524 — Shipping Zones Admin UI (Track C, OSS)

Status: done

## Summary

- Embed existing shipping zone and rate-tier API into Operations → Shipping
- Merchants can create/edit/delete zones and manage weight-based rates without API calls

## Why

PR-210–212 delivered zone-based shipping in core with a full admin API, but MERCHANT.md still listed zones as API-only. PR-524 closes that gap with a settings UI on the existing Shipping page.

## Scope

- `internal/interfaces/http/admin/dist/admin.js` — Shipping Zones section on `/admin/operations/shipping`
- `internal/interfaces/http/admin_handler_test.go` — wiring assertions for zone API usage
- `docs/guides/MERCHANT.md` — update known-gap table

## Out Of Scope

- New backend routes or domain changes (API from PR-210 is reused)
- Carrier API plugins
- Shipping label purchase
- Zone import/export

## Validation

- Operations → Shipping lists zones from `GET /api/v1/admin/shipping/zones`
- Create zone posts to `POST /api/v1/admin/shipping/zones` with countries, priority, free-shipping threshold
- Edit zone updates via `PUT /api/v1/admin/shipping/zones/{id}`
- Delete zone removes zone and tiers via `DELETE /api/v1/admin/shipping/zones/{id}`
- Rates panel loads/creates/deletes tiers via existing `/rates` endpoints
- Users without `shipping.read` see a forbidden message
