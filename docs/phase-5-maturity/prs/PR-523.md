# PR-523 — Audit Export + Retention (Track C, OSS)

Status: done

## Summary

- CSV/JSON export of persisted `admin_audit_log` rows via admin API
- Configurable retention job prunes rows older than `audit.retention_days`
- Admin UI download buttons on Settings → Audit Log

## Why

PR-434 added in-app audit persistence and read-only listing. Merchants still need offline copies for compliance workflows and a way to cap table growth without manual SQL.

## Scope

- `internal/domain/admin/audit_config.go` — `audit.retention_days` config helper
- `internal/domain/admin/audit_log.go` — `DeleteBefore` on repository port
- `internal/application/exporter/audit_log.go` — batched CSV/JSON export
- `internal/application/admin/audit_retention.go` — `audit.retention` job handler
- `internal/infrastructure/postgres/audit_log_repo.go` — `DeleteBefore` implementation
- `internal/interfaces/http/audit_log_admin.go` — `GET /api/v1/admin/audit/export`
- `internal/platform/runtime/audit_retention.go` — daily cron registration (`0 3 * * *`)
- `internal/application/admin/audit.go` — `audit.export` audit action
- `cmd/api/main.go` — export route, retention handler + scheduler wiring
- Admin UI: CSV/JSON download buttons on audit log page

## Out Of Scope

- PII redaction in exports
- Per-store audit retention (global config only)
- Storefront/customer action audit
- Signed/immutable audit archives

## Validation

- `GET /api/v1/admin/audit/export?format=csv` returns CSV attachment (`audit.read`)
- `GET /api/v1/admin/audit/export?format=json` returns JSON array (`audit.read`)
- Export honors the same `action`, `resource_type`, `resource_id`, `from`, `to` filters as list
- With `audit.retention_days=90`, `audit.retention` job deletes rows older than 90 days
- With `audit.retention_days=0` or unset, retention job skips deletion

## Configuration

- Config key: `audit.retention_days` (integer days; `0` = retain forever)
