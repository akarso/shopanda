# PR-540 — Merchant Outbound Webhooks (Track E, OSS)

Status: done

## Summary

- Merchants register HTTPS webhook endpoints for order and payment domain events
- Deliveries are HMAC-signed and retried via the existing job queue
- Admin API manages endpoint CRUD under Settings permissions

## Why

Integrators need push notifications when orders are paid or payments change state. Inbound payment-provider webhooks already exist; PR-540 adds merchant-owned outbound subscriptions.

## Scope

- `migrations/060_create_webhook_endpoints.sql` — endpoint storage
- `internal/domain/webhook/` — endpoint model, supported event catalog, repository port
- `internal/infrastructure/postgres/webhook_endpoint_repo.go` — persistence
- `internal/infrastructure/webhook/sign.go` — HMAC-SHA256 signing helper
- `internal/application/webhook/` — admin service, event dispatcher, `webhook.deliver` job handler
- `internal/interfaces/http/webhook_endpoint_admin.go` — admin CRUD + event catalog
- `cmd/api/main.go` — bus wiring, routes, worker registration
- Admin integrations page shows configured endpoint count

## Out Of Scope

- Full webhook management UI (API-first; integrations page summary only)
- Delivery log/history UI
- Per-store webhook scoping
- Customer/catalog event subscriptions

## Supported events

- `order.created`, `order.confirmed`, `order.paid`, `order.cancelled`, `order.failed`
- `payment.completed`, `payment.failed`, `payment.refunded`

## Delivery format

- `POST` JSON envelope: `{ id, event, source, created_at, data }`
- Headers: `X-Shopanda-Event`, `X-Shopanda-Delivery`, `X-Shopanda-Signature` (hex HMAC-SHA256 of body)
- Retries: job queue default (3 attempts with backoff)

## Validation

- `POST /api/v1/admin/webhooks` returns endpoint + one-time `secret` (`settings.write`)
- Publishing `order.paid` enqueues `webhook.deliver` for subscribed active endpoints
- Deliver handler posts signed payload; non-2xx responses fail the job for retry
- `GET /api/v1/admin/webhooks/events` lists supported event names
