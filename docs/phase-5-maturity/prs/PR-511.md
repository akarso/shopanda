# PR-511 — Navigation Builder (Track B, OSS)

Status: done

## Summary

- DB-backed header/footer menus with nested items
- Link types: custom URL, category, CMS page
- Admin list/get/update API and public resolved menu API
- Storefront header nav loads from DB with theme.yaml fallback

## Why

Storefront navigation was hard-coded in theme YAML. Merchants need editable menus linking to categories and CMS pages without theme file changes.

## Scope

- `migrations/053_create_menus.sql` — `menus`, `menu_items`, seed `header`/`footer`
- `internal/domain/cms/menu.go` — menu entities, link types, item validation
- `internal/infrastructure/postgres/menu_repo.go` — list/find/save (atomic item replace)
- `internal/application/cms/menu_resolver.go` — resolve category/page targets to URLs
- `internal/interfaces/http/menu_admin.go` — `GET/PUT /api/v1/admin/menus`
- `internal/interfaces/http/menu.go` — `GET /api/v1/menus/{code}`
- `internal/interfaces/http/storefront.go` — header nav from DB; nested `Children`
- `themes/default/templates/layout.html` — nested primary nav markup
- `cmd/api/main.go` — wiring

## Out Of Scope

- Admin SPA navigation editor UI (API only)
- Footer menu rendering in theme (footer menu seeded for future use)
- Replacing category nav strip (unchanged)
- Multi-store menu scoping
- Menu item translations

## Validation

- `GET /api/v1/admin/menus` lists header and footer menus
- `PUT /api/v1/admin/menus/{header-id}` with nested url/category/page items persists tree
- `GET /api/v1/menus/header` returns resolved URLs (`/categories/{slug}`, `/pages/{slug}`)
- Storefront shows DB header menu when items exist; falls back to theme.yaml otherwise
- Invalid parent references and cycles rejected on save
