# PR-542 — Kafka / SQS Queue Plugins (Track E, OSS)

Status: done

## Summary

- Alternative `jobs.Queue` backends for Kafka and Amazon SQS
- Config-gated core plugins register when `queue.driver=kafka` or `queue.driver=sqs`
- Shared JSON job envelope in `internal/infrastructure/jobqueue`

## Why

Operators scaling beyond single-node Postgres need broker-backed job queues without forking core worker logic. Redis and RabbitMQ already ship as core plugins; PR-542 adds the two stretch brokers called out in Phase 5.

## Scope

- `internal/infrastructure/jobqueue/` — shared job JSON envelope + retry backoff
- `internal/infrastructure/kafka/` — Kafka topic-based `jobs.Queue`
- `internal/infrastructure/sqs/` — SQS `jobs.Queue`
- `plugins/core/kafkaqueue/` — core plugin (`core/kafka-queue`)
- `plugins/core/sqsqueue/` — core plugin (`core/sqs-queue`)
- Config: `queue.kafka.*`, `queue.sqs.*`, env overlays, validation
- `plugins/core/register.go` — driver switch wiring
- Docs: PR spec, config example, C4 diagram

## Out Of Scope

- Managed topic/queue provisioning (operators create topics/queues ahead of boot)
- Exactly-once semantics beyond existing worker idempotency contract
- Replacing Postgres as default queue driver

## Config

```yaml
queue:
  driver: kafka   # or sqs
  kafka:
    brokers: ["localhost:9092"]
    topic_prefix: shopanda
  sqs:
    queue_url: https://sqs.us-east-1.amazonaws.com/123456789012/shopanda-jobs
    failed_queue_url: https://sqs.us-east-1.amazonaws.com/123456789012/shopanda-jobs-failed
    region: us-east-1
```

Environment fallbacks: `KAFKA_BROKERS`, `SQS_QUEUE_URL`, `AWS_REGION`.

## Validation

- `queue.driver=kafka` registers `core/kafka-queue` only
- `queue.driver=sqs` registers `core/sqs-queue` only
- `plugins.core.postgres_queue=true` still overrides alternate drivers
- `go test ./internal/infrastructure/jobqueue/... ./plugins/core/... ./internal/platform/config/...`
