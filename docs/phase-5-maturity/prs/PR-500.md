# PR-500 — Customer Groups Domain (Track A, B2B)

Status: done

## Summary

- Core `customergroup` domain port for B2B customer segmentation
- B2B plugin schema, Postgres repository, and admin HTTP API
- Plugin admin route registration mounted by the API server

## Why

Merchants need customer tiers (wholesale, VIP, regional buyers) before group-aware pricing (PR-501) and advanced promotion conditions. Groups live in the commercial B2B module; open core defines only the port contract.

## Scope

- `internal/domain/customergroup/` — `Group` entity + `Repository` port
- `plugins/b2b/migrations/001_create_customer_groups.sql` — `customer_groups`, `customer_group_members`
- `plugins/b2b/groups/` — Postgres repo + admin handler
- Permissions: `b2b.groups.read`, `b2b.groups.write` (Admin, Manager)
- Admin API:
  - `GET/POST /api/v1/admin/customer-groups`
  - `GET/PUT /api/v1/admin/customer-groups/{groupId}`
  - `GET/PUT/DELETE /api/v1/admin/customers/{customerId}/customer-group`
- `internal/platform/plugin` — `RegisterAdminRoute` / `AdminRoutes`; mounted in `cmd/api/main.go`
- Embedded plugin migrations via `migrate.RunFS`
- Tests: domain, admin handler (stub repos), plugin init, Postgres repo (integration when `SHOPANDA_TEST_DSN` set)

## Out Of Scope

- Group-aware pricing (PR-501)
- Storefront exposure of group membership
- Multi-group membership per customer (one group per customer in this PR)
- Admin UI screens (API only)

## Validation

- Enable B2B plugin with `DEV-*` license → startup logs customer groups registered
- `POST /api/v1/admin/customer-groups` creates a group; list returns it
- `PUT /api/v1/admin/customers/{id}/customer-group` assigns membership; GET returns group
- Manager role can read/write groups; customer JWT receives 403 on admin routes
