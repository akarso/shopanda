# PR-513 — Abandoned Cart Recovery (Track B, OSS)

Status: done

## Summary

- Hourly `cart.recovery` scheduled job scans stale signed-in customer carts
- Sends one recovery email per cart via existing `email.send` job queue
- Tracks sends with `recovery_email_sent_at` so carts are not re-emailed

## Why

Phase 4 deferred marketing automation. This PR adds minimal abandoned-cart recovery for authenticated customers without changing cart lifecycle semantics (carts stay active so shoppers can return to `/cart`).

## Scope

- `migrations/056_add_cart_recovery_email.sql` — `recovery_email_sent_at` + partial index
- `internal/domain/cart/cart.go` — recovery timestamp field
- `internal/domain/cart/repository.go` — `FindRecoveryCandidates`, `MarkRecoveryEmailSent`
- `internal/infrastructure/postgres/cart_repo.go` — query + mark-sent persistence
- `internal/application/cart/recovery_handler.go` — batch scan, template render, email enqueue
- `internal/application/notification/service.go` — `cart_recovery` email template
- `internal/platform/runtime/cart_recovery.go` — hourly cron registration
- `cmd/api/main.go` — worker handler + scheduler wiring
- `internal/application/cart/recovery_handler_test.go` — handler unit tests

## Out Of Scope

- Guest cart recovery
- Multiple recovery emails or drip campaigns
- Cart status transition to `abandoned`
- Admin UI for recovery settings (24h threshold is code default)
- SMS or push notifications

## Validation

- Active customer carts with items, `updated_at` ≥ 24h ago, and no prior send are candidates
- Guest carts and empty carts are excluded
- Recovery email includes item names, quantities, prices, and cart URL
- `MarkRecoveryEmailSent` is idempotent (second send skipped)
- Scheduler enqueues `cart.recovery` hourly; worker processes batch of up to 50 carts
- Inactive/disabled customers are skipped without failing the whole batch
