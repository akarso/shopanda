# PR-1042 — Cache Admin API + CLI

Status: done

## Summary

- `GET /api/v1/admin/cache/stats` (per cache-tier visibility — L1 vs L2, approximate key counts), `POST /api/v1/admin/cache/clear` (by prefix, tag, key, or all).
- CLI parity: `app cache:stats`, `cache:clear --prefix|--tag|--key|--all`.

## Why

There was no admin visibility into the cache at all — not stats, not manual clearing. This is the same gap Track A closed for jobs, applied to cache.

## Scope

- `internal/interfaces/http/admin/cache_admin.go` — `CacheAdminHandler`.
- `GET /admin/cache/stats` — per-backend approximate stats: Postgres via `SELECT count(*) FROM cache` (and `cache_tags` row count); Redis via `DBSIZE`/`INFO memory`; L1 reports entry count and hit/miss counters from the in-process store.
- `POST /admin/cache/clear` — body `{"prefix": "..."}` \| `{"tag": "..."}` \| `{"key": "..."}` \| `{"all": true}`. The `all` case is gated behind a **distinct** permission (`cache.clear_all`). Every clear is audit-logged with what was cleared.
- New `cache.read`/`cache.write`/`cache.clear_all` permissions (admin-only).
- CLI commands wrapping the same `cache.AdminService` the HTTP handler uses.

## Out Of Scope

- Real hit/miss rate tracking for L2 (Postgres/Redis) — L1 gets this cheaply (in-process counters). If this turns out to matter operationally, Track D's PR-1047 is the place for Prometheus-based L2 hit/miss.
- Cache admin GUI — PR-1043.

## What changed

- `internal/domain/cache/cache.go` — `Stats(ctx) (Stats, error)` and `FlushAll(ctx) (int64, error)` on the `Cache` port. A custom implementation must implement both (same contract as PR-1039's tag methods). Redis `FlushAll` is documented as prefix-scoped scan+DEL, never `FLUSHDB`.
- `internal/infrastructure/postgres/cache_store.go` — `Stats` (`COUNT(*)` of `cache` and `cache_tags` with a 1.5s cap, then `pg_class.reltuples`); `FlushAll` deletes both tables in one statement (can stall writers on a large UNLOGGED cache).
- `internal/infrastructure/redis/cache_store.go` — `Stats` (`DBSIZE` + `used_memory` from `INFO memory`); `FlushAll` `SCAN`s the store prefix and `DEL`s in batches. SCAN MATCH globs are escaped; a literal `HasPrefix` filter covers adapters that ignore backslash-escapes. Empty store prefix is refused. Returned `deleted` is value keys only. Test pins that a key outside the prefix survives (not `FLUSHDB`), glob prefixes stay literal, and empty prefix cannot delete foreign keys.
- `internal/infrastructure/localcache/store.go` — process-lifetime hit/miss counters on `Get`; `Snapshot()` for admin stats. `Clear` does not reset the counters.
- `internal/application/cache/admin.go` — `AdminService` shared by HTTP and CLI. `Clear` requires exactly one selector; empty/whitespace prefix/tag/key is treated as omitted so it cannot bypass `cache.clear_all`. `all` also clears registered L1 stores in this process; targeted clears do not.
- `internal/domain/rbac/{permission.go,catalog.go,role_permissions.go}` — `cache.read`/`cache.write`/`cache.clear_all`, admin-only.
- `migrations/079_backfill_cache_admin_permissions.sql` — inserts the three grants for `role='admin'` (`ON CONFLICT DO NOTHING`). Required because `role_permissions` is the source of truth after `InitEffectivePermissions` (same class of gap 075 closed).
- `internal/interfaces/http/admin/cache_admin.go` + `admin_middleware.go` (`RequireAnyPermission`) — stats behind `cache.read`; clear route behind write-or-clear_all, handler normalizes first (422) then requires `cache.clear_all` for `all` and `cache.write` for targeted. Successful HTTP stats are not audit-logged (polled).
- `cmd/api/{wire_services.go,wire_routes.go}` — wires `AdminService` with RBAC-catalog L1; storefront category-nav L1 is registered when `frontend.enabled` via `sfHandler` (not a package-shadowing local).
- `cmd/api/cache_cli.go` — `cache:stats` / `cache:clear`; bootstraps plugins so a redis cache driver actually resolves. `preparePermissionRegistry` / `freezePermissionRegistry` wrap `InitAll` (same as other CLI startup paths) so `plugins.example.enabled` can `RegisterPermission`. CLI has no L1 (separate process) and **no RBAC** (ops trust boundary, documented in RUNBOOK). `cache:clear` audit-logs with `AdminID` `cli:<os-user>`.
- `internal/interfaces/http/admin/dist/admin.js` — `cache.*` added to the admin role's client-side `adminRoleDefinitions()` so the roles editor matches compiled defaults (GUI for this API is PR-1043).
- `openapi.yaml` — `/admin/cache/stats`, `/admin/cache/clear`.

## Review follow-up

Code review of the first landing. Blockers and majors addressed in this same PR:

- Redis `DeleteByPrefix` escaped SCAN globs (`*`, `?`, `[`, `\`) and filters `HasPrefix` after SCAN so `{"prefix":"*"}` with `cache.write` cannot wipe the store.
- Redis `FlushAll` refuses empty prefix; config rejects empty `cache.redis.key_prefix` whenever `cache.driver=redis`. `TestLoad_CacheDriverEnvOverlay` sets `SHOPANDA_CACHE_REDIS_KEY_PREFIX` so env overlay still loads.
- Redis `FlushAll` returns value-key deletions counted by a Lua `DEL` (keys that expired between SCAN and DEL are not counted). Empty-prefix `DeleteByPrefix("")` is refused, matching `FlushAll`.
- Postgres stats: `COUNT(*)` with a per-store 1.5s timeout, `pg_class.reltuples` fallback; `l2.approximate` is true when the estimate is used. Tests set the timeout on the store instance (no package-wide mutation).
- `TestCacheStoreDB_StatsAndFlushAll` (skip without `SHOPANDA_TEST_DSN`). Per-store `SetStatsCountTimeout(store, 0)` pins `Approximate` without waiting 1.5s.
- HTTP tests for whitespace / `all:false` / glob prefix / 422-before-403; `RequireAnyPermission` grant/deny/guest.
- CLI `--all` documented as an RBAC bypass (ops trust boundary), not HTTP permission parity.
- Successful empty `FlushAll` still reports `deleted: 0` (omitted only when an error leaves the count unknown).
- Roadmap PR-1042 cell rewritten without `|` so the three-column table stays intact.
- RUNBOOK L1 remediation: HTTP `{"all": true}` clears L1 only in the handling API process; CLI cannot clear an API process's L1; other replicas wait on invalidation/TTL. Removed the outdated "no manual flush" claim.
