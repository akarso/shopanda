# PR-1043 — Cache Admin GUI

Status: done

## Summary

- Stats dashboard (per cache tier/type), manual clear form (prefix/tag/key/all) with a confirmation step before `all`.

## Why

Closes out Track C's admin-reachability requirement with an actual UI, matching PR-1031/PR-1038's pattern for the other two subsystems.

## Scope

- New "Cache" screen in the admin SPA: stats panel (L1 entry count, L2 approximate key count, tag count), clear form with a mode selector (prefix/tag/key/all) and a distinct, harder-to-misclick confirmation for `all` (type-to-confirm or a second explicit step, not just a single "Are you sure?" dialog — this is the single most destructive admin action shipped in this phase).
- Navigation entry alongside the jobs/schedules/search screens.

## Out Of Scope

- Nothing beyond PR-1042's API surface — UI only.

## What changed

The bundled admin SPA (`internal/interfaces/http/admin/dist/`) is hand-authored vanilla JS with no build step — same pattern as PR-1031/PR-1038.

- `internal/interfaces/http/admin/dist/cache_admin_ui.js` — clear-form helpers (`modeOptions`, `buildPayload` trims selectors, `bindClearForm`, `newStatsLoadGate`) shared by the SPA and Node tests.
- `internal/interfaces/http/admin/dist/admin.js`:
  - `renderCacheAdminPage` at `/admin/operations/cache` — L2 occupancy cards (backend, keys, tag rows, memory) plus an L1 table (name, entries, hits, misses). **Refresh stats** re-fetches `GET /admin/cache/stats`.
  - Clear form: mode selector filtered by `cache.write` (prefix/tag/key) and `cache.clear_all` (`all`). Targeted modes send a trimmed selector. `all` keeps **Clear** disabled until the operator types `CLEAR ALL`. After a successful full flush, `withButtonBusy`'s restore re-runs the confirm gate so Clear stays disabled. The whole form is locked for the request; busy state waits for stats refresh.
  - `refreshCacheNavVisibility()` hides the nav link without `cache.read`, called from `init()` and post-login (also calls `refreshSearchNavVisibility` after login, matching jobs).
- `internal/interfaces/http/admin/dist/index.html` — **Cache** under Operations; loads `cache_admin_ui.js` before `admin.js`.
- `internal/interfaces/http/admin/dist/admin.css` — `.cache-confirm-all` warning panel; `.badge-approximate`.
- `internal/interfaces/http/admin/cache_admin_ui_test.js` + `TestCacheAdminUI_Node` — DOM-level Node tests for permission-filtered modes, confirm gating, Enter-submit while disabled, the post-success disable invariant, and reverse-order stats-load completion.
- `docs/guides/MERCHANT.md` — Cache walkthrough + compiled-role permission limitation.
- `docs/guides/DEVELOPER.md` — GUI pointer, SPA vs DB-effective permission limitation, and Node 22 for `TestCacheAdminUI_Node`.

## Review follow-up

- **Blocker — fixed.** Successful `all` clear called `updateClearModeUI()` inside the busy promise, then `withButtonBusy` restore forced `submitBtn.disabled = false`. `withButtonBusy` now takes `afterRestore`; the confirm gate runs after restore. Node test: type `CLEAR ALL` → success → confirm cleared → submit disabled.
- **Major — tests.** Substring wiring remains, plus Node DOM-level tests (mode filter, confirm gate, Enter-submit, restore race, form lock, trim).
- **Major — SPA permissions.** Documented in MERCHANT.md and DEVELOPER.md: the screen uses compiled `adminRoleDefinitions()`, not DB-effective grants. Fixing that needs `/auth/me` permissions for the whole panel (same as jobs/search).
- **Major — trim.** GUI sends `String(value).trim()` for prefix/tag/key. CLI/API still pass literals (keys can contain spaces).
- **Major — form lock + stats.** Mode/value/confirm disabled for the request; `loadStats()` is returned from the clear path so busy covers refresh. Overlapping stats GETs ignore stale responses.
- **Minor — skipped.** Nav-link flash before JS permission refresh matches Jobs/Search; not unique to Cache.
- **Minor — fixed (round 3).** Guard if `ShopandaCacheAdminUI` is missing; MERCHANT refresh copy is approximate/replica lag only; UI scope note says "database"; form lock sets `aria-disabled` on mode/value/confirm.
- **Minor — fixed.** Confirm copy is not `role="alert"`; value/confirm both use `hidden`; targeted value cleared after success; approximate badge is not `badge-pending`; `aria-describedby` on the confirm input; non-array `l1` is an error, not an empty table.
- **Stale stats race — fixed.** `loadStats()` uses `newStatsLoadGate()` so an older in-flight GET cannot overwrite counts after a later refresh (including the post-clear refresh). Node test finishes two loads in reverse completion order.
- **Node in `go test ./...` — fixed.** `TestCacheAdminUI_Node` still requires `node` on `PATH`. Documented in `docs/guides/DEVELOPER.md`; CI unit job installs Node 22 via pinned `actions/setup-node@v7.0.0`.
