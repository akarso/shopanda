# PR-1045 — Fragment Mechanism (ESI-equivalent)

Status: done

## Summary

- App-level "hole" mechanism for customer-specific content in an otherwise-cacheable page: `{{fragment "name"}}` renders an htmx placeholder with a required skeleton; `/fragments/{name}` always returns `Cache-Control: no-store` and real per-request state.
- Documented as the ESI-equivalent for this architecture (no edge/CDN layer to resolve literal ESI).

## Why

Real ESI is resolved by an edge cache. Shopanda has none, so the equivalent effect is app-level: cached HTML (PR-1044) contains a placeholder; the browser (htmx) fetches live snippets after the shell loads.

## Scope

- Theme FuncMap accepts `{{fragment "name"}}` via `theme.WithFragment` (domain has no HTTP paths).
- Storefront adapter owns fragment URL map, skeletons, and htmx hole markup (`fragment_helper.go`); wired at serve boot.
- Fragment handlers in `internal/interfaces/http/storefront/fragment.go` (plus existing cart/search-suggest wrapped with `withFragmentCacheControl`):
  - Always `Cache-Control: no-store`.
  - `/fragments` added to Phase 10 `CacheControlMiddleware` denylist.
- **Shipped fragments:** CSRF token, personalized greeting, cart-count, mini-cart, recently viewed (cookie history + PDP recorder).
- **Wishlist:** N/A — default theme has no wishlist UI (noted in DEVELOPER.md).
- Default theme `_header.html` / `product.html` use fragments when `Layout.UseFragments` is set (FPC cacheable chrome) and keep SSR tokens/names when FPC is off.
- Cacheable layouts keep logout URL for signed-in shoppers; empty CSRF skeleton + fragment load the real token. `/fragments/csrf` **mints** the cookie when missing. FPC requires `hx-get="/fragments/csrf"` **inside** each logout form (not a path string elsewhere). Recently-viewed only records/renders `StatusActive` products. Unknown-name warnings are per helper instance (`FragmentTemplateFunc(devWarn)`), not process-global.

## Out Of Scope

- Server-side fragment caching.
- Plugin-registerable fragment extension point.
- Flipping `cache.full_page.enabled` default to true (still false; safe to opt in with the default theme).
