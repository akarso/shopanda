# PR-1047 — Observability + Rollup

Status: done

## Summary

- Full-page cache hit/miss/bypass Prometheus counters, miss render histogram, and purge counters (bounded labels).
- Process-local `FPCObserver` exposed on `GET /admin/cache/stats` (`fpc`) and rendered on the Cache admin GUI.
- RUNBOOK.md incident-response entries for low hit rate, never-cached pages, and stale-despite-purge.

## Why

Track D was correct-by-design but invisible in production. Operators need the same observability pass Phase 10 applied to HTTP/checkout/jobs, applied to full-page cache.

## Scope

- Metrics (via `metrics.Recorder` + `FPCObserver`):
  - `shopanda_fpc_requests_total{route,outcome}` — `hit` / `miss` / `bypass` (terminal disposition only)
  - `shopanda_fpc_render_duration_seconds{route}` — miss render histogram
  - `shopanda_fpc_purge_total{trigger}` — keys deleted for `tag_invalidation` / `manual_url` / `unknown` (soft-TTL is delete+miss, not a purge)
  - `shopanda_fpc_backend_get_errors_total` — cache backend Get failures (≤1 per request; also process-local `backend_get_errors`)
- Admin: `Snapshot.FPC` on cache stats; Cache GUI “Full-page cache” section (hit rate = hits/(hits+misses), pages_stored estimate, purge key counts). Serve GUI notes worker-bus tag purges.
- RUNBOOK + MERCHANT updates.

## Out Of Scope

- Grafana dashboards / alerting rules (Phase 10 precedent: example PromQL only).
- Cluster-wide admin stats (process-local counters + Prometheus scrape per instance).
