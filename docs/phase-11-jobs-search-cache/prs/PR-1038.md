# PR-1038 — Search Admin GUI

Status: planned

## Summary

- Reindex trigger screen: scope picker (all / products / categories / since-date), progress bar, run history table.
- Per-row "reindex now" action on the product and category admin grids.

## Why

Closes out Track B's "admin API to trigger and progress endpoint" and "manual mode: reindex this one now" requirements with an actual UI, not just curl.

## Scope

- New "Search" screen in the admin SPA: scope picker form → `POST /admin/search/reindex` (PR-1035) → for the bulk path, a progress bar polling `GET /admin/search/reindex/{runID}` until terminal; for the synchronous single-item path, an inline success/failure result with no polling.
- Run history table: past `search_index_runs` rows (scope, counts, duration, status) — read-only, no action needed beyond viewing.
- Product admin grid and category admin grid each get a row-level "Reindex now" action, calling the same synchronous single-item endpoint PR-1035 exposes.
- Navigation entry alongside PR-1031's jobs/schedules entries.

## Out Of Scope

- Anything not already covered by PR-1035's API surface — this PR is UI only, no new backend behavior.

## Validation (planned — run when implementing)

- Manual QA: trigger each scope type, confirm progress bar reflects real counts (seed a large-enough product set that progress is visibly incremental, not instant), confirm per-row "reindex now" on both product and category grids.
