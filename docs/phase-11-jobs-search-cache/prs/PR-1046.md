# PR-1046 — Invalidation Wiring + Stampede Guard

Status: done

## Summary

- Event subscribers call `DeleteByTag` for product / category / page tags when catalog, price, stock, or CMS page events fire — every cached page that rendered the entity is purged.
- Admin/CLI purge-by-URL escape hatch deletes concrete FPC keys across store × auth vary dimensions.
- Process-local per-key miss coalescing so a popular invalidated page is re-rendered once under concurrent load (bounded wait, then render-anyway).

## Why

PR-1044 writes tags; without this PR a price change leaves every tagged page stale until TTL. Separately, concurrent misses after invalidation can stampede the origin. Both ship together.

## Scope

**Invalidation wiring:**
- `internal/application/cache/fpc_invalidation.go` — same shape as the existing prefix-based `InvalidationSubscriber` / search index subscriber (lives in application, not HTTP: domain events → `cache.Cache`, no HTTP logic). Async `bus.OnAsync`.
- Events: `catalog.EventProductCreated/Updated`, `pricing.EventPriceUpserted`, `inventory.EventStockUpdated`, `catalog.EventCategoryCreated/Updated/Deleted`, `cms.EventPageCreated/Updated/Deleted`.
- Tags: `product:{id}`, `category:{id}`, `page:{id}` (matching what storefront writes). Content-block-only edits have no domain event — N/A until one exists; operators use purge-url / tag clear.

**Escape hatch:**
- `POST /api/v1/admin/cache/purge-url` `{"path":"/products/…"}` — `cache.purge_url` permission (admin-only by default).
- CLI: `app cache:purge-url <path>`.

**Stampede guard:**
- `MissCoalescer` in `application/cache` — process-local; first miss renders, waiters block up to `DefaultStampedeWait` (2s) then render-anyway. Panic-safe (`defer` close/map delete). Waiters never replay leader BYPASS/raw CSP; they HIT with nonce rotation or re-render locally. Documented: cross-instance locking is out of scope.

## Out Of Scope

- Cross-instance distributed stampede locks.
- Predictive cache warming.
- Content-block domain events (none today — `cms:` tags need manual/tag clear).
