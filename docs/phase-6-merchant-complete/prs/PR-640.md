# PR-640 — Product Reviews Admin UI (Track E, OSS stretch)

Status: done

## Summary

- Admin list and moderate product reviews
- Approve or reject pending reviews from Catalog → Reviews

## Why

Reviews exist via API (PR-514), but merchants need moderation without database access.

## Scope

- `admin.js` — `/admin/catalog/reviews` moderation grid
- Product edit **Reviews** panel with summary + link to filtered moderation view
- Wire existing review admin API (`GET /admin/reviews`, `POST .../approve`, `POST .../reject`)
- `products.read` to view; `products.write` to approve/reject

## Out Of Scope

- Review submission on storefront (REST submit already exists)
- Fake review import
- Syndication to Google
- Backend API changes

## Validation

- Pending review appears in admin; approve makes it visible on PDP
- Reject hides review from storefront
- Product edit shows review summary and link to product-filtered moderation list
- `go test ./internal/interfaces/http -run TestAdminHandler_StaticJS -count=1`

## What changed

- Catalog → **Reviews** nav link and `/admin/catalog/reviews` route
- Status filter (pending / approved / rejected / all) with paginated grid
- Approve and reject actions for pending reviews; status badges and storefront visibility hints
- Product edit **Reviews** panel: counts, preview table, link to `?product={id}` filtered view
- `admin_handler_test.go` — reviews wiring and nav assertions
