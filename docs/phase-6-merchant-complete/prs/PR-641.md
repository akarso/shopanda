# PR-641 — Abandoned Cart Settings Admin UI (Track E, OSS stretch)

Status: done

## Summary

- Marketing → Abandoned Cart settings screen for enable/disable and delay hours
- Wire config-backed recovery settings so the hourly worker respects merchant choices

## Why

Recovery emails run via scheduler (PR-513), but merchants could not tune delay or toggle without editing config YAML.

## Scope

- `admin.js` — `/admin/marketing/abandoned-cart` settings form
- Config admin `marketing` group keys: `marketing.cart_recovery.enabled`, `marketing.cart_recovery.delay_hours`
- Recovery handler loads settings from `config.Repository` at job run time

## Out Of Scope

- Cart contents preview per abandonment
- SMS recovery
- A/B testing
- Live email template preview (link to Settings → General for SMTP)

## Validation

- Disable recovery; worker skips with `cart.recovery.skipped` and no emails enqueued
- Change delay; next scheduled run uses configured stale threshold
- `go test ./internal/application/cart/... ./internal/interfaces/http/... -count=1`

## What changed

- **Backend:** `recovery_settings.go` — load enabled + delay from config (defaults: enabled, 24h)
- **Backend:** `recovery_handler.go` — respects settings; skips when disabled
- **Backend:** `config_admin.go` — `marketing` config group with validation (delay 1–720)
- **Backend:** `cmd/api/main.go` — pass `configRepo` as recovery handler `Settings`
- **Admin UI:** Marketing → **Abandoned Cart** nav link and settings form
- Tests: recovery handler skip-when-disabled, config admin marketing group GET/PUT
