# PR-620 — Webhook Endpoints Admin UI (Track C, OSS)

Status: done

## Summary

- Full webhook endpoint CRUD on Integrations (replace API-only hint)
- Wire PR-540 webhook admin API

## Why

Integrations showed endpoint count and pointed merchants to curl. Integrators expect a settings screen for URL, events, active flag, and one-time secret.

## Scope

- `admin.js` — webhook section on `/admin/integrations` + dedicated CRUD routes
- Gate all webhook admin calls with Settings permissions (PR-540 / `cmd/api/main.go`):
  - Read: `GET /api/v1/admin/webhooks/events`, `GET /api/v1/admin/webhooks`, `GET /api/v1/admin/webhooks/{id}` (`settings.read`)
  - Write: `POST /api/v1/admin/webhooks`, `PUT /api/v1/admin/webhooks/{id}`, `DELETE /api/v1/admin/webhooks/{id}` (`settings.write`)
- List/create/edit/delete endpoints
- Event subscription checkboxes from `GET /api/v1/admin/webhooks/events`
- Display secret once on create/rotate

## Out Of Scope

- Delivery log/history
- Test delivery button (stretch follow-up)
- Per-store webhook scoping

## Validation

- Create HTTPS endpoint subscribed to `order.paid`; secret shown once
- User without `settings.write` cannot create/edit/delete; without `settings.read` cannot list
- Disable endpoint; deliveries skip inactive endpoints (existing behavior)
- Delete endpoint removes from list

## What changed

- Integrations page links to **Manage webhooks** (replaces curl/API hint)
- `/admin/integrations/webhooks` — endpoint list grid
- `/admin/integrations/webhooks/new` — create form with event checkboxes
- `/admin/integrations/webhooks/{id}` — edit, rotate secret, delete
- One-time signing secret banner on create and when `rotate_secret` is checked
- `admin_handler_test.go` — webhook CRUD wiring assertions
