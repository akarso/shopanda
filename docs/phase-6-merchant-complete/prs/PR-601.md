# PR-601 — Content Blocks Admin UI (Track A, OSS)

Status: done

## Summary

- Replace Content → Blocks placeholder with block list and create/edit forms
- Wire PR-512 admin content-block CRUD API

## Why

PR-512 shipped block types and storefront SSR rendering, but admin shows `renderPlaceholder("Blocks")`. Merchants cannot create hero/rich-text/carousel blocks from the UI.

## Scope

- `admin.js` — `/admin/content/blocks` grid + create/edit routes
- Full CRUD against PR-512 admin content-block API:
  - `GET /api/v1/admin/content-blocks` — grid list (`content.read`)
  - `GET /api/v1/admin/content-blocks/{id}` — edit form load (`content.read`)
  - `POST /api/v1/admin/content-blocks` — create (`content.write`)
  - `PUT /api/v1/admin/content-blocks/{id}` — update (`content.write`)
  - `DELETE /api/v1/admin/content-blocks/{id}` — delete (`content.write`)
- Forms per block type with validated config fields (title, body, product IDs, etc.)

## Out Of Scope

- Block placement on home/pages (PR-602)
- Rich HTML WYSIWYG (plain text fields match API)
- Block translations

## Validation

- Create hero, rich_text, and product_carousel blocks
- Edit and delete blocks from grid
- Invalid config shows API validation message
- Blocks route no longer uses placeholder

## What changed

- `/admin/content/blocks` lists blocks from `GET /admin/content-blocks` (title, type, status, updated)
- `/admin/content/blocks/new` creates blocks with type-specific config forms
- `/admin/content/blocks/{id}` edits title, config, and active flag; delete via `DELETE /admin/content-blocks/{id}`
- Block types: `hero` (headline, subheadline, CTA, image URL), `rich_text` (body), `product_carousel` (title, product IDs)
- `admin_handler_test.go` asserts content blocks route and CRUD wiring strings
