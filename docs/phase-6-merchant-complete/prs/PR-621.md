# PR-621 — Order Invoice Admin UI (Track C, OSS)

Status: planned

## Summary

- Order detail: list invoices and download/open PDF when available
- Add thin admin HTTP wiring for invoice metadata + PDF download (no new invoicing domain; routes do not exist today)

## Why

MERCHANT.md states invoices are email-first with no admin viewer. Support teams need PDF access from the order screen. Invoices are persisted via `invoice.InvoiceRepository` and PDFs stored at `invoices/{invoiceId}/invoice-{number}.pdf`, but `cmd/api/main.go` has no admin invoice routes yet despite `invoices.read` in RBAC.

## Scope

- `internal/interfaces/http/` — minimal admin invoice handlers (list + PDF stream) wired in `cmd/api/main.go`
- `admin.js` — invoices panel on order detail
- **List (metadata):** `GET /api/v1/admin/orders/{orderId}/invoices` — invoice id, number, created_at (`invoices.read`)
- **Download:** `GET /api/v1/admin/invoices/{invoiceId}/pdf` — admin-proxied PDF bytes (`Content-Type: application/pdf`); load from storage path or re-render via `invoicepdf.Renderer`; do not expose raw storage URLs or presigned S3 links to the browser
- Hide panel when user lacks `invoices.read`; empty state when order has no invoice

## Out Of Scope

- Regenerate invoice from admin
- Credit note editor
- Peppol/e-invoice dispatch

## Validation

- Paid order with invoice shows download link via admin PDF route
- PDF opens or downloads successfully through admin-proxied endpoint (not direct storage URL)
- Orders without invoice show clear empty state
- User without `invoices.read` sees forbidden state
