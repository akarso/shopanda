# PR-622 — Refund UX Polish (Track C, OSS)

Status: planned

## Summary

- Improve order refund button UX: provider hints, errors, confirmation copy
- No new payment domain — polish existing admin refund action

## Why

Refund exists on order detail for Stripe-capable deployments, but messaging is opaque when provider lacks refund support or API errors occur.

## Scope

- `admin.js` — refund panel improvements on order detail
- Show when refunds unavailable (manual pay, missing provider)
- Surface API error messages; confirm full vs partial where supported

## Out Of Scope

- New payment providers
- Partial refund domain model changes (if still unsupported, say so clearly)
- Refund history grid (transactions page covers read-only ledger)

## Validation

- Stripe order: refund succeeds with clear confirmation
- Manual-pay order: refund action hidden or disabled with explanation
- Failed refund shows server error without silent failure
