# PR-622 — Refund UX Polish (Track C, OSS)

Status: done

## Summary

- Improve order refund button UX: provider hints, errors, confirmation copy
- No new payment domain — polish existing admin refund action

## Why

Refund exists on order detail for Stripe-capable deployments, but messaging is opaque when provider lacks refund support or API errors occur.

## Scope

- `admin.js` — refund panel improvements on order detail
- Gate refund actions on `orders.write` (matches `POST /api/v1/admin/orders/{orderId}/refund` in `cmd/api/main.go`)
- Detect refund capability before showing actions: Stripe refunder registered (route exists), payment `status=completed`, `method=stripe`, and order `status=paid`; hide with explanation for manual pay, missing provider, or non-refundable payment state
- Full refund only — backend rejects partial amounts (`refund.go`: amount must equal payment total); do not show partial amount input
- Surface API error messages; confirm before issuing full refund

## Out Of Scope

- New payment providers
- Partial refunds (domain and API remain full-refund-only)
- Refund history grid (transactions page covers read-only ledger)

## Validation

- Stripe paid order with `orders.write`: full refund succeeds with clear confirmation
- Manual-pay or non-Stripe order: refund action hidden or disabled with explanation
- Partial amount rejected by API if attempted; UI does not offer partial refund
- Failed refund shows server error without silent failure

## What changed

- Order detail **Payment & Refund** panel loads payment from transaction ledger and evaluates eligibility
- `probeRefundRoute` detects whether `POST /admin/orders/{id}/refund` is registered (Stripe refund handler)
- Explanatory copy for manual pay, missing payment, non-Stripe, non-completed, already refunded, missing provider ref, and missing `orders.write`
- **Issue full refund** button with confirmation dialog; posts full payment amount (no partial input)
- API errors surfaced in-panel; success message and panel refresh after refund
- `userHasPermission` helper for client-side `orders.write` gating
- `admin_handler_test.go` — refund panel wiring assertions
