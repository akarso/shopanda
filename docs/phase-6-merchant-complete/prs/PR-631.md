# PR-631 — Product Category Picker UX (Track D, OSS stretch)

Status: done

## Summary

- Replace dropdown/paged category assignment on product edit with a searchable tree picker
- Toggle checkboxes to assign or remove categories immediately

## Why

Categories have a full admin tree (Phase 4+), but the product form used a flat dropdown with separate paging for available and assigned lists — confusing for multi-category products.

## Scope

- `admin.js` — product form category tree picker with checkboxes
- Wire existing `POST/DELETE /admin/categories/{id}/products/{productId}` assignment API
- `categories.write` gates checkbox edits; read-only users see disabled tree

## Out Of Scope

- Category merge/split tools
- Collection assignment (if separate concept)

## Validation

- Assign product to multiple categories from product edit without CSV
- Selected categories persist on reload (checkboxes reflect `category_ids`)
- Search filters tree while preserving parent nodes for matches
- `go test ./internal/interfaces/http -run TestAdminHandler_StaticJS -count=1`

## What changed

- Product edit **Categories** panel: hierarchical checkbox tree instead of dropdown + paged tables
- `filterCategoryTreeForSearch` prunes tree by name/slug while keeping ancestor paths
- Immediate save on toggle; assigned count updates in place
- `categories.write` permission gating for checkbox edits
- `admin.css` — `admin-tree-list` and `product-category-picker` styles
- `admin_handler_test.go` — tree picker wiring assertions
