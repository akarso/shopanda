# PR-651 — No Placeholder Nav Policy (Track F, OSS)

Status: planned

## Summary

- Enforce: admin nav items must not route to `renderPlaceholder` for shipped APIs
- Hide or gate nav until UI PR lands; add regression guard

## Why

Phase 5 delivered many admin APIs without UI, leaving placeholder screens that look broken to merchants. Phase 6 closes the gap; this PR prevents regression.

## Scope

- Audit `admin.js` routes vs sidebar nav; remove or hide entries without real screens
- Optional test: assert no placeholder render for linked nav paths (or allowlist during migration)
- Document rule in `DEVELOPER.md` or `FRONTEND.md`

## Out Of Scope

- Rewriting admin SPA framework
- Feature flags per nav item (unless already present)

## Validation

- Sidebar click never lands on generic “coming soon” for a shipped backend feature
- New API-only features require explicit “hidden until UI” in PR checklist
- CI or test documents placeholder allowlist (empty at phase end)
