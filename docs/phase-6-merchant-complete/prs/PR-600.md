# PR-600 — Navigation Builder Admin UI (Track A, OSS)

Status: done

## Summary

- Replace Content → Navigation placeholder with a working menu editor
- Wire existing PR-511 admin menu API (`GET/PUT /api/v1/admin/menus/{id}`)

## Why

PR-511 shipped DB-backed menus and storefront rendering, but admin still shows `renderPlaceholder("Navigation")`. Merchants expect to edit header/footer links without curl or theme YAML.

## Scope

- `internal/interfaces/http/admin/dist/admin.js` — `/admin/content/navigation` list + edit
- Load header/footer menus; nested item editor (label, link type, target)
- Save via existing menu admin API; surface validation errors from API
- `internal/interfaces/http/admin_handler_test.go` — route/wiring assertions as needed

## Out Of Scope

- Footer theme rendering changes (already seeded; storefront header is live)
- Drag-and-drop ordering beyond API array order
- Multi-store menu scoping
- New backend routes

## Validation

- Content → Navigation lists menus (header, footer)
- Edit header: add nested item linking to category, page, and custom URL
- Save persists; storefront header reflects changes after reload
- Invalid parent/cycle shows API error in UI
- No `renderPlaceholder` for Navigation route

## What changed

- `/admin/content/navigation` lists menus from `GET /admin/menus` (title, code, status, updated)
- `/admin/content/navigation/{id}` edits menu title, active flag, and flat item list
- Item editor: label, link type (`url` / `category` / `page`), target picker, parent, position, active, add/remove
- Save via `PUT /admin/menus/{id}`; API validation errors shown in form message area
- `admin_handler_test.go` asserts navigation route and CRUD wiring strings
