# PR-1213 — Admin email-template API

Status: done

## Summary

- List / get / put / delete / preview / test-send under `/api/v1/admin/email-templates`.
- PUT validates parse + sample execute (reject CR/LF subjects) before Upsert so bad rows cannot break production sends; real admin actor required (not `"system"`).
- Test-send is overridable-only, mailbox-validated, `[TEST]`-prefixed, deadline + per-admin rate limit (`rate_limited`/429, stamped after validation).
- Preview/test-send report `source` / `resolved_locale` / `fallback`; `exact=1` matches GET’s exact-locale lookup.
- List uses `ListMetaByStore` (no subject/body); `source=db` when any allowlisted locale row exists.
- Cart-recovery sample includes `Price` for the builtin body as well as file fields.

## Why

UI needs a contract. Preview must not send. Editors with `content.write` must not be able to brick order/recovery mail or relay auth templates.

## Scope

- Admin routes + Content RBAC.
- Raw subject/body retained on `mail.Templates` (`builtin` / `file` origin) for GET without a DB row.
- Revert (DELETE) removes DB row only; allowlist enforced on DELETE.
- `ValidateRenderable`, `WithExactLocale`, `RenderResult` metadata, `ListMetaByStore`, `PutParsed` clears stale sources.
- Tests: broken PUT leaves no row; auth/claim test-send does not call Send; GET vs preview locale; cart-recovery sample fields; invalid `to` / nil mailer; preview decode 422.

## Out Of Scope

- Admin SPA (PR-1214).
- WYSIWYG.
- Unsaved-draft preview body in the request.
- Dedicated `email_templates.*` permissions.
- Constraining links inside overridable HTML bodies (editor can still rewrite payment/cart URLs in those four templates).
