# PR-1202 — Persistence + admin/public API

Status: done

## Summary

- Migration `117` for `store_identities`, `store_addresses`, `store_tax_identifiers` with length/token CHECKs.
- Postgres `StoreIdentityRepo` + `storeidentity.Service` (placeholders, invoice/returns read fallbacks).
- Admin REST per [`STORE_IDENTITY.md`](../specs/STORE_IDENTITY.md) §4 (`SettingsRead` / `SettingsWrite`); partial PUT + audit.
- Public `GET /api/v1/store/identity` (imprint-safe tax IDs only; `private, no-store` + `Vary: Host`).
- Backfill: scoped `store::{id}::store.address` then bare `store.address`; `UK`→`GB`; skip invalid rows.

## Why

Merchants and storefronts need a single read/write path. Headless cannot scrape admin config keys.

## Scope

- Store-scoped CRUD; unique `(store_id, address.role)`, `(store_id, tax type)`.
- Empty address roles returned as placeholders (`persisted: false`).
- Invoice address fallback is a read helper (invoice → general), not a silent write.
- Tax upsert validates type against the in-process registry (PR-1201).
- RBAC aligned with store/config update (`settings.read` / `settings.write`).
- Tests: bare+scoped backfill, UK country, skip newline/over-long, invoice fallback, partial PUT, unknown role 422, public cache headers + tax filter.

## Out Of Scope

- Admin SPA pages (PR-1203–1204).
- Invoice PDF / email / footer consume (PR-1205).
- Per-type `Public` flag on the registry (hardcoded imprint allowlist for now).
