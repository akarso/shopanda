# PR-1205 — Invoice, email, storefront consumers

Status: done

## Summary

- Invoice PDF seller block sealed at issue time (`seller_snapshot` JSONB); re-render and email attach use that snapshot (or the stored PDF), never live identity.
- `order.paid` → `invoice.Service.HandleOrderPaid` → `GenerateFromOrder` (wired in `cmd/api`); seals snapshot, stores PDF, publishes `invoice.created`.
- Leftover row is not success: `ensureIssued` stores a missing PDF and re-publishes `invoice.created`.
- `SavePreparing` renders before commit so a layout failure rolls the insert back. Transient storage failure after commit still uses `ensureIssued`.
- Tall item names/SKUs split across pages (no permanent render error). Header+row space is reserved together.
- Failed `email.send` heal replaces the job payload (fresh PDF) and resets attempts under the stable id (`ReplaceFailed`).
- S3 `Read`/`Head`; `pdfStored` prefers `Head`; never treats “cannot probe” as missing.
- Notification `EmailData` brand fields from identity; cart recovery brands once per scan.
- Storefront layout struct carries imprint fields for PR-1231; SSR does not query identity until the footer template exists.
- Invoice tax lines are VAT-style only (`InvoiceSellerTaxType` = imprint allowlist).

## Why

Identity that nothing prints is inventory, not a product. A tax document that reprints today’s legal name tomorrow is worse. A seal that nothing calls is dead code. Acking “row exists” without a PDF or email leaves the shopper unpaid in paper.

## Scope

- `seller_snapshot` on `invoices`; `invoice.Service` seals before Save/PDF; wired on `order.paid`.
- `SavePreparing` + post-commit storage; conflict / `order_id` UNIQUE → `ensureIssued`.
- Invoice email: stable job id, dedupe, `ReplaceFailed` with fresh payload.
- S3 `Read`/`Head`; multi-page item rows; full DejaVu LICENSE.
- All `EmailData` construction sites; recovery brand cache.
- Layout field types on `StorefrontLayoutData` (render in PR-1231).
- Tests: repair path; Save conflict; delete failure; page-break rows; Polish seller; seal; VAT-filter.

## Out Of Scope

- Theme HTML rewrite (PR-1223 / PR-1231).
- Changing GPSR fields.
- Per-order `store_id` (still FindDefault until orders carry store scope).
- Holding the DB transaction open across object-store I/O.
