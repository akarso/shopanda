# PR-1205 — Invoice, email, storefront consumers

Status: done

## Summary

- Invoice PDF seller block sealed at issue time (`seller_snapshot` JSONB); re-render and email attach use that snapshot (or the stored PDF), never live identity.
- UTF-8 DejaVu font embedded; Polish legal names/streets extract correctly from content streams.
- Notification `EmailData` brand fields from identity; cart recovery brands once per scan.
- Storefront layout struct carries imprint fields for PR-1231; SSR does not query identity until the footer template exists.
- Invoice tax lines are VAT-style only (`InvoiceSellerTaxType` = imprint allowlist).

## Why

Identity that nothing prints is inventory, not a product. A tax document that reprints today’s legal name tomorrow is worse.

## Scope

- `seller_snapshot` on `invoices`; `invoice.Service` seals before Save/PDF.
- `invoicepdf` UTF-8 font + wrapped seller lines; compression on.
- All `EmailData` construction sites; recovery brand cache.
- Layout field types on `StorefrontLayoutData` (render in PR-1231).
- Tests: Polish seller extraction; invoice address over general; sales→general email; VAT-only tax filter.

## Out Of Scope

- Theme HTML rewrite (PR-1223 / PR-1231).
- Changing GPSR fields.
- Per-order `store_id` (still FindDefault until orders carry store scope).
- HTTP “generate invoice” admin surface (service is constructed with seller loader for when that lands).
