# PR-1200 — Identity domain

Status: planned

## Summary

- Add `Identity`, `Address` (four roles), and `TaxIdentifier` in `internal/domain/store` (or a sibling `storeidentity` package if `store` would bloat).
- Constructors validate role, ISO country on addresses, non-empty type/value on tax IDs.
- No postgres, no HTTP.

## Why

Store Information cannot be more config strings. Invoices and imprint need typed legal name, addresses, and tax IDs.

## Scope

- Domain types + unit tests for normalize/validate.
- Address roles: `general`, `invoice`, `shipping_origin`, `returns`.
- Contact emails: general / sales / support (format check only).

## Out Of Scope

- Registry of tax ID types (PR-1201).
- Persistence and API (PR-1202).
