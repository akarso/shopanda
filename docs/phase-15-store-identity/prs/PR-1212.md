# PR-1212 — DB template store

Status: done

## Summary

- Add `email_templates` table (store, name, locale, subject, body).
- Render-time resolution: DB exact locale → DB empty locale (store default language) → file/builtin registry from boot.
- Wire overrides into notification, cart recovery, and guest order-claim send paths.
- No admin HTTP (PR-1213).

## Why

Merchant overrides must survive deploys. Files stay the shipped default.

## Scope

- Migration `119_create_email_templates.sql`.
- Domain `EmailTemplate` + repository + `RenderWithOverrides`.
- Postgres adapter; serve + worker wiring.
- CR hardening: fail closed on `FindDefault` when overrides are wired; primary-subtag locale (never synthetic `en`); subject `text/template`; overridable-name allowlist (auth/token templates stay file-only); claim skips fixed English `text/plain` when HTML comes from DB; recovery fails (does not mark sent) on locale/store lookup error; request language preferred for claim; `updated_at = now()` on conflict; shared store+locale resolve helper.
- Tests: override wins; locale chain; FindDefault error leaves queue empty; subject keeps `&`; claim `de` override omits English text; recovery locale fail; `updated_at` advances.

## Out Of Scope

- HTTP admin API (PR-1213).
- Preview sample data.
- Public plugin `extapi` template APIs.
- Caching override misses (correctness first).
