# PR-1568 — NoCache prefix cuts at path `{` params

Status: done

## Summary

`NoCachePathPrefixes` / `pathPrefixFromPattern` cut the ServeMux pattern at
the first `{` and trim a trailing `/`, so `GET /api/x/{id}` yields `/api/x`
and `CacheControlMiddleware` can match real request paths. The denylist is
prefix-based — siblings under that prefix also get no-store. `RegisterPublicRoute`
rejects `NoCache` when a `{` cut leaves an empty or single-segment prefix
(`/{id}`, `/api/{v}/x` → `/api`, `/webhook/{id}` → `/webhook`). Fully static
one-segment mounts (`GET /customizer`) are allowed.

## Scope

- `pathPrefixFromPattern` brace cut + trim
- Registration validation: reject only when brace cut shortens to empty/1-seg
- Unit + middleware cases for `/api/x/123` after cut; accept static `/customizer`
- ROADMAP follow-up → done

## Out of scope

- Pattern-aware CacheControlMiddleware (static prefix only)
- No C4 change — prefix string only
