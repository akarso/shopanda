# PR-1552 — Migrate demos; ImportBoundary pkg-only

Status: done

## Summary

Tightened `plugins/plugin_imports_test.go`'s `TestImportBoundary` so the only allowed shared
import prefix for non-core plugins is `modulePath + "/pkg/"` (removed `internal/domain`,
`internal/application`, `internal/platform` from the allowlist). `plugins/core/*` stays exempt
(`SkipDir`) since it implements the driver adapters the SDK itself wraps.

Every plugin under `plugins/` — all demo/reference plugins and the commercial `plugins/b2b/`
module — now implements `pluginsdk.Plugin` (`Init(h pluginsdk.Host) error`) instead of the
core-internal `plugin.Plugin` (`Init(app *plugin.App) error`), and is registered via
`registry.Register(pluginsdk.Adapt(x.New()))` in `cmd/api/register_plugins.go`. No plugin under
`plugins/` (excluding `plugins/core/*`) imports `internal/*` in non-test code anymore.

## Plugins migrated

`sitekit`, `warehousedemo`, `integrationdemo`, `importdemo`, `exportdemo`, `maildemo`, `taxdemo`,
`slotsdemo`, `promodemo`, `pimdemo`, `cartdemo`, `checkoutdemo`, `example`, and `b2b`
(`b2b/groups`, `b2b/pricing`).

## `pluginsdk` / `extapi` additions needed to unblock the migration

- **`pluginsdk.Host`**: `RegisterTaxCalculator`, `RegisterMailSender`, `RegisterConfig`,
  `Slots(registrant) SlotsAPI`, `Customers() (CustomerPort, bool)`,
  `IntegrationOrderStatusUpdater()` / `IntegrationShipmentStatusUpdater()` /
  `IntegrationStockSyncer()`, `ConfigValue` / `ConfigBool` / `ConfigInt` / `ConfigInt64`,
  `BootstrapDB() (*sql.DB, bool)`.
- **`extapi`**: `TaxCalculator` / `TaxRate` / `TaxMode` / `CalculateTax` (bit-for-bit reimplementation
  of `internal/domain/tax.Calculate`), `MailSender` / `MailMessage` / `MailAttachment`,
  `ConfigField` / `ConfigDefinition` (closures own plugin state directly, no `*config.Config`
  parameter), `CartView` / `CartLineView`, `CustomerView`, `EventOrderCreated`,
  `PricingContext.AddItemAdjustment` / `SetItemPrice` (needed by `taxdemo` inclusive-tax rebasing
  and `b2b`'s group-price override).
- **`pluginsdk.CustomerPort`** / `NewCustomerPort`, plus `plugin.CapCustomers` /
  `BindCustomerPort` / `CustomerPort()` in `internal/platform/plugin/service_ports.go` and
  `bindProductPorts` in `cmd/api/plugin_ports.go` — mirrors the existing Catalog/Orders port
  pattern.
- **`pluginsdk.Migrator`** / `MigrationSpec` / `ApplyMigrationFS` wrapping
  `internal/platform/migrate.RunPluginFSOptions`, so Migrator plugins (`sitekit`, `b2b`) don't
  import `internal/platform/migrate` for their integration-test helpers.
- **`pluginsdk.SDK.CLI()`** / `CLICommand` / `CLIContext` wrapping `internal/platform/cli.Command`
  (used by `example`).
- **`pluginsdk.JSON` / `JSONError` / `ParsePagination` / `AdminCurrencyScope` /
  `AdminStoreScope` / `ValidationError` / `NotFoundError` / `ConflictError` / `InternalError`**
  wrapping `internal/platform/httpx` + `internal/platform/apperror` + `internal/application/admin`
  — needed by `b2b`'s admin HTTP handlers.
- **Hook payload fix**: the `"cart"` hook context value changed from the internal `*domain/cart.Cart`
  to the public `*extapi.CartView` (`internal/application/cart/{hooks,service,validation}.go`),
  since plugin hook handlers (e.g. `cartdemo`'s min-quantity validator) must not type-assert an
  internal type.
- **Config secret-redaction fix**: `internal/platform/config.flatten` was refactored into
  `flattenWith(cfg, redact func(string) string)`. The existing (redacting) `flatten()` stays
  unchanged for admin-display / `Get`; the new exported `Flatten()` uses an identity redact
  function so plugin runtime config reads (`Host.ConfigValue`) get real secret values —
  `warehousedemo`, `integrationdemo`, and `pimdemo` build `Authorization: Bearer <secret>` headers
  from exactly these config keys, so the redacted `"***"` placeholder would have silently broken
  outbound auth. `plugins.b2b.license_key` was also missing from the flatten map entirely (only
  `plugins.b2b.enabled` was flattened) — added as a redacted/secret entry, matching the other
  plugin API-key fields.
- **Review follow-up — `ConfigValue` scoping**: `Host.ConfigValue` (bare `AsHost`) exposed the
  **entire** unredacted `Flatten()` map to every plugin, so any plugin could read another
  plugin's API key (`plugins.<other>.*`) or a core secret (`database.password`, `redis.url`,
  etc.) by guessing the dotted key — not just its own config. `AsHostFor(app, pluginName)` (what
  `pluginsdk.Adapt`/`sdk.New` construct for every real plugin) now scopes `ConfigValue` /
  `ConfigBool` / `ConfigInt` / `ConfigInt64` to keys under that plugin's own `plugins.<slug>.*`
  namespace (slug = first `/`-segment of `Plugin.Name()`); anything outside that prefix reads as
  empty/zero. The bare `AsHost(app)` (tests/harness only, no plugin name) stays unscoped —
  intentional, since harness callers already have full `*plugin.App` access anyway. No existing
  plugin reads config outside its own namespace, so this is a pure tightening with no caller
  changes needed.
- **Review follow-up — PII stripped from default read ports**: `extapi.OrderView` dropped
  `ContactEmail` and `extapi.CustomerView` dropped `Email`; `pluginsdk.OrderPort.FindByID` /
  `CustomerPort.FindByID` (the default composition-root adapters any plugin gets from
  `Require(CapOrders)` / `Require(CapCustomers)`) no longer populate them. PII should not ride
  along on a generic read port just because a plugin wanted order status or customer ID — there
  is no privileged accessor for the real address yet; add one gated by a narrower capability if a
  concrete integration needs it. Updated `plugins/b2b/groups/admin_handler_test.go` fixtures
  (only the test's `Email` struct-literal field; `b2b`'s own handlers never read
  `CustomerView.Email`).

## B2B: eliminated domain imports (no allowlist exception)

Per the plan's preference for thin public surfaces over a boundary exception: `b2b`'s
`internal/domain/customergroup` dependency was **not** promoted to a new `pkg/extapi` type (no
other code in the repo depends on that domain package outside its own tests — confirmed by repo
search), so the simplest, smallest-surface fix was to **move `Group` / `GroupPrice` and their
repository interfaces into the plugin itself**:

- `plugins/b2b/groups/group.go` (new) — `Group`, `NewGroup`, `Update`, `Repository` (copied
  verbatim from `internal/domain/customergroup/{group,repository}.go`; already self-contained,
  no further internal dependency).
- `plugins/b2b/pricing/group_price.go` (new) — `GroupPrice`, `NewGroupPrice`,
  `GroupPriceRepository`, using `extapi.Money` instead of `internal/domain/shared.Money`.
- Postgres repos (`groups/postgres_repo.go`, `pricing/postgres_repo.go`) now implement the local
  interfaces; `database/sql` + `jackc/pgx` stay (stdlib/external, both allowed).
- Admin handlers (`groups/admin_handler.go`, `pricing/admin_handler.go`) use
  `pluginsdk.CustomerPort` / `pluginsdk.CatalogPort` for cross-cutting reads instead of
  `internal/domain/customer` / `internal/domain/catalog`, `pluginsdk.JSON*` / `*Error` instead of
  `internal/platform/httpx` / `apperror`, and `google/uuid` instead of `internal/platform/id`
  (same v4 UUID format the existing `Group.ID` regex already required).
- `b2b/pricing/group_price_step.go` now implements `extapi.PricingStep`
  (`Apply(ctx, extapi.PricingContext)`), using the new `SetItemPrice` method to override a cart
  line's unit price/total with the group-scoped price.
- `b2b/permissions.go` — plain untyped string constants (`PermissionGroupsRead = "b2b.groups.read"`,
  …) instead of `rbac.Permission`-typed constants; converts implicitly at
  `Host.RegisterPermission(permission string, roles ...string)`.
- `b2b/migrations.go` — `pluginsdk.Migrator` / `MigrationSpec` / `ApplyMigrationFS` instead of
  `internal/platform/plugin.Migrator` / `internal/platform/migrate`.
- `b2b/plugin.go` — `Init(h pluginsdk.Host)`; declares `Require(CapDB/CapCustomers/CapCatalog)`,
  reads `h.BootstrapDB()` / `h.Customers()` / `h.Catalog()` / `h.ConfigBool` / `h.ConfigValue`
  instead of `app.Bootstrap.{DB,Customers,Variants}` / `app.Config.Plugins.B2B.*`.

`google/uuid` (already an indirect dependency) was promoted to a direct `go.mod` requirement
(`go mod tidy`).

## Registration

`cmd/api/register_plugins.go`: all non-core plugin registrations converted to
`registry.Register(pluginsdk.Adapt(x.New()))` (`cartdemo`, `promodemo`, `importdemo`,
`exportdemo`, `checkoutdemo`, `slotsdemo`, `taxdemo`, `maildemo`, `pimdemo`, `integrationdemo`,
`warehousedemo`, `example`, `b2b`; `extref` already used this pattern from PR-1551). `sitekit`
stays unregistered (scaffold reference only, per PR-1525 precedent).

## Intentional exceptions

None. Every plugin under `plugins/` outside `plugins/core/*` now passes the pkg-only
`TestImportBoundary` with no allowlist carve-out — including `b2b`, which the phase plan treated
as the hard case.

## Out of scope

- No C4 change — no new component, container, port, or integration; `b2b` continues to register
  through the same plugin registry, just via the public SDK bridge (`pluginsdk.Adapt`) instead of
  directly implementing the core-internal `plugin.Plugin` interface.
- External module publish / fork→module guide (Track E2–E4) — later, not required to land PR-1552.
- `b2b` quotes / PO / approvals — unchanged, still planned.

Postgres-backed tests skipped, consistent with every other DSN-gated integration test in the repo.
