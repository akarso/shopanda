# PR-1607 — order.line.display language

Status: done

## Summary

Pass a BCP 47 primary `language` on `order.line.display` (`OrderLineDisplayLanguage()`),
persist the resolved checkout language on `orders.language`, and fall back to the
store language when the order has none (legacy rows / email path).

## Scope

- Migration `113_add_orders_language.sql` (nullable TEXT, primary-tag check)
- `Order.Language`; postgres hydrate/save; `CreateOrderStep` persists only when
  `LanguageOK` (WithLanguage set) — missing context leaves NULL
- `EnrichOrderLineDisplayRows(..., language, …)`; sealed with `order_id` /
  `variant_id` / `language` in `InvokeContinueOnError`
- Storefront pages: `LanguageOK` then store language (`DisplayLanguage`)
- Email: order language, else `WithStoreLanguageLookup` (FindDefault at build)
- `translation.LanguageOK` / `PrimaryLanguage` (rejects Low/und) / `DisplayLanguage`
- ROADMAP gap → done; AGENTS / EXTENSION_POINTS

## Out of scope

- Translating core email copy / theme strings
- Metal Dogs localized thumbnail label/alt (product)
- No C4 change — same enrich call sites
