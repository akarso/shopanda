# PR-1575 — Shared process-kind plugin boot helpers

Status: done

## Summary

`AssertNeedsMetExcept` skip lists for serve, worker, scheduler, and plugin CLI
live in `cmd/api/plugin_boot.go`. Production composition roots call
`assertServeNeedsMet` / `assertWorkerNeedsMet` / `assertSchedulerNeedsMet` /
`assertPluginCLINeedsMet` instead of inlining capability lists. Tests call
`bootServePlugins` / `bootWorkerPlugins` (bind + Init + assert) so a change to
the production list cannot drift from product acceptance coverage.

Acceptance: a plugin with `Need(CapCatalogSeed)` boots via `bootServePlugins`
and `bootWorkerPlugins`; `assertSeedCLINeedsMet` fails when CatalogSeedPort
was not bound.

## Scope

- `cmd/api/plugin_boot.go` — skip lists, assert helpers, boot* test helpers
- Wire all previous inline `AssertNeedsMetExcept` call sites in `cmd/api`
- Plugin CLI keeps CapIntegration* skip via `assertPluginCLINeedsMet`
- Acceptance tests in `plugin_boot_test.go`; existing port tests use assert*

## Out of scope

- Extracting full `wireServeRuntime` / DB open into boot helpers
- Binding CapCatalogSeed on serve/worker
- NeedsInCLI API surface
- No C4 change — assert/boot wiring only
