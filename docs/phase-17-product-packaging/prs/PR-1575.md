# PR-1575 — Shared process-kind plugin boot helpers

Status: done

## Summary

`AssertNeedsMetExcept` skip lists for serve, worker/scheduler, and plugin CLI
live in `cmd/api/plugin_boot.go`. Production composition roots call
`assertServeNeedsMet` / `assertWorkerNeedsMet` / `assertPluginCLINeedsMet`
instead of inlining capability lists. Scheduler shares `assertWorkerNeedsMet`
(one skip list until they diverge). Tests call `bootServePlugins` /
`bootWorkerPlugins` to lock those skip lists — thinner than full
wireServeRuntime / runWorker, not a substitute for production Init wiring.

Acceptance: a plugin with `Need(CapCatalogSeed)` (+ `CapCart` on serve) boots
via the helpers; seed CLI without CatalogSeedPort fails through
`runPluginCLICommand` + the same assert `bindPluginCLIPortsFromBoot` uses.

## Scope

- `cmd/api/plugin_boot.go` — skip lists, assert helpers, bootServe/bootWorker
- Wire all previous inline `AssertNeedsMetExcept` call sites in `cmd/api`
- Plugin CLI keeps CapIntegration* skip via `assertPluginCLINeedsMet`
- Acceptance tests lock CapCart on serve helper; CLI unbound-seed via Run path

## Out of scope

- Extracting full `wireServeRuntime` / DB open into boot helpers
- Separate scheduler skip list / `bootSchedulerPlugins` (unused until lists differ)
- Binding CapCatalogSeed on serve/worker
- NeedsInCLI API surface
- No C4 change — assert/boot wiring only
