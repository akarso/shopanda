# PR-1605 — Order line display enrich + image kind

Status: done

## Summary

Add `order.line.display` so plugins can append derived shopper-facing fields
(e.g. Metal Dogs `OrderThumbnailURL`) to confirmation email and storefront
order lines, and render `Kind=image` as HTTPS-only `<img>` in default templates.

## Scope

- Hook `order.line.display` (`extapi.HookOrderLineDisplay`): payload
  `order_id`, `variant_id`, **cloned** public `extensions` map; append via
  `AppendOrderLineDisplayField` (`Code`/`Label`/`Kind`/`Value`/`Alt`)
- `InvokeContinueOnError` (order.line.display-only): deep-copy `extensions`
  per handler; seal `order_id`/`variant_id`; restore `fields` by value on
  error/panic (in-place mutate + pointer replace); cancel between handlers
  only (empty registrant); skip-and-log
- `NormalizeDisplayRow`: scheme case-insensitive → `https`; `ssrf.ValidateURL`
  + hostname resolve/`FilterAllowedIPs` (nip.io/localdomain fail closed);
  userinfo/localhost./zone reject; caps; skip via Info
- Template `Extensions` map built from stored + **normalized** enrich rows
  (overwrite); deep-cloned hook map never shared with template
- Notification + storefront wire `WithOrderLineHooks`; `Kind`/`Alt` on rows
- Default email + theme templates: `Kind=image` → `<img>`; else text
- ROADMAP E6b blockers → done; AGENTS / EXTENSION_POINTS

## Out of scope

- Stored `FieldTypeImage` in the extension domain (display kind only)
- Proxy / CDN rewriting of image URLs
- Product-plugin Metal Dogs E6b implementation itself
- No C4 change — same hooks registry + notification/storefront call sites
