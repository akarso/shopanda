# PR-1572 — CapCatalogSeed is CLI-seed-only

Status: done

## Summary

`bindProductPorts` no longer binds `CapCatalogSeed`. Serve and worker skip it
via `AssertNeedsMetExcept(..., CapCatalogSeed)` (same pattern as serve-only
`CapCart`). CLI seed composition roots call `bindCatalogSeedPort` then keep
`CapCatalogSeed` off the skip list so write access stays out of serve/worker.

## Scope

- Split `bindCatalogSeedPort` out of `bindProductPorts` (nil boot → error)
- Serve: `AssertNeedsMetExcept(CapCatalogSeed)` after `BindCartPort`
- Worker / scheduler / CLIs: `AssertNeedsMetExcept(CapCart, CapCatalogSeed)`
- Tests: non-serve skip, seed boot binds, serve unbound, nil-boot fail-closed

## Out of scope

- Rewiring product-fork seed CLIs (call `bindCatalogSeedPort` in the same
  change set that enables seeding against this pin)
- Entrypoint allowlist enforcing “no bind on serve” (convention + tests)
- NeedsInCLI API surface beyond AssertNeedsMetExcept
- No C4 change — capability binding only

## Validation

```bash
go test ./cmd/api/ -count=1 -run 'NonServeBoot|SeedBoot|ServeBoot|NilBoot'
go test ./internal/platform/plugin/ -count=1 -run 'AssertNeedsMetExcept'
go build -o /tmp/shopanda-api ./cmd/api/
```
