# PR-1566 — CatalogSeedPort Status / Type / Attributes

Status: done

## Summary

Widen `CatalogSeedPort` seeds so product plugins can seed draft catalog
rows without going storefront-visible, and carry product/variant attributes
(Metal Dogs: parent SKU, size). Stops hard-coding `StatusActive` on
`EnsureProduct`; empty `Status` keeps `NewProduct`'s draft default.

**Breaking vs PR-1564:** callers that relied on silent `active` must set
`Status: "active"` explicitly. Create-only honesty: disagreeing `Status` /
`Type`, or Attributes that fail match rules (`nil` = no check; `{}` =
assert empty; non-empty = subset keys), error instead of soft
`created=false`.

## Scope

- `CatalogProductSeed`: `Status`, `Type`, `Attributes` (deep-copied)
- `CatalogVariantSeed`: `Attributes` (deep-copied)
- Adapter validates status/type via domain messages; `Product.Validate()`
  before Create; reject `downloadable`+`active` (same as CSV/admin)
- Create-only mismatch errors for Status/Type; Attributes: nil / {} /
  subset keys (extra stored keys OK); JSON deep-copy
- Unit tests: draft default, active/archived, whitespace status/type,
  invalid tokens, mismatch + subset, `{}` vs nil, downloadable+active,
  `[]string` clone, Import fields + Import mismatch, Create conflict re-read
- EXTENSION_POINTS + ROADMAP follow-up → done

## Out of scope

- Updating product seed CLIs in forks (Metal Dogs migrates after bump)
- Attribute registry / type checks (free-form, same as Metal Dogs need)
- Composing bundle/grouped/configurable children on seed — operator owns
  composition; documented on the seed DTO
- Price-history change — already written by `EnsurePrice` (PR-1564)
- No C4 change — seed DTO fields only
