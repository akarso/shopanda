# PR-1555 — CatalogPort ProductSlug + FindVariants

Status: done

## Summary

Hooks that check “variant belongs to product slug X” no longer need
`FindVariant` + `FindProduct` per cart line. `CatalogVariant.ProductSlug` is
filled on read; `CatalogPort.FindVariants` and cart tax-class loads share
`catalog.LookupVariants` / `LookupProducts` (batch + per-id fallback, cap 100).

## Scope

- `extapi.CatalogVariant.ProductSlug` (empty = unavailable under current read
  scope — hooks must fail closed, not skip)
- `CatalogPort.FindVariants`; results keyed by requested id
- Shared `internal/domain/catalog` batch helpers (FindByIDs/ListByIDs optional;
  batch error → per-id so one bad UUID does not fail the set)
- Docs: EXTENSION_POINTS / ROADMAP follow-up → done

## Out of scope

- No C4 change — port field + method only
- Does not add `FindByIDs` to the domain `VariantRepository` interface
  (optional capability on postgres, same pattern as cart tax-class batching)
- No change to catalog admin APIs
