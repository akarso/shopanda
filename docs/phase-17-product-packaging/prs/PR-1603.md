# PR-1603 — Order confirmation email + storefront lines expose extensions

Status: done

## Summary

Put `VariantID` / `SKU` and public `order_item` extension values on
confirmation-email line maps and on storefront order line rows (account
order detail + HMAC checkout confirm), so product plugins (Metal Dogs E6b)
can render per-line design data without a custom hook yet.

## Scope

- `extension.PublicOrderItemAPIByVariant` + `ExtensionMapFromAPIItems` +
  `ExtensionDisplayRows` / `FormatExtensionDisplayValue` (Label, Yes/No,
  skip JSON composites; soft per-field decode)
- `notification.WithOrderExtensions` → Items: `VariantID`/`SKU`,
  `Extensions` (override map), `ExtensionsList` (default template);
  list failure is skip-and-log (email still enqueues)
- Account order detail + HMAC `/checkout/confirm` lines; Stripe
  `payment/return` uses matching confirm flash (guest or signed-in) or else
  owning `CustomerID` only; `ViewOrderURL` only after that match; flash cleared
- Default email + theme templates show labeled extensions when present
- ROADMAP E6b blockers → done; AGENTS / EXTENSION_POINTS note

## Out of scope

- Plugin enrich hook for derived fields (signed thumbnail URL) — follow-up
  if product templates cannot build URLs from public extension values alone
- Private / owned PluginOnlyWrite fields on shopper email/SSR (same as JSON
  order API: `includePrivate=false`)
- Money exponent formatting for int/money extension fields
- No C4 change — same notification + storefront ValueAPI wiring
