# PR-1547 — Unified port wiring

Status: done

## Summary

- `bindProductPorts` in `cmd/api/plugin_ports.go` binds catalog/order ports and marks `CapDB` before `InitAll`.
- Called from serve (`wire_services`), worker, scheduler, providers, cache/schedule/extension-field CLIs, and search-reindex bootstrap.
- `serve` late-binds `CartPort` after `cart.Service` construction, then calls the strict `AssertNeedsMet`.
- **Review follow-up**: every non-serve composition root above never binds `CartPort` (only serve constructs `cart.Service`), so they now call `plugin.App.AssertNeedsMetExcept(plugin.CapCart)` instead of `AssertNeedsMet` after `InitAll`/`InitAllContext`. Without this, enabling any plugin that declares `Needs(CapCart)` (e.g. `plugins/extref`) breaks worker/scheduler/search-reindex/cache/schedule/extension-field boot. `serve` is unaffected — it keeps `AssertNeedsMet()` after `BindCartPort`.
- **Review follow-up**: `pluginsdk.Host.Catalog()` / `Orders()` / `Customers()` / `BootstrapDB()` previously returned the composition-root port to *any* plugin once it was bound for *any* plugin's `Need` — a plugin that never declared `Needs(CapCatalog)` (or called `Require(CapCatalog)`) could still read `h.Catalog()` just because some other plugin's capability caused the root to bind it. Each getter is now gated behind `declaredOrUnscoped(cap)` (`pkg/pluginsdk/apphost.go`), which checks `App.CapabilityDeclaredBy(cap, pluginName)` for Hosts created via the new `AsHostFor(app, pluginName)` (what `pluginsdk.Adapt`/`sdk.New` use for every real plugin); the bare `AsHost(app)` (tests/harness) stays unscoped for back-compat. `Host.Require` now calls the new `App.RecordNeedsFor(pluginName, cap)` directly with the Host's own plugin name instead of relying on `App.CurrentPluginName()`, so attribution (and therefore gating) is correct even when `Require` is called outside the `InitAllContext` loop.

## Why

Catalog/order ports were only implied on the serve path; worker and CLIs with DB must expose the same Host surface during plugin Init.

## Scope

- `cmd/api/plugin_ports.go`, `plugin_bootstrap.go`, wiring in `main.go`, `providers.go`, `cache_cli.go`, `schedule_cli.go`, `extension_field_cli.go`, `wire_services.go`.
- No change to no-DB paths (`cli_plugins`, import/export report) — no `AssertNeedsMet` without DB bootstrap.
- `internal/platform/plugin/service_ports.go`: new `App.AssertNeedsMetExcept(skip ...Capability)`.

## Out of scope

- Binding cart in worker (plugins that Need cart cannot run on worker-only processes until a cart adapter is added).
