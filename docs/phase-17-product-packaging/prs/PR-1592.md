# PR-1592 — `SyncJobs.Enqueue` `WithJobID` + idempotent Conflict resolve

Status: done

## Summary

Idempotent sync enqueue (Metal Dogs MIG3b) needs a stable queue job id.
`SyncJobs.Enqueue` always generated a new id, so plugins kept
`plugin.App.BoundQueue()`.

- `pluginsdk.EnqueueOption` / `WithJobID(uuid)` on `SyncJobs.Enqueue`
- Dual-mode `plugin.WithJobID` on `Integration.Enqueue`
- UUID-only ids (fail closed); Redis duplicate Enqueue → `apperror.Conflict`
- On Conflict with `WithJobID`, Enqueue resolves via bound `JobsPort`:
  same sync Type + pending/processing/reclaiming → success (no-op);
  terminal → `Requeue(WithRequeueTerminal)`; wrong Type → hard error
- Second Enqueue payload is discarded (documented)
- Without JobsPort, Conflict remains `IsConflict` but is not auto-resumed

## Scope

- `internal/platform/plugin/sync_job.go` + tests
- `pkg/pluginsdk/sync.go` + `sdk_test.go`
- `internal/infrastructure/redis/job_queue.go` (Conflict on duplicate)
- PLUGINS / AGENTS / SYNC_JOB_OBSERVABILITY / ROADMAP

## Out of scope

- `JobsPort.Enqueue` / payload rewrite on resume
- Broker queues without Reader still cannot auto-resolve Conflict (need JobsPort)
- No C4 change
