# PR-1604 — HTTP access log uses route pattern, not raw path

Status: done

## Summary

Stop writing `r.URL.Path` into `http.request` / `http.panic` logs. Use the
matched ServeMux pattern (already captured for metrics/tracing) so path
secrets on plugin routes (e.g. HMAC tokens) do not land in access logs.

## Scope

- `LoggingMiddleware` / `RecoveryMiddleware` → `accessLogPath` via
  `routeMatchFromContext` (fallback `unmatched`)
- Tests: templated route keeps secret out of the log line; probe wrap logs
  `unmatched`
- ROADMAP row → done

## Out of scope

- Reverse-proxy / load-balancer access logs (still see the raw URL)
- Changing the JSON field name (`path` still holds the route template)
- Per-route redact opt-in (`WithNoCache`-style) — not needed once patterns
  are logged
- No C4 change

## Validation

```bash
go test ./internal/interfaces/http/shared/ -count=1 -run 'LoggingMiddleware_|RecoveryMiddleware_|StackedStatus'
```
