# PR-1548 — Hook sees extensions + auth

Status: done

## Summary

- `cart.add_item.before` (and after) payload includes `extensions` (field codes; values for non-plugin-only or trusted codes), `plugin_write_codes`, and `actor_user_id` / `actor_role` from `auth.IdentityFrom`.
- Plugin-write trust remains stripped from the hook `ctx`; plugin-only **values** are redacted unless the pre-strip grant named that code.

## Review follow-up

- **Owner-scoped redaction (review blocker)**: a trusted plugin-only value used to show up on *every* handler registered on the same hook, not just the handler belonging to the field's owner — any registrant could read another plugin's owned plugin-only value just because the write path trusted the field code. Added `hooks.Registry.InvokeAdapted(ctx, hookCtx, adapt func(registrant string, src *Context) *Context)`, which calls `adapt` once per handler (in priority order) so each handler gets its own payload view; other payload keys stay shared across the chain like `Invoke` (handlers still see each other's `Set` calls). `extension.ValueService.FieldOwner(code string) string` surfaces the registry's existing `Owner(code)` through the cart-facing `pluginOnlyFieldChecker` interface. Cart's `invokeCartItemHook` now calls `invokeCartHookAdapted`, and `extensionInputsForHook(inputs, trusted, registrant, checker)` takes the current handler's registrant: a redacted plugin-only value is shown only when trusted **and** (the field has no recorded owner **or** the owner equals the current registrant). `field_code` is still always present; only `value` is conditionally omitted.
