# PR-1556 — cart.validate `pending_line` on AddItem

Status: done

## Summary

`AddItem` runs `cart.validate` before the extension upsert, so stored
`CartView.Items[].Extensions` never included the values being added. Hooks
now receive `pending_line` (`extapi.PendingCartLine`: variant, resulting
quantity, extensions) with the same per-registrant plugin-only redaction as
`CartView`. Removes the need for product plugins to smuggle values via a
goroutine-keyed map.

## Scope

- `extapi.PendingCartLine` + `pending_line` hook key during AddItem validate
- Redaction via `redactPendingLine` (owner-only plugin-only fields)
- `extref` `cart.validate` checks pending + stored design_id
- Docs: EXTENSION_POINTS / AGENTS / ROADMAP follow-up → done

## Out of scope

- No C4 change — hook payload field only
- Does not merge pending into `CartView.Items` (separate key keeps stored vs
  in-flight clear)
- Update/remove/coupon validate paths leave `pending_line` unset
