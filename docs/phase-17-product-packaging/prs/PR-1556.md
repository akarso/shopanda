# PR-1556 — cart.validate `pending_line` on AddItem

Status: done

## Summary

`AddItem` runs `cart.validate` before the extension upsert. The cart line
passed to hooks is the stored extensions with pending AddItem codes overlaid
(pending wins on the same code). `pending_line` mirrors the in-flight inputs
and is set only when AddItem carries extensions (quantity-only bumps do not).
Same per-registrant plugin-only redaction as `CartView`.

## Scope

- Overlay pending codes onto the validate cart line; `pending_line` when
  extensions are present
- Clone map/slice pending values so handlers cannot mutate the upsert payload
- `extref` validates the effective cart line only
- Docs: EXTENSION_POINTS / AGENTS / ROADMAP follow-up → done

## Out of scope

- No C4 change — hook payload field only
- Update/remove/coupon validate paths leave `pending_line` unset
