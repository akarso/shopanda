# PR-1579 — Invalid UUID job id → not-found (Get / Requeue / Retry / Cancel)

Status: done

## Summary

Postgres `jobs.id` is a `uuid` column. Non-UUID ids used to surface SQLSTATE
`22P02` from `JobQueue.Get` / lock / transition lookups. `jobs:requeue`
always calls `Get` before `Requeue`, so fixing only `Requeue` left the
operator command dumping raw SQL.

Shared adapter helpers (`jobIDUnusable`, `isInvalidTextUUID`) map bad ids to
the same miss semantics as a missing row:

| Surface | Non-UUID outcome |
| --- | --- |
| `Get` | `(nil, nil)` |
| `Requeue` / `RequeueWithBeforeCommit` | `jobs.ErrRequeueNotFound` |
| `Retry` / `Cancel` (`transitionStatus`) | `apperror.NotFound` |

`TestJobQueue_Requeue_MissingID` uses a well-formed absent UUID so DSN runs
still cover `sql.ErrNoRows`. Parse-reject paths are covered by no-DSN tests.
CLI operator miss is pinned without DSN via injectable Get/Requeue ports
(`TestRunJobsRequeue_GetMissFriendlyNotFound` / Show sibling).

## Scope

- `job_uuid.go` helpers; `Get` / `RequeueWithBeforeCommit` / `transitionStatus`
- Retarget MissingID; InvalidUUID / Get / Retry+Cancel no-DSN tests; helper unit tests
- CLI: `runJobsRequeueWith` / `runJobsShowGet` + fake-Get miss tests (no DSN)
- Domain `ErrRequeueNotFound` comment adapter-neutral
- `formatJobsRequeueError` NotFound = missing/deleted under TOCTOU; unusable id stays on Get miss line
- RUNBOOK: Get / Requeue / Retry / Cancel treat non-UUID as not-found

## Out of scope

- Redis / broker string-id behavior (already miss-friendly)
- Accepting compact / braced PG UUID forms via `id.IsUUID` (stricter than PG)
- HTTP handler changes (already map Get nil → 404)
- Adding `./cmd/api` to `scripts/ci/integration.sh` (CLI miss covered in unit via fakes)
- No C4 change
