# PR-1559 — BoundQueue + sync request_id reinjection

Status: done

## Summary

Products need the composition-root queue (not a plugin `RegisterQueue`
fallback) for health/read paths, and sync handlers that call
`requestctx.RequestID(ctx)` need the same ID that was stamped into the
payload at enqueue. Adds `App.BoundQueue()` (mirror of `BoundMediaStorage`)
and reinjects payload `request_id` onto the sync handler context when ctx
has none.

## Scope

- `App.BoundQueue() (jobs.Queue, bool)` — BindQueue instance only
- Sync `Handle`: reinject `request_id` via `requestctx.WithRequestID` when
  missing on ctx (top-level envelope then inner payload)
- Tests + `SYNC_JOB_OBSERVABILITY.md` note

## Out of scope

- No change to `RegisterQueue` / `Queue()` semantics
- No job delivery fence / `ErrSkipOutcome` (PR-1565)
- No C4 change — no new container or component

## Validation

```bash

```
