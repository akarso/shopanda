# PR-1598 — SSR Stripe PaymentIntent confirm

Status: done

## Summary

SSR checkout confirms Stripe PaymentIntents with Stripe.js, including SCA/3DS
redirect returns. Place-order is PRG (POST → flash cookie → GET confirm) so
refresh does not create a second order. Misconfiguration is shopper-safe.

## Scope

- `payment.stripe.publishable_key` (only wired when Stripe enabled)
- POST `/checkout/confirm` → 303 GET `/checkout/confirm` (HMAC flash; `Secure` via `IsRequestSecure`; remint refreshes `exp`)
- Stripe misconfig clears flash (no `client_secret` left in jar); remint failures logged + cleared
- `return_url` from `server.public_base_url` (not request Host/proto)
- `GET /checkout/payment/return` neutral copy (webhook owns paid); clears flash
- Confirm template: Stripe.js Payment Element; CSP only when `AllowStripeCSP`
- Tests: forged/expired flash, TLS `Secure`, missing `public_base_url` misconfig
- `Cache-Control: private, no-store` on confirm/return; `/checkout` no-cache prefix
- SSR `CodeUnavailable` → 503 with Message; shopper-safe Stripe misconfig copy
- ClientCode must be `plugin.<slug>`; Details deep-copied for
  `map[string]interface{}` / `[]interface{}` trees; JSONError drops
  unmarshalable details without upgrading status
- Tests for Stripe JS, missing key, Unavailable 503, return route, CSP scope,
  Cache-Control

## Out of scope

- Dashboard-side card attach
- Signed flash cookie (HttpOnly path-scoped cookie; client_secret already in HTML)
