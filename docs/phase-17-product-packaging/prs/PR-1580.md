# PR-1580 — Context-aware ReadableStorage.Read (localfs)

Status: done

## Summary

`localfs.Storage.Read` used `os.ReadFile` with no context. Product wrappers
and invoice PDF reload need a cancellable full-object read.

**Decision:** `media.ReadableStorage.Read(ctx, path)` takes a non-nil
`context.Context` (same shape as `Head` / `SignedURL`). localfs checks
`ctx.Err()` before open and between 32 KiB windows, preallocates from
`Stat` on the success path, and keeps `ReadContext` only as a concrete
alias for Metal Dogs call sites.

**Not the local grant hot path:** storefront local downloads use
`SignedURLStorage` (`Head` + HMAC GET → `Open` + `http.ServeContent`).
Client disconnect already stops ServeContent writes. `ReadableStorage.Read`
covers invoice PDF, Readable-only backends, and product wrappers.

HTTP call sites treat `context.Canceled` / `DeadlineExceeded` as client-gone
(no Internal 500 / no error-level delivery logs).

## Scope

- `media.ReadableStorage.Read(ctx, path)` godoc (honour ctx; no chunk-size detail)
- localfs `Read` (prealloc + chunk cancel) + `ReadContext` alias
- Between-chunk cancel test (`testAfterReadChunk` + mutable `readChunkSize`)
- Storefront Readable-only branch + invoice PDF: client-gone handling
- DEVELOPER / ReadableStorage / C4: SignedURL vs Readable roles
- Drive-by (unrelated): `search_admin_test` `jobs` → `domainjobs` so `./admin` compiles

## Out of scope

- Streaming rewrite of invoice PDF via `Open` (still full `[]byte`)
- Changing `Save` / `Delete` to take ctx
- S3 `ReadableStorage` (S3 grants stay SignedURL + Head)
