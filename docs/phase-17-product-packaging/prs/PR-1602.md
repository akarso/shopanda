# PR-1602 — `WithEventJobID` for RegisterOnEvent

Status: done

## Summary

Let `RegisterOnEvent` derive a stable queue job id from the event payload
(`WithEventJobID`), so plugins do not need a dispatcher job that calls
`Enqueue(..., WithJobID)`. Conflict resolves like `WithJobID` when JobsPort
is bound.

CR follow-up on this tip also hardens the stack: worker attaches OrderPort
extensions, flattens typed `order.created` for EventJobID, parent-locked
`withOwner`, detached publish + snapshot resume, `ListCreatedSince` cursor
rules, `LinesForOrders`, and docs.

## Scope

- `extapi.SyncJob.EventJobID` + `pluginsdk.WithEventJobID`
- Event path uses `NewSyncJobEnvelopeWithID`; Conflict → `ResolveEnqueueConflict`
- Reject EventJobID on cron/manual registration
- AGENTS / PLUGINS recipes; ROADMAP → done

## Out of scope

- Changing default (random) job ids when EventJobID is unset
- Transactional enqueue with the order commit
- No C4 change
