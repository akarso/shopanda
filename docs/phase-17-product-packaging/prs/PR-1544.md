# PR-1544 — Public checkout + composition contracts

Status: done

## Summary

- `extapi.CheckoutStep` + `CheckoutContext` (cart qty/count, meta).
- `extapi.ProductCompositionStep` + block API for PDP.
- Host coerces public steps when registering.
- **Review follow-up**: `CheckoutContext` gained `Address()` (new `extapi.Address`), `ContactEmail()`, `ShippingMethod()`, `PaymentMethod()` (all read from `checkout.Context.Input`), and `OrderID()` (from `checkout.Context.Order`, empty until the create-order step runs). Implemented in `checkoutContextView` (`pkg/pluginsdk/checkout_adapt.go`). `Host.RegisterPricingStep` / `RegisterCheckoutStep` / `RegisterCompositionStep` now **panic** when the registered step cannot be coerced (public contract or already-domain step), instead of silently registering it — a silently-registered uncoercible step previously only surfaced as a dropped step ("plugin.step.invalid_type") much later, at core pipeline wiring time, not during the plugin's own Init. `coerceCompositionStep` also now validates "pdp"/"plp" step types instead of unconditionally passing through.
- **Review follow-up (PII)**: `checkoutContextView.Address()` / `ContactEmail()` now always return the zero value. Every checkout step on the workflow (any plugin, any purpose) previously received the full shipping/billing address and contact email on every invocation regardless of whether that step needed PII — there was no way to scope it to the step(s) that actually need it. `ShippingMethod()`/`PaymentMethod()`/`OrderID()` are unaffected. A scoped, trust-gated PII grant (same idea as the cart plugin-only-field owner check in PR-1548) is deferred to a future PR; `extapi.CheckoutContext`'s doc comments note the stop-gap.
- **Review follow-up**: an unknown `RegisterCompositionStep` pipeline name (anything other than `"pdp"`/`"plp"`) now also **panics** via `coerceCompositionStep`, instead of passing the step through unchanged — consistent with the bad pdp/plp type panic above; a typo'd pipeline name previously only surfaced as a dropped step at core wiring time.
- **Review follow-up**: `AsHost`'s doc comment now says explicitly that it is test-only/unscoped — no production path reaches it (`Adapt`/`sdk.New`/`pluginsdk/harness` all use `AsHostFor`).
