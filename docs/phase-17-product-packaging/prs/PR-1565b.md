# PR-1565b — OnQueueBound / OnRequeued / Queue.Requeue

Status: done

## Summary

Job fence slice 2: `OnQueueBound` / `OnRequeued` with reclaim hooks before
the job is dequeueable again (Postgres `FOR UPDATE`; Redis two-phase
`reclaiming` Lua). Attempt passed; hook error/panic fails Requeue. Distinct
requeue errors; `DefaultRequeueMinAge` = 5m (CLI `--min-age`, min 1s);
Postgres ages on DB clock. Typed-nil bind rejected; live Reader/Admin.
`ErrSkipOutcome` skip-only walks `Unwrap() []error` before cancel leaves.
Redis: once `beginRequeueLua` takes an id, only commit, abort, or
stale-reclaim repair schedule it — `Dequeue` never resolves, releases, or
re-pushes it. `claimJobLua` claims only pending/meta-less ids (others are
popped and left alone) and stamps `updated_at_ms`/`claimed_at_ms` from Redis
`TIME`, which `saveJob` keeps; `beginRequeueLua` and the reclaim lease also
use Redis `TIME`. `saveJobMetaLua` refuses any write over reclaiming and a
processing write unless meta is the same claim; release is a CAS on attempt
+ `claimed_at_ms`. In-progress = meta `reclaiming` younger than the fixed
`DefaultRequeueMinAge` lease (caller `--min-age` cannot steal; missing
`reclaiming_at_ms` falls back to `updated_at_ms`; read errors retry, never
abort). `Complete`/`Fail` on a reclaim past the lease repair it to pending
and schedule ready via Redis-5-safe `LREM`+`LPUSH` (no `LPOS`) only when
the id is on neither ready nor delayed — cleanup errors surface.
`commitRequeueLua` LPUSHes the fresh reclaim copy without scanning ready;
when a delayed member exists, commit/ensure/repair `LREM` every ready copy
and do not push. `promoteDelayed` `LREM`s before `LPUSH`. `Enqueue` is
atomic and rejects a second id (no ready-list scan on the hot path).
`Fail` delayed retries `LREM` ready; terminal complete/fail `ZREM`
delayed and expire meta with the blob TTL; `releaseClaim` skips ready
push when delayed wins.
`claimJobLua` `ZREM`s delayed on claim. `commitReclaim` treats meta
`pending` as success only after the id is on ready or delayed. Complete,
fail, commit, promote, and enqueue stamps use Redis `TIME`. CI
integration runs Redis 5 (`SHOPANDA_TEST_REDIS_URL`) so the repair canary
cannot skip. Durable commit/abort. Postgres `pluginsdk.RequeueTx` (no blind hook retry
on COMMIT failure). Brokers: missing inflight → `ErrOutcomeNotApplied`.
CLI refuses a second JobQueue when bound value lacks Reader/Admin;
`jobs:requeue` maps `ErrRequeueInProgress`.

- Changing Admin.Retry semantics (still failed→pending, attempts=0; OnRequeued not called)
- Lease heartbeat (reclaim in-progress uses fixed DefaultRequeueMinAge; claim freshness still caller min-age)
- Passing reclaim `*sql.Tx` into hooks (document: no second-conn jobs UPDATE)
- No C4 change — bind hooks only
