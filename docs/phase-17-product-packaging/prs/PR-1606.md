# PR-1606 — CartPort private PluginOnlyWrite for owner

Status: done

## Summary

Trusted plugin write of an **owned** `PluginOnlyWrite` + `VisibilityPrivate`
cart_item field succeeds without `canAccessPrivate=true`, and
`CartPort.Get` / `Ensure*` / `cart.validate` return that field to the owning
plugin (same rule as `OrderPort` line reads). Public storefront lists stay
`includePrivate=false`. Hardened: exclusive-string conflict sees private
values before Save; nil checker fails closed; validate adapts on a cloned
context; unowned private PluginOnlyWrite stays forbidden on the cart path.

## Scope

- `ValueService.validateBatchValues` / `Delete`: trusted `pluginWriter` for an
  **owned** PluginOnlyWrite field counts as private access for that field only;
  empty owner or non-PluginOnlyWrite private still returns `ErrForbiddenPrivateField`
- `CartView` loads `ListByCartItems(..., true)`;
  `keepCartExtension` / `FilterCartViewForPlugin` / `redactPendingLine`
  mirror `ordersPort.keepOrderExtension`; nil checker fails closed (drop)
- `cartPort.viewFor` always filters (empty owner strips private)
- `rejectExclusiveStringConflicts` uses `includePrivate=true` so private
  ExclusiveString conflicts fail before `carts.Save`
- `cart.validate` and `cart.add_item.before` clone the hook context per
  registrant (no private payload on the shared context); `hooks.Context.Clone`
  shallow-copies Payload; nil checker fails closed on hook inputs too
- Tests: private+plugin write/delete/unowned/non-plugin; CartPort Get owner
  sees `acme.design_id`; ExclusiveString conflict before Save; opaque writer
  omit on validate + before; before-hook clone retention; cart.validate with
  `VisibilityPrivate`
- ROADMAP DID1 gap → done; EXTENSION_POINTS / AGENTS note

## Out of scope

- Changing public storefront / HTML cart JSON to expose private fields
- Admin API `canAccessPrivate` paths
- Metal Dogs design_id product wiring (consumes this fix)
- No C4 change — same ValueService + CartPort filter seams
