# PR-1574 — Plugin CLI auto-binds CapCatalogSeed

Status: done

## Summary

`runPluginCLICommand` keeps the Init `*plugin.App` and, for `RequiresDB`
commands owned by a plugin that declared `Need(CapCatalogSeed)`, opens the DB,
binds product ports + `CatalogSeedPort` on that App, then runs the command.
Assert skips `CapCart` and `CapIntegration*` (Init-before-bind; failed
warehouse/integration Init must not break seed). No `*sql.DB` on
`pluginsdk.CLIContext` — use `Host.CatalogSeed` / `BootstrapDB`+`CapDB`.
Products do not edit `cli_plugins.go`.

## Scope

- `pluginCLIRuntime{Registry, App}`; owner-scoped `bindCatalogSeedPort`
- `cli.Command.Plugin` attribution; `RequiresDB` fail-closed for seed Needs
- Assert skip CapIntegration* + CapCart (+ CapCatalogSeed when not binding)
- Injectable open/bind for `runPluginCLICommand` e2e tests
- `pluginsdk.CLICommand.RequiresDB` (no CLIContext.DB)

## Out of scope

- Product-owned bind hook (auto-bind covers the acceptance test)
- Wiring CapIntegration* before plugin CLI Init (skip instead)
- Binding CapCatalogSeed on serve/worker
- No C4 change

## Validation

```bash
go test ./cmd/api/ -count=1 -run 'PluginCLI|RunPluginCLI|BindPluginCLI'
go test ./internal/platform/plugin/ -count=1 -run 'CapabilityNeeded'
go build -o /tmp/shopanda-api ./cmd/api/
```
