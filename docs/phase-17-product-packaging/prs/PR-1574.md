# PR-1574 — Plugin CLI auto-binds CapCatalogSeed

Status: done

## Summary

`runPluginCLICommand` keeps the Init `*plugin.App`. Any `RequiresDB` command
opens the DB and binds product read ports (`bindProductPorts`). `CatalogSeedPort`
is bound only when **that command's owning plugin** declared `Need(CapCatalogSeed)`
(`cli.Command.Plugin` from Init). Assert skips `CapCart` and `CapIntegration*`
(Init-before-bind; failed warehouse Init must not break seed). Empty Plugin
owner while CapCatalogSeed is Needed fails closed. No `*sql.DB` on
`pluginsdk.CLIContext` — use `Host.CatalogSeed` / `BootstrapDB`+`CapDB`.
Products do not edit `cli_plugins.go`.

## Scope

- `pluginCLIRuntime{Registry, App}`; owner-scoped `bindCatalogSeedPort`
- `cli.Command.Plugin` attribution; RequiresDB / empty-owner fail-closed
- Assert skip CapIntegration* + CapCart (+ CapCatalogSeed when not binding)
- `pluginCLIDeps` injection for tests (no package globals)
- `pluginsdk.CLICommand.RequiresDB` (no CLIContext.DB)

## Out of scope

- Product-owned bind hook (auto-bind covers the acceptance test)
- Wiring CapIntegration* before plugin CLI Init (skip instead)
- Binding CapCatalogSeed on serve/worker
- No C4 change
