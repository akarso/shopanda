# PR-1549 — Atomic cart extension + Save

Status: done

## Summary

- `AddItem`: `carts.Save` first; extension `UpsertBatch` only after successful Save; upsert failure compensates by restoring prior line snapshot (qty, unit price, assignment) and re-saving.
- Guest merge: `CopyTarget` runs **before** `MergedGuestID` is persisted; failed copy leaves guest rows; retry finishes copies. Heal path on `MergedGuestID` match re-copies before cleanup.
- UpdateItem has no extension upsert path — no change.

## Review follow-up

- Save + upsert are still not one DB transaction (compensation + version-aware tests cover the failure path).
- **CopyTarget vs Save (review blocker)**: `CopyTarget` commits independently of the cart `Save` that follows it in `mergeIntoCustomerCart`, so a `Save` failure (or a later `CopyTarget` failing mid-loop) used to leave the customer cart's pre-existing extension values on a shared variant silently overwritten by the guest's value even though the merge never became durable (`MergedGuestID` never persisted). Added `extensionValueWriter.ListByTarget`/`ReplaceTarget` (implemented on `extension.ValueService`, delegating to `DeleteAllForTarget` + `UpsertBatch`/`repo.ListByTarget`). `mergeIntoCustomerCart` now snapshots the customer cart's existing extension rows for every variant about to be copied *before* any `CopyTarget` call, and restores those snapshots (delete-all then restore, or leave empty) both when `Save` fails and when a later `CopyTarget` in the same loop fails after an earlier one already copied. `MergedGuestID` is left unset on the persisted cart either way (`Save` failed, so the DB cart row is unaffected). New test: `TestService_ClaimGuestCart_SaveConflictAfterCopyRestoresCustomerExtensions`; `TestService_ClaimGuestCart_CopyFailureKeepsGuestRowsAndRetryFinishes` extended with a pre-existing customer value to assert the partial-copy rollback too.
- **Heal path copies dropped lines (review blocker)**: `finishMergedGuestExtensionCopies` (used when `MergedGuestID` is already durable but cleanup is retried) copied *every* guest line's extensions onto the customer cart, including a line `unclaimableGuestLines` had dropped from the original merge (never added to `customerCart.Items`) — this could resurrect an orphaned extension row for a variant the customer cart doesn't have. It now only copies guest variants that exist on `customerCart.Items`. New test: `TestService_ClaimGuestCart_HealRetryDoesNotCopyDroppedLineExtensions`.
- **compensateAddItemLine no longer reprices (review blocker)**: compensation used to call `recalculate` after restoring the line snapshot, which re-runs the pricing pipeline against the *current* catalog — a price list change between the original `AddItem` and the later extension-upsert failure would silently reprice the "restored" line instead of giving back the price the customer actually saw. `compensateAddItemLine` now only restores quantity, unit price, and assignment from the snapshot and calls `Save` directly; it does not call `recalculate`. New test: `TestService_AddItem_ExtensionUpsertFailureDoesNotRepriceCompensatedLine`.
