# PR-1581 — Fix cart extension fake data race in concurrent ClaimGuestCart

Status: done

## Summary

`TestService_ClaimGuestCart_ConcurrentSaveConflictKeepsGuestExtensions` raced
on `memCartExtensionValueRepo.values`: one `ClaimGuestCart` iterated the map
in `ListTargetIDsByTypeAndIDPrefix` while the other wrote via
`Upsert`/`UpsertBatch`. Without `-race` that sometimes fatal'd the whole
package (`concurrent map iteration and map write`, no `--- FAIL`); with
`-race` it failed reliably. The barrier Save already returns Conflict for the
losing merge — the test incorrectly required both calls to succeed.

- Guard test fakes used on the concurrent path: extension values map,
  `stubCartRepo` / `versionCartRepo`, `trackingExtWriter` counters,
  `stubPriceRepo` reads/writes.
- Fix `barrierSaveCartRepo` so the loser waits until the winner's Save
  finishes (otherwise FindByID misses `MergedGuestID` and wrongly restores).
- Accept success and/or Conflict from the two claims (still assert guest
  extension kept + `MergedGuestID`).
- `scripts/ci/unit.sh` (and product-init seed) runs
  `go test -race ./internal/application/cart/` after `go test ./...`.

## Scope

- `service_extensions_test.go` fakes + barrier + concurrent expectations
- `service_test.go` cart/price stub locks
- `scripts/ci/unit.sh` + seed + `scripts/ci/README.md`

## Out of scope

- `-race` for the entire `./...` unit suite
- Production cart/extension repos (Postgres already concurrent-safe)
- No C4 change

## Validation

```bash

go test -race ./internal/application/cart/ -count=3 -run 'ConcurrentSaveConflictKeepsGuestExtensions'
```
