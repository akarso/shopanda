# PR-1576 — Terminal job requeue (keep attempts + OnRequeued)

Status: done

## Summary

`Queue.Requeue` gains `WithRequeueTerminal()` for terminal → `pending` while
keeping `attempts`, setting `run_at=NOW()`, leaving `last_error` unchanged,
and running `OnRequeued` / `RequeueTx` in the same Postgres transaction.

**CLI vs API:** `jobs:requeue --terminal` accepts non-exhausted `failed`;
`--force` is required for `done`/`cancelled` and for exhausted
`attempts >= max_retries` (including `max_retries=0`; prefer `jobs:retry`
for a fresh budget). `--force` is a **no-op** on non-exhausted failed.
Audit records `force_flag` + `force_required`. `Queue.Requeue` +
`WithRequeueTerminal()` does **not** enforce `--force` (API ungated).
Missing id → `ErrRequeueNotFound` on Postgres and Redis. Redis/brokers →
`ErrRequeueUnsupported` for terminal mode.

Adjacent: jobs CLI still hard-codes `queue.driver=postgres` checks — see
PR-1577 (`Host.PlatformConfig` / `RequireQueueDriver`) on #621; not closed here.

Includes PR-1578 fixture cherry-pick so DSN CI is not red if merge order slips.
