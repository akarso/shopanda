# PR-1567 — CatalogSeedPort EnsurePrice Update mode

Status: done

## Summary

`EnsurePrice` stays create-only by default. `CatalogPriceSeed.Update`
opts into amount changes with a price-history snapshot in the same
transaction when db+WithTx are bound (standalone Ensure opens one short
tx per price; prefer `Import` for large loops). Same amount is a no-op;
missing rows still create. Create-only hits soft-no-op **before** money
validation. On write failure, `written` is false.

**Breaking observation vs PR-1564:** the bool is `written` (create **or**
amount-changing Update), not insert-only — external plugins that counted
`true` as “row inserted” will mis-count on re-seed with `Update`.

Seed price writes do **not** emit `pricing.EventPriceUpserted` and bypass
admin grouped/dynamic-bundle price guards — operators must reindex /
invalidate after plugin CSV re-seed (RUNBOOK + EXTENSION_POINTS).

Also documented/tested: empty `Status` on an existing `active` product is
a soft no-op; Attributes subset match rejects missing seed keys (cannot
add attrs on re-seed).

## Scope

- `CatalogPriceSeed.Update bool`
- Adapter: create-only short-circuit before `NewMoney`; `written=false` on err;
  snapshot derived from price row; injectable `priceTx` for atomic Upsert+Record
- Unit tests: create-only / Update / Import / store-scoped / create-miss /
  invalid-currency create-only / priceTx rollback / sequential fail /
  Attributes missing key / empty Status on active
- EXTENSION_POINTS + RUNBOOK + ROADMAP → done

## Out of scope

- Publishing `EventPriceUpserted` from seed host (operator reindex for now)
- Admin `LockTypeAndModes` rejection on seed (intentional escape hatch)
- Updating product/variant Status/Type/Attributes in place
- No C4 change — seed DTO flag only
