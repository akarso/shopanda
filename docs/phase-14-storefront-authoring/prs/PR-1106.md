# PR-1106 — CORS allowlist

Status: done

## Summary

Browser headless clients on another origin had no CORS middleware. The first draft treated `*` as “reflect any Origin” plus credentials — that is rejected.

## Scope

- `http.cors.allowed_origins` / `SHOPANDA_HTTP_CORS_ALLOWED_ORIGINS`
- `http.cors.allow_credentials` / `SHOPANDA_HTTP_CORS_ALLOW_CREDENTIALS` (default false)
- `shared.CORSMiddleware` on storefront API prefixes only (not admin/setup/webhooks/docs)
- `*` is anonymous (`Access-Control-Allow-Origin: *`, no credentials). `*` + credentials disables the wildcard
- Unmatched `OPTIONS` calls `next` (rate limit / 405 stay honest)

## Out of scope

- Cookie session for headless (JWT Bearer stays the API auth)
- CSRF on `/api/v1` (only relevant if an operator enables credentials + cookies)

## Validation

```bash
go test ./internal/interfaces/http/shared ./internal/platform/config
```

No C4 change — middleware on the existing API server.
