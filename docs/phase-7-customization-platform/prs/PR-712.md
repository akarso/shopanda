# PR-712 — Theme Inheritance + Stable API Draft (Track F, OSS)

Status: planned

## Summary

- Add theme inheritance via `parent:` in `theme.yaml`
- Child themes override selected templates while inheriting parent templates/slot markers
- Introduce first public stable API draft for extension contracts (**hooks + slots only**)

## Why

Theme inheritance improves developer UX by avoiding full theme forks. In parallel, plugin authors need a narrow, explicit stable surface so hook/slot integrations are safe across refactors.

## Scope

- Theme engine:
  - support `parent:` resolution
  - deterministic override order (child wins on filename match)
  - clear error messages for missing/invalid parent themes
- Stable API draft (v0):
  - introduce public package for hook/slot contracts (names/constants/types)
  - keep internal packages as implementation details; add bridge/adapters as needed
  - document **Stable v0** vs **Internal**
- Tests:
  - child theme inherits parent templates
  - child overrides one template without copying full theme
  - stable hook/slot contracts compile and map to runtime behavior

## Out Of Scope

- Partial template split (`_header`, `_footer`) — PR-713
- Dev warnings/admin slot catalog — PR-714
- Full plugin API freeze (this PR only drafts hooks/slots stable surface)

## Validation

- Render with parent-only template succeeds from child theme
- Render with child override wins over parent template
- Stable hook/slot constants usable from sample plugin code without importing internal packages
