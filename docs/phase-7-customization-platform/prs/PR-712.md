# PR-712 — Theme Inheritance + Stable API Draft (Track F, OSS)

Status: done

## Summary

- Theme inheritance via `parent:` in `theme.yaml`
- Child themes override templates by filename; parent templates/layout are inherited
- First public Stable v0 draft for hook/slot contracts in `pkg/extapi`

## Why

Theme inheritance improves developer UX by avoiding full theme forks. In parallel, plugin authors need a narrow, explicit stable surface so hook/slot integrations are safe across refactors.

## Scope

- Theme engine:
  - `parent:` resolution (relative or absolute path)
  - deterministic override order (child wins on filename match)
  - circular parent detection and clear missing-parent errors
- Stable API draft (v0):
  - `pkg/extapi` — hook points, slot anchors, placements
  - `docs/guides/EXTENSION_API.md` — Stable v0 vs Internal policy
  - compatibility guard tests in `pkg/extapi/compat_test.go`
- Tests:
  - child inherits parent-only template
  - child override wins; non-overridden pages inherited
  - invalid parent and circular chain errors

## Out Of Scope

- Partial template split (`_header`, `_footer`) — PR-713
- Dev warnings/admin slot catalog — PR-714
- Full plugin API freeze

## Validation

- `go test ./internal/domain/theme/... ./pkg/extapi/...`
- Child theme renders inherited `listing` without local copy
- Child `product` override renders child markup; `listing` still inherited
- `pkg/extapi` constants match internal hook/slot catalogs

## What changed

- **`internal/domain/theme/inherit.go`** — parent chain resolution and template overlay
- **`internal/domain/theme/theme.go`** — `Parent` field in `theme.yaml`
- **`pkg/extapi/`** — Stable v0 hook/slot contracts
- **`docs/guides/EXTENSION_API.md`** — stability policy and usage examples
- Tests: `inherit_test.go`, `pkg/extapi/compat_test.go`
