# PR-709 — Plugin Asset Manifest Injection (Track E, OSS)

Status: done

## Summary

- Plugins declare CSS/JS bundles with route targets and load order
- Storefront layout emits `<link>`/`<script>` with CSP nonce support
- Deterministic merge when multiple plugins register assets

## Why

Small frontend customizations should not require copying the entire theme.

## Scope

- Asset manifest type on `plugin.App` (path, placement: head/footer, routes[])
- Asset collector at request time filtered by current route
- Layout template hooks for injected assets + nonce attribute
- Tests: plugin asset appears on gated route only; order stable across plugins

## Out Of Scope

- Admin asset upload UI
- Bundler/build pipeline for plugins (authors ship static files)

## Validation

- Plugin registers JS for `/cart`; script tag present on cart page only
- CSP nonce on injected script when storefront CSP enabled
- No duplicate includes when same plugin re-registers on reload (dev)

## What changed

- **`internal/application/assets/`** — `Manifest`, `Registry`, route gating, priority ordering, dedup on re-register
- **`internal/platform/plugin/assets.go`** — `SetAssetRegistry`, `Assets(registrant).Register(manifest)`
- **`internal/interfaces/http/storefront_assets.go`** — `WithAssets`, `WithCSPEnabled`, layout asset resolution, CSP header
- **`StorefrontLayoutData`** — `Assets`, `CSPEnabled`, `CSPNonce` fields
- **`themes/default/templates/layout.html`** — head CSS/JS and footer JS injection hooks
- **`internal/platform/config`** — `frontend.csp_enabled` + `SHOPANDA_FRONTEND_CSP_ENABLED`
- **`cmd/api/main.go`** — shared `assetRegistry` wired to plugin app and storefront
- Tests: registry route gating/order/dedup, plugin registration, storefront cart-only asset + CSP nonce
