# PR-717 — Nested `slot_container` Fix (Track F, OSS)

Status: done

## Summary

- Replaced regex-based `slot_container` preprocessing with depth-aware matching
- Nested `slot_container` blocks expand correctly (inner containers first)
- Docs updated: nesting is supported in `PLUGINS.md` and `THEME_SLOTS.md`

## Why

PR-711 documented that nested `slot_container` blocks broke because the preprocessor matched the first `{{/slot_container}}`. Theme authors had to use explicit `slot` markers for nested regions — unnecessary friction when nesting is a natural layout pattern.

## Scope

- `preprocessSlotContainers` — depth-aware open/close pairing; recursive inner expansion
- `findSlotContainerOpen` — anchor match must start at the scanned `{{` (no false positives across `{{ define }}` blocks)
- Tests:
  - unit: nested, sibling, unclosed, page template with defines
  - integration: nested containers render with correct DOM order

## Out Of Scope

- Lint rule for malformed slot blocks (unclosed containers still pass through unchanged)
- Strict anchor validation CI mode (PR-720)
- `layout.yaml` block ordering (PR-716)

## Validation

- `go test ./internal/domain/theme/...`
- `go test ./plugins/slotsdemo/...`
- Existing default theme slot render tests unchanged
