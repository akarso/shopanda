# PR-705 — Cart Item Extension Capture (Track C, OSS)

Status: done

## Summary

- Read/write extension values on `cart_item` targets
- Cart API exposes extensions on line items (admin + storefront cart)
- PDP/add-to-cart path accepts extension payload for declared cart_item fields

## Why

Product-level defaults are not enough; line items need per-row custom data (gift message, engraving, selected option).

## Scope

- Extend cart application layer to validate and store cart_item values
- REST cart endpoints include `extensions` on items when present
- Storefront cart template shows public extension values (simple list renderer)
- Tests: add item with extension, update quantity preserves extensions

## Out Of Scope

- Checkout snapshot to order (PR-706)
- Computed-only fields (resolver hook later)

## Validation

- Add cart line with extension value; GET cart returns value on item
- Invalid field or type rejected at add-to-cart
- Storefront cart page displays public extension label/value

## What changed

- Added `domainext.CartItemTarget(cartID, variantID)` for cart line extension target IDs
- Extended `cart.Service` with optional extension writer: validates on add, upserts after save, deletes on remove, copies on guest merge
- `AddItemOptions` carries `Extensions[]` and `UpdatedBy`; quantity updates preserve stored values
- Cart REST handler accepts `extensions` on add-item body and returns `extensions` on each line item
- Storefront: PDP form fields (`ext__{code}`), add-to-cart passes extensions, cart template lists label/value
- Wired `extensionValueService` into cart service, cart handler, and storefront handler in `cmd/api/main.go`
- Tests: `service_extensions_test.go`, cart handler extension tests, fixed `NewService` / `AddItemOptions` call sites across test suite
