# PR-713 — Layout Partials (Track F, OSS)

Status: done

## Summary

- Split default `layout.html` into `_header.html`, `_nav.html`, and `_footer.html` partials
- Theme engine loads `_*.html` as layout partials (not page templates) with parent/child inheritance
- Child themes can override a single partial without copying the full layout shell

## Why

Monolithic `layout.html` forces theme authors to fork the entire shell to change header, nav, or footer. Partials keep slot markers in place while allowing surgical overrides — the main DX win of theme inheritance (PR-712).

## Scope

- Theme engine:
  - `_*.html` files resolved as partials (skipped from page template registry)
  - partial overlay follows same child-wins-by-filename inheritance as pages and layout
  - partials parsed into the layout template set before page templates
- Default theme split:
  - **`_header.html`** — brand bar, search, account/cart widgets; includes `_nav.html`
  - **`_nav.html`** — primary nav + category nav with `layout.nav` / `layout.category_nav` slots
  - **`_footer.html`** — footer with `layout.footer` slot container
  - **`layout.html`** — DOCTYPE/head/body shell, main slot container, shared `nav-items` / `content-blocks` defines
- Tests:
  - partials are not registered as page templates
  - child overrides `_footer.html` only; inherits parent header and page templates

## Out Of Scope

- Dev warnings / admin slots catalog (PR-714)
- Remaining page anchors (PR-715)
- Theme author guide (PR-719)
- `layout.yaml` block ordering (PR-716)

## Validation

- `go test ./internal/domain/theme/...`
- Default theme slot render tests still pass (all layout anchors present)
- Child theme with only `_footer.html` renders parent header + child footer + inherited product page
