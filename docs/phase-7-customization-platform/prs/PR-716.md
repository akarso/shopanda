# PR-716 — `layout.yaml` Block Ordering (Track F, OSS)

Status: done

## Summary

- Optional `layout.yaml` declares block order within fixed containers (first slice: `pdp.info`)
- Template markers `{{layout_blocks}}` / `{{block}}` preprocess at theme load
- Child themes inherit and override container order via theme `parent:`

## Why

Theme authors needed to reorder PDP info sections (e.g. move actions above description) without duplicating entire templates or adopting Magento-style layout XML.

## Scope

- **`layout.yaml`** — `containers.<name>.blocks` ordered list
- Preprocessor — depth-aware `layout_blocks` / `block` expansion before slot_container pass
- Inheritance — child `layout.yaml` overlays parent per container key
- Default theme — `pdp.info` blocks: meta, description, composition, detail_grid, actions
- Tests — reorder unit tests, product page render order, layout inheritance

## Out Of Scope

- Cross-container block moves
- Runtime merchant reordering / admin UI
- Block ordering on cart, checkout, or other pages (future containers can follow same pattern)

## Validation

- `go test ./internal/domain/theme/... ./internal/infrastructure/themefs/... ./plugins/slotsdemo/...`
- Default theme product page unchanged (layout order matches prior template order)
- Child `layout.yaml` with `actions` first renders actions before meta

## What changed

- **`internal/domain/theme/layout.go`** — `LayoutConfig`, `OrderedBlockNames`, overlay
- **`internal/domain/theme/blocks.go`** — layout block preprocessor
- **`internal/infrastructure/themefs/layout.go`** — load/inherit `layout.yaml`
- **`themes/default/layout.yaml`**, **`themes/default/templates/product.html`**
- **`docs/guides/THEME_SLOTS.md`** — block ordering section
