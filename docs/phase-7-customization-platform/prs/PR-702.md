# PR-702 — Admin Field Registry API (Track A, OSS)

Status: planned

## Summary

- REST CRUD for extension field definitions at `/api/v1/admin/extensions/fields`
- RBAC via existing admin permissions pattern
- Private fields omitted unless `include_private` + capability

## Why

Operators and integrators need to define public custom fields without SQL or plugin redeploys.

## Scope

- `internal/interfaces/http/extension_field_admin.go` — list/get/create/update/delete
- Request/response DTOs aligned with [CUSTOMIZATION_PLATFORM.md](../specs/CUSTOMIZATION_PLATFORM.md) §7.1
- Audit log for definition mutations
- Duplicate field code on `POST` → `409 Conflict` with `code: conflict` (same as attribute/product admin handlers via `apperror.Conflict`)
- Handler tests: CRUD, validation errors, duplicate conflict, private field filtering

## Out Of Scope

- Admin SPA grid for field definitions (stretch backlog)
- Value endpoints (PR-703)

## Validation

- `GET /api/v1/admin/extensions/fields?target_type=product` returns public fields
- `POST` creates field; duplicate code returns `409` with `code: conflict` (never `422`)
- Caller without private capability never sees `visibility=private` definitions
- `go test ./internal/interfaces/http/... -run ExtensionField`
