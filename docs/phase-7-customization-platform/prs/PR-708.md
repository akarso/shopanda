# PR-708 — Slot Registry + Storefront Markers (Track D, OSS)

Status: planned

## Summary

- Template slot markers in default theme (e.g. `{{slot "pdp.after_price"}}`)
- Plugin slot renderer registration with deterministic order
- Render slots on PDP and cart views

## Why

Merchants and plugins need HTML injection points without forking `layout.html` for every feature.

## Scope

- Slot registry service + `RegisterSlotRenderer(name, priority, renderFn)` on plugin port
- Theme templates: add markers on PDP + cart (minimal set)
- Storefront composition loads registered renderers into page data
- Tests: registered renderer output appears in HTML; unknown slot noop

## Out Of Scope

- Admin slot configuration UI
- Every page type (start with PDP + cart)

## Validation

- Reference test plugin registers slot renderer; PDP HTML contains rendered fragment
- Two renderers same slot compose in priority order
- Missing slot marker does not break template parse
