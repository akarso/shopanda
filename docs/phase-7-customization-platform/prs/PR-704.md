# PR-704 — Product Extensions Admin Panel (Track B, OSS)

Status: done

## Summary

- Generic **Extensions** section on product edit in `admin.js`
- Renders public fields for `product` scope with type-appropriate widgets
- Load/save via PR-703 value API

## Why

Merchants need a discoverable place to edit custom product data without API calls.

## Scope

- `admin.js` — `setupProductExtensionsPanel`, widgets for string/int/bool/enum/json/date/datetime
- Wire into product edit flow after core fields
- `admin_handler_test.go` wiring assertions
- Respect read-only when user lacks write permission

## Out Of Scope

- Field definition CRUD UI (API-only in PR-702)
- Plugin custom widget override (stretch)
- Variant-level extension editor

## Validation

- Product edit shows Extensions panel when public fields exist
- Save persists values; reload shows updated data
- Private fields not shown in default panel
- `go test ./internal/interfaces/http/... -run 'TestAdminHandler_StaticJS|ExtensionValue'`

## What changed

- Added `#product-extensions-panel` section to product edit form shell in `admin.js`
- Added `setupProductExtensionsPanel` — loads field defs + values in parallel, hides panel when no public stored fields
- Added helpers: `filterProductExtensionFields`, `buildExtensionValueLookup`, `renderExtensionFieldWidget`, `renderProductExtensionsForm`, `collectExtensionValues`
- Widget mapping: string/textarea, int/money (number), bool (checkbox), enum (select), json (textarea), date, datetime
- Save via `PUT /api/v1/admin/products/{id}/extensions`; read-only when `extensions.write` missing
- Added `extensions.read` / `extensions.write` to client-side admin role permission mirror
- Added `expectedProductExtensionsWiring` assertions in `admin_handler_test.go`
