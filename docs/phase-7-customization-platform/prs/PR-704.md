# PR-704 — Product Extensions Admin Panel (Track B, OSS)

Status: planned

## Summary

- Generic **Extensions** section on product edit in `admin.js`
- Renders public fields for `product` scope with type-appropriate widgets
- Load/save via PR-703 value API

## Why

Merchants need a discoverable place to edit custom product data without API calls.

## Scope

- `admin.js` — `setupProductExtensionsPanel`, widgets for string/int/bool/enum/json
- Wire into product edit flow after core fields
- `admin_handler_test.go` wiring assertions
- Respect read-only when user lacks write permission

## Out Of Scope

- Field definition CRUD UI (API-only in PR-702)
- Plugin custom widget override (stretch)
- Variant-level extension editor

## Validation

- Product edit shows Extensions panel when public fields exist
- Save persists values; reload shows updated data
- Private fields not shown in default panel
- Integration/E2E harness (or handler test with rendered product edit HTML): panel renders, public value save round-trips via value API, reload confirms persistence, private fields stay hidden
- `go test ./internal/interfaces/http/... -run 'TestAdminHandler_.*Extension|TestProductExtensions'`
