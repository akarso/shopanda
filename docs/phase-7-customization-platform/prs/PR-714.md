# PR-714 — Slot Dev Ergonomics + Stable API v0 (Track F, OSS)

Status: planned

## Summary

- Dev-mode diagnostics for slot registrations that do not match current theme markers
- Admin slot catalog endpoint for tooling (`GET /api/v1/admin/extensions/slots`)
- Harden stable API v0 for hooks/slots with compatibility checks and policy docs

## Why

After PR-711/712, developers have a catalog and inheritance model. This PR removes silent failure modes and formalizes compatibility guarantees for the first stable extension surface.

## Scope

- Slot ergonomics:
  - warn in dev mode when a plugin registers an anchor absent from active theme markers
  - keep runtime behavior non-breaking (missing markers remain no-op in production)
- Admin API:
  - expose slot catalog + current registrations in read-only endpoint
  - align payload naming with hooks catalog conventions
- Stable API v0 hardening:
  - publish compatibility policy (deprecation + break window)
  - add compatibility guard tests for stable hook/slot contracts
  - verify tooling/admin endpoints use canonical names from stable contracts

## Out Of Scope

- New page anchors (PR-715)
- Block reordering (`layout.yaml`, PR-716)
- Nested `slot_container` parser changes (PR-717)

## Validation

- Registering unknown slot anchor in dev mode emits warning
- Admin slot catalog endpoint returns deterministic payload
- Compatibility guard tests fail on accidental hook/slot contract breaks
