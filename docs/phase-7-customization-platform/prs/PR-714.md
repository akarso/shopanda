# PR-714 — Slot Dev Ergonomics + Stable API v0 (Track F, OSS)

Status: done

## Summary

- Dev-mode warning when a plugin registers a slot anchor absent from the active theme
- `GET /api/v1/admin/extensions/slots` — read-only catalog + registrations
- Stable API v0 compatibility policy and expanded guard tests

## Why

After PR-711/712/713, developers have a catalog, inheritance, and partials. This PR removes silent slot misconfiguration and formalizes compatibility guarantees for the first stable extension surface.

## Scope

- Slot ergonomics:
  - `themeapp.DeclaredAnchorsFromDir()` — inherited template anchor scan (`internal/application/theme`)
  - `slots.Registry.SetThemeMarkers()` + `SetDevMode()` — warn on `slots.registration.unmarked_anchor` in dev
  - production render behavior unchanged (unmarked anchors remain no-ops)
- Admin API:
  - `GET /api/v1/admin/extensions/slots` (`extensions.read` RBAC)
  - payload mirrors hooks catalog: `name`, `handlers` (`placement`, `priority`, `registrant`)
  - standard catalog entries include `group` and `description`; order follows `extapi.SlotAnchorNames()`
- Stable API v0:
  - expanded `docs/guides/EXTENSION_API.md` compatibility policy (deprecation + break window)
  - expanded `pkg/extapi/compat_test.go` guard tests

## Out Of Scope

- New page anchors (PR-715)
- `layout.yaml` block ordering (PR-716)
- Nested `slot_container` parser fix (PR-717)

## Validation

- `go test ./internal/application/slots/... ./internal/domain/theme/... ./internal/interfaces/http/... ./pkg/extapi/...`
- Dev-mode registration for unmarked anchor emits warning
- Admin slots endpoint returns stable catalog order + handler registrations
- `pkg/extapi/compat_test.go` guards hook/slot contract drift
