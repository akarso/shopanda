# PR-701 — Field Definition Persistence (Track A, OSS)

Status: done

## Summary

- Postgres migration for extension field definitions
- Repository implementing domain port; soft-delete
- Registry loads persisted definitions at startup and merges with plugin registrations

## Why

Field definitions must survive restarts and be manageable without redeploying plugins for merchant-created fields.

## Scope

- `migrations/` — `extension_fields` table (code PK, JSON definition, deleted_at)
- `internal/infrastructure/postgres/extension_field_repo.go`
- Wire repo into registry bootstrap in `cmd/api/main.go`
- Integration tests: save, list by target_type, soft-delete hides from default list

## Out Of Scope

- Value storage (PR-703)
- Admin HTTP (PR-702)
- Multi-store field scoping

## Validation

- Persisted field visible after API restart
- Soft-deleted field omitted from default registry list
- Plugin-registered fields still merge correctly
- `go test ./internal/infrastructure/postgres/... -run ExtensionField`

## What changed

- Added migration `061_create_extension_fields.sql` — `code` PK, JSONB `definition`, `deleted_at` soft-delete
- Added `internal/domain/extension/repository.go` — `FieldRepository` port
- Added `internal/infrastructure/postgres/extension_field_repo.go` — save, find, list by scope, soft-delete
- Added JSON tags + `ToFieldDef()` on domain field types for persistence round-trip
- Added `Registry.LoadPersisted` — merges DB fields after plugin init; plugin registrations win on code conflicts
- Wired repo bootstrap in `cmd/api/main.go` after `InitAll`
- Tests: registry merge unit test; postgres integration tests (`ExtensionField`)
