# PR-1090 — Local SignedURLStorage, private blobs, BindMediaStorage

Status: done

## Summary

- Local filesystem implements `media.SignedURLStorage` via HMAC tokens served at
  `GET /api/v1/media/local-signed/{token}` so storefront download delivery can
  ClaimDelivery then 302 without reinventing a product-side shim.
- Shared private path contract: `PrivateBlobsPrefix` / `IsPrivatePath`; S3 Save
  skips public ACL and uses private Cache-Control for downloads **and** blobs.
- `BindMediaStorage` / `BoundMediaStorage` mirror job queue bind (fail-closed,
  no Register fallback); composition root binds on serve/worker/scheduler/CLIs.

## Why

Metal Dogs (and any product plugin) needed private local delivery + a single
bound media instance after Init. Empty optional `sign_secret` plus duck-typed
route wiring made HA local deploys unsafe and left private blob keys public on S3.

## Scope

- `localfs.NewWithSecret` / `NewEphemeral` (DEV-only); token length caps;
  expiry skew; `Open` + `ServeContent` streaming; always attachment disposition
- `media.LocalSignedHandler`; wire via named interface (not duck-type alone)
- Relative redirect allowlist: single-segment path under
  `/api/v1/media/local-signed/`, reject `..` / `%2e` / host / query / fragment
- Config: require `media.local.sign_secret` when `media.storage=local` unless
  `SHOPANDA_DEV_MODE`; env `SHOPANDA_MEDIA_LOCAL_SIGN_SECRET`
- Docs: config.example.yaml, DEPLOYMENT, DEVELOPER; this PR + index/roadmap

## Out of scope

- Absorbing Metal Dogs product media adapters (post-merge product work)
- Range requests beyond what `http.ServeContent` already provides
- Changing public `uploads/` ACL defaults
