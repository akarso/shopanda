# PR-1094 — Retire plugin-only extension field definitions

Status: planned

## Summary

- Give operators a supported way to retire a plugin-only definition (for example after uninstalling its plugin).

## Why

Plugin-only definitions are immutable via the API, so uninstalled plugins leave permanent fields; today the only way out is a manual SQL soft-delete plus restart.

## Scope

- One explicit operator path (CLI command, e.g. `app extension-field retire <code>`), audited, that soft-deletes a plugin-only definition and optionally purges its values.
- The admin HTTP API keeps refusing (`plugin_only_field_immutable`).
- Document the one-way latch (making an ordinary field plugin-only via the API) and the retire procedure in RUNBOOK.md.

## Out of scope

- Anything not listed above (one PR = one responsibility).

## Validation

- CLI integration test against Postgres (`SHOPANDA_TEST_DSN`); registry reload after retire.
- Docs: RUNBOOK.md, DEPLOYMENT.md if config/flags are added.
- `go test ./...`; `make check` once PR-1096 has landed.
