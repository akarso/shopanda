# PR-1089 — Sync job observability (request_id, Attempts, JobResult, CountsByType)

Status: done

## Summary

Platform-owned HTTP→job correlation, attempt/duration metrics, and per-type
queue depth so product plugins do not reimplement the same plumbing.

## Why

Checkout/`order.created` and other event-triggered sync jobs need the same
`request_id` correlation as manual `Enqueue(r.Context(), …)`, plus honest
success/failure duration metrics operators can dashboard.

## Scope

- `plugin.InjectRequestID` + injection on Enqueue / sync enqueue paths
  (treat empty/nil/non-string as unset)
- `event.Bus.Publish` / `PublishAsync(ctx, …)` stamp `Meta["request_id"]`;
  async dispatch annotates shutdown ctx; sync event triggers copy Meta into
  payload (PublishAsync takes ctx so sync-failure fallbacks keep correlation)
- `extapi.SyncJobContext.Attempts` from dequeued job
- Worker: `request_id` / `duration_ms` logs; `JobResult` after successful
  Complete (Complete failure → failed); unknown type records JobResult
- `jobs.Reader.CountsByType` (+ Postgres + `application/jobs.Service`,
  TrimSpace empty check)
- `requestctx.Middleware` caps/normalizes inbound `X-Request-ID`
- Job duration histogram buckets through 5m; Prometheus outcome clamp
- Guide: `docs/guides/SYNC_JOB_OBSERVABILITY.md`

## Out of scope

- Changing `/healthz` / `/readyz`
- Free-form job types
- Product-specific `correlation_id` naming (alias at the product plugin)
- Optional `jobs.Reader` interface split (CountsByType is required; out-of-tree
  Readers must implement it — same pattern as prior Reader growth)
- Migrating out-of-tree / product-fork call sites of the old
  `PublishAsync(evt)` signature (in-tree callers updated in this PR)

## What changed

- Bus correlation for OnAsync without inheriting Publish cancel
- Worker JobResult ordering / unknown-type / complete_failed log fields
- Request ID normalization before durable storage
- Tests: worker JobResult outcomes, Complete-failure interaction, Attempts
  via Dequeue, Publish→OnAsync→envelope `request_id`

## Follow-up

- **API break:** `PublishAsync(evt)` → `PublishAsync(ctx, evt)`. Product/fork
  call sites that use Publish-then-`PublishAsync` sync-failure fallbacks must
  pass the request context (or otherwise stamp `Meta["request_id"]`) or
  correlation is dropped on that path. In-tree callers are updated.
- Product sites with alternate `jobs.Reader` must add `CountsByType`.
