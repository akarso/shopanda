# PR-1088 — SDK + docs + example

Status: done

## Summary

- `pluginsdk` helpers: `RegisterManual` + `Enqueue` (run-now); document `RegisterOnEvent` as the primary event→queue path.
- `plugins report` shows `trigger=manual` / `trigger=cron(…)` / `trigger=event(…)`.
- Example plugin uses `RegisterOnEvent("demo.order_created", order.created, …)` so envelope `trigger=event`.
- Core: checkout emits `order.created` after save and `order.failed` when unpaid compensation transitions pending→failed (merchant webhooks + example job).

## Why

PR-1087 is unused if authors cannot find it. Phase 8 already taught `RegisterCron` / `RegisterOnEvent`; this PR surfaces Manual for “run later” without teaching Manual as the default event path. Emitting `order.created` without `order.failed` would leave webhook/ERP subscribers with phantom orders when a later checkout step fails.

## Scope

- `pkg/pluginsdk` — `RegisterManual` + `Enqueue` (same pattern as PR-850).
- PLUGINS.md, DEVELOPER.md, EXTENSION_POINTS.md, PLUGIN_COMPOSITION.md, example README.
- `./app plugins report` text format includes `trigger=<kind>`.
- `plugins/example`: `RegisterOnEvent` + publish→enqueue test (queue arg, not BindQueue); handler reads post-JSON `map` under `"data"`; separate `Enqueue`/BindQueue run-now test.
- Checkout `CreateOrderStep` publishes `order.created` after save; unpaid compensation / `payment.failed` publish `order.failed` when `FailIfPending` changes status (activates the existing webhook subscription list entry).

## Out Of Scope

- New reference plugin (warehouse demo stays cron).
- Generic job types.
- Admin GUI for plugin jobs (Phase 11 jobs UI is enough).
- Changing `eventPayload` wrapping of typed structs (`{"data": …}`).
- Moving `order.created` to post-`checkout.completed` (kept at create time; pair with `order.failed`).
- Publishing `order.failed` / `order.cancelled` / `order.confirmed` from admin or integration `StatusService.ApplyStatus` (still only `order.paid` there).

## What changed

- `pkg/pluginsdk/sync.go` — `RegisterManual`, `Enqueue`.
- `internal/application/pluginreport` — text lines use `trigger=…`.
- `plugins/example` — `RegisterOnEvent` (not Manual+OnAsync→Enqueue); handler/README teach JSON-map `data` after dequeue (typed assert only on in-memory queues).
- `internal/application/order` — `PublishCreated` / `PublishFailed`.
- Checkout: `CreateOrderStep` → `order.created`; `compensateUnpaidOrder` + `compensateFailedPayment` → `order.failed` on pending→failed (publish errors are logged; credit restore / revoke still run).
- Docs + phase index/roadmap (Phase 13 site-ready gate complete).
