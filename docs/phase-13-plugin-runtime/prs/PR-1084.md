# PR-1084 — `RunPluginFS` + lock + namespaced versions

Status: planned

## Summary

- Add `migrate.RunPluginFS(db, pluginName, fsys, dir)` that applies pending SQL like `RunFS`, but records versions as `plugin:{pluginName}:{basename}` and holds a PostgreSQL advisory lock for the whole apply batch.

## Why

`schema_migrations` tracks by basename. Core tests already hit this (PR-1003). B2B’s `001_create_customer_groups.sql` is unique only by luck. `RunFS` has no lock; `serve` and `worker` both `Init` and can both attempt the same `CREATE TABLE`.

## Scope

- `internal/platform/migrate` — `RunPluginFS`, lock, namespaced insert/lookup.
- Reject empty/whitespace `pluginName`.
- Leave `Run` / `RunFS` and core `migrations/` hygiene unchanged.
- Unit tests: namespace key shape; second plugin with the same basename is a different version; concurrent apply does not double-apply (advisory lock).

## Out Of Scope

- Switching B2B over (PR-1085).
- `RegisterMigrations` / `app migrate` (PR-1086).

## Follow-up

- PR-1085 — B2B consumer + backfill of old basename rows.
