# PR-1086 — `Migrator` + `app migrate`

Status: done

## Summary

- Plugins that own SQL implement optional `plugin.Migrator` (`Migration() MigrationSpec`) — one FS / dir / options declaration per plugin.
- `app migrate` / `setup` apply core `migrations/` then every Migrator FS via `RunPluginFSOptions` (**no `InitAll`**).
- `InitAllContext` applies each Migrator **before** `Init` when `Bootstrap.DB` is set; panics recovered; fail-fast on first Migrator error. Every `InitAll` caller fails on `DependsOnErr` / `MigrateFailed` via `InitSummaryError`. Boot signal contexts are checked after Stop so SIGTERM during wiring exits.

## Why

Operators already treat `app migrate` as the schema step. Calling `InitAll` on that path forced broker/Redis dials and full app wiring. Declaring SQL on the plugin type keeps migrate Postgres-only and makes the boot safety net automatic.

## Scope

- `plugin.Migrator` (single `MigrationSpec`), `CollectMigrations(dependsOn)`, `ApplyMigrationRegistrations`, `MigrateResult`.
- Panic recovery around `Migration()` and apply; typed-nil FS rejected via `ReadDir`.
- `depends_on` sort errors fail migrate **and** InitAll when any Migrator is registered.
- `InitAllContext(ctx)`; `PluginMigrateApply` / `PluginMigrateVerify`; `InitSummaryError`.
- B2B implements `Migrator`; Init does not call `RunPluginFS`.
- Docs + tests (no-DSN collect/panic/depends_on/entry state).

## Out Of Scope

- Down migrations / separate `plugin_schema_migrations` table.
- Multiple MigrationSpecs per plugin.

## What changed

- `internal/platform/plugin` — Migrator + collect/apply; InitAll pre-Init apply with recover; live entry state under depends_on.
- `plugins/b2b` — `Migration()` only.
- `cmd/api` — migrate/setup without InitAll; serve/worker/scheduler use InitAllContext + buffered boot-signal watcher (Stop retains a late SIGTERM); all short-lived CLIs (incl. discovery facet sync) use PluginMigrateVerify / InitSummaryError.
- Docs: PLUGINS, DEPLOYMENT, RUNBOOK, B2B README, phase index/roadmap.
