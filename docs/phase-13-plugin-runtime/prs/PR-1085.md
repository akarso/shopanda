# PR-1085 — Move B2B onto `RunPluginFS`

Status: done

## Summary

- B2B `Init` calls `RunPluginFS` with plugin name `shopanda/b2b` instead of `RunFS`.
- Legacy bare basename rows are adopted for a **frozen allowlist** (`001`–`004`) under the same per-file lock/tx, without re-executing DDL.
- Fresh applies of those four also dual-write the bare key (rollback-safe for pre-1085 binaries).

## Why

PR-1084 is unused until the one in-tree plugin with tables uses it. Changing the version key without a scoped backfill would re-exec DDL on every shop that already ran B2B `Init`, or silently skip DDL if a future basename collided with core/`RunFS`.

## Scope

- `migrate.PluginFSOptions.AdoptBareBasenames []string` (not a boolean) — claim namespaced key first, then adopt if bare exists and basename is allowlisted; dual-write bare on fresh allowlisted apply.
- `PluginFSResult{Applied,Adopted}`; B2B logs when `Adopted > 0`.
- B2B `Init` lock wait 30s/file, 2-minute overall timeout; `ErrMigrationLockHeld` fails boot (documented).
- Tests: adopt allowlist, flag-off re-exec, mixed state, dual-write, concurrent adopt; B2B fresh reset + atomic adopt rewrite.
- `RUNBOOK.md` + B2B README: key format, reset, lock wait, rollback policy.

## Out Of Scope

- `RegisterMigrations` / `app migrate` (PR-1086).
- Renaming SQL files.

## What changed

- `internal/platform/migrate` — `AdoptBareBasenames`, `PluginFSResult`, claim-then-adopt, dual-write bare.
- `plugins/b2b` — `pluginName`, `LegacyBareMigrationBasenames`, bounded Init migrate, logging.
- `plugins/b2b/migrations_test.go`, `export_test.go` — embed-derived basenames + adopt/fresh tests.
- `RUNBOOK.md`, `plugins/b2b/README.md` — operator notes.
