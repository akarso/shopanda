# PR-1085 — Move B2B onto `RunPluginFS`

Status: done

## Summary

- B2B `Init` calls `RunPluginFS` with plugin name `shopanda/b2b` (`Name()`) instead of `RunFS`.
- Treat already-applied B2B basenames as applied under the new keys so existing deployments do not re-run DDL.

## Why

PR-1084 is unused until the one in-tree plugin with tables uses it. Changing the version key without a backfill would re-exec `CREATE TABLE` (and 003/004 constraint work) on every shop that already ran B2B `Init`.

## Scope

- `plugins/b2b/migrations.go` — `RunPluginFSOptions(ctx, db, Name(), …, AdoptBareVersions: true)`.
- **Backfill every embedded basename** that already has a bare-key row in `schema_migrations` and no namespaced `plugin:shopanda/b2b:{basename}` row: insert the namespaced key only (do not re-exec SQL). Not hard-coded to 001/002 — every file under `migrations/` is considered.
- Backfill runs **inside the same per-file advisory lock / transaction as apply** (`migrate.PluginFSOptions.AdoptBareVersions`).
- B2B plugin/init tests + migrate adopt tests; integration when `SHOPANDA_TEST_DSN` is set.
- `plugins/b2b/README.md` notes namespaced versions.

## Out Of Scope

- Registering migrations on `plugin.App` (PR-1086).
- Renaming the SQL files.

## What changed

- `internal/platform/migrate` — `PluginFSOptions.AdoptBareVersions`; under lock, remap bare → namespaced before claim+exec.
- `plugins/b2b/migrations.go` / `plugin.go` — `RunPluginFSOptions` with adopt; name from `Name()`.
- `plugins/b2b/migrations_test.go`, `export_test.go` — namespaced recording + legacy adopt.
- `plugins/b2b/README.md` — migration tracking note.
