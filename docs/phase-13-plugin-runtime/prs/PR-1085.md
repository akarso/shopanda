# PR-1085 — Move B2B onto `RunPluginFS`

Status: planned

## Summary

- B2B `Init` calls `RunPluginFS` with plugin name `shopanda/b2b` (`Name()`) instead of `RunFS`.
- Treat already-applied B2B basenames as applied under the new keys so existing deployments do not re-run DDL.

## Why

PR-1084 is unused until the one in-tree plugin with tables uses it. Changing the version key without a backfill would re-exec `CREATE TABLE` (and 003/004 constraint work) on every shop that already ran B2B `Init`.

## Scope

- `plugins/b2b/migrations.go` — `RunPluginFS(ctx, db, Name(), …)`.
- **Backfill every embedded basename** that already has a bare-key row in `schema_migrations` and no namespaced `plugin:shopanda/b2b:{basename}` row: insert the namespaced key only (do not re-exec SQL). Do **not** hard-code 001/002 — deployments may already have 003 and 004 under bare keys; re-running them under new keys is luck today, not a contract.
- Backfill must run **inside the same per-file advisory lock / transaction as apply** for that basename (extend the runner with an optional remap hook, or claim the namespaced key from the bare row under the lock before exec). Otherwise `serve` and `worker` can race.
- B2B plugin/init tests updated; integration test when `SHOPANDA_TEST_DSN` is set.
- `plugins/b2b/README.md` notes namespaced versions.

## Out Of Scope

- Registering migrations on `plugin.App` (PR-1086).
- Renaming the SQL files (unnecessary once the tracking key is namespaced; renaming would desync old basename rows).

## Follow-up

- PR-1086 — `app migrate` applies registered plugin FS.
