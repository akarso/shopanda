# PR-1085 — Move B2B onto `RunPluginFS`

Status: done

## Summary

- B2B `Init` calls `RunPluginFS` with plugin name `shopanda/b2b` instead of `RunFS`.
- Legacy bare basename rows are adopted for a **frozen allowlist** (`001`–`004`) under the same per-file lock/tx, without re-executing DDL.
- Fresh applies of those four also dual-write the bare key (rollback-safe for pre-1085 binaries).

## Why

PR-1084 is unused until the one in-tree plugin with tables uses it. Changing the version key without a scoped backfill would re-exec DDL on every shop that already ran B2B `Init`, or silently skip DDL if a future basename collided with core/`RunFS`.

## Scope

- `migrate.PluginFSOptions.AdoptBareBasenames []string` — claim namespaced key first, then adopt if bare exists and basename is allowlisted; dual-write bare on fresh allowlisted apply; **error if an allowlist entry is missing from the FS**.
- `PluginFSResult{Applied,Adopted}` return type (API change from `int`); B2B logs when either count is non-zero.
- B2B `Init` lock wait = `DefaultPluginLockWait` (5m/file, lock only; no overall DDL timeout).
- Probe/connection errors after SQL must not `DELETE` version rows (peer may have committed); stale-claim clear only when the in-tx probe positively sees an ended transaction, and then under the plugin lock.
- Tests: adopt allowlist validation, flag-off re-exec, mixed state, dual-write, concurrent adopt; B2B fresh/adopt assert `PluginFSResult`; allowlist ⊆ embed FS (no DSN); probe-error peer-claim retention; short lock wait vs long peer SQL.
- `RUNBOOK.md` + B2B README + `DEPLOYMENT.md`: key format, reset, lock wait, rollback policy.

## Out Of Scope

- `RegisterMigrations` / `app migrate` (PR-1086).
- Renaming SQL files.

## What changed

- `internal/platform/migrate` — `AdoptBareBasenames`, `PluginFSResult`, claim-then-adopt, dual-write bare, allowlist ⊆ FS check, safe stale-claim clear.
- `plugins/b2b` — unexported legacy allowlist (`001`–`004` frozen), Init lock wait = 5m, migration result logging.
- `plugins/b2b/migrations_test.go`, `export_test.go` — embed-derived basenames + outcome assertions.
- `RUNBOOK.md`, `plugins/b2b/README.md`, `DEPLOYMENT.md` — operator notes.
