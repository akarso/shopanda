# PR-1092 — Field ownership for plugin-only extension fields

Status: planned

## Summary

- Record which plugin registered an extension field and enforce it on plugin-only writes.

## Why

Today "plugin-only" means trusted in-process code that knows the field code; plugin A can write plugin B's field and the `plugin:<name>` label is advisory (see PR-1091 Known limits).

## Scope

- `app.Extensions()` gets a scoped, named wrapper (like `app.Hooks(name)`); `RegisterField` records the owner on the registry entry.
- `WithPluginWrite(ctx, registrant, codes...)` (app entry point) rejects codes owned by another plugin; `updated_by = plugin:<owner>` becomes trustworthy.
- Compatibility: unnamed `app.Extensions().RegisterField` keeps working (owner empty = any trusted code may write).

## Out of scope

- Anything not listed above (one PR = one responsibility).

## Validation

- Test that currently pins accepted cross-plugin writes (`TestValueService_PluginOnlyWrite_AnyPluginMayNameAnyCode`) flips to rejected for owned fields.
- Docs: EXTENSION_POINTS.md, PLUGINS.md; no schema change.
- `go test ./...`; `make check` once PR-1096 has landed.
