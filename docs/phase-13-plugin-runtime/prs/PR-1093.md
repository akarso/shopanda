# PR-1093 — Narrow port for core-internal extension operations

Status: done

## Summary

- Stop exposing `DeleteAllForTarget` / `CopyTarget` / snapshot on the same service as request-facing methods.

## Why

These methods intentionally skip the PluginOnlyWrite guard and today rely on caller discipline; a mistaken wire-up to a handler would bypass it with no compile-time barrier.

## Scope

- Extract a small core-internal port (cart line removal, orphan cleanup, claim/merge copy, order snapshot) implemented by `ValueService`.
- Cart and checkout services depend on the narrow port; HTTP handlers, GraphQL and the admin API only see the validated, gated methods.
- No behavior change.

## What changed

- `internal/application/extension/value_ports.go`: `ValueAPI` (request-facing: `Registry`, `List`, `ListByOrderItems`, `UpsertBatch`, `Delete`) and `CoreValueOps` (`DeleteAllForTarget`, `DeleteOrphanCartItemExtensions`, `CopyTarget`, `SnapshotCartItemToOrderItem`), both implemented by `*ValueService`.
- Storefront (cart, order, checkout, SSR), admin (value admin, order admin) and the GraphQL resolver now depend on `extensionapp.ValueAPI`; constructors/`WithExtensions` take the interface. Wiring passes the same `*ValueService`.
- Cart and checkout keep their local interfaces, each a subset of `CoreValueOps` plus the gated methods they use; wiring checks them at compile time.
- `value_ports_test.go` pins both method sets, so adding an ungated method to `ValueAPI` fails a test.
- Caveat: handlers now receive an interface; wiring never passes a nil `*ValueService`, but a typed-nil pointer would be a non-nil interface. No behavior change; no C4 change (no new component).

## Out of scope

- Anything not listed above (one PR = one responsibility).

## Validation

- Compile-level: handlers' dependency types no longer expose the ungated methods.
- Existing cart claim/merge/remove/snapshot tests stay green.
- `go test ./...`; `make check` once PR-1096 has landed.
