# PR-1093 — Narrow port for core-internal extension operations

Status: planned

## Summary

- Stop exposing `DeleteAllForTarget` / `CopyTarget` / snapshot on the same service as request-facing methods.

## Why

These methods intentionally skip the PluginOnlyWrite guard and today rely on caller discipline; a mistaken wire-up to a handler would bypass it with no compile-time barrier.

## Scope

- Extract a small core-internal port (cart line removal, orphan cleanup, claim/merge copy, order snapshot) implemented by `ValueService`.
- Cart and checkout services depend on the narrow port; HTTP handlers, GraphQL and the admin API only see the validated, gated methods.
- No behavior change.

## Out of scope

- Anything not listed above (one PR = one responsibility).

## Validation

- Compile-level: handlers' dependency types no longer expose the ungated methods.
- Existing cart claim/merge/remove/snapshot tests stay green.
- `go test ./...`; `make check` once PR-1096 has landed.
