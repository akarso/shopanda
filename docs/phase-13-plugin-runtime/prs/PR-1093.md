# PR-1093 — Narrow port for core-internal extension operations

Status: done

## Summary

- Stop exposing `DeleteAllForTarget` / `CopyTarget` / snapshot on the same service as request-facing methods.

## Why

These methods intentionally skip the PluginOnlyWrite guard and today rely on caller discipline; a mistaken wire-up to a handler would bypass it with no compile-time barrier.

## Scope

- Extract a small core-internal port (cart line removal, orphan cleanup, claim/merge copy, order snapshot) implemented by `ValueService`.
- Cart and checkout services depend on the narrow port; HTTP handlers, GraphQL and the admin API only see the validated, gated methods.
- No behavior change.

## What changed

- `internal/application/extension/value_ports.go`: `ValueAPI` (request-facing: `Registry`, `List`, `ListByOrderItems`, `UpsertBatch`, `Delete`), implemented by `*ValueService` (compile-time assertion). The ungated operations (`DeleteAllForTarget`, `DeleteOrphanCartItemExtensions`, `CopyTarget`, `SnapshotCartItemToOrderItem`) are not on it; cart and checkout keep their own local interfaces for the subset they use. (An exported `CoreValueOps` interface was dropped in review: nothing consumed it.)
- Storefront (cart, order, checkout, SSR), admin (value admin, order admin) and the GraphQL resolver depend on `extensionapp.ValueAPI`.
- **Nil safety:** `AsValueAPI(*ValueService)` returns an untyped nil for a nil pointer; all wiring (`wire_services.go`, `wire_routes.go`) goes through it so handlers' `== nil` checks keep working (a typed nil in an interface is non-nil). Tested.
- Tests: `ValueAPI` has none of the ungated method names (and `ValueService` still has them, so a rename cannot empty the check); `AsValueAPI` nil behavior; an admin handler test driven by a fake `ValueAPI` (substitutability; Delete → 403).
- Honest limits: the guarantee is compile-time for constructors, not against a handler type-asserting the interface back to `*ValueService`; `Registry()` still returns the concrete `*Registry` (pre-existing). The GraphQL plugin builds its own `ValueService`: it holds only the repo and the shared `App.ExtensionRegistry()` (where the ownership/plugin-only state lives), so there is no state to diverge from the REST instance. No behavior change; no C4 change.
- CI note: `scripts/ci/unit.sh` runs `go vet ./...`, which already fails on `origin/dev` (copied lock in `download_account_test.go`); fixed in PR-1096, not here.

## Out of scope

- Anything not listed above (one PR = one responsibility).

## Validation

- Compile-level: handlers' dependency types no longer expose the ungated methods.
- Existing cart claim/merge/remove/snapshot tests stay green.
- `go test ./...`; `make check` once PR-1096 has landed.
