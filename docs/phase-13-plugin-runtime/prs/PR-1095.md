# PR-1095 — Trust-propagation hardening and coverage gaps

Status: done

## Summary

- Strip the plugin-write marker at remaining core ctx-forwarding choke points (pricing pipeline, checkout workflow, job worker) and close the test gaps deferred from PR-1091.

## Why

PR-1091 stripped the marker in the event bus and `cart.AddItem` only. Pricing steps, checkout steps, and job handlers could still inherit a grant when callers forwarded a trusted ctx.

## Scope

- Strip at:
  - `pricing.Pipeline.Execute` (`pluginwrite.Strip`)
  - `checkout.Workflow.Execute` (`extensionapp.StripPluginWrite`, after recover/compensate defers)
  - `jobs.Worker.safeHandle` (`pluginwrite.Strip`)
- Lint: `TestRequiredStripSitesPresent` requires an active (non-comment) strip call at each listed dispatcher; `plugin_write.go` and webhook delivery are not listed (wrapper / no extension-write path).
- Tests: strip preserves cancel + request id and clears every granted code; re-`Grant` on stripped ctx sticks; order_item admin PUT → `forbidden_plugin_only_field` with empty repo; create-order plugin-only snapshot via `Workflow.Execute` with a trusted parent; `WithPluginWrite` panic in a job → failed job (not process crash); `PluginWriteContext` returns the error; definition-guard repo error → HTTP 500 on PUT and DELETE without leaking the repo message.
- Docs: `EXTENSION_POINTS.md` + `plugin_write.go` / `App.WithPluginWrite` panic and strip-site wording.

## Out of scope

- Automatic discovery of new ctx-forwarding dispatchers (allowlist remains manual).
- Import-boundary rule forbidding domain → `pluginwrite` (choke points stay next to the callback).
- Extra strip on `DeliverHandler` (worker already strips; delivery is not an extension-write path).
- PR-1096 gofmt/vet cleanup.
- Dedicated `plugin.App` port to add a cart line.
