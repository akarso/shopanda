# PR-852 — Replace-by-Name Pipeline Steps

Status: done

## Summary

- `RegisterPricingStep(step, replace:<step>)` substitutes a plugin step for a named core pricing step
- `pkg/extapi.ReplacePricingStep` and `pluginsdk.Replace` helpers for plugin authors
- `MergePluginSteps` applies replacements before before/after inserts; duplicate replace rejected at merge and registration

## Why

PR-810 added `before:` / `after:` positioning, but integrators replacing core behavior (e.g. custom VAT instead of default tax step) still had no first-class seam. Replace-by-name lets one plugin occupy the core step slot without forking `main.go`.

## Scope

- `internal/application/pricing/position.go` — `StepPositionReplace`, replace merge semantics
- `internal/platform/plugin/pricing_steps.go` — validate replace positions; panic on duplicate replace target
- `pkg/extapi/pricing.go` — `ReplacePricingStep`
- `pkg/pluginsdk/pricing.go` — `Replace` helper
- Unit tests for parse, merge, registration, extapi, pluginsdk

## Out Of Scope

- Reference tax replacement plugin (PR-853)
- Checkout / composition replace-by-name
- Admin merged pipeline preview with live core instances (PR-851)

## API

```go
// extapi
app.RegisterPricingStep(myVATStep{}, extapi.ReplacePricingStep("tax"))

// pluginsdk
sdk.Pricing().Register(myVATStep{}, pluginsdk.Replace("taxes")) // alias → tax
```

Replace registrations:

- Occupy the core step's slot in the merged pipeline (core step removed)
- Allow `before:tax` / `after:tax` to anchor on the replaced step name
- Panic at registration if two plugins replace the same core step (aliases normalized)
- Error at merge if replace target is not present in the core pipeline

## Validation

## What changed

- Integrators can replace named core pricing steps (one winner per step) instead of stacking duplicates
