# PR-832 — Idempotency Store

Status: done

## Summary

- Add `Idempotency-Key` dedupe middleware for inbound integration mutating requests
- Ship `IdempotencyStore` port with in-memory implementation for tests and Postgres repo for production
- Wire Postgres store on `plugin.App`; `RegisterSecureRoute` applies idempotency after auth when store is configured

## Why

PR-831 secured inbound ERP routes with API key and optional HMAC. ERP systems retry POST callbacks on timeouts; without idempotency, duplicate order-status updates could apply twice. PR-832 adds safe replay semantics before the reference plugin (PR-833).

## Idempotency model

**Header:** `Idempotency-Key` (optional; when absent, request passes through)

**Methods:** POST, PUT, PATCH, DELETE when key is present

**Request fingerprint:** SHA-256 hex of raw body

| Outcome | HTTP | Error code |
| --- | --- | --- |
| First claim | runs handler, stores response | — |
| Same key + same body | replays stored status/body | `X-Idempotency-Replayed: true` |
| Same key + different body | 409 Conflict | `idempotency.conflict` |
| Same key in flight | 409 Conflict | `idempotency.in_progress` |

Default TTL: 24 hours (Postgres `expires_at` column).

Middleware order on secure routes: **auth → idempotency → handler**.

## Plugin API

No plugin changes required. When the API process wires `SetIntegrationIdempotencyStore`, secure routes dedupe automatically:

```go
app.Integration("acme").RegisterSecureRoute("POST", "order-status", auth, handler)
// ERP retries with same Idempotency-Key + body replay the first response
```

## Validation

- `go test ./pkg/integrationhttp/... ./internal/platform/plugin/...`
- `go build ./cmd/api/`
- First POST with key runs handler; retry replays response without second handler call
- Same key with different body → `idempotency.conflict`
- Unauthenticated retry does not consume idempotency slot (auth runs first)

## What changed

- Inbound integration POST retries are safe: duplicate ERP callbacks replay the original response instead of re-running handlers
