# PR-840 — Sync Job Registration Port

Status: done

## Summary

- Add `RegisterSyncJob` on `app.Integration(slug)` for outbound integration work
- Support cron (`@every 5m` or 5-field cron) and event triggers with queue-backed retry
- Wire handlers on worker, event triggers on API process, cron triggers on scheduler

## Why

Track E starts with a documented way for plugins to register outbound sync work (warehouse pull, PIM push) without ad hoc cron binaries or direct queue handler registration in `cmd/api/main.go`.

## Scope

- `pkg/extapi/sync_job.go` — `SyncJob`, `SyncJobContext`, `OnEvent`, `Cron`, job type helper
- `internal/infrastructure/cron/normalize.go` — `@every` shorthand → 5-field cron
- `internal/platform/plugin/sync_job.go` — registration + duplicate detection
- `internal/application/integration/sync_runtime.go` — enqueue, worker handlers, trigger wiring
- `cmd/api/main.go` — wire handlers (worker), events (server), cron (scheduler/dev)
- Unit tests (registration, event enqueue, cron normalize)

## Out Of Scope

- `pkg/integrationsdk` HTTP/GraphQL helpers (PR-841)
- Reference warehouse/PIM plugins (PR-842–843)
- Registration report CLI (PR-851)

## Plugin API

```go
app.Integration("acme").RegisterSyncJob(extapi.SyncJob{
    Name:    "warehouse.stock",
    Trigger: extapi.Cron("@every 5m"),
    Handler: pullStockLevels,
})
app.Integration("acme").RegisterSyncJob(extapi.SyncJob{
    Name:    "pim.enrich",
    Trigger: extapi.OnEvent("catalog.product.updated"),
    Handler: syncProductToPIM,
})
```

Queue job type: `integration.sync.{slug}.{name}` (e.g. `integration.sync.acme.warehouse.stock`).

Handler context includes `DB`, `Logger`, event `Payload`, and job metadata. Read plugin config via closure during `Init` (same pattern as other reference plugins).

### Process wiring

| Trigger | Enqueued from | Executed on |
| --- | --- | --- |
| Event | API server (`bus.OnAsync`) | Worker |
| Cron | Scheduler (`scheduler` cmd or dev embedded scheduler) | Worker |

Failures reuse the existing `jobs.Queue` retry contract (`MaxRetries` optional per job).

## Validation

- `go test ./pkg/extapi/... ./internal/platform/plugin/... ./internal/application/integration/... ./internal/infrastructure/cron/...`
- `go build ./cmd/api/`
- Register cron + event jobs → distinct job types, no duplicate registration
- Event publish enqueues job with event payload
- `@every 5m` normalizes to `*/5 * * * *`

## What changed

- Plugins register outbound sync jobs through a single port; core wires queue retry and trigger scheduling
