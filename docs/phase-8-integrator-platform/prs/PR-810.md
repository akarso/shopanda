# PR-810 — Pricing Step Positioning

Status: done

## Summary

- `RegisterPricingStep(step, position...)` — optional `before:<step>` / `after:<step>` positions
- Canonical core step catalog + aliases (`promotions` → `cart_promotions`, `taxes` → `tax`, …)
- `MergePluginSteps` wires plugin steps into the core pricing pipeline at startup
- Stable v0 constants in `pkg/extapi` (`PricingStepCatalog`, `AfterPricingStep`, `BeforePricingStep`)

## Why

Integrators need custom price rules **after promotions** or **before tax** without forking `main.go`. Append-only registration forced all plugin steps immediately after base price.

## Scope

- `internal/application/pricing/position.go` — parse, merge, `CoreStepCatalog`
- `internal/platform/plugin/pricing_steps.go` — positioned registration + `PricingStepRegistrations()`
- `cmd/api/main.go` — build core pipeline then merge plugin steps
- `pkg/extapi/pricing.go` — stable step names for plugin authors
- Example plugin fee step uses `after:promotions`
- Unit tests for merge, registration, extapi compat

## Out Of Scope

- Replace-by-name steps (PR-852)
- Checkout step positioning
- Admin introspection of pipeline order (PR-851)
- Cart hooks (PR-811)

## API

```go
// Default: after:base (same as omitting position — legacy behavior)
app.RegisterPricingStep(myStep{})

// After catalog + cart promotions, before tax
app.RegisterPricingStep(myStep{}, extapi.AfterPricingStep("promotions"))
app.RegisterPricingStep(other{}, "before:tax")
```

### Core step catalog (stable v0)

| Name | Step |
| --- | --- |
| `base` | Base price lookup |
| `catalog_promotions` | Catalog-wide promotions |
| `cart_promotions` | Cart/coupon promotions |
| `tax` | Tax calculation |
| `finalize` | Totals aggregation |

Aliases: `base_price`, `discounts`, `promotions`, `taxes`, `finalization`.

Invalid positions panic at registration (fail fast at startup).

## Validation

- `go test ./internal/application/pricing/... ./internal/platform/plugin/... ./pkg/extapi/...`
- `go build ./cmd/api/`
- Plugins without position still run after `base` (B2B group price unchanged)
- Example fee runs after promotions when enabled

## What changed

- Positioned pricing step registration
- Pipeline merge at startup replaces manual append in `main.go`
- extapi pricing catalog for plugin authors
