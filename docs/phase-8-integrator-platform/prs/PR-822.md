# PR-822 — Import Context + Errors

Status: done

## Summary

- Add `Skip` flag and structured `ImportError` to import row context (`importctx` + `extapi`)
- Row hook chain may skip rows silently or append coded errors; importers fail rows after chain
- All importer results expose aggregated `RowErrors []ImportError` alongside string `Errors`

## Why

PR-820–821 wired hooks into importers; integrators need non-throwing validation (`AppendError`) and intentional row skip (`SkipRow`) without aborting the whole import file.

## Scope

- `internal/application/importctx/errors.go` — `ImportError`, `AppendError`, `SkipRow`
- `RowContext` / `ImportRowContext` — `Skip`, `Errors` fields
- `internal/platform/plugin/import.go` — sync skip/errors across extapi bridge
- `internal/application/importer/rowhooks.go` — `RowHookOutcome`, `HandleRowHookOutcome`, `FormatImportError`
- All six importers — handle skip/errors; `RowErrors` on result types
- Tests: context skip/error, product import skip + append-error

## Out Of Scope

- Reference CSV remap plugin (PR-823)
- Admin import UI
- Changing core validation errors to structured `ImportError` (hook errors only for now)

## API

```go
app.Import("acme/erp").RegisterRowHook(extapi.ImportEntityProduct, 100, func(ctx *extapi.ImportRowContext) error {
    if ctx.Row["matnr"] == "" {
        ctx.AppendError("erp.missing_matnr", "MATNR is required")
        return nil
    }
    if ctx.Row["matnr"] == "SKIP" {
        ctx.SkipRow()
    }
    return nil
})
```

**After hook chain:**

| Outcome | Importer behavior |
| --- | --- |
| `SkipRow()` | Row skipped, no error recorded |
| `AppendError(code, msg)` | Row skipped; `RowErrors` + formatted `Errors` |
| Handler `return err` | Row skipped; `line N: import row hook: …` (unchanged) |
| No skip/errors | Continue with mutated row map |
