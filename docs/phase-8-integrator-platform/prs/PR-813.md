# PR-813 — Tax Calculator Port

Status: done

## Summary

- Introduce `tax.Calculator` port and `RegisterTaxCalculator` plugin registration
- Extract core default as `RateTableCalculator` (existing rate-table behavior)
- Wire pricing pipeline `TaxStep` to delegate to the active calculator

## Why

Integrators need to replace tax calculation (external ERP/VAT services, custom rules) without patching the pricing pipeline or forking `TaxStep`. PR-801 catalogued the port; PR-813 ships the contract and core default.

## Scope

- `internal/domain/tax/calculator.go` — `Calculator` interface
- `internal/application/pricing/rate_table_calculator.go` — core default implementation
- `internal/application/pricing/tax_step.go` — delegates to `tax.Calculator`
- `internal/platform/plugin/providers.go` — `RegisterTaxCalculator` / `TaxCalculator()`
- `cmd/api/providers.go` — `resolveTaxCalculator`
- `cmd/api/main.go` — pricing pipeline uses resolved calculator
- `internal/application/ports/catalog.go` + `snapshot.go` — tax port marked shipped
- Unit tests (pricing, ports, plugin registration)

## Out Of Scope

- Reference plugin replacing tax (PR-853 template / PR-814 adjacent work)
- Config driver switch for tax (single registration winner, like search/cache)
- Admin tax UI changes

## Port contract

```go
type Calculator interface {
    Calculate(ctx context.Context, pctx *pricing.PricingContext) error
}
```

`PricingContext.Meta` keys unchanged from core `RateTableCalculator`:

- Required when calculating: `tax_country`, `tax_mode`
- Optional: `store_id`, `tax_classes`

When both tax meta keys are absent, calculators should no-op (storefront carts without tax context).

## Plugin API

```go
app.RegisterTaxCalculator(myCalculator) // must implement tax.Calculator; panics on double register
```

When no plugin registers, core uses `pricing.NewRateTableTaxCalculator(taxRateRepo, "standard")`.

## Validation

- `go test ./internal/application/pricing/... ./internal/application/ports/... ./internal/platform/plugin/...`
- `go build ./cmd/api/`
- Existing tax step tests pass via `RateTableCalculator`
- `GET /api/v1/admin/extensions/ports` reports tax as `core_default` or `active` when plugin registered

## What changed

- Tax calculation is a replaceable port; pricing pipeline unchanged externally (`tax` step name preserved)
- Port introspection lists tax as shipped with core default `pricing.RateTableCalculator`
