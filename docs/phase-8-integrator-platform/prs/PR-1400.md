# PR-1400 — Shipment status (integration + admin)

Status: done

## Summary

- Core `shipping.StatusService` marks shipments shipped (with tracking), delivered, or cancelled and publishes `shipment.*` events.
- `extapi.IntegrationShipmentStatusUpdater` + `plugin.App` wiring for inbound warehouse/ERP callbacks.
- `integrationdemo` route `POST …/shipment-status`.
- Admin `GET`/`PUT /api/v1/admin/orders/{orderId}/shipment` + order-detail UI (replaces the shipping placeholder).

## Why

Checkout already creates a pending shipment and email listens on `shipment.shipped`, but nothing called `Ship` / `Deliver` / `Cancel`. Integrators and merchants needed a write path for tracking updates.

Numbered **PR-1400** (not 856) so it does not collide with phase-9 export-hook PR-856.

## Scope

- `internal/application/shipping` — status service + tests
- `pkg/extapi/integration_shipment.go` — port + error codes (incl. payload / conflict)
- `internal/platform/plugin` — setter/adapter
- `plugins/integrationdemo` — shipment-status route
- Admin HTTP + `admin.js` order detail panel
- Docs: this spec, phase index/roadmap, PLUGINS, INTEGRATOR_PLATFORM, DEVELOPER, MERCHANT, demo README

## Out Of Scope

- Publishing `shipment.created` from checkout
- Amending tracking after ship (mismatched tracking on already-shipped → validation error)
- Multi-package shipments / reopen after cancel
- Adding shipment events to merchant webhook `SupportedEvents`
- Carrier rate provider port

## What changed

| Area | Change |
| --- | --- |
| Application | `MarkShipped` / `MarkDelivered` / `Cancel`; refuse cancelled/failed orders; heal-republish `shipment.shipped` on idempotent ship; typed tracking/order errors |
| Integration | Conflict → 409; missing tracking / blank order id → 400 `invalid_payload`; amend/lifecycle/not-fulfillable → 422 |
| Admin | `orders.read` / `orders.write`; audit `shipment.read` (success only) + `shipment.update` (incl. invalid body/status); cancel confirm |
| UI | Order detail shipping panel |
