# PR-823 — Reference Plugin: CSV Remap

Status: done

## Summary

- Ship `plugins/importdemo` reference plugin demonstrating ERP CSV column remap on `import:products`
- `import.product.row` maps SAP-style columns (`matnr`, `maktx`, …) to core product fields
- Config + compile-time registration; product import integration tests

## Why

Track C (PR-820–822) shipped import hooks; integrators need a copy-paste reference for ERP column normalization without forking `internal/application/importer`.

## Scope

- `plugins/importdemo/` — plugin, remap handler, README
- `internal/platform/config` — `plugins.importdemo` config + env var
- `cmd/api/register_plugins.go` — opt-in registration when enabled
- Unit + product importer integration tests

## Out Of Scope

- Production ERP connectors (plugin is reference-only)
- Price/stock/category remap (extend pattern per entity)
- Admin CSV upload UI

## Plugin behavior

| ERP column | Core column |
| --- | --- |
| `matnr` | `sku` |
| `maktx` | `name` |
| `maktx2` | `description` |
| `ext_slug` | `slug` |

When `slug` is empty after remap, derived from `sku`. Missing `matnr`/`sku` → `importdemo.missing_sku` via `AppendError`.

Enable:

```yaml
plugins:
  importdemo:
    enabled: true
```

Example CSV:

```csv
matnr,maktx,maktx2
SKU-001,Widget,A fine widget
```

```bash
app import:products erp-products.csv
```

## Validation

- `go test ./plugins/importdemo/...`
- `go build ./cmd/api/`
- ERP CSV imports product with remapped sku/name/slug
- Empty matnr row skipped with structured `importdemo.missing_sku`
- Plugin disabled → `Init` returns error (not loaded)
