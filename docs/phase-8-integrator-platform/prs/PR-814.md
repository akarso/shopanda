# PR-814 — Reference Plugin: Cart Rules

Status: done

## Summary

- Ship `plugins/cartdemo` reference plugin demonstrating integrator cart patterns
- `cart.validate` enforces per-line minimum quantity with structured errors
- `RegisterPricingStep(..., "after:promotions")` adds a flat handling fee
- Cart service integration tests cover blocked add + successful add with fee pipeline

## Why

Tracks B (PR-810–813) shipped the seams; integrators need a copy-paste reference showing how to combine validate hooks and positioned pricing steps without patching core.

## Scope

- `plugins/cartdemo/` — plugin, validate handler, handling fee step, README
- `internal/platform/config` — `plugins.cartdemo` config + env vars
- `cmd/api/register_plugins.go` — opt-in registration when enabled
- Unit + cart service integration tests

## Out Of Scope

- Production cart rules (plugin is reference-only)
- Admin UI for rule configuration
- Checkout validate surfacing

## Plugin behavior

| Mechanism | Registration | Default |
| --- | --- | --- |
| Min quantity | `cart.validate` hook | 2 per line |
| Handling fee | pricing step `cartdemo.handling_fee` at `after:promotions` | 50 minor units |

Enable:

```yaml
plugins:
  cartdemo:
    enabled: true
    min_quantity: 2
    handling_fee_minor_units: 50
```

Validation issue code: `cartdemo.min_quantity` (HTTP 422 on add/update when blocking).

## Validation

- `go test ./plugins/cartdemo/...`
- `go build ./cmd/api/`
- Add qty 1 → `ValidationFailed`, cart unchanged
- Add qty 2 → persists; merged pipeline applies 50 minor unit handling fee
- Plugin disabled → `Init` returns error (not loaded)

## What changed

- Reference cart-rules plugin wired via compile-time registration
- Demonstrates Phase 8 integrator acceptance: structured cart validation + custom pricing step
