# PR-812 — Cart Validate Chain

Status: done

## Summary

- Ship `cart.validate` hook chain with structured `CartValidationIssue` findings
- Run validation before cart mutations persist; block on error-level issues
- Surface `validation_errors` on storefront cart API responses (GET + mutations)

## Why

Before-hooks return generic errors. Integrators and storefronts need stable, machine-readable validation codes (min qty, assortment rules, B2B limits) without patching `cart.Service` or the HTTP layer.

## Scope

- `internal/application/hooks/context.go` — `HookCartValidate` + `CartHookPoints()`
- `internal/application/hooks/validation.go` — issue helpers
- `internal/application/cart/validation.go` — validate invocation + mutation guard
- `internal/application/cart/errors.go` — `ValidationFailed` error type
- `internal/application/cart/service.go` — validate before persist on add/update/remove/coupon paths
- `internal/interfaces/http/cart.go` — `validation_errors` in cart responses; 422 on blocked mutations
- `internal/platform/plugin/hooks.go` — sync mutable hook payload back from extapi handlers
- `pkg/extapi/hooks.go`, `pkg/extapi/validation.go` — stable hook + issue API
- Cart validate integration + HTTP tests

## Out Of Scope

- Reference cart rule plugin (PR-814)
- Checkout-level validate surfacing (checkout already has workflow steps)
- Admin UI for validation rules

## Hook placement

| Hook | When | Payload keys |
| --- | --- | --- |
| `cart.validate` | After in-memory mutation + recalculate, before persist; also on cart read via HTTP | `cart_id`, `customer_id`, `cart`, `validation_errors` (mutable `*[]CartValidationIssue`) |

Handlers append issues via `ctx.AppendValidationError(...)` (extapi) or `hooks.AppendValidationIssue(...)`. Do **not** return business-rule failures as handler errors — append structured issues instead.

| Issue level | Behavior |
| --- | --- |
| default / empty | Blocking — mutation is rejected with HTTP 422 `cart_validation_failed` |
| `warning` | Informational — included in `validation_errors` on successful responses |

## API

```go
app.Hooks("acme/rules").Register(extapi.HookCartValidate, 100, func(ctx *extapi.HookContext) error {
    qty, _ := ctx.Get("quantity") // not on validate payload — read from cart snapshot
    cart, _ := ctx.Get("cart")
    // inspect cart lines, append issues:
    ctx.AppendValidationError(extapi.CartValidationIssue{
        Code:      "acme.min_qty",
        Message:   "minimum order quantity is 5",
        VariantID: "var-1",
    })
    return nil
})
```

Storefront response shape:

```json
{
  "data": {
    "cart": { "...": "..." },
    "validation_errors": [
      { "code": "acme.min_qty", "message": "minimum order quantity is 5", "variant_id": "var-1" }
    ]
  },
  "error": null
}
```

Blocked mutation (422):

```json
{
  "data": {
    "cart": { "items": [] },
    "validation_errors": [{ "code": "acme.blocked", "message": "not allowed" }]
  },
  "error": { "code": "cart_validation_failed", "message": "cart validation failed (1 issue(s))" }
}
```
