# PR-843 — Reference Plugin: PIM GraphQL PDP

Status: done

## Summary

- Ship `plugins/pimdemo` reference plugin for outbound PIM GraphQL PDP enrichment
- Register `pim_enrichment` composition step on the PDP pipeline
- Fetch marketing content by product slug via `pkg/integrationsdk/graphql` with in-memory TTL cache

## Why

Track E (PR-840–842) shipped sync jobs, HTTP/GraphQL clients, and warehouse pull. Integrators also need a read-path reference showing how to enrich PDP API responses from an external PIM without forking core or importing Postgres from `plugins/*`.

## Scope

- `plugins/pimdemo/` — plugin, GraphQL fetcher, TTL cache, composition step, README, tests
- `internal/platform/config` — `plugins.pimdemo` config + env vars
- `cmd/api/register_plugins.go` — opt-in registration

## Out Of Scope

- Shared core cache port for PIM (plugin-owned in-memory TTL cache only)
- PLP/listing enrichment
- Production PIM connector certification
- Plugin SDK helpers (Track F, PR-850+)

## Plugin behavior

| Concern | Implementation |
| --- | --- |
| Pipeline | `RegisterCompositionStep("pdp", …)` — runs after core PDP steps |
| GraphQL | `POST {pim_graphql_endpoint}` with slug variable |
| Cache | In-memory TTL (default `5m`, configurable) |
| Failure mode | Log + skip block; PDP still returns core product data |

Enable:

```yaml
plugins:
  pimdemo:
    enabled: true
    pim_graphql_endpoint: "http://localhost:9091/graphql"
    pim_api_key: optional-bearer-token
    cache_ttl: "5m"
```

Mock PIM query:

```graphql
query ProductEnrichment($slug: String!) {
  product(slug: $slug) {
    marketing_title
    marketing_description
    specs { key value }
  }
}
```

PDP response adds a `pim_enrichment` block when content is returned.

## Validation

- Plugin Init registers one PDP composition step
