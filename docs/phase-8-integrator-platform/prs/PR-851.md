# PR-851 — Registration Report

Status: done

## Summary

- Ship `internal/application/pluginreport` builder for plugin registrations and infrastructure ports
- Log structured `plugin.registration.summary` at startup after plugin init
- Add `./app plugins report [--json]` CLI (no database required)

## Why

PR-801 added admin port introspection; integrators still need a single view of behavioral registrations (pricing steps, hooks, import hooks, sync jobs, routes) without spelunking `main.go` or guessing from logs.

## Scope

- `internal/application/pluginreport/report.go` — `Build(registry, app, cfg)`
- `internal/application/pluginreport/format.go` — text + JSON formatters
- `internal/application/pluginreport/summary.go` — startup log summary
- `cmd/api/plugins_report.go` — CLI bootstrap + `plugins report` command
- `cmd/api/main.go` — command dispatch, help text, startup summary
- Unit tests

## Out Of Scope

- Replace-by-name pipeline steps (PR-852)
- Admin HTTP endpoint for full registration report (ports endpoint remains PR-801)
- Merged pricing pipeline preview with live core step instances

## CLI

```bash
./app plugins report
./app plugins report --json
```

Report sections: plugins (lifecycle), infrastructure ports, core + plugin pricing steps, hooks, import row hooks, composition steps, checkout steps, sync jobs, public/admin routes.

## Validation

- `go test ./internal/application/pluginreport/... ./cmd/api/... -run 'Plugin|pluginreport|PluginsReport'`
- `go build -o /tmp/shopanda-api ./cmd/api/`
- `./app plugins report` with cartdemo enabled lists pricing step and cart.validate hook
- Server startup emits `plugin.registration.summary` with counts

## What changed

- Integrators can inspect all registered extension points from CLI and see registration counts at startup
