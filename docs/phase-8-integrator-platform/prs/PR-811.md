# PR-811 — Cart Lifecycle Hooks

Status: done

## Summary

- Ship cart lifecycle hooks: `cart.add_item.before`, `cart.update_item.before`, `cart.remove_item.after`, `cart.recalculate.before`
- Wire hooks in `cart.Service` at documented lifecycle points
- Extend `pkg/extapi` stable v0 hook catalog + compat tests

## Why

Integrators need to validate or block cart mutations and inject pricing context without patching `cart.Service`. PR-810 positioned pricing steps; PR-811 adds synchronous cart hook seams.

## Scope

- `internal/application/hooks/context.go` — hook name constants + `CartHookPoints()`
- `internal/application/cart/hooks.go` — shared invoke helpers
- `internal/application/cart/service.go` — hook invocation in Add/Update/Remove/recalculate
- `pkg/extapi/hooks.go` — stable hook point constants
- `pkg/extapi/compat_test.go` — internal/stable parity
- Cart hook integration tests

## Out Of Scope

- `cart.validate` structured errors (PR-812)
- Reference cart rule plugin shipped in PR-814 (`plugins/cartdemo`)
- Admin hook catalog UI changes (existing `GET /api/v1/admin/extensions/hooks` lists new hooks automatically)

## Hook placement

| Hook | When | Payload keys |
| --- | --- | --- |
| `cart.add_item.before` | After price lookup, before in-memory add | `cart_id`, `customer_id`, `variant_id`, `quantity`, `cart` |
| `cart.add_item.after` | After persist (unchanged) | same |
| `cart.update_item.before` | Before quantity mutation | same |
| `cart.remove_item.after` | After persist | `cart_id`, `customer_id`, `variant_id`, `quantity` (0), `cart` |
| `cart.recalculate.before` | Before pricing pipeline | `cart_id`, `customer_id`, `cart`, `pricing_meta` (mutable map → `PricingContext.Meta`) |

Handler errors are split by hook timing:

- **Before hooks** (`cart.add_item.before`, `cart.update_item.before`, `cart.recalculate.before`): an error stops the operation before the mutation or pricing run completes. The cart is not persisted with the attempted change.
- **After hooks** (`cart.add_item.after`, `cart.remove_item.after`): the mutation has already been saved when the hook runs. An error is logged for observability; the service still returns the successfully persisted cart and does **not** roll back. Callers must not retry the same mutation solely because an after-hook error was logged — the line add/remove already succeeded.

## API

```go
app.Hooks("acme/rules").Register(extapi.HookCartAddItemBefore, 100, func(ctx *extapi.HookContext) error {
    return nil // return error to block add
})

app.Hooks("acme/rules").Register(extapi.HookCartRecalculateBefore, 100, func(ctx *extapi.HookContext) error {
    meta, _ := ctx.Get("pricing_meta")
    m := meta.(map[string]interface{})
    m["acme.tier"] = "gold"
    return nil
})
```
