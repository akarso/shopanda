# PR-821 — Wire Core Importers

Status: done

## Summary

- Invoke import row hook chain in all six CLI importers after header parse, before persist
- Add `WithRowHooks(registry)` on each importer; shared `RowHookRunner` helper
- Bootstrap plugins on `import:*` CLI commands so registered hooks run

## Why

PR-820 shipped the registry; integrators need CLI imports to actually call registered hooks so ERP column remaps take effect before DB writes.

## Scope

- `internal/application/importer/rowhooks.go` — `RecordToRow`, `RowHookRunner`, `RowHookError`
- Wire row hooks in: `products`, `prices`, `stock`, `categories`, `customers`, `attributes`
- `cmd/api/import_plugins.go` — `bootstrapImportRegistry` (plugin Init + shared registry)
- `cmd/api/main.go` — all `import:*` commands pass registry via `WithRowHooks`
- Tests: row hook remap + hook error skip; fix order-independent product import test

## Out Of Scope

- `Skip` flag and aggregated `ImportResult` errors (PR-822)
- Reference CSV remap plugin (PR-823)
- Async import job wiring (unchanged)

## Behavior

1. Parse CSV header and validate entity-specific columns (products relax required-column header check when row hooks enabled — hooks may add columns)
2. For each data row: build row map → `registry.Invoke` → read fields from mutated map
3. Handler error → row skipped, `line N: import row hook: …` in result errors
4. Continue existing persist / transaction boundaries unchanged

## Validation

- `go test ./internal/application/importer/...`
- `go build ./cmd/api/`
- Product CSV with `matnr` + hook mapping to `sku` imports successfully
- Hook handler error skips row without double-counting

## What changed

- CLI importers invoke plugin row hooks pre-persist; plugin registration from PR-820 is now effective on `import:*` commands
