# PR-1313 — Admin forms + settings

Status: planned

## Summary

- Form layout: sections/fieldsets with headings, label/hint/error pattern, two-column grid on wide screens.
- Unify `admin-form-hint`, `settings-scope-note`, `settings-scope-badge`, `settings-scope-banner` into one documented set.
- Validation states (invalid, required, disabled) and a consistent save/cancel bar.
- Product edit sections (`product_*_section.js`) adopt the same field pattern.

## Why

Settings and product edit are long forms; inconsistent hints and scope notes make store/website scoping hard to read.

## Scope

- `admin.css` forms section; `admin.js` and `product_*_section.js` markup.
- Keep input `name`s / `id`s used by `collectProductPayload` and section tests.
- Before/after screenshots: settings general, a scoped setting, product edit (each product type).
- Skills: `typography`, `webapp-testing`.

## Out Of Scope

- New fields or validation rules.
- Phase 15 Store Information / Address forms if not yet merged (they adopt this pattern when they land).

## Decisions

- Sticky save bar vs bottom-of-form buttons — propose with recommendation.
