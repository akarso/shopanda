# PR-1301 — Design direction

Status: planned

## Summary

- Put decisions D1–D9 (see [`../specs/VISUAL_REFRESH.md`](../specs/VISUAL_REFRESH.md) §2) to the maintainer, one at a time, each with options and a recommendation.
- Render candidate palettes and type pairings as a static preview page (swatches, contrast ratios, sample table/form/product card) so choices are made on visuals, not hex codes.
- Record answers in `specs/DESIGN_DIRECTION.md`.

## Why

Admin and storefront need a single agreed direction before tokens are written. Choosing silently inside implementation PRs leads to drift and re-work.

## Scope

- `specs/DESIGN_DIRECTION.md`: per decision — chosen option, rationale, date; final primitive palette, semantic role mapping, type scale, spacing scale, radius, shadow per surface.
- Preview page under `docs/phase-16-visual-refresh/preview/` (static HTML, not shipped in the binary).
- Skills: `bencium-controlled-ux-designer` (ask-first), `typography`, `design-system`.

## Out Of Scope

- Shipping any token or CSS into admin or themes (PR-1310 / PR-1320).

## Decisions

All of D1–D9. Expected questions:

1. Admin personality (recommend: neutral tool).
2. Storefront personality (recommend: refine current warm editorial).
3. Keep and vendor Pico, or drop it (recommend: keep + vendor).
4. Fonts per surface (recommend: admin system stack; storefront one self-hosted display face).
5. Accent palette per surface — pick from 3 rendered options.
6. Admin density (recommend: compact tables, comfortable forms).
7. Dark mode scope (recommend: admin only).
8. Icon sprite yes/no and set (recommend: small Lucide subset).
9. Accessibility target (recommend: WCAG 2.2 AA).

- PR-1320 — storefront foundation.
