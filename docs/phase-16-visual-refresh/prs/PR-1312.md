# PR-1312 — Admin lists + tables

Status: planned

## Summary

- One table style (density per D6, sticky header, numeric alignment, row hover, truncation).
- One list toolbar (search, filters, primary action) and pagination style.
- One status badge/chip component replacing ad-hoc `badge` / `chip` variants.
- Empty and "no results" states.

## Why

Lists (orders, products, customers, returns, coupons, …) are where merchants spend most time. Today each `render*` builds its own markup.

## Scope

- `admin.css` components section: `.admin-table`, `.admin-toolbar`, `.admin-pagination`, `.badge` (with semantic variants), `.empty-state`.
- `admin.js`: list renderers emit the shared classes; small helper(s) for badge and empty state if it removes duplication. No behavior change.
- Update `*_test.js` / Go tests only where asserted markup changes.
- Before/after screenshots of every list route.

## Out Of Scope

- Server-side pagination/filter changes.
- Forms and detail pages (PR-1313).

## Decisions

- Status → color mapping (e.g. order states) — propose table with recommendation.
